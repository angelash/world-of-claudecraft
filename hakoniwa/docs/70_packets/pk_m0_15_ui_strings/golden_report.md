# PK-M0-15 界面字符串表：`c.` 键替换的金样报告

> 发行工程第 8.4 节第 5 步的同一方法（PK-M0-14 的 [golden_report.md](../pk_m0_14_text_keys/golden_report.md) 第 1 节）：内核把内容显示名从字符串换成内容键后，原样的世界哈希必然改变，
> 因此把事件与世界里的每个 `TextRef` 先用 `locales/zh-Hans/` 的表与内容查表渲染成中文，再比较。入口见 [README.md](README.md)。

## 1. 方法

- **跑什么**：无模型档、种子 `20261115`（`tests/playthrough/harness.ts` 的 `SEED`），自动玩家各走一遍两条结局路线 `release` 与 `rule_merca`，直到结局；
  `tests/playthrough/text_golden.playthrough.test.ts` 记录自动玩家结果、全部事件渲染后的哈希（总、按种类、每 20000 tick 一窗）、每次换幕与结局时各系统切片、元数据、AI 状态与全部旗标。
  本包给它加了 `TEXT_GOLDEN_MAX_TICKS`（默认 6000000），两次运行都在上限内正常走到结局。
- **怎么比**：`node tools/i18n/golden_diff.ts <替换前.json> <替换后.json>`，逐项比较（耗时不比）。
- **隔离并行改动**：工作区里同时有 PK-M0-29（历法、成长、`data/` 数值）与 PK-M0-25（台词包，删除 `data/dialogue/templates.json`）的未提交改动。
  开工时把 `src/`、`data/`、`locales/` 与通关测试复制成"替换前"快照；替换后不直接在工作区跑，而是复制一份"替换后"快照，数据目录与替换前逐字节相同，
  只叠加本包的文件（内核、渲染器、字符串表与生成物）。所以两次运行的玩法输入完全一样，比较只反映本包的改动。
- **渲染路径**：金样测试在开局时调用 `setContentText(contentTextLookup(content))`，与客户端启动一局的做法相同；替换前的 `contentTextLookup` 按记录逐字段查，
  替换后由抽取器按同一套键生成，两者对同一内容给出同样的文字。

## 2. 结果

| 轮 | 改动 | release | rule_merca |
| --- | --- | --- | --- |
| 一 | 城建、经济（集市、物品、配方）、战略（郡、兵种）、女神行动的地点、任务交付标题换成内容键（39 处），界面表迁移，渲染器、伪本地化 | 一致 | 一致 |
| 二 | 审查后补换：女神名与神行动标签、梅尔卡的拒绝与供奉记录、商会名、生产缺料与竞争者的物品名、城建连通性拒绝、行军路线与野战名的郡名（另 19 处），客户端内容名回退，伪语言列表分隔符 | 一致 | 一致 |

"一致"指 `golden_diff.ts` 输出 `identical (text rendered)`：自动玩家结果、全部事件逐个渲染后的序列、7 个换幕检查点与结局的切片、元数据、AI 状态与全部旗标都相同。

| 路线 | 结局 | tick | 事件数 | 渲染后事件流哈希 |
| --- | --- | --- | --- | --- |
| release | release | 2366897 | 324011 | `194c3b4cf66266aa` |
| rule_merca | rule_merca | 1778105 | 308735 | `69b495bf5cbd3c02` |

这组数字是替换前快照（含 PK-M0-29 当时的玩法改动）的结果，与 PK-M0-14 报告里的基线（tick 1935113 与 1474289）不同，原因是 PK-M0-29 的历法与成长改动，与本包无关。

## 3. 第二轮

第二轮的快照在第一轮"替换后"快照上叠加审查后改动的文件（内核十余个文件、渲染器、字符串表），数据目录仍与替换前相同。两条路线的结果与第 2 节表中数字逐项相同，`golden_diff.ts` 输出 `identical (text rendered)`。

## 4. 未换的参数

任务接受标签（`sys.quests.label.accept`）仍以任务标题字符串传：PK-M0-29 的在制测试 `tests/quests.test.ts` 按字符串参数断言它，本包不改那份测试；
其余未换的系统（战场、对话、认知、NPC、场景、导演、同伴等）见 [progress.md](progress.md) 的遗留表。渲染结果不受影响。
