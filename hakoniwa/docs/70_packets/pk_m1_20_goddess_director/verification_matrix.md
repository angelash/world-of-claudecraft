## 3. 自动玩家路线（末次代码变更之后，一次，后台）

命令：`npx vitest run --config vitest.playthrough.config.ts tests/playthrough/act1_minimal.playthrough.test.ts`（合入他包的序章与地图之后；整套 `npm run playthrough` 两次在后台被连接中断或超过一小时，没有跑完，所以只跑了代表性的一条）。

| 路线 | 结果 | 用时 |
| --- | --- | --- |
| `act1_minimal` | FAIL：7 级、死亡 67 次，`stuck: no progress for 230400 ticks while: rest (backing off)`（第 696684 tick，第一幕 0 tick） | 1088 秒 |
| `replay_segments`（整套里的一次） | 存到第 29 档后钩子超时（要 40 档） | 2781 秒 |

这两处停滞不是本包造成的。证据：同一条路线、同一种子，跑到第 450000 tick，带导演与不带导演的结果逐项相同（6 级、死亡 42 次、10 个任务、都停在 `fight dian_rat (defend)`）；女神系统去不掉（场景运行器读它的切片，去掉就崩），但她第一幕菜单上没有碰战斗的动作（神谕、加护的经验加成、神迹的信心与士气、调价、梦、征兆、凝视，另有梅尔卡的特产与借贷、莫伊拉的预言、希尔薇的兽引，战斗只读 `monster` 与 `xp` 通道，加护只加经验）。PK-M1-12、PK-M1-27、PK-M1-35 的验收矩阵记着同一类停滞（`q_a1_m02_raven` 的练级与落石开关、自动玩家的就绪规则），归 PK-M1-35 与自动玩家（PK-M1-10）。本包第 1.1 节的 20 个种子用自己的夹具，不经自动玩家，不受它影响。
