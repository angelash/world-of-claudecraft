# 第一轮可玩版本：交付说明（截至 2026-11-15）

> 本文记录第一轮实现做到了什么、怎么运行、如何验证、还缺什么。架构与约定见
> `../50_tech/architecture.md`、`../50_tech/ai_architecture.md`、`../50_tech/implementation_conventions.md`；
> 实现期间做出的决定见 `../00_vision/decision_log.md` 的 D-057 到 D-061。

## 1. 怎么运行

1. 仓库根目录安装主工程依赖（提供 Vite、Vitest、TypeScript、Biome）：`npm ci`。
2. 进入 `hakoniwa/` 安装本子项目的依赖（官方 Claude SDK，供开发服务的模型代理使用；`three`，供 HD-2D 渲染）：`npx npm@10 ci`。
3. `npm run dev`，打开 `http://localhost:5180/`（游戏）与 `http://localhost:5180/editor.html`（编辑器与审核工作台）。
4. 可选：在启动开发服务的环境里提供 Claude 凭据（`ANTHROPIC_API_KEY` 或 `ant auth login`），并在游戏设置里打开"大模型"开关，
   女神与 NPC 就会由模型驱动；没有凭据时全部走规则兜底，游戏照样完整可玩。
5. 测试：`npm test`（默认套件）、`npm run playthrough`（无模型通关，较慢，约 10 分钟）、`npm run typecheck`、`npm run build`、
   `npm run format -- <文件>`（固定版本的 Biome）。

## 2. 已实现的内容

### 2.1 确定性内核（`src/core/`）
20Hz 固定步长、按系统命名的随机流、世界切片与事件、命令队列（外部命令先于系统命令）、AI 请求端口（带确定性兜底与截止时间）、
存档（快照不含重放日志）与重放（初始世界加命令日志，不调用模型即可复现一局）、架构守卫（逻辑层禁止 DOM 与非确定性 API）。

### 2.2 玩法系统（`src/systems/`，按相位顺序）

| combat | 九职能与编外者伪职业、技能、光环、仇恨、经典公式与位阶威压、魔物 AI、首领机制、波次（兽潮）、掉落与经验、退回门内 |
| party | 从者与同伴、跟随与协助、羁绊 |
| doors | 千门回廊：门的钥、提示、开启与关闭、功能解锁、封印松动与躁动 |
| npc | 人设卡、五档分级推理、日程与需求、行动、多维关系、记忆与日记、AI 每日计划与批量日记 |
| dialogue | 交谈、内置与外部选项、自由输入、NPC 回答（规则模板或模型） |
| cognition | 目击与信念画像、常识上限与解释库（"凡人不信"）、传闻传播与失真、声望、鉴定（D-029）、威压感知 |

| director | 莫伊拉的叙事导演：张力计、巧合与喘息 |

### 2.3 AI 层（`src/ai/`、`src/game/ai_roles/`、`tools/`）
提供方无关的运行器（并发、预算、5 级降级、超时、冷却、过时作废）、9 个角色包加通用兜底、审计日志；开发服务代理用官方 SDK 调用
Claude（结构化输出、提示缓存、显式 effort、拒绝检查与服务端回退），密钥只在服务端。推荐档见 D-059 与 `ai_architecture.md`。

### 2.4 客户端（`src/client/`）
渲染是 HD-2D 三维场景（`src/client/hd2d/`，Three.js，D-058），沿用 my_ai_town 的做法：正交斜俯视相机（俯角默认 36 度，
可在 30 到 82 度间调；方位角可 360 度旋转；整数缩放档）；整张地图画成一张像素地面贴图（每格 16 像素，软地块之间有序抖动过渡，
水面在着色器里动）；有顶地点按外壳挤出立体房屋与屋顶，玩家所在与选中目标所在的建筑掀顶溶解（摆放建筑时全部掀开）、外墙降为半高剖面；人物纸娃娃、魔物、树、石、
装饰都是朝向镜头的像素立牌，按"竖直立在脚下"计算深度，人物脚下有接触阴影；太阳平行光阴影加天光，门灯、路灯、窗光烘进静态光照图，
另有至多 8 盏动态光；天气粒子与后期链（调色、暗角、颗粒，高档另有泛光与移轴）。名字、头顶标记、对话与心声气泡、浮字画在叠加的
覆盖层画布上，位置由三维投影得出。

画质档分高、中、低、平面。平面档是 Canvas2D 俯视平面渲染（`src/client/render/flat_renderer.ts`），无 WebGL 时自动使用；
两种渲染都实现 `src/client/render/renderer.ts` 的 `WorldRenderer` 接口，由 `src/client/hd2d/index.ts` 的 `createWorldRenderer`
创建（HD-2D 建不起来时退回平面）。每张地图用风格包定画风（`MapDef.style`，没写时按区域映射）；地图外观层（`style`、`looks`、
`decor`，类型与编号表在 `src/systems/world/look.ts`）只有渲染器读，改外观不改玩法。

视角操作：滚轮与 +、- 换缩放档，右键拖动左右转方位、上下改俯角，Z、X 键各转 45 度，G 键在街景与俯视间切换，Home 键复位，
视角偏好存本机。输入（WASD 与方向键按屏幕方向移动、点击寻路、Tab 选敌、E 交互、数字键技能、V 鉴定）、HUD 与全部窗口（角色、
千门回廊、任务、传闻与声望、同伴、背包与交易、商会、领地与摆放预览、战场画面（俯视战术图）、大陆地图、女神与神之记录、设置、存档）、
全屏场景面板。开发模式工具只在开发构建中存在。

### 2.5 编辑器与可视化审核工作台（`src/editor/`）
内容编辑器（按模式生成表单、保存前差异审查与内容校验；地图外观层也在这里按表单编辑）、地图编辑器（以俯视格子编辑逻辑层与空间层：
地块、地点、出生点、出口、可走性与连通性检查、撤销）、
世界检视器（加速运行、旗标与修正项、实体与事件流、快照、确定性检查）、内容检查台、AI 审计台（含历史日志与揭示复核）、
角色检视（NPC 记忆、信念、关系；女神的神力、神约与神迹账）、任务与剧情图（旗标写入索引与可达性分析）、平衡实验室（战斗、战场、经济）。

### 2.6 自动玩家（`src/game/autoplay/`）
只用玩家命令的无头机器人，用于 D-010 验收与回归。

## 4. 待设计确认的事项

1. D-060 的平衡改动（首领等级同步、无貌之王大幅削弱、战役英雄等级下限）是为了让三人小队的第一轮内容可通关，需要设计方确认方向。
2. 等级曲线与内容等级段脱节：主线经验约把玩家带到 11 级，而内容按 15 到 60 级设计（见 `../40_design/content/content_outline.md` 体量对照表）。
3. 无模型通关约需 200 万 tick，主要耗在三段游戏内等待（立村、领地自治度 40、国家自治度 60）；需要空闲快进或调整自治度增长节奏。

## 5. 已知缺口（进入详细设计与第二轮实现时处理）

- 设计文档 B-001 的四份系统文档仍未撰写，战斗、千门、同伴、成长的实现目前以正典与第一轮代码为准。
- 两扇危险门（渡魂之门、破门之门）对应的仪式尚未实现；诸神之战路线的触发条件不足；立国事件链（无主之地、众愿、界石）只映射到现有旗标。
- 战场与大陆视图缺少若干字段（英雄当前命令与技能范围、能否立国的信号、征兵费用、行军进度等）。
- 表现层后续项：战场进入 HD-2D 场景（兵团用烘焙帧图集加实例化立牌，A-14）；编辑器内嵌 HD-2D 预览（A-16）；按 GPU 计时自动降画质档（A-13）。
- HD-2D 第一轮未做的部分（`../50_tech/art_pipeline.md` 的目标规格）：按需重画（目前逐帧绘制）；超过显卡贴图上限的大地图地面分块；
  界外轻雾；窗光贴图的像素抗锯齿采样；四坡屋顶两端的像素密度统一；人物接触阴影与选中环的像素化画法；静态光照图与动态光的颜色换算统一。
- 场景效果给自治度的加分会被城建的每日结算覆盖。
- 大模型路径只在模拟提供方与审计台上验证过，尚未在真实模型下跑完整一局。
- 战斗系统少数地方直接写世界实体字段（集中在 `combat/entity_ops.ts`），待补世界端口后替换。
- 详细设计待办 B-002 到 B-013（变量注册表、编号规则、内容体量缺口等）见决策日志第 3 节。
