## 0. 一页结论

1. **风格一句话：像素微缩模型加电影光。** Three.js 正交斜俯视相机；地面是一张像素贴图，房屋是贴像素贴图的立体墙与屋顶，人物、魔物、树石与装饰是朝向镜头的像素立牌，再叠太阳阴影、光照图与电影化后期（D-003、D-058）。
2. **素材全部 AI 生成（D-018）。** 人物、魔物、首领、兽伴坐骑、地面、墙面与屋面、立面构件、道具、远景、图标、特效、界面、兵团、地图与宣传图，都是用户把提示词库交给小九 AI 生成的位图，经导入管线进入游戏。
   提示词库 `assets/prompts/` 有 16 个风格包、82 个模板与按类别的条目文件，`npm run prompts` 展开成逐条可复制的提示词与预期清单。
3. **单一像素密度。** 1 格 = 1 米 = 场景 1 个单位 = 16 像素。AI 原图在导入时网格对齐降采样到每米 16 像素，按风格包调色板量化，描边统一为 1 像素的深色邻色描边，光向固定左上。
4. **一致性靠四件事：** 风格锚（每个风格包一段固定锚句加 8 到 16 色锚色）、参照先行（风格板、人物与魔物三视图）、固定描述块（同一角色的每张图重复同一段辨识特征）、导入量化（调色、描边与尺寸由代码统一）。
5. **人物：** 约 40 名主要角色（含女神形象）有独立整套帧图、8 表情头像与半身立绘；其余约 300 名有名 NPC 与全部居民用 AI 生成的纸娃娃部件组装（固定人台、键色换色、头部刚体层），
   每名有名 NPC 另有 4 表情头像（D-078）；主角是玩家自定外观，同样用纸娃娃。
6. **魔物按体型分模板：** 小、中、大、巨型、多足、长躯、飞行、无定形、亚龙；蛛、蜈、水蛭、亚龙各有自己的剪影，不与狼共用。首领有 6 行动作表、巨型首领的分部件拆图与登场插画。
7. **程序化绘制的位置：** 素材到位前的占位，以及平面降级档里没有对应位图的部分（平面屋顶、墙顶）。任一编号的素材未通过审核时自动退回程序化占位，所以任何内容在任何时刻都能显示。
8. **数量：** 全作 9,129 张入库位图（各类别见第 9.1 节，以提示词库统计为准），按里程碑分批：M0 51、M1（序章与第一幕）2,229、M2 3,110、M3 3,447、M4 6；以提示词库统计为准（第 9 节）。
9. **画质档：** 超高、高、中、低、平面。超高与按 GPU 计时的自动降档在 M3（Beta）上线，降档告知玩家，每局至多两次（D-078）。任何档都保留可行动信息（2.12、4.10）。
10. **合规：** 每个文件登记生成工具、提示词编号与哈希、日期、种子、参照与审核状态；保留生成服务写入的隐式标识；Steam 内容调查如实申报开发期 AI 生成的美术与音频，以及运行时由玩家配置的大模型生成的文本（6.7）。

## 1. 风格规范

### 1.1 风格目标与红线

- **目标：** 西方奇幻边陲的"箱庭"微缩感。镜头像在俯看一座被精心照看的微缩模型，这正是书名的字面意思。白天明快，夜里冷暗配暖光；
  轻快表层下有澱的暗流（`../00_vision/vision.md` 第 6 节）。
- **红线一：不复刻任何具体作品的美术**（`../00_vision/vision.md` 第 8 节）。提示词、风格锚与给生成者的说明里不出现任何作品、作者、画师、工作室、商标的名字，
  也不写"HD-2D"这个词，一律写成"高清像素微缩场景、带现代光影的像素立体透视场景"；不以在世画师为模仿对象。从 my_ai_town 借鉴的是方案与做法，造型、色板、题材全部原创（D-017）。
- **红线二：素材不自带环境光影。** 每个模板都写明"不画投影、不画地面、光从左上方照来"；投影、环境色、昼夜与天气由渲染层统一施加（调研 1.4 节）。
- **红线三：素材里不写字。** 招牌、告示、书页、碑文只用纹章与图形；导入校验对每张图做文字检测（13 节第 12 步）；所有文字由界面层从文本表绘制（D-077，`src/shared_ui/text.ts` 的 `T`）。
- **红线四：观感让位于可读性。** 第 2.12 节与第 4.10 节的保留清单优先于任何光影、后期与特效。
- **红线五：风格只来自本作。** 素材的风格只来自本作的风格锚、调色板与已审定的参照图；生成工具自带的"风格预设"若以其他作品或画师命名，一律不用。

### 1.2 视角与相机

| 项     | 规格                                                               | 说明                                                                                       |
| ------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 投影   | `THREE.OrthographicCamera` 正交斜俯视                              | 无透视变形，远近同大，像素尺寸处处一致                                                     |
| 俯角   | 默认 `DEFAULT_PITCH` 36 度，范围 `PITCH_MIN` 30 到 `PITCH_MAX` 82  | 地面纵深在屏幕上缩为 sin(俯角)，竖直高度显示为 cos(俯角)；俯角越低越像街景                 |
| 方位角 | `yaw` 360 度可转；默认 0 表示屏幕上方是地图北方                    | 与内核 +y 向南一致，默认视角下与编辑器的俯视地图同向                                       |
| 预设   | `VIEW_PRESETS`：街景（俯角 36）、俯视（俯角 64）                   | 街景看人与街巷，俯视看布局、城建与战斗站位                                                 |
| 跟随   | 相机跟随玩家                                                       | 拉远时地图外是深色"界外"底色与轻雾；街景俯角下远处是远景天幕（2.13）                       |
| 偏好   | 俯角、方位角、缩放档存本机                                         | 不进存档，不影响回放                                                                       |

- 依据：my_ai_town 的同一组相机参数与"街景、俯视"预设（调研 1.5、2.3 节）。实现位于 `src/client/hd2d/view.ts`，缩放与操作见 2.3。
- 人物与魔物的显示朝向由"内核朝向加上相机方位角"量化得出（3.5，`view.ts` 的 `screenFacing`），所以转动镜头时人物相对屏幕的朝向始终正确。
- AI 素材的绘制角度据此统一为"略带俯视的正面角色视角"：立牌后仰正对镜头，画面上看到的永远是素材的正面，所以素材本身不画成 36 度俯视的透视图。

### 1.3 尺度与像素密度

- **1 格 = 1 米 = 场景 1 个单位**；地面每格 16 像素（`TILE_PX` 16）。
- **单一像素密度：** 地面、墙面、立牌（人物、魔物、树、道具）都按每米 16 像素进入游戏，整幅画面的像素颗粒一样大。
  AI 生成画布比入游戏尺寸大得多（第 11 节），导入管线按内容高度把它降到每米 16 像素，所以模板里写"人物约占格高的六成"等比例措辞，就是为了让降采样后的本体高度落在下表区间。
- 野外地图在距离上做视觉压缩（`../20_world/geography.md` 第 7.2 节），压缩的是地点之间的距离，不是物件的画法。

| 对象                                   | 实际尺寸                   | 像素                                   |
| -------------------------------------- | -------------------------- | -------------------------------------- |
| 1 格                                   | 1 米                       | 16                                     |
| 标准人形身高（Q 版，H）                | 约 1.75 米                 | 本体约 28（帧格 48×48，锚点 (24, 44)） |
| 小型人形（矮人、半身人、孩童，HS）     | 约 1.1 到 1.4 米           | 本体约 20 到 22（帧格 48×48）          |

  墙面同样每米 16 像素（民居墙约 42 像素，塔楼 96 像素）。风格包按功能给默认值，地图外观层的 `looks` 可逐地点覆盖（5.2）。

### 1.5 描边与光向

- **光向固定左上：** 亮面朝左上，暗面朝右下。每个模板都写"光从左上方照来"；导入审核把光向错误列为淘汰项（不能靠代码修正）。
  场景里的太阳只决定投影与整体明暗，不改立牌的固有明暗，这与 my_ai_town 的做法一致（调研 1.4 节）。
- 每种材质 2 到 3 级明暗加最多 1 级高光；大面积过渡只用有序抖动。

| 对象                       | 规则（导入管线第 7 步强制执行）                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 人物、魔物、树、石、装饰   | 外轮廓 1 像素，颜色取相邻填充色色阶的描边级（深化邻色，不用纯黑）；底边与右边取深描边级；大体型（帧格不小于 96 或 `scale` 不小于 1.5）受光侧再提亮一级 |
| 内线                       | 只在材质交界处（皮肤与布、布与金属）出现，保留 AI 原图里的交界明暗                                                                                     |
| 墙面与屋面贴图             | 不描外轮廓；砖缝、木筋、瓦行用本材质的暗级；屋檐与墙顶留一行亮边                                                                                        |
| 地面                       | 不描边                                                                                                                                                  |
| 特效                       | 不描边，加色混合                                                                                                                                        |
| 头像与半身立绘             | 外轮廓 1 像素深色邻色；内部保留原图的明暗                                                                                                               |

禁止：纯黑描边、双像素描边、半透明抗锯齿边。立牌像素的不透明度只有全透明与全不透明两档；灵体、潜行等"整体半透明"是渲染参数，不是素材里的半透明边。

### 1.6 人物比例

- **约 1.6 到 1.8 头身的 Q 版大头**（沿用 my_ai_town 的比例，调研 1.6 节）：标准人形本体约 28 像素，头约占身高的五成半到六成，头最宽处略宽于肩。
  标准是武器、兽耳兽尾、标志物在 28 像素内一眼可辨。
- 脸极简：眼睛是竖向 2 到 3 像素的块；嘴平时不画，说话、笑、惊讶时才画。个体主要靠发型轮廓、服色与标志物区分。
- 种族一眼识别：每个种族至少有一个剪影特征（耳、角、尾、翼、体型）和一个色彩特征（`../20_world/races.md` 第 0.2 节）；
  兽耳兽尾（希雅为狼、奈拉为狐）、精灵尖耳、矮人与半身人的矮体型、魔族的角与翼都必须在 28 像素内可辨。
- 人比门矮一点：人约 1.75 米，门楣 2.1 米（1.3）。
- **头像与半身立绘用正常比例**（3.6）：Q 版只用于场景立牌；同一角色的 Q 版三视图与正常比例胸像画在同一张三视图参照上（`chr_turnaround` 第 4 格），保证两种比例是同一个人。

### 1.7 建筑与道具

- **建筑是立体的：** 外墙是按格挤出的墙体，屋顶是几何体，表面贴 AI 生成的无缝墙面与屋面贴图（`bld_wall`、`bld_roof`），墙基、压檐与檐边贴条带（`bld_trim`），
  门窗、招牌、雨棚、烟囱等是贴在墙面上的立面构件（`bld_facade`）。外观由功能决定，靠特征认出功能，不靠写字（调研 1.7 节）：
  礼拜堂的高墙与圆窗、公会的交叉剑与羽笔招牌、酒馆的酒杯招牌、铁匠铺的锤砧招牌、店铺的货摊与雨棚。
- **几何表达不了的标志性结构**（白石穹顶、钟楼尖顶、巨树之门、圆形毡帐、黑岩尖塔）用标志性构件立牌（`bld_landmark`）立在外壳上方或旁边；
  第四幕起的风格包另需"穹顶""圆锥帐顶""尖塔"三种屋顶几何，由 `look.ts` 的 `ROOF_SHAPES` 扩展。
- **功能到外观的词表**（风格包给候选，按地点编号确定性挑选，2.6）：屋顶形状、屋面、屋顶三色、墙材、门漆、纹章招牌（不含文字）、朝外墙面按间隔开窗，夜里自发光。
- **装饰与道具：** 路灯、井、木桶、木箱、招牌、栅栏、货摊、长椅、旗帜、火盆、雕像、墓碑、草垛、车（`DECOR_KINDS`）以及各风格包的特有物件是像素立牌，只画不挡路（5.2）。
  尺寸按人体定：柜台到人的胸口，椅面到膝盖（调研 1.7 节）。会阻挡的东西（墙、树、石、水）由空间层的格子决定，不由装饰决定。

### 1.8 昼夜与天气

- **时间来源：** 游戏内时钟来自内核（`src/core/time.ts` 的 `daylight`）；1 倍速下 1 游戏日等于 24 现实分钟（D-070）。
- **天光：** 由时刻派生白天、金色时刻、蓝调、夜四个权重，乘风格包的 `LightPalette` 得出太阳与天光的颜色、强度，以及整体乘色与只乘暗部的冷色，
  做出"亮处暖、暗处青"（调研 1.3、1.8 节）。室内地图（遗迹、地底、神庭殿内、地球开场）用固定室内光，不随时刻变化。
- **入夜点灯：** 每盏灯、每栋房子的窗按自身编号散列出点亮门槛，夜色加深时陆续点亮；夜窗与点亮的灯使用立面构件里的"夜"变体（`bld_facade`、`prop_*` 的点亮格），屋顶夜里保留微光。
- **天气是内核状态：** `Weather` 取晴、阴、雨、暴雨、雾、雪、落灰（`src/systems/world/types.ts`）；女神等经注册修正项改变天气（`weatherOverride`，D-013），渲染只读。
- **天气表现：** 雨、雪、落灰、火星是屏幕层粒子（代码绘制），闪电整屏闪；湿地压暗并降饱和，雪天提亮；澱让紫色微粒与暗角随等级加重；神庭有暖光微粒与暖色暗角（2.8）。
  素材只有一套，天气不重画素材。

## 2. 渲染方案

### 2.1 技术栈、入口与降级

- **依赖：** `three`（与母工程同版本），后期用 three 自带的 `EffectComposer`；不另加 2D 引擎。
- **接口：** `src/client/render/renderer.ts` 的 `WorldRenderer`（`setMap`、`render`、`hitBoxes`、`screenToGround`、`setQuality`）。会话、HUD、输入只认这个接口。
- **入口：** `src/client/hd2d/index.ts` 的 `createWorldRenderer` 先建 HD-2D 渲染器；建不成（无 WebGL、上下文创建失败）或玩家选"平面"画质时，
  退回 `src/client/render/flat_renderer.ts` 的 Canvas2D 平面渲染（D-058）。思路同 my_ai_town 的 `TownMap`（调研 2.1 节）。
- **素材解析：** 渲染层经素材解析器（`src/client/assets/` 的 `AssetResolver`）按编号取已审核通过的处理后素材（图集页、帧元数据、色样行）；
  编号没有通过审核的素材时返回程序化占位（6.4）。解析器是纯逻辑加加载器两层，纯逻辑登记在 `CLIENT_PURE_CORES`。
- **平面降级档：** 俯视平面像素图，与 HD-2D 读同一份场景描述（`src/client/render/scene.ts`）、同一批位图（地面图集、立牌图集、图标）与同一套覆盖层；
  三维外壳在平面档里没有对应位图，屋顶与墙顶由程序化绘制（`src/client/render/roofs.ts`）。只保证可玩与信息完整，不追求观感。
- **渲染对内核只读：** 经 `GameView` 读世界，只通过命令改变世界（`architecture.md` 第 7 节）；回放世界可以驱动渲染逐帧确定地截图（6.4）。
- **模块（`src/client/hd2d/`）：** 纯逻辑、Node 测试的有 `view.ts`、`style_packs.ts`、`daylight.ts`、`layout.ts`、`textures.ts`、`geometry.ts`、`ground.ts`、`lightmap.ts`、`standee.ts`、`quality.ts`；
  用 Three.js 与 DOM 的有 `shaders.ts`、`materials.ts`、`scene_builder.ts`、`entities.ts`、`post.ts`、`weather_overlay.ts`、`hd2d_renderer.ts`。
  纯逻辑模块不引 three 与 DOM，登记在 `tests/client_purity.test.ts` 的 `CLIENT_PURE_CORES`（6.6）。

### 2.2 HD-2D 的构成

| -------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------- | -------------------------------------- |

### 2.3 相机与像素清晰度

- **整数缩放档：** `ZOOM_STEPS` = 1、2、3、4、5、6、8、10、12，表示每个地面像素占几个设备像素；默认按视口高度选档。缩放只停在整数档上（调研 2.3 节）。
- **像素抗锯齿采样：** `WebGLRenderer({ antialias: false })`；贴图用线性采样加"像素抗锯齿采样"着色器：采样点吸到最近贴图像素中心，
  只在像素交界留一个屏幕像素宽的过渡；不生成 mipmap。整数档下与最近邻一样锐利；转动方位角、斜俯视使贴图像素在屏幕上不是正方形时，边缘也不闪不爬。
- **键鼠操作：** 滚轮与 `+`、`-` 换缩放档；右键拖动时左右转方位角、上下改俯角；`Z`、`X` 各转 45 度；`G` 在街景与俯视预设之间切换；
  `Home` 复位；WASD 与方向键的移动方向相对屏幕，先按方位角旋转，再作为移动意图交给内核。
- **手柄操作：** 右摇杆转方位角与俯角，缩放与预设切换在手柄绑定表里（D-081）；按键表与改键以 `../40_design/ux_and_onboarding.md` 为准。

### 2.4 立牌与遮挡

- **立牌：** 人物、魔物、树、石、装饰都是像素立牌：竖板后仰正对镜头，随方位角转向，所以在任何视角下看到的都是素材的正面。
- **竖直深度（upright depth）：** 立牌后仰时上半截在几何上伸到了身后，照实写深度会扎进身后的墙。所以立牌的深度按"竖直立在脚下"计算：
  身前的东西挡得住它，身后的东西再高也挡不住它。这等价于 2D 游戏的"按脚底排序"（调研 2.5 节）；平面降级档直接按脚底 y 排序，同值按稳定实体 id 排。
- **锚点来自素材元数据：** 每一帧的脚底锚点由导入管线写进帧元数据（13 节第 8 步），立牌按锚点立在格子坐标上；飞行体的锚点是地面投影点，本体按 `lift` 抬高。
- **接触阴影：** 人物与魔物脚下烘一块像素化椭圆，大小按帧元数据里的占地宽度。
- **选中与悬停：** 脚下画像素环，颜色与形状按关系区分（4.1）。
- **实例化：** 树与石按变体做成实例化立牌，每种变体一个 `InstancedMesh`，同屏上百棵树也只是几次绘制。
- **遮挡不藏信息：** 名字、头顶标记、敌方施法条画在覆盖层上，不参与深度遮挡，所以被墙挡住的单位仍显示名字与标记（屋顶盖着的屋内除外，见 2.6）。
  被墙体挡住的自身与队友本体额外画一个单色剪影（所有画质档）；玩家所在建筑总是掀开；镜头可转动绕开遮挡；室内地图的墙一律是半高剖面墙。

### 2.5 地面与水

- **地面：** 载入地图时把整张地图的地面烘成一张像素画布贴图（每格 16 像素）。每种地块取所属风格包的 AI 地面瓦片（`tile_ground`，每张覆盖 4×4 米、64×64 像素），
  按世界坐标采样，所以瓦片四边无缝衔接；同一地块有多个变体时按 4×4 米区块的坐标散列选用，避免一眼可见的重复。
  软地块（草、土、沙、灰、雪、田等）之间是 3 像素宽的 4×4 有序抖动过渡（代码按遮罩生成）；地面点缀件（`tile_detail`，花丛、碎石、落叶、灰斑）按格坐标散列撒进贴图；水岸画白沫。
  墙、树、石的格子只画底色，它们本身是立体墙或立牌（`ground.ts`）。
- **水：** 在着色器里动。按每格一像素的水体遮罩（浅水、深水）画像素化浪线与闪光；水色取风格包；浅水与深水分档，不做渐变。
- **重画时机：** 地面贴图在载入地图时画一次，格子变化（城建、剧情事件）时只重画变化的区块。
- **尺寸：** 最大地块 192×192 格（`../20_world/geography.md` 第 7.1 节）对应 3072×3072 像素，在常见设备的贴图尺寸上限以内；更大的地图按块切分。
- **界外：** 俯角较高时地图外是深色"界外"底色与轻雾；街景俯角下远处是远景天幕（2.13）。

### 2.6 建筑、屋顶与掀顶

- **外壳：** 每个有顶地点（民居、店、礼拜堂、公会、酒馆、作坊、官署、塔等）的外壳 = 地点矩形外扩一圈；外壳内的墙格挤成立体墙，只生成外露面；
  门格留门洞，门楣在 2.1 米；朝外的墙面按间隔贴窗构件，夜里换成夜窗变体并自发光，按房屋编号错开点亮（`layout.ts`、`textures.ts`）。
- **贴图：** 墙面与屋面贴所属风格包的 AI 无缝贴图，按世界坐标采样（墙面每 4 米、屋面每 4 米重复一次）；墙基、墙顶、屋檐、山墙封檐贴条带；
  门、窗、招牌、雨棚、烟囱、阳台、花箱、壁灯等按立面槽位贴上（`bld_facade` 的 16 格构件）。
- **外观挑选：** 墙材、屋顶形状、屋面、屋顶色、门漆、招牌纹章由风格包按功能给候选，按地点编号确定性挑选，同一张地图每次打开都一样；地图外观层的 `looks` 可逐地点覆盖（5.2）。
- **独立墙块：** 不属于建筑的墙格（城墙、栅栏、遗迹、室内地图的墙）挤成独立墙块。室内地图（遗迹、地底、神庭殿内、地球开场）的墙一律做成半高剖面墙，镜头能看到里面。
- **掀顶：** 玩家所在的建筑、选中目标所在的建筑自动掀开。屋顶按 4×4 有序抖动一格格溶解（约 160 毫秒）；掀开后外墙降为半高剖面（远离镜头的几面约 1.3 米，朝向镜头的一面约 0.5 米，随镜头转动而换），
  屋内灯亮。屋顶盖着时，屋里人的名字与头顶标记不显示。依据：my_ai_town 的 `RoomCovers` 与 `dissolve`（调研 4.9 节），自行实现。
- 城建摆放模式下全部掀开（5.4）；室内细节见 5.6。

### 2.7 光照：太阳、天光、光照图与动态光

- **太阳与天光：** 太阳平行光带阴影贴图，房屋、树、人物投影，地面与房屋受影；半球天光补暗部。颜色与强度由 `daylight.ts` 按时刻得出的
  白天、金色时刻、蓝调、夜四个权重乘风格包的 `LightPalette` 得出；阴天、雨、雾、落灰压暗；室内地图用固定室内光。
- **人造光分两类：**

| 类         | 内容                                                         | 实现                                                         | 何时更新                                                         |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| 静态光照图 | 门灯、路灯、窗光、掀开后屋里的灯                             | 世界空间贴图，每格 4 像素；地面、墙、立牌一次采样受光        | 只在点亮档变化或屋顶开合时重画；入夜按各自门槛错开点亮           |
| 动态光     | 玩家夜里的随身光、女神与灵体的光晕、发光特效、内容给的额外光源 | 着色器统一变量，最多 8 盏                                    | 每帧；超出 8 盏时按优先级与离镜头中心的距离取舍，玩家随身光总在其中 |

- **像素感：** 光的衰减分三档台阶，并在台阶交界加有序抖动，不出现平滑渐晕（调研 1.4 节）。
- **为什么用光照图：** 几百盏灯只是一次贴图采样，不受点光源数量限制（调研 2.6 节）。

### 2.8 天气与氛围

- **粒子：** 雨、雪、落灰、火星粒子与雾层画在屏幕层，沿用 `src/client/render/weather_fx.ts`：每个粒子是时间与序号的纯函数，不存状态，帧可复现。闪电整屏闪一下。
- **环境着色：** 湿地压暗并降饱和；雪天提亮；雾天整体加一层雾色。
- **澱：** 澱等级越高，紫色微粒越多、暗角越重。地图存正典级（`MapDef.sediment`，0 到 5，临界记 6，标尺见 `../20_world/power_system.md` 与 D-039），渲染级按 [`map_briefs.md`](../40_design/world/map_briefs.md) 第 1.2 节的公式换算（渲染 = 正典级 × 7 / 6，四舍五入）；逻辑层与城建读数一律用正典级。这是玩家判断危险的线索，属于可行动信息，任何画质档都显示（2.12）。
- **神庭：** 暖光微粒与暖色暗角，恒定柔光。
- **环境小动物与飘落物**（萤火、落叶、蝴蝶、鸦影）：AI 小特效序列帧（`vfx_small`、`vfx_loop`）按风格包撒布，属于超高与高档的观感项。
- **减少动画：** 尊重系统"减少动画"偏好与游戏内"减少闪烁和震动"设置：粒子降密度，闪电不整屏闪。

### 2.9 后期链

`post.ts` 用 `EffectComposer` 串起：

```text
渲染场景
  -> 体积光与晨雾、散景景深、水面倒影（仅超高）
  -> 泛光（超高、高）
  -> 调色：风格包"胶片"参数（饱和度、暗部抬升、暖、青、对比）
           按时刻的整体乘色与暗部乘色
           暗角、颗粒、移轴（移轴仅超高与高）
  -> 输出：ACES 色调映射与 sRGB
```

- 整体调色只在这里做一次：素材与贴图不做整体调色，换风格包、换时刻只改参数（调研 1.3 节的胶片调色思路）。AI 原图若带整体色偏，导入时按风格包量化板拉回。
- 威压、阿什在场的冷色、梦境滤镜等演出效果也是调色参数（4.9、7.4），不另出素材。

### 2.10 覆盖层（名字、气泡、浮字、提示）

- WebGL 画布上叠一张 2D 画布（沿用 `src/client/render/overlay_painter.ts`），画名字、头顶标记、发言、心声与神谕气泡、浮字、出口与交谈提示、移动目标、摆放标签；
  位置由立牌锚点的三维投影得出，按设备像素取整，画面平移时不抖。
- 文字一律来自文本表（D-077），用系统字体，不用像素字体（中文可读性优先，调研 6.7 节）。系统缺中文字体时用 SIL OFL 授权的后备字体：Linux 与 Steam Deck 构建打包思源黑体（Noto Sans CJK SC）的简体子集，1.1 加繁体子集；Windows 与 macOS 用系统字体（[`release_engineering.md`](release_engineering.md) 第 8.5 节）。
- 头顶标记是 16×16 的 AI 像素字形（`ico_marker`），按整数倍显示，程序化字形（`src/client/render/markers.ts`）作占位；每次只显示优先级最高的一个（3.6）。
- 气泡由 `src/client/render/bubbles.ts` 取首句、按中文断行、按长度停留 3 到 6 秒，同屏心声有上限（7.2）；浮字见 `src/client/render/floating_text.ts`（4.3）。
- UI 是干净的现代界面，不做像素边框；像素只出现在世界、头像、半身立绘与图标里（调研 6.7 节）。界面主题件（卡片底图、角花、九宫格边框）是 AI 生成的平面纹样，不是像素画。

### 2.11 性能与画质档

- **按需重画：** 镜头动、有人在走、屋顶开合、粒子在下、动画在播时逐帧画；画面静止时按环境节拍推进水与微粒，无变化不画；窗口最小化时停（调研 2.6 节）。
- **烘焙：** 地面贴图载入时画一次；光照图只在点亮档变化或屋顶开合时重画；纸娃娃组装结果按外观键烘进帧图集并缓存（3.7）。
- **实例化：** 树与石每种变体一个 `InstancedMesh`；同屏大量同类单位用图集加实例化立牌（4.8）。
- **目标：** 1080p 集显中档 60 帧；场景规模预算见 `architecture.md` 第 10 节；纹理内存预算见第 14 节。画质档的调度、首次启动选档与自动降档以 [`release_engineering.md`](release_engineering.md) 第 6.7 节为准，AI 位图的纹理内存预算以其第 6.8 节为准。

画质档（`quality.ts` 的 `QUALITY_IDS` 扩展一档 `ultra`）：

| 档   | 阴影                    | 后期                                                   | 像素比上限 | 观感项                                                                 |
| ---- | ----------------------- | ------------------------------------------------------ | ---------- | ---------------------------------------------------------------------- |
| 超高 | 4096，柔化              | 体积光与晨雾、散景景深、水面倒影、泛光、调色、移轴、颗粒 | 2          | 草丛与踩踏痕迹、环境小动物全量、远景天幕 3 层；M3 后按性能余量开放（D-078） |
| 高   | 2048，柔化              | 泛光、调色、移轴、颗粒                                 | 2          | 环境小动物半量、远景天幕 3 层                                          |
| 中   | 1024                    | 调色、颗粒                                             | 1.5        | 远景天幕 2 层（远山、云带）                                            |
| 低   | 无                      | 只保留调色                                             | 1          | 远景天幕只留远山；特效装饰粒子减半                                     |
| 平面 | 无                      | Canvas2D 俯视平面渲染，保留光照乘色与天气粒子          | 按整数缩放档 | 无天幕（俯视看不到天空）                                               |

- **默认档：** 桌面取高；无 WebGL 时自动使用平面。尊重"减少动画"：关闭屏幕震动、顿帧、镜头摇晃，粒子降密度。
- **自动降档（D-078，M3 上线）：** 桌面版（Electron）用 WebGL 计时查询测 GPU 帧时间，网页试玩版取不到时用 CPU 侧帧时间；连续 10 秒超出当档预算时降一档，
  以提示条告知玩家并可在设置里撤回；每局至多两次，从不自动升档；设置里可关闭。降档是一次性地改玩家所选档位，画质开关始终读这个静态档位，不读帧率调速器（主工程规则，[reuse_map.md](reuse_map.md) 第 5 节）。

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |

### 2.13 远景天幕

- **用途：** 室外地图在街景俯角下看得到地平线方向，远处用分层天幕表现区域的地貌与气候（D-078）：远山、中景林线或城郭剪影、云带，各一层。
- **结构：** 天幕是一条环绕镜头的圆柱形横带，固定在镜头位置、随方位角转动，所以永远在无限远处；每层是一张左右首尾无缝衔接的横长条（`bg_layer`，入游戏 1024×256 像素），
  天空部分在素材里是透明的，天空渐变、日月与星空由代码按 `LightPalette` 绘制。
- **视差：** 镜头平移时远山层位移系数 0.02、中景 0.05、云带另按时间缓慢漂移（每游戏小时一屏的四分之一），层间有轻微视差而不破坏"无限远"。
- **与俯角的关系：** 俯角 30 到 45 度时天幕全显；45 到 60 度时随俯角上升向上淡出；60 度以上（俯视预设）不显示，换回"界外"底色与轻雾。
- **昼夜与天气：** 天幕乘与场景相同的整体乘色与暗部乘色；雨雾天按雾色混合并压低对比；室内地图、神庭殿内、地下与门廊幽境不显示天幕（门廊幽境的远处是代码绘制的门影层）。
- **每个室外风格包一套三层**（`art_bg_<风格包>_far`、`_mid`、`_clouds`），另有五套两层的特殊天幕 `art_bg_sky_<名>_far`、`_near`：神域高空、天穹（第六幕可见）、终雾边缘、地球夜城（序章）、梦境门海（第 9 节）。
- **天幕包：** 地图默认用本图风格包的天幕；`sealed_ruins`、`forge_deep`、`door_corridor`、`earth_modern` 没有自己的天幕，露天段用所在区域风格包的天幕；地图可在图集字段 `sky` 另指天幕包
  （[world_map.md](../40_design/world/world_map.md) 第 9.1 节）。特殊天幕的用法：地球夜城用于序章地球四景的室外段；梦境门海用于梦境场景；神域高空用于神域区域的露天段；
  天穹在第六幕起替换室外地图的云带层，远景与中景照旧；终雾边缘只用于结局演出，由过场指定。逐图的天幕包见 [map_briefs.md](../40_design/world/map_briefs.md) 第 1.7 节与各图简报。
- **公平：** 天幕是纯观感，任何档可减层；天幕永远画在场景最远处，不覆盖任何场景元素与覆盖层。

## 3. 角色：AI 帧图与纸娃娃

人物分两条路：约 40 名主要角色各有一整套 AI 帧图（独立帧图集）；其余有名 NPC、居民、人形敌人、人形兵种与主角用 AI 生成的纸娃娃部件在运行时组装。
两条路输出同一种东西：每个外观键、动作、朝向、帧号对应一帧像素，HD-2D 把它贴到立牌上，平面降级档直接画。程序化纸娃娃（`src/client/sprites/`）是两条路共同的占位。

### 3.1 外观数据

- **世界侧 `Appearance`**（`src/systems/world/types.ts`）：`base`（体型原型或别名）、`colors`、`scale`、`glyph` 是程序化占位与纸娃娃换色共用的字段；
  素材引用字段由内容数据填写，取值都是素材编号（6.5）：

| 字段       | 内容                                                                                      | 谁有                               |
| ---------- | ----------------------------------------------------------------------------------------- | ---------------------------------- |
| `sheet`    | 主要角色的帧图集编号（例 `art_chr_yeyu`，展开为各动作条）                                 | 约 40 名主要角色                   |
| `doll`     | 纸娃娃配方：体型（`h`、`hs`、`hb`）、服装、头型、发型、耳角、头饰、胡须、后挂件、主手、副手、色样行 | 其余有名 NPC、居民模板、人形敌人、人形兵种、主角 |
| `portrait` | 头像表情表编号（`art_por_<主体>`）                                                        | 全部有名 NPC 与女神                |
| `bust`     | 半身立绘编号（`art_bust_<主体>`，含表情差分）                                             | 约 40 名主要角色                   |
| `variants` | 状态变体：键为台账条件，值为另一组 `sheet`、`portrait`、`bust`（例：陆辰第五幕卸下披风）  | 少数主要角色                       |

- **解析顺序：** `sheet` 优先；没有则组装 `doll`；两者都没有通过审核的素材时退回程序化占位（`src/client/sprites/look.ts` 的 `lookFromAppearance`）。
- **客户端 `SpriteLook`**：把 `base` 归一到原型 `ARCHETYPES`，不认识的确定性退回人族；颜色解析失败用原型默认色；`scale` 按四分之一档夹在 0.5 到 4，并生成稳定缓存键。
- **AI 的介入方式：** 运行时生成或演化 NPC 时，模型只从纸娃娃部件编号与色样编号里挑；没给或对不上的字段按稳定 NPC id 散列确定性挑选（调研 3.2 节的做法）。运行时与构建时都不生成图像，图像全部在开发期生成并审核。
- **主要角色与有名 NPC** 的外观写死在内容数据里，依据 `../30_story/characters.md` 的外貌与"像素要点"、人物目录的摘要卡；有名 NPC 的纸娃娃配方先定，再用配方的组装预览图作为生成头像的参照（12 节），保证头像与场景里的人一致。

### 3.3 部件分层（纸娃娃）

纸娃娃的全部部件由 AI 在**固定人台**上生成：每种体型（`h`、`hs`、`hb`）先出一张人台三视图（`doll_mannequin`），再用人物动作条模板（`chr_*`）出人台的全部动作条，
这套人台动作条是所有服装的姿势基准。部件层与生成方式：

| 层（自下而上）     | 内容                                                       | 生成模板                         | 组装方式                                                                 |
| ------------------ | ---------------------------------------------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| 后挂件             | 披风后摆、尾巴、后翼、背负武器与行囊                       | `doll_back`（三向两帧摆动）      | 按身体帧的背部锚点叠放，摆动帧按步伐相位切换                             |
| 身体与服装         | 身体、服装、鞋、腰带（一个服装就是一整层）                 | `doll_outfit_ref` 加 `chr_*` 动作条 | 以人台动作条为参照逐条生成；导入时用人台的头部遮罩去掉灰色光头，只留身体  |
| 头部后层           | 后发、头饰后沿                                             | `doll_head` 第 2 行              | 刚体，按每帧的头部偏移贴上                                               |
| 头型               | 脸型与肤色、眼位                                           | `doll_head` 第 1 行              | 刚体，头比身体晚一拍（`HumanoidPose` 的 `headBob` 偏移）                 |
| 表情               | 眼 8 种、嘴 6 种                                           | `doll_face`                      | 只在正面朝向贴在头型的脸部锚点上；侧面与背面用头型自带的眼位             |
| 头部前层           | 前发、耳、角、头饰前沿、胡须                               | `doll_head` 第 1 行              | 刚体，同头型偏移                                                         |
| 手持物             | 武器、工具、标志物（信囊、硬币、计数珠等）                 | `doll_held`（八个握持角度）      | 按每帧的手部锚点与姿态角取最近的握持角度贴上                             |
| 特效挂点           | 门纹亮点、光环、澱雾                                       | 特效序列帧                       | 由渲染层绘制，不进纸娃娃                                                 |

- **姿势对齐：** 同一体型的所有服装共享人台的头部偏移与手部锚点；导入时校验服装帧与人台帧的轮廓重合度（头部与手部区域偏差不超过 1 像素），不合格即返工。
- **头部是刚体：** 头部部件每个朝向只画一次（`doll_head` 的四列：下、右、上、左），各帧只取一组偏移，所以发型、头饰、耳角的数量增长不增加动作帧的产量。
- **换色：** 服装、头发、后挂件用键色生成（1.4），导入后存为色槽索引，运行时按色样行上色；"一套新衣服"优先是新配色，其次是新服装层，成本顺序见 9.2。
- **服装覆盖的动作：** 纸娃娃人台与可装备外观（玩家与同伴能穿的护甲外观）共 13 条动作条，不含突刺与专属小动作（突刺用近战挥击条加手持物前指角度）；居民服装出 8 条（待机、行走、奔跑、受击、倒地、生活甲、生活乙、情绪）；
  人形敌人与兵种的服装出 9 条（待机、行走、奔跑、近战或远程或施法其一、受击、倒地、战斗待机、生活甲、情绪）。动作条清单见 3.4 的表。
- **主要角色不走纸娃娃：** 他们的整套帧图把发型、服装、武器、标志物一起画进每一帧；专属待机小动作单独一条（`chr_signature`，内容来自 `../30_story/characters.md` 的"像素要点"）。

### 3.5 方向与镜像

- **4 个显示朝向（D-078）：** 下、右、上、左；左向帧是右向帧的镜像（`generate.ts` 的 `mirrorX`），实绘下、右、上三向。
- **朝向换算：** 内核朝向是连续角度（`atan2(dy, dx)`，+y 向南）；动画状态按地图坐标记住朝向，显示时加上相机方位角（`view.ts` 的 `screenFacing`），
  再由 `anim_spec.ts` 的 `dirFromFacing` 量化到 4 向；镜头转动时静止的人物也随之换面，从未移动过的人物一律正面朝向镜头。
- **镜像后的不对称：** 武器在镜像后换手是可接受的约定（像素游戏的通例）。决定辨识的不对称特征按下列方式保持正确：
  - 纸娃娃头部件画真正的左向（`doll_head` 第 4 列），所以单侧发饰、偏分刘海、单侧角饰在左向帧里也在正确的一侧。
  - 主角右手背的门纹、无貌者反相的门纹（`../30_story/characters.md` 第 2 节）是渲染层按手部锚点画的 1 到 2 像素亮点，不进素材。
  - 主要角色的单侧标志（例如夜羽的白色鬓发）写进该角色的固定描述块并画进三向帧；左向镜像后若换边，由导入工具为这名角色生成"左向修正件"（只覆盖头部区域的小图，取自右向帧头部的镜像再把标志区域换回原侧）。

### 3.6 表情、头像、半身立绘与头顶符号

- **场景表情：** 纸娃娃的眼 8 种、嘴 6 种（`doll_face`）由结构化状态驱动（心情、交谈、受伤、惊讶）；眨眼、呼吸、按字张嘴的节奏按实体 id 散列错开，一群人不会同时动（调研 3.4 节）。
  主要角色的场景表情画在动作条里（情绪动作、受击），不另贴表情件。
- **头像（D-078）：** 全部有名 NPC 与女神有 AI 生成的像素头像（64×64，按整数倍显示）：约 40 名主要角色 8 种表情（`por_main`：中性、微笑、开怀或得意、生气、悲伤、惊讶、思索、专属），
  其余有名 NPC 4 种（`por_npc`：中性、高兴、生气、担忧）。居民模板的头像从纸娃娃组装结果截取头肩区域（与场景里的人一致）。
  头像条、对话框、角色卡、传闻来源链共用同一个头像解析函数。
- **半身立绘（D-078）：** 约 40 名主要角色有正常比例的像素半身立绘（256×384，按整数倍显示，`bust_base`），加 6 种表情的头肩差分（`bust_expr`，128×128，按脸部锚点贴回），
  用于对话与过场；对话框优先显示半身立绘，其他人显示头像。
- **特例：** 无貌者没有脸，对话界面不显示头像与半身立绘，只显示一个空的头像框（`../30_story/characters.md` 第 4.8 节）；
  门口的女人的半身立绘有三档清晰度（剪影、半张脸在阴影里、第六幕正名后的全貌），随封印松动度切换；女神的神降与显形状态是状态变体（3.1 的 `variants`）。
- **头顶符号：** 16×16 的 AI 像素字形（`ico_marker`），不是文字或 emoji。`MarkerKind`：任务、交付、惊讶、疑问、目击之眼、思考、耳语、生气、心、门纹，
  扩展灵光（定了新目标）、汗（急需）、饿、威压；按 `MARKER_PRIORITY` 每次只显示最高的一个。触发全部来自结构化数据（7.2）。

### 3.7 帧缓存与实例化

- **素材形态：** 立牌类素材在处理后存为"色槽索引图加色样行"：每像素一个字节的索引（WebGL 的 R8 贴图），颜色在着色器里查色样行。
  好处：显存是 RGBA 的四分之一；纸娃娃换色、澱化变色、闪白、受击变红都只换色样行，不重画像素。
- **图集：** 导入管线按类别与风格包把帧打进 2048×2048 的图集页（13 节第 11 步）；帧元数据（帧矩形、锚点、占地宽、动作时长）随图集一起加载。
- **纸娃娃组装缓存：** 同一外观键（体型、服装、头部件、手持物、后挂件、色样行）的全部帧在首次需要时组装一次，烘进运行时图集并缓存，最近最少使用淘汰；
  `src/client/sprites/sprite_cache.ts` 的 `SpriteCache` 保留同一键值接口，背后的帧来源换成素材。
- **形状与颜色分离：** 大规模场景（兵团、群众）同一服装层只有一份索引图集，每个实例的色样行打包为实例属性，千人千色只需要少量图集（4.8）。
- 表情、头顶符号、特效挂点是叠加层，不进烘焙图集。

### 3.8 魔物

### 4.2 施法条

- 玩家与目标的施法条在 HUD（`src/client/hud/unit_frames.ts`），带技能图标；敌方头顶有小施法条（覆盖层），可打断与不可打断用边框形状区分（不可打断带盾形边）。

### 4.3 伤害数字

- 渲染：`src/client/render/floating_text.ts`，每条浮字是起始时间的纯函数，同一实体的多条按栈错开；画在覆盖层，用系统字体，数字走本地化的数字格式。

- 暴击放大一档并短促弹跳；大量范围伤害时同目标合并、总数设上限。

### 4.4 命中反馈

- 命中帧同步与音效选择（武器类、护甲类、蓄力与重击标记）见 [`../40_design/audio_direction.md`](../40_design/audio_direction.md) 第 7.16 节；映射表 `data/audio/cues.json`。
- **闪白与受击：** 受击首帧把色样行换成闪白行，同时播受击姿势；击退位移以内核为准，表现只做缓动，不得造成位置误读。
- **顿帧与震动：** 暴击或重击时只冻结受击者与攻击者的动画 2 到 3 帧，内核照常推进；屏幕震动只用于首领重击与大型法术；减少动画与"减少闪烁和震动"开启时两者都关闭。
- **命中火花：** 每个学派一套 AI 小特效（`vfx_small`，8 帧），物理分钝、锐、穿三种；在命中帧（动作表的关键帧）播放，音效同帧（`../40_design/audio_direction.md`）。

### 4.6 地面预警

地面预警由代码绘制，不用 AI 素材：它的形状必须与内核的格子区域逐格一致。

| 形状           | 对应主工程机制                   | 表现                                                       |
| -------------- | -------------------------------- | ---------------------------------------------------------- |

| 直线与冲锋路径 | `charge` 与冲锋类                | 带箭头的条带                                               |
| 环形           | 环形定身变体                     | 内空外实                                                   |
| 脉冲           | 持续地面区域                     | 每次脉冲闪一次边缘                                         |

- 预警是贴在地面平面上的像素贴花，与地面一起透视缩短，所以画面上的形状与内核的格子区域在任何俯角、方位角下都完全对应。

### 4.8 RTS 规模

- **战场格与地图格：** 1 战场格 = 8 米 = 8×8 地图格（1 地图格 = 1 米 = 16 像素），即一个战场格渲染为 128×128 像素（[`catalog_warfare_strategy.md`](../40_design/content/catalog_warfare_strategy.md) 第 7.2 节，[`map_briefs.md`](../40_design/world/map_briefs.md) 第 10.1 节）；兵团立牌在格内按阵型排开。

- **战场进入 HD-2D（D-078）：** 战场在第三幕内容量产前（M2 期内）进入 HD-2D 场景，俯视战术图保留为指挥视图。
  英雄与精英是完整实体，按上文表现；普通兵是兵团（D-012），表现为图集加实例化立牌，帧号、色样行、闪白、透明度打包为每实例属性。
- **兵团素材：** 人形兵种用阵营服装层（纸娃娃）按兵种烘成兵团图集；非人形兵种（骑兵、战兽、攻城器械、飞行兵）用兵团立牌动作表（`unit_sheet`、`unit_sheet_large`，行军 4、攻击 4、待机 2 加受击 2、倒地 4）。
  兵团的帧比主要角色少，细节也少，适合成百上千同屏。
- **血条与士气：** 兵团只显示一条兵团血条与士气条，不给每个士兵画血条；英雄保留个人血条。
- **指挥：** 框选显示选择环与编队号；下达指令后画目标线与集结点。拉远到兵团卡片（兵种徽记 `ico_unit`、人数、士气）。
- **战争迷雾：** 遮罩贴图，边缘有序抖动；只计算可见窗口（[city_rts_slg.md](../10_research/open_share/city_rts_slg.md) 第 3 节）。
- **城镇里的大战：** 第一幕兽潮之夜的守城战发生在城镇场景里，同屏数十只魔物与守军，用同一套图集加实例化立牌承载。

### 4.9 谨慎支柱

- **鉴定上限**（显示规则按 D-029，`../20_world/power_system.md` 第 2.6 节）：超出所用水晶上限显示"上限+"（如"34+"）；超出鉴定者感知上限的存在，
  名字旁等级显示"？"，鉴定卡显示模糊条带而不是数字；无页显示"无记载"；魔物与无貌者显示残页（`../40_design/game_framework.md` 第 10 节）。
- **威压：** 靠近强者时画面边缘轻微降饱和加暗角（调色参数，2.9），强度随位阶差分级，只给模糊提示不给精确数值；感知类的门让提示更准确。声音上同步播威压心跳 `sfx_pres_heartbeat_*`（[`../40_design/audio_direction.md`](../40_design/audio_direction.md)），二者互为视觉与听觉对等。
- **守门人阿什：** 他所在的画面整体偏冷（`../30_story/characters.md` 第 3.9 节的演出要求），同样是调色参数。

## 5. 地图与城建表现

### 5.1 地图文档三层

沿用 my_ai_town"一张地图同时喂三个读者"的结构（调研 4.1 节），格式自行设计，类型在 `src/systems/world/types.ts` 的 `MapDef` 与 `src/systems/world/look.ts`：

| 层     | 内容                                                                                          | 读者               |
| ------ | --------------------------------------------------------------------------------------------- | ------------------ |
| 逻辑层 | 地点 `locations`、出口 `exits`、刷新点与出生点 `spawns`                                        | 内核、AI 题面      |
| 空间层 | 格子 `rows` 与图例 `legend`（地块种类决定可走性、碰撞、寻路）                                  | 内核               |
| 外观层 | `style`（风格包）、`looks`（逐地点建筑外观覆盖）、`decor`（装饰，只画不挡路）                  | 只有渲染器         |

- 改外观不改玩法：外观层只有渲染器读，内核与 AI 看不到它。
- 内容校验检查外观层的引用：风格包编号存在、`looks` 指向的地点存在、装饰在地图内且种类已知（`src/content/index.ts` 的 `validateContent`）。
- 编辑：编辑器的地图工具（`src/editor/map/`）以俯视格子编辑逻辑层与空间层；外观层在内容编辑器里按表单编辑。
  编辑器内嵌 HD-2D 预览（D-078），在 M2 上线，同一视窗也是素材审核的游戏内预览（15 节）。

### 5.2 外观层：风格包、建筑外观与装饰

- **`style`：** 风格包编号（1.4）；不写时按 `region` 映射。
- **`looks`：** 逐地点建筑外观覆盖，键是地点 id，可覆盖屋顶形状、屋面、屋顶色、墙材、墙高、招牌、标志性构件；没覆盖的维度仍由风格包按地点编号挑。
- **`decor`：** 装饰列表，每项是种类、格坐标与变体号；装饰是立牌（`prop_*` 的 4 个变体之一），只画不挡路。路灯与门灯类装饰同时向光照图登记光源（2.7）。
- 字段名与取值表以 `src/systems/world/look.ts` 为准，本节只定语义。`DECOR_KINDS` 随风格包特有物件扩展，每个种类在每个风格包有一张道具表（缺的退回 `lothar_plain` 的同类）。

### 5.3 地点与标签

- 地点名与房间名由界面层绘制（文本表或玩家命名），不写进贴图；屋顶盖着时房间名浮在屋顶上方，掀开后回到房间上沿（调研 4.9 节）。
- 名字重叠时合并（例如"广场 8 人"带一摞小头像，点开是名单），沿用 my_ai_town `clusterNames` 的思路（调研 3.6 节）。
- 具名落脚点（如"东头""水边"）只在逻辑层存在，不画在地面上；调试视图可显示。

### 5.4 可摆放格的可视化

- **进入摆放模式：** 全镇屋顶掀开，地图压暗，只有可放的区域亮起并写"还能放约 N 件"；拉近后画出放置格（调研 4.8 节）。
- **幽灵建筑：** 指针下是半透明的立体外壳（与正式建筑同一套 `layout.ts` 生成，所见即所得）加占地格；可放为绿框，不可放为红框并带原因（5.5）。
- **入口与路线：** 画出入口箭头、入口到最近道路的白色点线；被挡时画红线，并把挡路物描红。
- **网格：** 放置格是 1 格；建造的规划单位是地段，以 `../40_design/systems/city_building.md` 第 3.3 节为准。

### 5.5 拒绝原因的屏幕解释

每种拒绝在画面上都有证据（调研 4.8、4.10 节）。原因码是内核校验器的机器码，以 `../40_design/systems/city_building.md` 第 3.4 节为准；文本取自文本表，画面证据由渲染层绘制：

| 原因码       | 玩家看到的意思（示例）       | 画面证据                                         |
| ------------ | ---------------------------- | ------------------------------------------------ |
| `bounds`     | 这里不在村子的地界里         | 地界边线高亮，越界的格子描红                     |
| `terrain`    | 这里没有矿脉                 | 不合要求的地块描红；合要求的地块在附近亮起       |
| `overlap`    | 这里已经有木屋               | 重叠物描红                                       |
| `road`       | 大路上不能盖房               | 道路高亮                                         |
| `entrance`   | 门口会被堵住                 | 被堵的入口箭头变红                               |
| `slot`       | 干活的人站不到跟前           | 操作位画红色叉形标记                             |
| `reach`      | 从村里走不到这里             | 从聚落中心画走线，断开处标红                     |
| `keep_reach` | 这样会把粮仓围死             | 被围住的建筑描红，最窄处标出宽度                 |
| `defense`    | 城门口不能盖房               | 城门内外的禁建区高亮                             |
| `taboo`      | 这块地的澱太重，住不了人     | 澱浓度热力层                                     |

材料不足、尚未解锁不属于摆放校验，在建造菜单里标出缺的材料与所需的门或法令（建筑小图 `ico_building`）。

### 5.6 掀顶与室内

- **触发：** 玩家所在的建筑、选中目标所在的建筑自动掀开；摆放模式全部掀开（2.6）。
- **掀开后：** 外墙降为半高剖面，门在哪面就在那里留门洞；屋顶按 4×4 有序抖动溶解约 160 毫秒；屋内灯亮，光照图重画。
- **室内：** 室内地面是地面贴图里的地板格（风格包的地板瓦片）；北墙内面贴室内墙面贴图与室内立面构件（护墙板、壁挂、窗、架）；家具是道具立牌（调研 4.9 节"立三面半高墙"的做法）。
- **室内地图：** 遗迹、地底、神庭殿内、地球开场等室内地图没有屋顶，墙一律是半高剖面墙。

### 5.7 建造阶段

| 阶段             | 表现                                                         | 素材                                                                 |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------------- |
| 0 规划           | 蓝图幽灵：占地格虚线、外壳轮廓线                             | 代码（`layout.ts` 的外壳）                                           |
| 1 地基           | 打桩、石基、材料堆                                           | 通用道具立牌（材料堆按木、石、砖与小、中、大尺寸档）                 |
| 2 框架           | 脚手架、木构架、半截墙                                       | 同一外壳，墙高按进度取一部分，贴"框架"墙面贴图与脚手架立面构件       |
| 3 封顶           | 外壳完成，屋顶按抖动由下向上长出                             | 掀顶溶解的反向                                                       |

| 受损、废墟、澱化 | 裂缝、焦痕、澱紫侵蚀叠加在墙面贴图上；废墟用遗迹残墙（1.6 到 2.4 米） | 叠加纹样贴图（`vfx_overlay`）与独立墙块                        |

### 5.8 视野与迷雾

- 探索层：未探索区域压暗并降饱和，边缘有序抖动；已探索但不在视野内的区域保留地形与建筑，不显示单位。
- 战场层：战争迷雾按 4.8。
- 神之视线不是迷雾，是另一张叠加层（7.5）。

## 6. 素材方案：AI 生成，程序化占位

### 6.1 总原则

1. **AI 出图，代码统一。** 全部美术素材由 AI 生成（D-018）；像素密度、调色板、描边、透明度、锚点与帧格由导入管线统一，不靠生成者手调。
2. **需求即提示词。** 每张素材都是提示词库里的一个条目（编号、模板、风格包、主体描述、参照依赖、里程碑），条目由内容目录的条目推出，不在提示词库之外临时出图。
3. **参照先行。** 每个风格包先出风格板，每个角色与物种先出三视图，再批量出动作条与变体（第 12 节）。
4. **风格包收口。** 世界类素材的颜色只来自所属风格包的量化板，生灵类素材只来自生灵色板；素材文件里不出现游离的颜色。
5. **确定性。** 素材是固定文件；同样的外观、动作、方向、帧号永远取到同样的像素；纸娃娃组装与挑选用稳定编号散列，不用随机数。
6. **内容不等美术。** 任何编号在任何时刻都有可显示的外观：素材没有通过审核时退回程序化占位（6.4），内容校验与覆盖测试会列出缺口（6.6）。
7. **原创与干净。** 提示词不含其他作品、作者、画师、工作室与商标名称；素材里不写字；每个文件可追溯到生成工具、提示词与审核人（6.5、6.7）。

### 6.3 生产流程

| 步  | 做什么                 | 谁                     | 要点                                                                                                                                     |
| --- | ---------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 写条目                 | 主会话与写作代理       | 从内容目录、角色设定与分幕文档推出 `assets/prompts/specs/<名>.json` 的条目：主体中英文描述（外形、配色、材质、姿态、辨识特征，不写剧透）、模板、风格包、参照依赖、里程碑 |
| 2   | 展开提示词             | 用户（本机）           | 提交的源是 `templates.json`、`templates_audio.json` 与 `specs/*.json`；`npm run prompts` 在本机生成 `assets/prompts/out/<名>.md`（逐条可复制）、`.csv` 与 `out/manifest.json`（预期素材清单），`out/` 不提交（`hakoniwa/.gitignore`）；`npm run prompts:check` 确认 `out/` 与条目一致 |
| 3   | 出风格板与参照         | 用户（小九 AI）        | 风格包风格板、人台、人物与物种三视图先出先审，定稿后作为后续条目的参照依赖（12 节）                                                       |
| 4   | 批量生成               | 用户（小九 AI）        | 按里程碑与批次逐条生成；附上条目写明的参照图；每批先出 4 张试样                                                                         |
| 5   | 落盘                   | 用户                   | 按模板的 `outDir` 与条目编号命名，放进 `assets/art/<类>/`（`assets/README.md`）                                                         |
| 6   | 登记                   | 用户或主会话           | `npm run assets:register` 把新文件写进 `assets/manifest.json`：工具、日期、种子、参照、提示词哈希、隐式标识；状态为"审核中"               |
| 7   | 导入                   | 主会话                 | `npm run assets:import` 抠色、切格、降采样、量化、描边、锚点、元数据，输出到 `assets/processed/`（13 节）                               |
| 8   | 自动校验               | 主会话                 | `npm run assets:check` 与 Vitest（6.6）；不合格的直接标"返工"并写原因                                                                   |
| 9   | 审核                   | 用户（主审）           | 编辑器的素材浏览器与 HD-2D 预览里看：1 倍与 3 倍、三种光照、目标风格包、与同屏素材并排（15 节清单）                                     |

| 11  | 打包                   | 构建                   | 通过的素材进图集（`npm run assets:atlas`），随构建输出；未通过的编号运行时退回占位                                                       |

### 6.4 程序化占位与平面降级档

- **占位：** 现有的程序化绘制代码全部保留，作为每一类素材到位前的占位：纸娃娃与生灵模板（`src/client/sprites/`）、地面色阶（`src/client/render/tile_art.ts`）、
  墙面与屋面（`src/client/hd2d/textures.ts`）、装饰（`src/client/render/decor_art.ts`）、头顶字形（`src/client/render/markers.ts`）、程序化图标配方（类别通用）。
  素材解析器（2.1）按编号查素材清单，状态不是"通过"时返回占位；所以开发顺序可以是"先内容后素材"，内容条目进数据的当天就能在游戏里看到。
- **占位的确定性：** 占位与素材一样按外观参数确定性生成，回放与截图一致；开发构建可用 `?art=procedural` 强制全部占位，对比素材到位前后的观感与性能。
- **平面降级档：** Canvas2D 平面渲染使用同一批位图（地面图集、立牌图集、特效俯视小图、图标）；三维外壳在平面档里没有对应位图，屋顶与墙顶由程序化绘制（`src/client/render/roofs.ts`），
  屋顶纹理取风格包屋面贴图的主色。平面档不显示远景天幕（2.13）。
- **录像重演出片**（调研 6.6 节的做法，自行实现）：商店截图与宣传片由渲染器回放存档录像、劫持时钟逐帧推进、按镜头表（机位、俯角、方位角、焦点、隐藏界面）逐帧截图合成；
  仓库保存镜头表与最终图片，原始帧不入库。截图展示的是游戏实际画面，宣传插画另由 `key_*` 模板生成并在商店页标注为插画。

### 6.5 命名、编号与素材清单

- **编号：** `art_<类>_<主体>[_<部分>][_<朝向或序号>]`，小写英文加下划线，全库唯一（`<类>` 取 6.2 表的前缀）。有内容 ID 的主体直接用内容 ID（`art_mon_dian_rat_d`），没有的用描述性英文。
  - 朝向后缀：`_d`（面向镜头）、`_r`（朝右）、`_u`（背向镜头）；参照图后缀 `_ref`；人物动作条后缀为动作名（`art_chr_yeyu_walk`）；变体用两位序号（`art_tile_lothar_plain_grass_02`）。
  - 编号与文件名会随发行包分发，玩家看得到，所以**编号不得含剧透**：例如门口的女人用 `door_woman`，无貌之王用无貌者的编号加 `_crowned`，不出现正名与身份真相。
  - 同一编号的含义不变，改含义就开新编号；废弃编号在清单里标为"停用"并保留记录，旧存档与旧内容仍能解析到占位。
- **文件：** `assets/art/<模板的 outDir 去掉 art/ 前缀后的目录>/<编号>.png`，例 `assets/art/monsters/art_mon_dian_rat_d.png`；文件名不写日期、人名、`final` 之类。
- **素材清单 `assets/manifest.json`：** 美术与音频共用一份清单，每个文件一条记录，与文件双向一一对应：

| 字段                  | 内容                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `id`                  | 素材编号（等于提示词条目编号）                                                           |
| `kind`                | `art` 或 `audio`                                                                         |
| `file`                | 相对 `assets/` 的路径                                                                    |
| `template`、`style`   | 生成所用模板与风格包                                                                     |
| `promptHash`          | 生成时所用提示词全文（中文或英文，见 `promptLang`）的 sha256 前 12 位                    |
| `promptLang`          | `zh` 或 `en`                                                                             |
| `tool`                | 生成工具编号（`assets/tools.json` 的登记项，例 `xiaojiu`）                               |
| `toolVersion`         | 工具或模型版本（工具界面显示的版本号；没有则写生成日期）                                 |
| `seed`                | 种子（工具提供时）                                                                       |
| `refs`                | 生成时附上的参照图编号                                                                   |
| `generatedAt`         | 生成日期（YYYY-MM-DD）                                                                   |
| `sha256`              | 原图文件的 sha256                                                                        |
| `aigcLabel`           | 原图元数据里的生成服务隐式标识（服务提供者编码、内容编号），没有则写 `none`              |
| `converted`           | 原图是否经过格式转换（例如 JPG 另存为 PNG）                                              |
| `status`              | `review`（审核中）、`approved`（通过）、`rework`（返工）、`rejected`（淘汰）、`retired`（停用） |
| `reason`              | 返工与淘汰的原因码（15 节）                                                              |
| `reviewer`、`reviewedAt` | 审核人与日期                                                                          |
| `milestone`           | 条目所属里程碑                                                                           |
| `notes`               | 自由备注                                                                                 |

- **工具登记 `assets/tools.json`：** 每个生成工具一条：编号、名称、使用的版本、服务条款链接、条款查阅日期、条款是否允许商用、生成物权利归属的条款摘要、是否写入隐式标识。
  条款不允许商用或权利不清的工具不得用于入库素材。
- **兜底：** 缺素材时按 6.4 显示占位，并由覆盖测试报出（6.6）。

## 7. AI 行为的视觉呈现

### 7.1 原则

- **画面只读结构化字段**，从不解析模型原文去决定表情、符号或位置（调研 6.1 节）。
- **三种距离：** 头顶（符号、名字、气泡）、身旁（发言卡、脚下操作环）、侧栏（角色卡、动态列表、传闻簿）。
- **看见的只能是玩家能感知的：** 画面遵守揭示台账（`../30_story/reveal_ledger.md`）与神之视线规则，女神的幕后动作不会因为"系统知道"就显示出来。
- **无模型档有同等位置：** 没有配置大模型时，同一位置显示内置 AI 的模板句与预写台词（D-010、D-068），界面不出现"等模型"之类的空洞状态。

### 7.3 心声、发言与动态列表

- 动态列表三种条目：想法、对话、世界事件；按游戏日分段；收起时只浮两行最新动态，重要事件置顶到被关闭或被更新的重要事件替下（调研 6.3 节的做法，自行设计）。

### 7.5 神之视线

依据：`../20_world/world_bible.md` 第 5 节与第 11 节"神之视线外"。

- **解锁时机：** 第二幕"神之视线显性化"（`../40_design/game_framework.md` 第 4 节）之后，玩家可打开"视线"叠加层。
- **叠加层内容（全部来自内核计算值）：** 神殿与圣所的覆盖范围画成女神主色的地面贴花，边缘有序抖动；信徒目击者头顶小眼形标记，颜色为其信仰的女神；
  野外的动物耳目（希尔薇）是淡绿的点状区域；HUD 上一排眼形计量显示每位女神的"注视度"（女神纹章加填充度，纹章为 `ico_ui` 的女神组），高注视度时眼形张开。
- **目击的即时反馈：** 玩家做出超凡事迹时，看见的 NPC 头顶闪"目击之眼"符号；这些人随后可能成为传闻源头（7.6）。
- 叠加层只显示玩家角色"有理由知道"的部分：解锁前完全不显示；解锁后对未知女神的覆盖用"？"区域。

### 7.6 传闻与认知画像

- **传闻卡：** 每条传闻一张卡：说法（由"主体、事件、程度"结构化数据经文本模板生成，可选模型润色）、来源链（头像串）、可信度（5 档条）、
  失真标记（被证实为误的部分划线标出，原说法与事实并排）、传播范围（地点列表）。
- **传播的画面：** 两个 NPC 交换传闻时头顶出现"耳语"符号与传闻主题小图标（战斗、财富、神迹、罪行，`ico_ui` 的传闻组）；地图窗口可打开"传闻扩散"视图，以地点之间的涟漪显示一条传闻的传播路径。
- **认知画像（"镇上怎么说你"）：** 按地点汇总的面板：估计的强度（一个范围条而不是数字）、标签（怪人、运气好、骗子、英雄等）、代表性说法、可信度分布。

### 7.7 无模型档与可观测

- 无模型档：所有 AI 呈现位置都有模板版；动态列表照常运作；女神神谕回到预写文本（D-010）。
- 调试视图（开发构建）：NPC 头顶显示推理分级（L0 到 L4）、唤醒原因、最近一次回执；发布构建不含此视图。

## 12. 一致性方法

| 层               | 做法                                                                                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 风格锚           | 每个风格包一段固定的中英文风格锚句与 8 到 16 色锚色（`templates.json` 的 `styles`），同一风格包的每个条目原样拼进提示词；模板里固定媒介描述（像素密度、描边、光向、背景、视角），全库一致 |
| 风格板           | 每个风格包在批量生产前先出一张风格板（`art_style_<风格包>`，一包一张图）：两种地面瓦片、一种墙面、一种屋面、一张立面构件、两件道具、一个居民立牌；主审定稿后，这几张图作为本包所有条目的参照图（条目的 `deps`）                          |
| 三视图参照       | 每个主要角色、每套纸娃娃服装、每个魔物与首领物种先出三视图（`chr_turnaround`、`doll_outfit_ref`、`mon_turnaround`）；定稿后它是这个主体全部后续图的参照图                                              |
| 固定描述块       | 同一主体的每个条目使用同一段主体描述（发型与发色、瞳色、脸型、服装与配色的十六进制值、标志物、体型、种族特征），写在条目的 `subject` 里，不在不同条目中改写措辞；动作差异只写在模板与 `extra` 里           |
| 参照图的用法     | 小九 AI 支持参考图时，把参照图作为"角色参考"或"图生图"输入（参照强度从 0.5 起试，保持轮廓与配色、允许姿势变化）；不支持时，把参照图的固定描述块完整写进提示词并提高批内试样数                          |
| 种子复用         | 工具提供种子时，同一主体的首个通过的图记下种子，后续条目从同一种子起步；种子与参照写进清单（6.5），返工时可复现                                                                                         |
| 同批同风格       | 同一模板、同一风格包的条目按批生成（每批不超过 50 条）；同一批的图标与道具在同一个会话里连续生成，避免工具版本或参数在批中途变化                                                                         |
| 跨图检查         | 导入工具对同一主体的动作条与其三视图比对：轮廓高度、头身比、主色占比、标志色存在与否；偏差超过阈值的标"返工"                                                                                            |
| 导入统一         | 无论原图怎样，导入后像素密度、调色板、描边、透明度与锚点都由代码统一，消除工具之间与批次之间的细微漂移（13 节）                                                                                       |
| 头像与场景一致   | 有名 NPC 先定纸娃娃配方，用组装预览图（正面待机帧放大）作为生成头像的参照图；主要角色的头像与半身立绘以三视图第 4 格的胸像为参照                                                                        |
| 版本冻结         | 一个里程碑内不换生成工具与模型版本；必须更换时，先用新版本重出风格板与三个代表性条目，主审确认风格一致后再继续                                                                                        |

## 13. 导入管线

代码位于 `tools/assets/`：命令行入口（`npm run assets:register`、`assets:import`、`assets:atlas`、`assets:check`），纯逻辑核心在 `tools/assets/core/`（Node 测试，`tests/art_import.test.ts`）。
不新增依赖：PNG 编解码用 `node:zlib` 自写（只处理 8 位 RGB、RGBA 与调色板 PNG），放在 `tools/assets/core/png.ts`。

| 步  | 名称             | 做什么                                                                                                                                               | 失败处理                                       |
| --- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 1   | 登记             | 按文件名匹配提示词条目（本机 `npm run prompts` 生成的 `out/manifest.json`）；记录工具、日期、种子、参照、提示词哈希、原图哈希；读出原图元数据里的隐式标识写进 `aigcLabel`           | 文件名对不上任何条目时拒收并列出最接近的编号   |
| 2   | 抠色             | 洋红背景按色差阈值抠除；去掉洋红色边（边缘像素若更接近洋红则透明，否则保留并在第 5 步量化）；黑底特效不抠                                             | 抠后主体面积过小或贴边即"返工"                 |
| 3   | 切格             | 按模板帧格把画布等分；在格间寻找背景带校正偏移；每格求内容包围盒                                                                                     | 格数与内容块数不一致即"返工"                   |
| 4   | 降采样           | 估计原图的有效像素块大小（边缘自相关），按块取众数色降到有效网格；再按目标本体高度（例：H 人形 28 像素）求整数比例，最近邻缩放到入游戏尺寸；从不用双线性 | 本体高度超出模板区间（1.3 节）即"返工"         |
| 5   | 调色量化         | 在 OKLab 中把每个像素映射到最近的板色：世界类用风格包量化板，生灵类用生灵色板（每张至多 32 色），纸娃娃的键色映射到色槽与色阶级；贴图类在色阶交界保留有序抖动 | 量化误差均值过大（原图偏色严重）即"返工"     |
| 6   | 透明二值         | 不透明度小于五成的像素置为全透明，其余全不透明                                                                                                       | 无                                             |
| 7   | 描边统一         | 剥去原图的外轮廓（1 到 2 像素的深色环），重算 1 像素描边：取相邻填充色色阶的描边级，底边与右边取深描边级，大体型受光侧提亮一级；禁用纯黑             | 无                                             |
| 8   | 锚点与对齐       | 每格求脚底锚点（最低不透明行的中点；飞行体取格底正中），把同一行各帧的锚点对齐到模板基线；按躯干中心消除帧间抖动；记录占地宽度                     | 帧间抖动超过 2 像素即"返工"                    |
| 9   | 镜像与修正       | 由右向行生成左向；头部件已有左向列的不镜像；需要时生成主要角色的左向修正件（3.5）                                                                     | 无                                             |
| 10  | 元数据           | 写 `assets/processed/<类>/<编号>.json`：帧矩形、锚点、占地宽、动作名与帧时长（取自 3.4）、色样行、导入工具版本、隐式标识与处理记录                     | 无                                             |
| 11  | 图集             | `assets:atlas` 把通过审核的处理结果按类别与风格包打进 2048×2048 图集页（MaxRects，留 1 像素间隙）；立牌存为色槽索引图加色样行，图标打进 1024×1024 页 | 单页放不下时自动分页                           |
| 12  | 校验             | 帧数等于帧格；尺寸等于入游戏尺寸；全部像素在调色板内；无纯黑；描边单像素；透明二值；贴图四边无缝（3×3 平铺后边界差值）；文字检测（高对比细小笔画密集区域判为疑似文字，交人工确认）；保留色占比；特效末帧亮度 | 不合格写原因码，状态"返工"            |
| 13  | 预览             | 生成联系表（每张原图与处理结果并排、1 倍与 3 倍）与编辑器 HD-2D 预览的跳转链接                                                                       | 无                                             |

- **处理结果入库：** `assets/processed/` 下的处理结果（PNG 与 JSON）体积小，随仓库提交；图集在构建时生成，不入库。处理是确定性的：同一原图、同一导入工具版本得到同一结果，由测试守住。
- **原图：** `assets/art/` 下的原图是来源证据与重新处理的输入，用 Git LFS 管理（仓库根目录 `.gitattributes`），不进发行包。
- **重新处理：** 导入参数或调色板变化时，`assets:import --all` 从原图全部重出；审核状态不变，联系表标出变化最大的条目供抽查。

## 14. 纹理内存与包体预算

立牌类素材按色槽索引图（每像素 1 字节）计；特效、远景、贴图按 RGBA（每像素 4 字节）计。下表是中档、1080p、一张常见地图同屏时的预算：

| 项目                         | 估算                                                                                         | 预算（中档）  |
| ---------------------------- | -------------------------------------------------------------------------------------------- | ------------- |
| 地面烘焙贴图                 | 每张地图一张；96×96 格约 9 MB；最大 192×192 格约 36 MB                                       | 40 MB 以内    |
| 墙面、屋面、条带、立面       | 当前风格包约 30 张贴图加立面构件，约 1 MB                                                     | 4 MB 以内     |
| 道具与树石                   | 当前风格包约 120 个立牌变体，索引图约 1.5 MB                                                  | 8 MB 以内     |
| 人物                         | 主要角色每人约 265 帧（0.6 兆像素，索引图 0.6 MB）；同屏常驻 24 人约 15 MB；纸娃娃组装图集约 10 MB | 32 MB 以内 |
| 魔物与首领                   | 当前区域约 30 种，每种 3 个朝向 24 格，索引图约 9 MB；首领 2 位约 5 MB                        | 24 MB 以内    |
| 特效                         | 常驻学派与通用约 60 套约 8 MB；招牌与首领特效按需加载                                         | 24 MB 以内    |
| 远景天幕                     | 3 层 1024×256，约 3 MB                                                                        | 4 MB 以内     |
| 光照图                       | 每格 4 像素，最大地图约 2.4 MB                                                                | 4 MB 以内     |
| 小计（场景素材）             | 约 110 MB                                                                                    | 140 MB 以内   |
| 阴影与后期缓冲               | 阴影 1024 约 4 MB；后期缓冲按像素比                                                           | 见下表        |

| 画质档 | 显存总预算（含缓冲） | 后期缓冲约 | 说明                                     |
| ------ | -------------------- | ---------- | ---------------------------------------- |
| 超高   | 640 MB               | 260 MB     | 阴影 4096 约 64 MB，像素比 2              |
| 高     | 400 MB               | 180 MB     | 阴影 2048 约 16 MB，像素比 2              |
| 中     | 280 MB               | 100 MB     | 像素比 1.5                               |
| 低     | 200 MB               | 40 MB      | 无阴影，像素比 1                         |
| 平面   | 进程内存 300 MB      | 不适用     | Canvas2D 使用同一批位图                  |

- **界面侧（DOM）：** 图标按需加载图集页，解码后常驻不超过 24 MB；头像不超过 16 MB；半身立绘最近使用的 6 位不超过 24 MB。
- **淘汰：** 素材解析器按地图与区域加载图集页，换区域时释放上一个区域的魔物与道具页；人物与特效按最近最少使用淘汰。
- **包体：** 处理后的全部素材（索引图与 RGBA 图集）约 150 到 300 MB；原图（约 9,000 张，十余 GB）不进发行包。商店与宣传图不随游戏分发。
- 预算由性能测试（`architecture.md` 第 10 节的场景规模基准）在 M2 与 M3 各实测一次，超出时先降特效常驻量，再降图集页数，不降可行动信息。

## 15. 生产批次与审核流程

### 15.1 分工

| 角色                       | 职责                                                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 用户                       | 美术方向与主审；用小九 AI 生成；最终决定通过、返工或淘汰                                                                   |
| 主会话与 AI 代理           | 从内容目录写条目、维护模板与风格包、运行 `npm run prompts`、登记、导入、自动校验、出预审报告（联系表加不合格原因）、维护覆盖测试 |
| 写作代理（各目录的主人）   | 条目的主体描述必须与目录正文一致（外形、配色、材质与辨识特征）；目录改动时同步条目                                         |

### 15.2 一个批次的流程

| 步  | 环节       | 产出                                                                                                       |
| --- | ---------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | 选批       | 一个模板乘一个风格包，或一个角色的整套帧图；不超过 50 条；参照依赖已全部通过                                |
| 2   | 试样       | 先生成 4 条；主审挑出 1 到 2 张作为本批的批内参照（记入 `refs`）                                           |
| 3   | 批量       | 生成其余条目，落盘并登记                                                                                   |
| 4   | 导入与校验 | 处理结果、自动校验结果、预审报告                                                                           |
| 5   | 人工审核   | 在编辑器素材浏览器与 HD-2D 预览里按 15.3 的清单逐条看                                                      |
| 6   | 定状态     | 通过、返工（调整导入参数或局部修图后复审）、淘汰（改条目的 `subject` 或 `notes` 后重生成）                  |
| 7   | 闭批       | 本批全部通过或淘汰到重生成队列；淘汰的原图移出仓库；图集重建                                               |

### 15.3 审核清单（原因码）

| 原因码        | 含义                                                     | 适用                         |
| ------------- | -------------------------------------------------------- | ---------------------------- |
| `identity`    | 与三视图或固定描述块不符（发型、配色、标志物、种族特征） | 人物、头像、立绘、魔物、首领 |
| `frames`      | 帧数、帧序、动作含义不对；格子错位                       | 全部动作类                   |
| `direction`   | 朝向错误或一张图里混了朝向                               | 动作类                       |
| `silhouette`  | 剪影不可辨或与别的物种过近（例：多足画成四足）           | 魔物、兽伴、兵团             |
| `scale`       | 体型、比例或头身比不对                                   | 立牌类                       |
| `light`       | 光向不是左上，或自带投影与环境光                         | 立牌类、贴图                 |
| `text`        | 出现文字、字母、数字或类似文字的符号                     | 全部                         |
| `seam`        | 无缝贴图有接缝或一眼可见的重复中心                       | 地面、墙面、屋面、纹样、天幕 |
| `palette`     | 量化后颜色失真、保留色被滥用                             | 全部像素类                   |
| `readability` | 1 倍显示时看不清（图标、符号、武器、标志物）             | 图标、立牌                   |
| `originality` | 与知名作品的角色、生物、标志或构图过近                   | 全部                         |
| `spoiler`     | 画面泄露了当前幕不该知道的真相                           | 全部                         |
| `quality`     | 畸形、多余肢体、糊、杂点                                 | 全部                         |
| `background`  | 立牌类原图里画进了场景背景（描述场景的风格锚容易引起）；返工时改用只描述生物与材质的锚变体 | 魔物、首领、兽伴、兵团、人物 |

- 每张图在 1 倍与 3 倍下各看一次；立牌类在目标风格包的白天、金色时刻与夜三种光照下看；与同屏的其他素材并排看（同一角色的不同动作条、同一风格包的道具与地面）。

### 15.4 里程碑闸门

| 里程碑 | 美术闸门（`ART_GATE` 覆盖测试加人工）                                                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| M0     | 全链路样板通过：`lothar_plain` 风格板、H 人台的待机与行走、一套居民服装、夜羽的三视图与待机行走、澱鼠一套、20 个图标、4 套特效；导入、图集、解析器、占位回退与全部校验跑通；技术原型 PT-07（AI 素材样板）实测生产单位成本与首轮通过率，结论写进决策日志 |
| M1     | M1 的全部编号为"通过"；垂直切片里不出现程序化占位（平面档的程序化屋顶除外）                                                                                            |
| M2     | M1 与 M2 的编号通过；M2 编号的占位不超过 10%；战场 HD-2D 与编辑器 HD-2D 预览上线                                                                                        |
| M3     | M1 到 M3 的编号通过率不低于 97%；超高档与自动降档上线                                                                                                                     |

| M5     | 商店与宣传图定稿；Steam 内容调查的 AI 申报与游戏内说明更新到发行版本                                                                                                    |
