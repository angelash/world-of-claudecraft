| HD-2D | 本作的场景表现，"像素微缩模型 + 电影光"：Three.js 三维场景、正交斜俯视相机、像素贴图地面与建筑、像素立牌、光照图与太阳阴影、电影化后期 | art_pipeline 第 2.2 节 |
| 立牌 | 朝向镜头的像素竖板，承载人物、怪物、树、石与装饰；按"竖直立在脚下"计算遮挡 | art_pipeline 第 2.4 节 |

| 风格包 | 一个地域的视觉参数集：地块色阶、建筑外观候选、树形、四时光照与胶片调色，加提示词侧的风格锚与锚色；全作 16 个，画风不影响玩法 | art_pipeline 第 1.4 节 |
| 掀顶 | 玩家所在或选中的建筑屋顶溶解掀开，外墙降为半高剖面，露出室内 | art_pipeline 第 2.6 节 |
| 外观层 | 地图文档的第三层（风格包、逐地点建筑外观、装饰），只有渲染器读，改外观不改玩法 | art_pipeline 第 5.1 节 |
| 平面档 | Canvas2D 俯视平面渲染，无 WebGL 或玩家选"平面"画质时使用的画质档；用同一批位图，屋顶与墙顶由程序化绘制 | art_pipeline 第 2.1、6.4 节 |
| AI 生成素材 | 美术与音频素材全部由 AI 生成：需求写成提示词库，用户交给外部生成工具出图出声，产物经导入管线进入游戏 | art_pipeline 第 6.1 节、decision_log D-018 |
| 提示词库 | `assets/prompts/` 下的模板与按类别的条目文件，每张素材一条（编号、模板、风格包、中英文提示词、参照依赖、里程碑），展开为逐条可复制的提示词与预期清单 | art_pipeline 第 6.3 节 |
| 风格锚 | 每个风格包固定的一段锚句加 8 到 16 色锚色，写进该风格包的每条提示词，保证同一地域的素材风格一致 | art_pipeline 第 1.4 节 |
| 导入管线 | 把 AI 原图处理成游戏素材的固定步骤：抠色、切格、降采样到每米 16 像素、按风格包调色板量化、统一描边、定锚点、打图集 | art_pipeline 第 13 节 |
| 程序化占位 | 素材到位前或审核未通过时由代码绘制的替身，保证任何内容在任何时刻都能显示 | art_pipeline 第 6.4 节 |
| 模型槽 | 玩家放模型的高档、中档、低档三个槽，每个槽是"连接加模型"，可以为空 | llm_providers 第 1.3 节 |
| 绑定角色 | 女神、核心 NPC、在场 NPC、离场批量、统治者与将领、审庭评审六个角色，各自按档位路由、固定某档或用内置 AI | llm_providers 第 1.3 节、decision_log D-067 |
| 预设 | 关闭（内置 AI）、单模型、分档、本机四种起点；全新安装默认"关闭" | llm_providers 第 4.4 节 |
| 花费上限、消耗台账 | 玩家设每小时、每日、每局的金额或 token 上限，用到上限时逐级转内置 AI；台账逐条记录请求的角色、状态、token 与金额 | llm_providers 第 8、9 节 |
| 文本键 | 内核只发文本键加参数，客户端按字符串表渲染；中文为源语言 | implementation_conventions 第 8 节、decision_log D-077 |
