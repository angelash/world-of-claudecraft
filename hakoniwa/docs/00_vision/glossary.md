## 6. 技术术语

| 术语       | 释义                                          | 出处                        |
| ---------- | --------------------------------------------- | --------------------------- |
| tick       | 内核的固定步长，20Hz                          | architecture 第 4.1 节      |
| 切片       | 世界状态中某个系统专属的部分                  | architecture 第 4.3 节      |
| 命令、事件 | 输入（玩家与 AI 提议）与已发生的事实          | architecture 第 4.4、4.5 节 |
| 提议       | AI 产出的结构化意图，以带 tick 的命令进入内核 | architecture 第 5 节        |
| 重放       | 初始世界 + 命令日志复现一局，不调用模型       | architecture 第 4.7 节      |
| GameView   | 客户端读取世界的只读查询接口                  | architecture 第 7 节        |
| WorldRenderer | 客户端渲染接口；HD-2D 渲染器与平面渲染器都实现它 | architecture 第 7 节 |
| HD-2D | 本作的场景表现，"像素微缩模型 + 电影光"：Three.js 三维场景、正交斜俯视相机、像素贴图地面与建筑、像素立牌、光照图与太阳阴影、电影化后期 | art_pipeline 第 2.2 节 |
| 立牌 | 朝向镜头的像素竖板，承载人物、怪物、树、石与装饰；按"竖直立在脚下"计算遮挡 | art_pipeline 第 2.4 节 |
| 纸娃娃 | 参数化像素人物：模型从枚举挑外观参数，代码分层绘制，头像也从这里导出 | art_pipeline 第 3 节 |
| 风格包 | 一个地域的视觉参数集：地块色阶、建筑外观候选、树形、四时光照与胶片调色；画风不影响玩法 | art_pipeline 第 1.4 节 |
| 掀顶 | 玩家所在或选中的建筑屋顶溶解掀开，外墙降为半高剖面，露出室内 | art_pipeline 第 2.6 节 |
| 外观层 | 地图文档的第三层（风格包、逐地点建筑外观、装饰），只有渲染器读，改外观不改玩法 | art_pipeline 第 5.1 节 |
| 平面档 | Canvas2D 俯视平面渲染，无 WebGL 或玩家选"平面"画质时使用的画质档 | art_pipeline 第 2.1 节 |
| 程序化优先 | 素材方案："模型挑参数，代码出像素"，场景素材全部由代码在运行时绘制 | art_pipeline 第 6.1 节 |
