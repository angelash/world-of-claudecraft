# 人物目录（二）：大陆诸国与诸族（Catalog of Continental Characters）

> 内容目录第 2 号（[总纲 12][bible]）。范围：家乡区域为 `holysee`、`grantia`、`mercato`（含赤砧山）、`silva`、`windfang`、
> `night`、`sleepscale`、`isles`（只作背景）的有名人物，以及跨国组织的领导层与骨干：冒险者公会总会、梅尔卡托商会联合、
> 圣教会与异端审判庭、魔导学院联盟、四大佣兵团（金秤军团、铁誓团、风牙猎团、灰帆团）、门徒会的干部链、散居遗民网络。
> 洛萨王国与灰烬荒原的本地人归人物目录（一）`catalog_characters_lotha.md`。
> 正典优先级按 `hakoniwa/CLAUDE.md`：本文属于 `40_design/`，与 `20_world/`、`30_story/` 冲突时以后者为准，差异登记在第 8 节。
> 条目格式、价值通道、功能角色与潜质代码一律取自[总纲][bible]第 2、9 节。撰写时点：2026-11-15。

## 0. 一页结论

1. **审计**：在本目录范围内，正典与分幕文档已有 53 位有名人物（第 2 节，另有 5 位共管人物只作引用）。其中只有 5 人有数据层人设卡，
   其余人物缺少功能角色与价值说明。本文为他们补上 ID、功能角色和价值，并给 9 个只有头衔的位置指定了人选。
2. **新增 150 人**（第 3 节），按七个区域加跨国组织编排；其中第 3.13 节二十五人来自其他目录的请求（迷宫、生灵、图鉴、采集、遗物与七秤会第七席）。每个国家都配齐了统治圈五职（君主、继承人、首辅、财政、谍报），
   2 到 7 名可在 SLG 与 RTS 中使用的新将领，以及神职、行会、学者、名匠和高阶师傅。
3. **一人多用**：每个新增人物都至少在两个规模上有用，覆盖个人、连队、领地、国家、联盟五档（第 4 节）。
   规则是：只有一个功能角色的人不新增。只承担传闻节点角色的人，本文一个也没有。
4. **谨慎的强者**（支柱 3）：12 位隐藏强者分布在大陆各处（第 3.11 节），其中 3 位是传说阶、9 位是英雄阶。
   全大陆的传说阶仍控制在"十几人"以内（[社会 2.1][soc]）。每位都写明表观等级 `apparentLevel`、真实位阶、破绽 `tells`（谁能读到），以及被挑衅后会发生什么。
5. **名匠与师傅**：六种工艺文化各有一位能为玩家锻造名器的匠人（第 3.9 节）。27 个流派各配一位第四到第五幕的师傅，
   他们是流派之门的缘钥；另选 14 组合技搭档，作为合技之门的缘钥（第 3.10 节）。
   这同时补上了[总清单 15][outline]登记的缺口："澄流之门、聆灵之门在第四幕没有落点"。
6. **第六幕证人**：新增 18 位可传唤的证人，每人对应一件或几件证据，可以作为旁证组合加 1（[六幕 4.1][a6]）。
   证人数量从 13 位扩到 31 位，证词分量按 1 到 3 标注（第 3.12 节）。
7. 正典口径（剑帝等级、兽王空位、两位星象学者、学城名等）按已入正典的裁决写定，见第 8.1 节；同伴的个人线钩子见第 3.14 节。

## 1. 读法与口径

### 1.1 范围与分工

| 规则 | 说明 |
| --- | --- |
| 按家乡区域分 | 人物归入出生与归属所在的区域。拉兹格这类夜境出身、后来投奔庭外之国的人，归本文（夜境）；乌尔萨克、卡娅这类风牙出身、第三幕已定居洛萨东部林地的移民，归目录（一） |
| 跨国组织 | 总部与领导层归本文；地方分支的人物归所在区域。例：公会总会长归本文，瓦伦堡大区会长奥托·克劳泽归目录（一） |
| 共管人物 | 门歌者塔维、门徒会右扉玛蒂、无貌者、海德薇·诺特、埃米尔·霍夫曼的家乡在洛萨或荒原，人设卡归目录（一），ID 依目录（一）：`tavi`、`mati`、`faceless`、`hedwig`、`emil`。本文只在门徒会与遗民网络的干部链里引用它们的 ID |
| 环海诸岛 | 只作背景：三位潮民，活动在金湾与盐镜港，不设可去的地点 |
| 不收录 | 女神与造主（见 `pantheon.md`）；第九代魔王（见 `characters.md` 第 7.2 节）；无名的居民模板（目录（一）的 `tpl_`） |

### 1.2 卡片字段与缩写

人物卡沿用[总纲 9.1][bible]的摘要卡字段，为了节省篇幅写成表格，列序固定为：

ID ｜ 名（英文代号）、年龄、种族 ｜ 位阶与等级 ｜ 职能与生业 ｜ 所在、势力与职位 ｜ 首登 ｜ 功能角色 ｜ 价值 ｜ 潜质 ｜ 秘密与揭示 ｜ 女神触点 ｜ 一句台词

ID 列同时充当人物的英文代号；只写了绰号的卡片，以 ID 为准。

| 缩写或符号 | 含义 |
| --- | --- |
| 位阶 | 凡初（1 到 9）、凡熟（10 到 19）、精英（20 到 34）、英雄（35 到 49）、传说（50 到 59）、神话（60）、超越；隐藏强者写"表 某阶 Lv／真 某阶 Lv" |
| 首登 | 幕次加拍：三落、四暗、五高（落地、暗面、高潮）；"传"表示该幕只有传闻 |
| 价值列 | 先写价值通道代码（[总纲 2.1][bible]，主通道在前）；再写"给"（对玩家能给什么）与"要"（他要什么）；最后写"独"（他在哪个系统里不可替代） |
| 人物的"去处" | 人物的去处是系统接口（功能角色）与"收礼"（赠予去处，[总纲 2.2][bible]）；只写有设计意义的礼物偏好 |
| 【真相】 | 只供设计者；括号内是最早可揭示的幕，台账编号按[揭示台账][rl]。凡人可见的名字与台词不泄露真相；第六司在第六幕正名前一律不出现名字 |
| 引用 | 引用其他目录的条目时写对方的 ID，对接表见第 8.2 节 |

### 1.3 ID 规则

- 人物 ID 不加前缀（[总纲 12][bible]），小写英文加下划线，全作唯一。
- 原样沿用数据层已有的 ID：人设卡 `selene`、`luchen`、`yui`、`aiden`、`marcus`（`data/npc/personas.json`）；
  场景说话人 `sasha`、`emperor`（剑帝）、`night_queen`（夜后）、`elwin`、`hart`、`eska`、`tavi`、`faceless`（`data/scenes/speakers.json`）。
- 正典已命名、但数据层还没有 ID 的人物，由本文按"名_姓"或"名_绰号"分配 ID（第 2 节）。新增人物同样按此规则命名。
- 揭示台账的信任变量写作 `trust.vespera`（夜后）、`trust.elwin`、`trust.selene`、`trust.ferryman`；夜后的信任变量按[注册表][wsr]规范为 `trust.night_queen`（`trust.vespera` 为别名），与人物 ID 一致；本文沿用数据层的 `night_queen`，统一方案登记在 8.3。
- 数据层的 `faction` 取值：沿用 `church`、`inquisition`、`heroes`、`academy`、`guild`、`mercator`、`remnants`；
  国家直接用 `data/strategy/nations.json` 的 ID（`holy_see`、`empire`、`league`、`silva`、`windfang`、`nightrealm`）；
  另新增 `disciples`（门徒会）、`golden_scale`、`ironoath`、`windfang_hunt`、`greysail`（四佣兵团）、`grey_rats`（灰鼠）、`dragonkind`（龙族），数据导入时写入势力表。
- 将领的兵种用 `data/warfare/units.json` 的单位 ID（如 `legion_phalanx`、`ironhoof_cavalry`、`elf_longbow`）。正典有、数据层还没有的兵种，写[RTS 3.3][rts]里的中文名。
- 官员的能力倾向用 `data/city/officials.json` 的八个维度：`food`、`works`、`civil`、`security`、`military`、`commerce`、`research`、`culture`。

### 1.4 阶、幕与数量约束

| 约束 | 本文口径 |

## 6. 数据导入要点

- 人设卡：沿用 `data/npc/personas.json` 的字段（`id`、`name`、`race`、`age`、`job`、`level`、`faction`、`goddess`、`devotion`、`traits`、`secrets`、`voice`、`tags`）。
  本文的"女神触点"一列可直接拆成 `goddess` 与 `devotion`；"一句台词"进 `voice.catchphrases`；【真相】只进 `secrets` 并按台账加解锁条件。
- 将领：按[RTS 4.4][rts]的 `General` 结构导入四项设计值与特性，战场技能复用主工程的效果词汇（[调研：战斗与内容盘点 8.2][r_inv]）；`loyalty` 由所属势力与玩家关系计算，不写死。
- 官员：能力倾向写入 `competence` 的对应维度，其余维度默认 40；`creed` 取女神触点里的主神（"无"写空值，城建目录的官员信条读空值为"不奉神"）。
- 隐藏强者：`level` 写真实等级，另加两个字段：`apparentLevel`（整数，对外的表观等级）与 `tells`（数组，每条 `{ text, reader }`，`reader` 取 `eye`、`tide_sight`、`deep_tide` 之一）；观澜、单位框（[界面][ux]的 `apparentLevel`）、认知系统与内置 AI 读它们（第 3.11 节）。
- AI 分级（分级思路见[调研：主工程 AI NPC][r_ainpc]）：统治圈、古龙与门徒会干部为 L1 或 L0 低频会话；其余 L2；第六幕证人在传唤时临时升为 L1（[NPC 社会][npc]）。

### 8.3 已决的设计问题

1. 古龙的数据族群与 AI 分级：`dragonkind`，与艾斯卡同为低频会话（L1 低频），每次会面只回答一个问题。
2. 第六幕证人：31 位。庭镜之门的传唤节奏写定为每个庭期至多传唤 6 名第 3.12 节的新增证人（主要角色与编号证据的证人不计），每人一次陈述，第二次传唤须带新的证物；三个庭期合计至多 18 人，其余证词以书面证言计（强度减 1）。庭期是审期六场审理两两一组（开庭与指控、质证一与质证二、陈述与终审），这条上限已写入[第六幕][a6]第 4.1 节。
3. 本文给 42 位正典人物分配的 ID 与目录（一）无冲突（`selene` 两边同指一人）；数据导入时以本文为准。
4. 将领四项与官员能力是设计值，战斗与城建联调时在数据层调整。
5. 隐藏强者的读数：`apparentLevel` 与 `tells` 写定为人设卡字段（第 3.11 节、第 6 节）。
