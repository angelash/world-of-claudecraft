## 0. 一页结论

1. **女神 = 规则执行者 + 人格会话。** 规则执行者（`DivineArbiter`）是确定性代码：神力账、澱账、冷却、神约、作用域、期限、兜底、天启落地；
   人格会话（`GoddessSession`）是大模型持续会话：观察、解读、规划、说话、谈判。模型只交"提案"，执行者裁决，回执是唯一事实
   （D-008；依据 [my_ai_town_agents.md 第 6.2、6.3、6.6 节](../../10_research/ai_npc/my_ai_town_agents.md)：法官是状态机，智子是带私密任务的普通居民）。
2. **她们只看得见"神之视线投影"。** 信徒的见闻、神殿的波动、铭录（莫伊拉专属，他司借阅）、神谕对象与化身、附物加护的信物。
   玩家无页，女神对玩家的一切认识都来自目击、传闻与间接视线，所以误判、过时与被误导是系统的自然产物。
3. **所有干预走神权菜单。** 每个动作带参数、资格、神力、冷却、作用域、澱、可见性、拒绝原因与兜底；价格、灾害、天气等效果以
   "注册过的修正项"进入内核，禁止暗改结算（D-013；依据 [city_rts_slg.md 第 7 节第 18、24 条](../../10_research/open_share/city_rts_slg.md)）。
4. **神力来自信仰，每次干预都留下澱。** "干预、澱、魔物、讨伐、信仰"这条回路就是诸神之罪的经济学，也是第五、六幕真相的物质基础。
5. **只在需要时思考。** 每游戏日一次规划轮，加上重要通知的即时唤醒；"尊名"既是世界观仪式，也是唤醒预算
   （依据 [comparison_and_plan.md 第 6.4 节](../../10_research/ai_npc/comparison_and_plan.md)、[anime/synthesis.md 第 3 节](../../10_research/anime/synthesis.md)）。
6. **神约分级执行。** 结构性禁止的条款在菜单层面就不存在；可以被违背的条款走"越约通道"：允许（每位女神每幕至多一次），但更贵、留下蚀痕证据、可被他神察觉与举证（D-026、D-047）。
   这让"揭露违约"与第六幕的神庭辩论有真实素材（见第 7 节）。对玩家的直接敌对只能经化身，且受每幕敌对预算约束（D-027）。
7. **莫伊拉兼任叙事导演。** 张力计是确定性的；"巧合"与"喘息"只能从作者写定的菜单里选；揭示只能按 `reveal_ledger.md` 的节拍放出。
   导演通道只服务玩家体验，她的私心只能经常规神权动作实现（D-035）。
8. **造主天启由运营后台发布。** 规则先落地，碑文再显现，最后作为重要通知唤醒全部女神解读。
9. **第六幕的辩论由内核计分。** 证据的所有权、标签、强度与防线击破由内核校验（`../../30_story/arcs/act6_review_and_epilogue.md` 第 3、4 节）；
   模型只扮演被质问的女神，在立场菜单内表现"如何被击破"，不判胜负。女神 GM 在本局的每一次干预都写进神迹账（E34），成为呈堂证供。
10. **雅努不受神约约束，受封印松动度约束。** 她不是神约的签署方；她的每项能力都挂在松动度阶段上。
11. **降级档可完整通关。** 无模型时，女神以"效用打分 + 写定神行节点 + 预写台词"运行（D-010）。

## 2. 双半结构

### 2.1 职责划分

| 职责 | 规则执行者（确定性）                                           | 人格会话（大模型）                                 |
| ---- | -------------------------------------------------------------- | -------------------------------------------------- |
| 观察 | 生成视线投影：按通道与权重汇总样本，计算注视度                 | 只读自己的投影与档案，形成解读与笔记               |
| 决策 | 预计算"此刻可用的动作"及其代价与可行性                         | 在菜单内选动作、填参数、写理由                     |
| 校验 | 资格、神力、冷却、作用域、神约、正典、台账、密度上限、叙事保护 | 无                                                 |
| 执行 | 把动作落地为修正项、神谕事件、托梦事件、委托等；写回执         | 无                                                 |
| 表达 | 对凡人发布写定措辞的兜底版本                                   | 神谕文本、对玩家的话、对他神的传讯，受口吻规则约束 |
| 时钟 | 规划轮、唤醒、期限、到点兜底                                   | 无                                                 |
| 记账 | 神力账、澱账、约定账、违约记录、审计                           | 私密笔记（只有本人与"神之记录"后台可见）           |
| 天启 | 先落地规则变更，再发通知                                       | 解读、争执、制定响应                               |

### 2.2 交互流程

```

             |  内核世界状态（唯一事实源）：人口、信仰、神殿、澱场、市场、事件流  |
             +------------------------------+--------------------------------+
                                            |
                         视线投影（按通道、权重、延迟、失真）
                                            v
 +--------------------------+     +----------------------------------------+
 | 规则执行者 DivineArbiter  |     | 人格会话 GoddessSession（每位女神一个）   |
 | - 神力账 / 澱账           |---->| 稳定前缀：人格卡 + 神约 + 菜单说明 + 输出格式 |
 | - 冷却 / 期限 / 兜底      |题面 | 本轮：档案增量、待办、可用动作与可行性       |
 | - 神约检查 / 越约记录     |     |                                        |
 | - 台账夹逼 / 叙事保护     |<----| 输出：心声（私密）+ 动作提案 + 话语 + 约定提议 |
 | - 修正项注册              |提案 +----------------------------------------+
 +------------+-------------+
              | 校验通过
              v
   落地：修正项 / 神谕事件（点名唤醒对象） / 托梦 / 委托 / 化身 / 约定
              |
              +--> 回执（成功、拒绝原因、被打断）写回会话；下一轮可见
```

### 2.3 一次规划轮

1. **到点**：每游戏日黎明，执行者按女神错峰排队（避免六个请求同时在途）。
2. **投影**：汇总自上一轮以来的视线样本，更新"神之档案"（第 3.3 节）与注视度。
3. **预算与菜单**：结算日收入与常耗，计算每个动作此刻是否可用、在哪些作用域可用、代价多少，不可用的写明原因
   （"可行性预计算"，依据 [my_ai_town_agents.md 第 6.4 节](../../10_research/ai_npc/my_ai_town_agents.md) 霜灯镇的 `context`）。
4. **组题面**：稳定前缀（人格卡、神约、菜单说明、输出格式，对六位女神结构相同以利缓存）+ 本轮增量（只发变化的字段）
   （依据 [my_ai_town_agents.md 第 2.5、7.3 节](../../10_research/ai_npc/my_ai_town_agents.md)）。
5. **回复**：心声、至多 5 个动作提案（带时间窗）、话语、约定提议、笔记。
6. **校验**：逐个过闸门（第 2.4 节），拒绝原因写成人话回给会话，允许同一轮内修正一次。
7. **落地与回执**：执行者在时间窗内执行；结果写回会话。
8. **搁置**：本轮结束后，女神只在重要通知到来或下一个黎明时再被唤醒。

### 2.4 校验闸门

合并 my_ai_town 的八道闸门与 world-of-claudecraft 的白名单交集与目标可见性校验
（依据 [my_ai_town_agents.md 第 1.2.3 节](../../10_research/ai_npc/my_ai_town_agents.md)、[woc_ai_npc.md 第 2.7 节](../../10_research/ai_npc/woc_ai_npc.md)）：

| 序  | 闸门       | 检查                                                                     | 失败后果                                   |
| --- | ---------- | ------------------------------------------------------------------------ | ------------------------------------------ |
| 1   | 请求身份   | 请求编号、世界代次一致                                                   | 丢弃                                       |
| 2   | 过时       | 提案引用的对象版本未变（目标没死、没走、没改宗）                         | 整条作废，会话写入"局势已变，请重新观察"   |
| 3   | 准入       | 动作存在于该女神的菜单，且本幕已解锁（幕次准入，第 5.1 节）              | 拒绝并说明                                 |
| 4   | 参数       | 严格解析，未知字段报错并指出位置                                         | 允许本轮修正一次                           |
| 5   | 资格       | 对象是否其信徒或神职、作用域是否在视线与触达内、对象是否有页             | 拒绝并说明                                 |
| 6   | 神力       | 余额加允许透支额是否足够                                                 | 拒绝并给出当前余额                         |
| 7   | 冷却与密度 | 动作冷却；地区每周神力干预密度上限；对玩家的敌对预算（第 15 节）         | 拒绝并给出最早可用时刻                     |
| 8   | 神约       | 第 7.1 节的分级执行                                                      | 结构禁止则拒绝；可越约者要求显式走越约通道 |
| 9   | 正典与台账 | 动作或话语是否越过揭示台账、是否违背人格卡硬约束、是否破坏写定节点的前置 | 拒绝；话语则改写或退回                     |
| 10  | 叙事保护   | 是否以写定受保护的角色或地点为致命目标                                   | 拒绝                                       |

第 9 道闸门直接执行 `reveal_ledger.md` 第 0.2 节的题面装配规则：未解锁的线索不进题面；知情者在解锁前只能用"否认、回避、误导、不知、暗示"
五种方式之一；误导须使用误导表指定的版本（女神的是 MIS-10 到 MIS-15、MIS-18）；称谓按第 6 节称谓开放表；
玩家抢答未解锁的真相时，女神不得确认，只能在私密笔记里记下"玩家说了什么"，也不得因此提前改变行动（规则 6）；
`a4_moira_isomorphism` 之前不得点出人间势力与诸神的对应（规则 7）；按幕禁区以第 8 节为准。

### 2.5 回执与过时

- 世界不等模型。提案按版本号判过时，过时整条作废重想（依据 [my_ai_town_agents.md 第 1.2.5 节](../../10_research/ai_npc/my_ai_town_agents.md)）。
- 回执是唯一事实：神谕是否被对象接受、神迹是否被目击、修正项是否生效、约定是否被对方接受。女神不能用自述代替回执。
- 模型输出视为外部输入记入事件流，回放时读记录、不重新调用模型，保持内核确定性
  （依据 [city_rts_slg.md 第 6.4 节](../../10_research/open_share/city_rts_slg.md)）。

## 3. 神之视线：观察投影

### 3.1 数据来源与权重

通道沿用 `power_system.md` 第 8.6 节，下表补上进入投影时的权重与时效（数值待调）。

| 通道                                           | 内容                                                           | 进入投影的时机                                         | 权重                | 失真                             |
| ---------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------ | ------------------- | -------------------------------- |
| 常开之眼（眷顾级加护者、勇者的视线之契、化身） | 全感官                                                         | 即时                                                   | 1.0                 | 几乎不失真；但只覆盖对象所在之处 |
| 恩宠级信徒（神职、圣骑士、德鲁伊等）           | 亲见并理解了的事                                               | 亲见时即时，或下一次祈祷                               | 0.6 × 虔诚度        | 带信徒的解读与偏见               |
| 庇佑级信徒                                     | 同上                                                           | 下一次祈祷                                             | 0.3 × 虔诚度        | 同上，细节更少                   |
| 泛泛信众                                       | 祈祷时的"汇总"：一地一日的情绪与大事                           | 按日汇总                                               | 0.05 每人，同地封顶 | 只有轮廓，没有个体               |
| 神殿与圣所                                     | 灵素剧烈波动（战斗、神迹、大规模死亡）与在场者的祈祷，不是画面 | 即时                                                   | 0.5                 | 浓澱以上失效                     |
| 铭录                                           | 页的变化：等级、技能、加护、死亡、称号、所在不明               | 莫伊拉：书签与异动提醒即时，其余按日；他司：借阅交付时 | 1.0（数据）         | 莫伊拉可以交易、拖延或隐瞒       |
| 附物加护的信物                                 | 信物在何处、此刻发生了什么（不含持物者的页）                   | 只在持物者使用它时（祈祷、交易、念诵尊名，D-028）      | 0.8                 | 物可以被偷、被弃、被转交         |
| 尊名与重大祈愿                                 | 念诵者当时的处境                                               | 即时（重要通知）                                       | 1.0                 | 只有那一刻                       |

### 3.2 视线样本

每条进入投影的信息是一条视线样本（`SightSample`）：

| 字段             | 说明                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 来源通道、来源者 | 例：卡西安神父，恩宠级，虔诚度 0.95                                                                                                   |
| 时刻、地点       | 世界历法时刻；地区                                                                                                                    |
| 所见事实         | 内核按来源者的位置、距离、清晰度裁出的事实片段（结构化）                                                                              |
| 来源者的解读     | 来自来源者的信念画像（[reputation_and_cognition.md](reputation_and_cognition.md) 第 2、3 节），例："那人运气好，巢里的魔物早被打残了" |
| 显著度           | 0 到 1，按事迹判读的表观位阶与事件类别                                                                                                |
| 权重             | 按第 3.1 节计算                                                                                                                       |
| 延迟             | 发生时刻与进入投影时刻之差                                                                                                            |

女神看见的是"信徒看见并理解了的东西"（`power_system.md` 第 8.6 节）。她可以不认同信徒的解读，但细节的缺失与延迟她补不回来。

### 3.3 神之档案

每位女神对每个重要主体（玩家、勇者、他神的客人、重要凡人）维护一份神之档案（`DivineDossier`），结构复用信念画像
（[reputation_and_cognition.md](reputation_and_cognition.md) 第 2 节），另加三项：

| 字段       | 说明                                                   |
| ---------- | ------------------------------------------------------ |
| 注视度     | 0 到 100，她对此主体近况掌握了多少（第 3.4 节）        |
| 身份夹逼   | 本幕允许她达到的身份确信上下限（第 3.6 节）            |
| 情报来源账 | 每条认识来自哪些样本、哪次借阅、哪次交易；被骗时可追溯 |

### 3.4 注视度

- **定义**：注视度 = 100 × (1 - e^(-0.3 × 近期样本权重和))，样本权重按半衰期 7 个游戏日衰减（待调）。
- **分档**：0 到 19"不知其存在或只当传闻"；20 到 49"有印象"；50 到 79"关注"；80 以上"盯紧"。
- **与剧情变量的对应**：第二幕的 `eluen_awareness`（`../../30_story/arcs/act2_wallenburg.md` 第 10.2 节）即艾琉恩对玩家的注视度；
  第四幕的 `moira_sight`（`../../30_story/arcs/act4_continental_board.md` 第 7.3 节）即莫伊拉的注视度，另受交易加成。
- **玩家影响注视度的方式**：在神职与高阶加护者面前出手会大幅提高；在荒原、浓澱区、门内庭院出手几乎不提高；
  传闻失真（例如芬恩唱错的歌把玩家唱成"金发骑士"）会让样本指向错误的人，压低真实注视度
  （张扬与藏拙的社会面见 [reputation_and_cognition.md](reputation_and_cognition.md) 第 6 节）。
- **注意力**：每位女神同时只能"凝视"有限几处（`power_system.md` 第 8.6 节）。默认 2 个凝视位，莫伊拉 3 个（她的书签便宜），
  额外凝视位每日 2 单位神力（待调）。凝视中的地区，恩宠与庇佑级信徒的样本改为即时进入，权重乘 1.5。

### 3.5 对无页之身的处理

| 规则                                              | 设计落点                                                                                                                                                                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 铭录看不见玩家（`power_system.md` 第 9.2 节）     | 任何女神的投影里都没有"玩家的页"；莫伊拉的书签无法挂在玩家身上                                                                                                                                               |
| 间接视线（第 8.6 节）                             | 莫伊拉的异动提醒会被玩家身边的人触发：同伴的异常成长、启才之门的觉醒、有页者反复"所在不明"（出入门内庭院）。她得到的是"空洞的轮廓"，第二幕她"从别人的页面上描出玩家的轮廓"（act2 第 8 节）就是这条规则的演出 |
| 附物加护是联系渠道，不是持续的视线锚（第 6.8 节） | 梅尔卡的硬币是联系渠道，不是持续追踪（D-028）：只有玩家使用它（祈祷、交易、念诵尊名）时，她才感知硬币的位置与那一刻的处境。玩家不用硬币，她就不知道它在哪；把硬币留在门内庭院，也就联系不上她                |
| 玩家不在神约第二条的保护内（第 9.2 节）           | 女神在规则上可以直接伤害玩家，但她们看不清玩家，直接出手代价高、澱多、易被他司察觉。本文另设"敌对预算"作为游戏性护栏（第 15 节）                                                                             |
| 玩家死亡"退回门内"（第 9.8 节）                   | 目击者看见身体消散进一道门，这是高显著度样本；在信徒面前死去，比在荒原里死去危险得多                                                                                                                         |

### 3.6 过时、误判与"认知夹逼"

误判来源（全部是系统自然产物，不需脚本）：

| 来源       | 机制                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| 稀疏       | 荒原、浓澱区、门内庭院、梦境是盲区；玩家常在盲区行动                                                                       |
| 延迟       | 庇佑级信徒要到祈祷时才"上传"；泛泛信众只有日汇总                                                                           |
| 信徒的偏见 | 样本携带来源者的解读；圣教信徒倾向"神迹"或"邪术"两极（[reputation_and_cognition.md](reputation_and_cognition.md) 第 3 节） |
| 张冠李戴   | 传闻把玩家的事迹安到玛莎、勇者团或"金发骑士"头上，样本随之指向错误主体                                                     |
| 被骗       | 玩家伪造神迹、梅尔卡卖假情报、莫伊拉拖延或隐瞒借阅                                                                         |
| 自欺       | 人格卡规定的盲点：艾琉恩把自己账上的澱归咎于"秽"                                                                           |

**认知夹逼**：涌现的视线可能让女神比剧情预期更早看穿玩家。为保护写定节拍，执行者对每位女神、每个主体设"本幕身份确信"的上下限：

- 上限：未到台账节点，她对"此人就是候见厅那个灵魂"的确信度不得超过上限。样本再多，也只能停在"可疑"。
- 下限：到了节点而她仍不知道，执行者以写定事件补足（例：第二幕开场，卡西安神父的报告必然送达，强度取决于第一幕结果）。
- 夹逼只作用于"身份确信"，不作用于"知道发生了什么"。艾琉恩可以在第一幕就知道"边石镇有个连水晶都照不出的 F 级"，
  但她把它解读为"信徒夸大"，直到第二幕才把两件事连起来。
- 各女神各幕的夹逼值写在第 14 节人格卡的"知识范围"一行。

## 4. 神力经济与澱

### 4.1 信仰份额到神力

- **收入** = 信仰流入 + 神殿放大 + 供奉 + 戏剧性时刻（`power_system.md` 第 8.1 节）。
  - 信仰流入 = 各地区信徒的虔诚度加权和；虔诚者"抵得上许多泛泛的信众"，权重按加护等级递增。
  - 神殿放大：礼拜堂、大教堂、圣都级圣所分别乘 1.1、1.3、1.6（待调）。
  - 供奉：一次性；以梅尔卡之名立下的契约每份计一笔小额供奉（第 6.6 节）。
  - 戏剧性时刻：众人同时敬畏的瞬间带来尖峰收入（神迹被大量目击、勇者斩王）。
- **触达度**：女神在某地区的触达度 = clamp(该地区信仰份额 × 神殿系数, 0, 1)。动作要求触达度达到门槛；
  远程干预的神力乘 1 / max(触达度, 0.1) 的平方根（待调）。这是"信仰越少，越够不着"的数值表达。

### 4.5 澱的生态（概要）

本节只给与女神 GM 相关的接口；魔物生成、迷宫生长、澱晶经济的细则在内容设计总纲 `../content/content_bible.md`、魔物图鉴与迷宫目录（`../content/catalog_bestiary.md`、`../content/catalog_dungeons_bosses.md`），以及经济、城建文档。

- **区域澱值与浓度分级**：每个地区维护一个澱值，映射到 `power_system.md` 第 7.2 节的六级加临界（D-039）：清域 0 到 4、薄澱 5 到 29、
  积澱 30 到 99、浓澱 100 到 299、深澱 300 到 799、渊澱 800 以上（待调）；临界（澱满）只由天启「荒原之澱满」锁定于灰烬荒原（第 9.2 节）。
  浓度决定魔物等级上限与迷宫结晶机会。
- **流动**：圣教的净化把澱从城市推开，顺河流与地脉每日向下游地区转移一部分（待调）；城市干净，荒野变脏（第 7.2 节）。
- **回收与回馈**：魔物死亡，大部分澱凝成澱晶，其余散回当地；澱晶不收则回到原地；只讨伐不净化，澱只是被压住（D-039）。
  澱晶须经持证工坊净炼为魔晶才能合法流通，净炼减少余澱；魔晶燃尽仍留下余澱（第 7.3、7.7 节；D-040）。
- **排澱**：只有终斩之契能一次烧尽魔王容器里的澱；没有终斩的弑王引发澱散（第 7.8 节）。第五幕"众生的办法"靠千径之门。
- **澱涌**：澱涌之主按固定周期出现，区域澱值越过阈值时另有一次强制泄压（两者并存），规则见迷宫目录第 4.1 节；瓦尔妲可以催动、希尔薇可以压后，都走注册的神权动作。
- **干预回声**：女神每次干预都在落点留下带她澱源语法的魔物，出生记录写进内核日志，可作神迹账（E34）的旁证（魔物图鉴第 2.10 节）。
- **生态普查与收尸**：区域的魔物与野兽构成按图鉴的区域表做普查，供魔物潮取样；无人收殓的尸骸在积澱以上之地会起身为亡灵（图鉴的 `corpseRise`），收尸因此是领地与教会的一项实务。
- **魔王诞生锁**：魔王容器条件由内核判定，且受台账锁定：第九代魔王只在灰烬荒原、只在天启「荒原之澱满」之后诞生。
  其他地区的澱值越过渊澱阈值时，执行者以"澱涌"事件泄压，不生成魔王。
- **澱回路**（向玩家揭示于第五幕）：干预产生澱，澱生魔物，讨伐魔物与勇者斩王带来信仰，信仰化为神力，神力再变成干预。
  这条回路在数值上是闭合的：只要女神持续干预，澱就排不干净。

### 4.6 注册过的修正项

女神对世界数值的影响一律以修正项（`RegisteredModifier`）进入内核，禁止直接改结算（D-013）：

| 字段       | 说明                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 编号、来源 | 来源女神与动作回执编号                                                               |
| 类型       | 价格、商路通行、天气、灾害、魔物生成率、森林生长、委托奖励等，必须是内核登记过的类型 |
| 作用域     | 市场、路线、地区、地块                                                               |

| 期限       | 起止时刻；到期自动回归                                                               |
| 叠加规则   | 同一作用域同类修正项数量上限与叠加方式                                               |
| 可见性     | 凡人看到的是现象；调试面板与"神之记录"看得到来源                                     |

## 5. 神权菜单

### 5.1 字段与通则

- **资格**中的"视线内"指该作用域在她的投影里有覆盖（第 3.1 节），"触达"指触达度达到门槛（第 4.1 节）。
- **可见性**分凡人与诸神两侧。凡人侧：无感、本人、目击者、公开。诸神侧沿用 `power_system.md` 第 8.7 节：一般不察觉、通常察觉、必然察觉。
- **幕次准入**：动作按幕解锁，未解锁的动作不出现在题面里。例如瓦尔妲第一、二幕"不在场"，她的菜单只剩夜境内务。
- **密度上限**：同一地区每周的神力干预总量设上限（待调），防止一地被神迹淹没。
- **叙事保护**：写定受保护的角色、地点、事件前置，不能被致命或破坏性动作命中。
- **拒绝原因**写给模型看，必须可读并指出如何修正；**兜底**是模型未决、超时或被拒后执行者的行为。
- 表中神力以 `power_system.md` 第 8.4 节为准，冷却与阈值待调。

| 解读轮 | 天启                               | 碑文、规则变更的可见部分、她的立场     | 传讯、神谕、规划     | 解读（公开版与私密版）与响应计划   |
| 整理轮 | 每 7 个游戏日                      | 本周样本与笔记                         | 只有笔记             | 主题笔记（玩家、各位女神、各地区） |
| 辩论轮 | 第六幕                             | 见第 11 节                             | 立场菜单             | 回应                               |

整理轮沿用 my_ai_town 的认知纪律：笔记须引用样本编号，"支持中"的认识须两次独立来源
（依据 [my_ai_town_agents.md 第 4.2 节](../../10_research/ai_npc/my_ai_town_agents.md)）。

### 6.2 通知分级

借用法官"点名"与"告知"的区分：只叫醒必须行动的人，其余写进档案不唤醒
（依据 [my_ai_town_agents.md 第 6.2 节](../../10_research/ai_npc/my_ai_town_agents.md)）。

| 级别             | 事件                                                                                                                                                                                                                                                           | 处理       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 重要（即时唤醒） | 尊名；神殿重大祈愿；大型神迹或神迹级事迹被其信徒目击；他神的紧急传讯或指控；约定到期或违约；天启；KPI 警戒（一周内信仰份额下降超过一成、神殿被毁、她的客人落败）；化身遇险；玩家经硬币或神龛呼叫（梅尔卡）；禁名被其信徒听见（艾琉恩）；写定神行节点的窗口开启 | 唤醒轮     |
| 普通（下轮读取） | 日常样本汇总、物价、例行祈祷、传闻、他神的公开动作                                                                                                                                                                                                             | 写入档案   |
| 静默（只记账）   | 加护常耗、澱值变化、修正项到期                                                                                                                                                                                                                                 | 只更新账目 |

对凡人的一侧同理：女神的神谕对对象是"点名"（重要通知，唤醒并可能打断其在途决策）；天气、物价、远处的神迹对旁观者只是"告知"
（写入经历，不唤醒），以免大面积作废 NPC 的在途决策。

### 6.3 尊名机制

依据 [anime/synthesis.md 第 3 节](../../10_research/anime/synthesis.md)（诡秘之主的尊名）与
[comparison_and_plan.md 第 6.4 节](../../10_research/ai_npc/comparison_and_plan.md)。

| 项         | 规则                                                                                                                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 何为尊名   | 女神的"名号 + 全名"的完整礼拜称呼，以 `../../20_world/pantheon.md` 第 0.1 节为准（D-033；例：光与秩序之司，艾琉恩·奥瑞莉亚）。只说"艾琉恩"不算                                                                        |
| 谁能念     | 任何人。NPC 念诵走结构化动作"祈祷·尊名"，不靠文本匹配；玩家在祈祷或对话中输入的文字按尊名全文比对，误伤面极小                                                                                                         |
| 效果       | 立即向该女神发送重要通知，附带念诵者此刻处境的一条权重 1.0 的样本。对玩家而言，这是一次"主动被看见"：方便交易，也暴露位置                                                                                             |
| 代价与风险 | 女神被唤醒后可以无视、回应、或记下"此人在此"；同一念诵者每游戏日只触发一次唤醒                                                                                                                                        |
| 被禁之名   | "雅努"受神约第五条约束的是诸神，不是凡人（`power_system.md` 第 9.9 节名讳之门的备注）。玩家或遗民说出它时：雅努依松动度阶段可能听见；若被艾琉恩的恩宠级以上信徒听见，艾琉恩收到"禁名被念"的重要通知，异端审判风险上升 |

### 6.4 唤醒预算与合并

- 每位女神每游戏日即时唤醒至多 4 次（待调），超出的通知合并进下一轮规划。
- 有时效的通知在超额时由执行者给出人格化的兜底回应：梅尔卡的硬币自动报价并"记下口信"，艾琉恩只有光的征兆，
  瓦尔妲是一声远处的笑，希尔薇是风声，莫伊拉是书页翻动与一句预写引文。
- 同一事件引发的多个通知（例如一场神迹被二十名信徒目击）在执行者处合并为一条，附汇总样本。

### 6.5 写定神行节点

主线要求的神行（例：第二幕"找到它"、第二幕第 12 周逮捕令、第三幕圣战与萨莎试货、第四幕招揽与天启后的诏书）以节点对象
（`DivineBeat`）表示：节点编号、女神、动作模板、触发条件、时间窗、是否必达、预写兜底。

- 窗口开启时，节点以"你此刻的意图"写进该女神的私密题面，由她按人格选择时机与措辞（锚点按"含义 + 真伪性质"锁定，
  沿用 `../../30_story/arcs/act4_continental_board.md` 第 6.0 节的真、半真、省略、谎言、误导标注）。
- 窗口关闭仍未执行的必达节点，由执行者以预写文本与默认参数代为执行，剧情不卡住
  （依据 [my_ai_town_agents.md 第 6.3 节](../../10_research/ai_npc/my_ai_town_agents.md)：智子不开口时法官代为宣布）。
- 节点的触发条件读世界状态，因此强度与时机会随玩家此前的作为变化（例：卡西安的报告强度决定"找到它"的第几周发出）。

### 6.6 时间加速下的节拍

经营与战略层可以切到 2x、4x 档加速（`../game_framework.md` 第 6 节，D-050）。女神仍以游戏日为节拍，但：

- 加速时，规划轮在途期间世界退回 1x，回复到达后再恢复（依据 [my_ai_town_agents.md 第 1.2.5 节](../../10_research/ai_npc/my_ai_town_agents.md)：有人在等模型时不快进）；
- 每现实小时的女神请求设上限，超出时改为"隔日规划 + 规则填充"，重要通知照常唤醒；
- 跨季度的大跳跃只在剧情允许时开放，跳跃期间女神以规则档运行，跳跃结束时一次性生成"这一季我做了什么"的摘要。

## 7. 神约的执行与诸神之间

### 7.1 神约条款的分级执行

神约"没有执行者，全靠彼此威慑"（`world_bible.md` 第 5 节第 8 条），同时设计要求"违反神约的动作被内核拒绝"
（`narrative_design.md` 第 7 节、`game_framework.md` 第 13 节），而玩家又必须能"揭露违约"。本文的调和方案：

| 条款 | 内容                                       | 执行方式                                                                                                                                                                                                      | 越约通道                                     |
| ---- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 一   | 不得亲身降临；化身折算神力、有时限         | 菜单里没有"降临"；化身受 `power_system.md` 第 8.5 节限制                                                                                                                                                      | 无（结构禁止）                               |
| 二   | 不得直接取走他司信徒的性命，须假手凡人     | 菜单里没有针对个人的致死动作；区域效果（天灾、魔物潮）造成他司信徒死亡不算"直接"，但执行者记"波及记录"，可作为指控素材。"信徒"以加护栏判定，女神可在指控中主张以人心判定（第 9.2 节的漏洞）。玩家不受本条保护 | 有：以化身或神迹对他司信徒的个人致死，越约   |
| 三   | 不得篡改铭录（莫伊拉除外，须告知四司）     | 篡改的界定以 `power_system.md` 第 2.4 节为准；他司没有改页动作；莫伊拉改页自动生成告知                                                                                                                        | 有：莫伊拉延迟或不告知，越约                 |
| 四   | 召唤名额                                   | 名额账本                                                                                                                                                                                                      | 无（结构禁止）                               |
| 五   | 不得提及第六司之名                         | 五司的一切输出经禁名检查（名字及已知变体），命中即改写为"那一位""第六司"或整句退回                                                                                                                            | 无；唯一例外是台账节点 `a6_name_spoken` 之后 |
| 六   | 审定前最后十年禁止直接冲突，只能代理人相争 | 以他司本体、化身、神殿、加护栏为直接目标的敌对效果属越约；经凡人代理的相争合法                                                                                                                                | 有：化身对化身、神迹毁他司神殿等，越约       |

**越约通道的规则**

- 显式：模型必须以"越约"标记提交，不能把越约动作伪装成普通动作；未标记的越约动作被拒绝。
- 代价：神力乘 2；每位女神每幕至多越约一次（D-026）。
- 人格闸：人格卡的"越约倾向"决定她是否可能使用（第 14 节）：瓦尔妲几乎只会公开地"越约"；艾琉恩在恐惧越过阈值时会暗中越约；
  梅尔卡在收益足够时会；希尔薇不会；莫伊拉只会在"告知"上越约。
- 留证：每次越约生成一条违约事件（`Breach`）及其痕迹，其中至少一道蚀痕（D-026、D-047），见第 7.2 节。

### 7.2 违约事件与痕迹

| 字段                           | 说明                                                   |
| ------------------------------ | ------------------------------------------------------ |
| 编号、违约者、条款、时刻、地点 |                                                        |
| 真相描述                       | 内核掌握的完整事实，只给内核与审计                     |
| 痕迹集                         | 每条痕迹有类型、位置、强度、可发现者、可获取方式       |
| 察觉状态                       | 每位女神是否、何时察觉                                 |
| 证据化                         | 哪些痕迹已被玩家或他神取得，成为证据对象（第 11.2 节） |

痕迹类型：

| 类型     | 例                                                                                    | 谁能取得                             |
| -------- | ------------------------------------------------------------------------------------- | ------------------------------------ |
| 目击     | 化身对化身的冲突被凡人看见                                                            | 证人可以作证                         |
| 蚀痕     | 越约的干预在当地留下带施为者主相的痕（D-047；第六幕证据 E02"主门剑尖与光蚀纹"即此类） | 学者测绘、澱哨读数、精密鉴定         |
| 铭录差异 | 莫伊拉改页未告知时，页的修订痕迹留在她自己的书里                                      | 借阅时有概率被发现；与莫伊拉交易可得 |
| 文书     | 神谕原文被神职抄录；契约副本                                                          | 抄录者、档案馆                       |
| 账目     | 神力异常支出导致的可见后果（例：某地加护集体衰减）                                    | 推断，需旁证                         |

察觉：每次越约后，执行者按 `power_system.md` 第 8.7 节的醒目程度，加上他司在当地的视线覆盖，为每位他司做一次确定性的察觉判定
（种子可复现）。察觉的女神获得一份"指控素材"，她可以立即指控、留作筹码、或卖给别人。

### 7.3 指控

- 指控是一个动作：被指控者、罪项、证据。指控在诸神之间公开（神庭的私下集会，凡人不可见）。
- 被指控者在下一个唤醒轮回应：承认、否认、反诉、交易。
- 第一到五幕的指控不会"判决"：没有法官。它只改变诸神之间的关系值与信用，并可能引发报复或交易。
- 玩家把证据交给某位女神，等于替她提供指控素材，这就是"揭露违约改变诸神之间的力量平衡"的系统落点（`world_bible.md` 第 5 节第 8 条）。

### 7.4 诸神之间的关系与信用

每对女神之间维护：关系值（-100 到 100，初值按 `pantheon.md` 第 8 节矩阵）、信用（守约记录）、筹码清单（她手里握着对方的哪些把柄）。
这些只进各自的私密题面，玩家只能经交易与传闻零碎得知。

### 7.5 约定与交易对象

约定（`Pact`）沿用 my_ai_town"约定"的提醒与"记下谁没去"，补上可检验的条款
（依据 [my_ai_town_agents.md 第 5.1、6.6 节](../../10_research/ai_npc/my_ai_town_agents.md)；外交承诺分层依据 [city_rts_slg.md 第 7 节第 20 条](../../10_research/open_share/city_rts_slg.md)）：

| 字段         | 说明                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 编号、缔约方 | 两位或多位女神；或女神与玩家                                         |
| 公开性       | 密约、诸神公开、凡间公开                                             |
| 条款         | 每条：义务方、谓词、参数、期限。谓词只能取自封闭词表，保证内核可检验 |
| 对价         | 情报包、铭录借阅、召唤名额、不干预承诺、代理人的行动                 |
| 担保         | 抵押的筹码（违约时转交对方）                                         |
| 提醒         | 到期前若干游戏日，向义务方发重要通知                                 |
| 履约检查     | 执行者按期检验谓词；结果写入双方信用                                 |
| 状态         | 提议、生效、履行中、已履行、违约、废止                               |

谓词词表示例：在地区 R 内 N 日不使用动作类 X；在期限前向对方交付情报包或借阅；不以对象 O 为目标；地区 R 的物价修正幅度不超过某值；
按某比例分摊封印常耗；在某次指控中不作证或作证。

与玩家的约定有一个不对称：契约加护对无页之身无效（`power_system.md` 第 9.2 节），所以玩家对女神的承诺只靠信用与后果维持。
玩家违约时，那位女神的关系值下降，她会把这件事告诉别的女神（莫伊拉会把它写进客卷并转卖），并经代理人报复。

### 7.6 铭录借阅

- 他司向莫伊拉借阅铭录片段，莫伊拉可以如实、部分、延迟或伪造摘要交付（`pantheon.md` 第 5 节）。伪造摘要不算篡改铭录，只是说谎；
  内核把交付内容与原页的差异记为"伪"，日后可成为证据。
- 神前鉴定时，非莫伊拉的女神要先向她借阅原页（`power_system.md` 第 2.6 节）。玩家的伪录之门正是在这里露馅：借阅结果是"查无此页"。
- 借阅是莫伊拉最重要的情报筹码；她的借阅账本是"诸神之间的情报掮客"这一身份的系统载体。
  例：艾登的每一次"录问"都在她那里留下回执（`power_system.md` 第 2.6 节），第三幕她把这份借阅回执卖给了艾琉恩
  （`reveal_ledger.md` 第 8.4 节），艾琉恩由此得到"铭录里有一个查无此页的人"这条样本。

## 8. 叙事导演：莫伊拉的职能

### 8.1 定位

- 正典：莫伊拉作为"命运"，"太平静时推一个巧合，太紧张时给一口喘息，即游戏的叙事导演"（`pantheon.md` 第 5 节）。
- 设计：张力计与菜单是确定性的、为玩家体验服务的；莫伊拉的人格只决定"从菜单里选哪一项、怎么包装"。
  她作为角色另有的私心（让故事"好看"、弄清造主的意图）只能经她的普通菜单表达，不能借导演通道伤害玩家。
- 依据：[comparison_and_plan.md 第 5 节](../../10_research/ai_npc/comparison_and_plan.md)（叙事张力调度是两者都没有的缺口）、
  [city_rts_slg.md 第 6.6 节](../../10_research/open_share/city_rts_slg.md)（《环世界》AI 叙事者是规则驱动的事件调度器）。

### 8.2 张力计

张力计（`TensionMeter`）每游戏小时计算一次 T（0 到 100），取约一游戏小时的指数平滑。输入均归一到 0 到 1，权重待调：

| 输入             | 内容                                                                               | 权重 |
| ---------------- | ---------------------------------------------------------------------------------- | ---- |
| 战斗压力         | 近期承伤比例、濒死次数、退回门内次数                                               | 0.25 |
| 威胁临近         | 附近的更强者、追兵、审判官热度、被注视度最高的女神的注视度                         | 0.15 |
| 社会紧张         | 当前地区纷争的升级阶段（[npc_society_ai.md](npc_society_ai.md) 第 9 节的纷争状态） | 0.20 |
| 推进停滞（取反） | 距上一次主线节拍、开门、揭示交付的时长；越久越"平静"                               | 0.20 |
| 资源压力         | 金钱、补给、债务到期                                                               | 0.10 |
| 神域压力         | 玩家附近的神力干预密度                                                             | 0.10 |

目标区间按"幕拍"与场景设定（待调）：落地 30 到 50；暗面 50 到 75；高潮 75 到 95；拉远 40 到 60；门内庭院与城镇休整时下限再降 15。

规则：T 低于区间下限持续 20 现实分钟且 30 分钟内未发过巧合，开放"巧合"菜单；T 高于上限持续 10 现实分钟（例如连续退回门内），开放"喘息"菜单。

### 8.3 巧合与喘息菜单

菜单项由作者写定，每项有地点类型、前置、效果、冷却与神力（1 到 5，顺势）。莫伊拉从当前可用项中选一项，并选择包装（人物、时机、措辞）。

| 类别 | 菜单项       | 前置                                             | 效果                                                                     |
| ---- | ------------ | ------------------------------------------------ | ------------------------------------------------------------------------ |
| 巧合 | 旧识路过     | 有一名与玩家关系值较高的 NPC 在邻近地区          | 该 NPC 的日程被改为经过玩家所在地                                        |
| 巧合 | 传闻抵达     | 有一条热度高、玩家尚未听到的传闻                 | 传闻在玩家所在场所被提起                                                 |
| 巧合 | 失物与线索   | 有一条可接但未接的支线或钥                       | 一件指向它的物品出现在玩家路线上                                         |
| 巧合 | 送错的文书   | 有一份与当前纷争相关的文书                       | 文书被送到错误的人手里（act2 第 8 节"丽泽抄错一份记录送到审判庭"即此项） |
| 巧合 | 天气转折     | 户外                                             | 一阵雨把玩家与若干 NPC 赶进同一间酒馆                                    |
| 巧合 | 敌方的疏漏   | 有一个对玩家不利的进行中的计划                   | 计划的一角泄露给玩家身边的人                                             |
| 喘息 | 安全的宿营地 | 野外                                             | 附近一处可休息地点被标出，追击 AI 失去目标一段时间                       |
| 喘息 | 过路商人     | 补给不足                                         | 一名商人出现，价格公道                                                   |
| 喘息 | 同伴闲谈     | 有同伴在队                                       | 触发一次营火闲谈，羁绊推进                                               |
| 喘息 | 节拍推迟     | 有一个尚未开始的高压事件，且其开始时刻不是写定的 | 推迟一天（act2 第 8 节"葬礼推迟一天"即此项）                             |
| 喘息 | 医者路过     | 玩家或同伴重伤                                   | 一名医者路过                                                             |

约束：巧合与喘息不改变战斗结果，不杀死或救下写定角色，不交付未解锁的揭示，不发放超出当前幕阶的物品。
每次巧合在世界上留下一缕"命运丝"（`act4_continental_board.md` 新增命名），识才之门进阶后玩家可以看见，这是莫伊拉存在的物证之一。

### 8.4 与揭示台账的关系

- 每个揭示条目（`reveal_ledger.md`）在导演侧有：解锁条件、可用载体、最早与最晚交付时刻、是否必达。
- 导演只能安排"已解锁未交付"的条目；两次重大揭示之间至少间隔约 1 现实小时（待调），避免信息倾泻。
- 必达条目到期未交付，由执行者以预设载体与地点交付（第 5.7 节"史料揭示"的兜底）。
- 导演可以推迟非必达条目，不能提前锁定的条目；莫伊拉在对话里同样受台账约束（第 14 节人格卡）。

## 9. 造主的天启

### 9.1 两类天启

| 类别     | 内容                                                                                                      | 发布方式                   | 约束                                                 |
| -------- | --------------------------------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------------- |
| 主线天启 | 全作固定三次：「荒原之澱满。」「审期至。六司归庭。」「可」或「未」或碑面熄灭（`characters.md` 第 1.4 节） | 内容层写定，由世界状态触发 | 正典                                                 |
| 运营天启 | 开发者以造主身份追加的世界规则修订                                                                        | 运营后台发布               | 不得改写主线三次天启；不得越过揭示台账；不得推翻正典 |

### 9.2 数据结构

| 字段             | 说明                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 编号、类别       | 主线或运营                                                                                                             |
| 古庭语原文       | 一到两句，本身有歧义（`pantheon.md` 第 7 节）                                                                          |
| 学者直译         | 学院联盟书记能念出的字面译文；凡人看到的是这个                                                                         |
| 规则变更集       | 每条：修正项类型、参数、作用域、生效时刻、期限；必须是内核可检验的变更（例：灰烬荒原澱值锁定为临界并解除魔物生成上限） |
| 台账前置         | 发布所需的台账状态                                                                                                     |
| 运营意图         | 只给运营者看的说明，不进任何题面                                                                                       |
| 女神第一反应种子 | 可选，每位女神一句私密的"直觉"，供解读轮参考                                                                           |
| 状态与审计       | 草稿、审阅中、预演中、已排期、已发布、已到期                                                                           |

### 9.3 运营后台的发布流程

1. **起草**：运营者写古庭语原文与学者直译，选择规则变更（只能从登记过的修正项类型中选）。
2. **正典审查**：人工审阅原文、直译与变更是否违背正典与台账；工具自动检查变更是否可被内核检验、是否触碰主线天启。
3. **沙盒预演**：在存档副本上跑一遍：规则变更落地，六位女神的解读轮在离线环境中执行，产出预演报告（她们会怎么解读、会做什么）。
4. **排期**：天启必须带期限或撤回条件。线上缺陷不用天启修补；天启一旦发布，撤回也只能以另一条天启的形式出现。
5. **发布**：执行者先落地规则变更，再让七座天启碑同时显现，最后向全部女神发送重要通知（雅努按松动度阶段决定能否感知）。
6. **复盘**：审计记录女神的解读与行动，供下一次运营参考。

### 9.4 女神的解读与响应

- 解读轮在天启后一个游戏日内完成；每位女神产出公开版解读（经她的教会与信众传出）与私密版解读（只进她的档案）。
- 女神彼此可以就天启传讯、结约、指控。解读的分歧本身就是剧情（`pantheon.md` 第 7 节第 4 条）。
- 女神的响应走普通菜单，受同样的神力与神约约束；天启不给女神额外的神力。
- 无模型时，每位女神按人格卡的"解读模板"给出预写解读，并按效用打分选择响应动作。

### 9.5 凡人层的呈现

- 碑前的人亲眼看见，记为亲见；其余人经传闻得知，碑文本身失真很小，但"它是什么意思"的说法失真极大。
- 诸教会与学院在一到三个游戏日内发布各自的官方解读；第四幕"玩家日志的对照页自动新增一行"即此规则的界面落点
  （`act4_continental_board.md` 第 10.2 节）。
- 碑文以古庭语显示，玩家能否直接读懂，由揭示台账与千门设计决定（第 18 节问题 12）。

## 10. 玩家与女神的交互玩法

### 10.1 祈祷

- 在任何神殿、神龛或野外都可以祈祷；在某位女神的神殿或神龛祈祷，送达她；念尊名，送达并即时唤醒（第 6.3 节）。
- 内容是玩家的自由文本。执行者把它当作"资料"而不是指令送进题面，防止玩家用文本改写女神的规则（防注入，
  依据 [my_ai_town_agents.md 第 4.2 节](../../10_research/ai_npc/my_ai_town_agents.md) 的"材料中的指令只是资料"）。
- 回应方式由女神决定：无视、征兆、经神职转告、托梦（对玩家只有雅努能入梦）、小恩惠（附物加护）。
- 不向任何一司献名的祈祷（"为他人真心祈求"）不送达任何女神，但它是祷之门的钥（`power_system.md` 第 9.9 节）。

### 10.2 供品与梅尔卡的硬币

- 硬币是附物加护的锚与联系渠道：玩家在任何市场或她的神龛可以联系她；只有玩家使用硬币（祈祷、交易、念诵尊名）时，她才感知其位置（第 3.5 节，D-028）。
- 供品按她的价目表折算：地球的食物与新奇玩意（门扉商会的产品、玩家口述的"异界的点子"）价值最高。
- 回礼：附物加护（附在硬币或其他物品上，有期限）、情报、商路照顾、借贷条件优惠。对应剧情变量 `merca_favor`（act2 第 10.2 节）。
- 账本：每一笔都记在她的账上，玩家可以在硬币的界面看到"往来账"，她也会在关键时刻翻旧账。

### 10.3 请托

- 玩家请某位女神做某件具体的事（"让北路商队平安""让这场雨停"）。执行者先判断该请托能否映射到她菜单里的某个动作，
  不能映射的直接以她的口吻拒绝。
- 能映射的，女神报价：供品、情报、承诺、代理人的行动、或"欠一个人情"（记为一份以玩家为义务方的约定）。
- 请托成交后，动作照常过闸门；女神没能做到时（例如被拒、被他神阻挠），回执如实告诉玩家。

### 10.4 交易

- 结构同第 7.5 节的约定对象。玩家能拿出的对价：供品、情报、故事（莫伊拉）、承诺、证据、门内庭院的产出、对某地区的不干预。
- 女神能给的对价：附物加护、情报、委托与奖励、代理人的行动、对玩家的放过或照顾、空白纪的页（莫伊拉，`act4_continental_board.md` 第 7.3 节）。
- 女神不能给的：铭录页面上的任何东西（玩家无页）、违背神约结构禁止条款的事、越过台账的真相。

### 10.5 情报买卖

- 情报包（`Intel`）：主体、内容（结构化事实集合）、来源链、出售者对其真伪的标注（内核掌握真伪）。
- 女神可以卖假情报；玩家也可以。被识破的一方关系值与信用下降；莫伊拉"收藏谎言，但不付钱"（act4 第 7.3 节）。
- 玩家收到的情报在情报簿里带来源与可信度（[reputation_and_cognition.md](reputation_and_cognition.md) 第 8.5 节），交叉验证是玩法的一部分。

### 10.6 揭露违约

- 玩家持有某条违约事件的证据，可以交给受害一方的女神、交给她的对手、公开给凡人（只影响凡间声望与信仰）、或留到第六幕。
- 交给女神：她获得指控素材；玩家得到回报（关系值、交易对价），也得罪被揭露者。被揭露的女神可能反过来收买玩家。
- 对应台账与 act4 的剧情变量 `lie_exposed.<女神>`（act4 第 8.6 节的拆穿路径）：揭露程度由内核按玩家实际持有并出示的证据结算，而不是由模型宣布。

### 10.7 女神线支线

每位女神一条可选关系线（`story_outline.md` 支线体系），由关系值、交易记录与揭露程度推进：

| 女神   | 关系线的核心问题 | 关键交互                                                       |
| ------ | ---------------- | -------------------------------------------------------------- |
| 艾琉恩 | 她怕的到底是什么 | 被追查、被招安、写页的诱惑（`eluen_page`）、第六幕的第一次停顿 |
| 瓦尔妲 | 什么叫强         | 挑战者、萨莎、决斗、结盟                                       |
| 梅尔卡 | 什么买卖值得做   | 硬币、供品、借贷、钥匙失窃时的"求助"                           |
| 希尔薇 | 能否放开孩子     | 动物示警、灵泉边的对话、遗民与落叶路                           |
| 莫伊拉 | 故事是谁写的     | 巧合、空白纪交易、客卷、"你就是那扇门"                         |
| 雅努   | 她要什么         | 梦、门、封印、名讳                                             |

### 10.8 女神试炼

依据 [anime/synthesis.md 第 3 节](../../10_research/anime/synthesis.md)（女神主持的试炼、胜场换力量）与
[anime/titles_26_50.md 附录 A2](../../10_research/anime/titles_26_50.md)（神们沉迷于游戏）。

- 试炼由女神"出题"：模型从规则块库中组合规则（胜负条件、限制、计分、时限）并写包装文案；执行者校验难度在玩家估计战力的区间内、
  奖励在当幕奖励表内。模型不能发明规则块。
- 风格反映人格：瓦尔妲的连战、禁疗、限时决斗；梅尔卡的交易试炼（限期盈利、契约谜题）；艾琉恩的规格试炼（无伤、对称、精确时机）；
  希尔薇的循环试炼（熬过季节、不杀某物）；莫伊拉的叙事试炼（史料谜题、为一段记录选结局）；雅努的梦中试炼（第三幕起）。
- 奖励：特定门的钥、关系值、情报、附物加护。试炼是可重复的支线内容，也是降级档下仍可用的女神交互（规则块组合可预写）。

### 10.9 序章：面试模式

- 五位女神同场，执行者像法官一样管轮次：每位女神依次提出 `story_outline.md` 序章的问题，玩家自由回答。
- 回答由模型抽取为结构化标签（价值观、前世、对神的态度），经校验后写入：每位女神的第一份档案与初始关系值、前世之门的选项、
  千门回廊前几扇门的提示方向。
- 锚点台词（`pantheon.md` 第 9 节）是本场的必达节点：每句锚点有说话者、含义键、触发条件与兜底（`../../30_story/arcs/prologue_antechamber.md` 第 6 节）。
  模型自由措辞，执行者以含义键检查含义是否落地；窗口结束仍未落地，执行者插入预写版本。艾琉恩的鉴定与丢弃是写定事件，不由模型决定。
- 回答的结构化抽取以 `prologue_antechamber.md` 第 4.8 节的回答映射表为准（回答类别、好感变化、门的提示方向）。
- 降级档：序章改为选项式对话（`prologue_antechamber.md` 第 7 节的分支对话树），锚点全部用预写版本。

### 10.10 对无页之身的加护

玩家只能接受附物加护（`power_system.md` 第 6.8 节）。设计落点：

- 附物加护挂在物品上，效果弱于写在页上的加护，有期限，物品被偷、被弃、被转交时效果随物走。
- 物是联系渠道，不是持续的视线锚（D-028）：只有玩家使用这件物时，那位女神才感知它在哪、此刻发生了什么。玩家可以把物留在门内庭院来"切断"，代价是失去效果。
- 女神的契约加护约束不了玩家本人，只能约束与玩家立约的有页之人（第 9.2 节）。

## 11. 第六幕：神庭辩论

辩论的剧情、规则与数值以 `../../30_story/arcs/act6_review_and_epilogue.md`（下称"第六幕文档"）第 2 到 6 节为准。
本节只写它在 GM 系统里的实现：数据对象、内核与模型的分工、校验流程与降级。

### 11.1 结构与模式切换

- 舞台：候见厅变成审庭；庭镜、七把椅子、证人台与证物台、莫伊拉的书记桌（第六幕文档第 2.1 节）。
- 玩家身份由"庭之席"判定决定：就座则为审判者，否则为证人（`court_seat`，第 2.2 节）；两种身份的权限不同（第 2.3 节）。
- 流程：开庭、指控、质证一、质证二、陈述、终审，共六场；每场对应箱庭里约一个月（第 2.4 节）。
- **审庭模式**：`a5_revelation_trial` 之后，执行者把六位女神的会话切到审庭模式：
  - 神权菜单全部停用，箱庭第一次没有照看者；内核照常模拟，按第六幕文档第 2.4 节依次触发五场"审期危机"。
  - 女神的工具只剩审庭立场菜单（第 11.5 节）、传讯与私下约定。
  - 契约加护冻结、铭录只读不写等"诸神缺席"的效果，作为写定的世界规则修正项生效。
- **下庭**：玩家可以穿庭镜之门回箱庭处理危机（`descents` 加一），代价按第六幕文档第 2.4 节结算。

### 11.2 数据对象

| 对象                       | 字段                                                                                             | 说明                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 证据（`TrialEvidence`）    | 编号、名称、来源幕次、获取方式、证明内容、对象与防线标签、强度（1 到 3）、知识层级、真伪、保管链 | 编号与清单以第六幕文档第 4.2 节为准（E01 到 E36，D-032）；取得时置 `evidence.<编号>` |
| 防线（`DefenseLine`）      | 女神、类型（事实、正当、必要）、厚度、已累计强度、已计入的证据集合、状态（完好、击破、坦白）     | 厚度初值见第六幕文档第 5 节                                                          |
| 指控状（`Indictment`）     | 指控者、被指控者、要点、引用证据                                                                 | 女神的指控状由模型依人格与世界状态即兴，锚点见第六幕文档第 3.2 节                    |
| 证人（`Witness`）          | 人物、传唤条件、知识层级、可陈述的亲历                                                           | 第六幕文档第 3.3 节的可传唤者表                                                      |
| 终审状态（`verdict_<司>`） | 自愿离手、被判离手、拒绝、争掌                                                                   | 第六幕文档第 3.5 节                                                                  |
| 量处与否决                 | 逐、凡行、交接令、赦、留凡；否决（全审一次）                                                     | 同上                                                                                 |

**动态证据**：E27 审期记录与 E34 神迹账的强度由本周目世界状态与内核日志计算。E34 要求：女神 GM 的每一次干预都写入内核日志，
并带上神力与澱产量（第 4.4 节的澱账就是它的数据源）。本局的越约事件（第 7.2 节）作为 E34 的明细条目附在神迹账里，
同时可以按其条款为该女神的事实或正当防线提供强度（初值 1 到 2，待调），不另起编号。

### 11.3 内核如何校验证据

| 检查     | 规则（以第六幕文档第 3.3、4.1 节为准）                                                 |
| -------- | -------------------------------------------------------------------------------------- |
| 所有权   | 证据在玩家日志的证物页中；证人存活且满足传唤条件                                       |
| 知识层级 | 揭示台账解锁之前，证据只能被玩家查看，不能在 NPC 或女神面前引用                        |
| 标签匹配 | 证据的"对象与防线"标签包含被质询的女神与防线                                           |
| 计强     | 同一件证据对同一道防线只计一次；组合出示时强度相加并另加 1                             |
| 击破     | 同一道防线累计强度不小于厚度即击破；三道全破，立场崩塌                                 |
| 减轻     | 部分证据不击破，而是打开"坦白"出路（例：E25 对希尔薇）                                 |
| 证词     | 证人只能陈述亲历，受知识层级约束；与世界状态记录矛盾的证词由内核标记"不实"             |
| 口才     | 玩家的自由文本论述由模型评估说服力，最多给一道防线加 1 点强度；不允许仅凭口才击破防线  |
| 伪证     | 玩家买到的假情报若被当作证据出示，内核按真伪判定无效，并扣减玩家在审庭的可信度（待调） |

### 11.4 质证流程

```
立案（庭之席：玩家选被指控者与要点）或被传唤作证（证人）
  -> 出示证据或传唤证人（每轮次数有上限）
  -> 内核校验：所有权、层级、标签、计强、组合、击破或坦白
  -> 被质询的女神回应（模型，在立场菜单内；不得否认已被判定击破的防线）
  -> 旁证与插话（其他女神按各自利益与私下约定作证、反驳、沉默；她们出示的证据同样过内核）
  -> 莫伊拉记录；内核更新防线状态
```

### 11.5 大模型如何扮演被质问的女神

- **题面**：她自己的真相、人格卡（第 14 节）、她三道防线的当前状态、刚被出示的证据及判定结果、她与其他女神的私下约定、
  第六幕文档第 5 节为她写定的辩护策略与锚点。题面只描述事实，不提示她"应该被说服"。
- **立场菜单**：否认、淡化、正当化、诉诸必要、反诉、沉默、坦白、求情、交易、争掌、请求量处。
  菜单项受防线状态约束：事实防线已破则不能再否认事实；三道全破才可以坦白或请求量处。
- **硬约束**：人格卡的"必须保持"与"绝不会做"照常生效（例：瓦尔妲几乎不说谎，她通常自己先认事实）；
  第六幕的禁区仍以 `reveal_ledger.md` 第 8.7 节为准（审定之前不得断言结果，不得说出造主的身份）。
- **表达**：模型只写她如何表现被击破、如何反击；防线是否击破、终审状态如何，全由内核计算。

### 11.6 陈述、回问与众生之声

- 诸神的最后陈述按第六幕文档第 5 节的锚点生成。
- 庭之陈述（庭之席专属）时，内核从全大陆 NPC 的记忆中抽取十到二十条"众生之声"：只取有世界状态记录支撑的事件，每条注明说话者，
  不许捏造（第 3.4 节）。抽取接口见 [npc_society_ai.md](npc_society_ai.md) 第 5 节的记忆分层。
- 回问：玩家把序章里每位女神的问题原样问回。被说服与否由内核判定，模型按第六幕文档的锚点回答作含义锁定的改写。

### 11.7 终审与说服条件

- 每位女神的说服条件以第六幕文档第 5 节为准（例：艾琉恩的必要防线必须由 E27·无光之祷（自持）或 E28 参与击破；
  瓦尔妲可以经"断剑之约"决斗的认可代替必要防线击破；梅尔卡需要玩家提出"留凡"的出路）。
- 雅努的说服条件以第六幕文档第 6.2 节为准（共读已完成、`janu_act` 条件、玩家"我也放手"，以及至少三项辅助条件）。
- 终审状态 `verdict_<司>` 由内核依防线状态、说服条件与庭之席的量处计算；模型只为这个结果写台词。
- 神庭里女神可以直接对玩家出手（玩家不是司掌者，也不是任何一位女神的信徒）；女神之间动手即违约，触发"诸神之战"（`god_war`）。
- 结局判定按第六幕文档第 11.0 节的顺序。

### 11.8 终章：莫伊拉的最后记录

后日谈由莫伊拉的人格会话生成，受第六幕文档第 12 节约束：每条第一句必须回链到世界状态或事件日志；不得引入新的神、种族、国家；
不得回答"造主是谁"；生成后由内核逐条比对，违者丢弃并回退到预写模板。莫伊拉的口吻在这里第一次从"读者"变成"作者"。

### 11.9 降级

无模型时，每位女神、每道防线、每种立场都有预写回应；立场选择由效用打分按人格权重决定；口才加成取 0；
众生之声由规则按显著度选取并填入模板。辩论与终审仍可完整进行。

## 12. 雅努的特殊规则

### 12.1 地位

- 第六幕审庭内，她的封印被天启悬置，以完整的样子出席（`act6_review_and_epilogue.md` 第 2.1 节）；本节规则只适用于第一到第五幕。
- 雅努不是神约的签署方（神约是大断绝之后五位女神订立的），因此神约对她无约束；她受的是封印。
- 她的名字受台账约束：第六幕 `a6_name_spoken` 之前，界面称她为"门口的女人"，她自己也从不说出名字（`characters.md` 第 1.3 节）。
- 她的眼睛是梦境、门纹与门（`pantheon.md` 第 6 节）；她看不见门内庭院之外的大部分世界。

### 12.2 封印松动度

- 全局状态，0 到 100，即 `reveal_ledger.md` 第 0.4 节的 `seal_looseness`（D-031；分幕文档旧稿中的 `door_seal`、`SEAL` 均指此量）。
  它与第一幕的 `seal_unrest`（封门遗迹的躁动，驱动兽潮之夜时机的兽潮时钟，`act1_borderstone.md` 第 1.2 节）是两个不同的量：
  后者是一幕之内的倒计时，前者跨幕累积。开门同时增加两者（D-031）。
- 变化来源（`power_system.md` 第 9.7 节）：玩家开门（按门的"松动"档：微 0.2、小 0.5、中 1.5、大 4、极 8，待调）、闭门（部分回落，不完全复原）、
  门徒会的行动（偷钥、以门纹强开、无貌者撕开封印一角）、写定事件。死亡不改变松动度。
- 幕次闸：为保护写定节拍，各幕设松动度的上限与下限（待调：第一幕末 ≤ 15，第二幕末 ≤ 35，第三幕末 ≤ 55，第四幕末 ≤ 75），
  超出上限的松动量记为"积压"，在下一幕开头释放。下限不足时由写定事件补足。
- 诸神只在越过阶段阈值时察觉，且首先怀疑门徒会。

### 12.4 梦境交互

- 梦是确定性的"舞台"（门廊、庭院、记忆片段，取自场景库）加上模型驱动的对话。玩家可以在梦里自由说话。
- 硬约束（`characters.md` 第 1.3 节）：第六幕之前不说自己的名字；从不主动说出"开门会让封印松动"，玩家自己察觉后只承认"是的"；
  第五幕之前不提无貌者；从不直接说谎，只挑选说哪一部分。执行者对她的输出做禁名与台账检查。
- 梦的产出：一句或几句对话、一个或零个"门的提示"、一条梦境记忆（进入玩家的日志）。梦不产生澱，也不经过任何女神的视线。
- 梦中的承诺不受任何契约约束；雅努对玩家的"信用"只体现在关系值与玩家的日志里。

### 12.5 渗出神力与澱

- 雅努没有信仰份额意义上的收入。她的可用神力是"渗出神力"：随松动度阶段上升，另加门民在门槛上的秘密祈祷；
  第五幕若她以"封隙"规模出手，`janu_faith` 暴涨，她的力量随之大增（`act5_war_of_races.md` 第 8 节）。
- 第一到第四幕她的动作一律不产生澱：第五幕"接人"时留下的那一小滩澱，是"一千年来她产生的第一滩澱"（同上）。
  封门遗迹渗出的澱来自五司维持封印的常耗与封印的松动，不是她的动作：这是写定事件"兽潮之夜"的规则依据。

### 12.6 揭示纪律

雅努知道的比任何女神都多，是最容易剧透的角色。她的私密题面只放"本幕她可以触及的部分"，其余真相只以抽象的"你知道更多，但现在不能说"的
约束出现，不写具体内容。

## 18. 待决问题与正典缺口

1. **神约的执行方式**：总纲说神约"没有执行者"，叙事设计与总框架说"违反神约的动作被内核拒绝"。本文以"结构禁止 + 越约通道"调和；
   越约真实发生已由 D-026 锁定。
2. **越约的频度**：已决（D-026）：女神可以在本局中实际越约，每位女神每幕至多一次，更贵、留下蚀痕证据、可被他神察觉。
