## 0. 一页结论

1. **内置 AI 是一等运行模式，也是唯一的兜底。** 每个决策请求在发出的那一 tick 就由内置 AI 算好提议并存进请求（"兜底先算"，[ai_architecture.md](../../50_tech/ai_architecture.md) 第 3.3 节）；
   无模型时它就是全部的决策者，有模型时它是超时、非法、过时与预算不足时的接替者，也是自动玩家与回放的基线。
2. **一条管线，两种提议者。** 菜单、内核闸门、执行、回执、事件、认知、传闻、关系、揭示台账、敌对预算全部共用；模型只替换"从菜单里选哪一项、怎么说"这一步（D-007、D-068）。
   切换没有第二套代码路径，所以无模型的一局只由种子与玩家命令决定。
3. **按角色逐个切换。** 切换粒度对齐 D-067 的六个绑定角色（女神、核心 NPC、在场 NPC、离场批量、统治者与将领、审庭评审），再细到单个行动者的降级（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 9.3 节）；
   任一角色可以单独走内置 AI，其余继续用模型。
4. **六种技术各管一摊。** 分层状态机管 NPC 的作息；效用评分管"在合法选项里挑一个"（动作、意图、方案、台词、话题）；行为树管功能角色、同伴、兵团与英雄的执行；
   HTN 管女神、统治者、首领的多步谋划；话题图加台词包管对话；规则表管叙事导演与反应。原语只有一份（`src/core/brain/`），各系统复用。
5. **NPC 按功能角色成形。** 内容总纲的 15 个功能角色各有一张效用动作库（动作与评分项）与一棵行为树；一个 NPC 的大脑是一棵根树（剧本、对话、紧急、纷争、职责、需求、目标、主动、社交、日程逐层让位），角色子树挂在职责层。
   需求扩到九项（饱腹、精力、安全感、财务、社交、信仰、面子、职责、心安），情绪不设数值，"心情"由需求档位与近事推出。
6. **对话 = 话题图 + 台词包 + 意图分类。** 台词包 `ln_<npcId>` 的槽位契约与台词目录共用（第 7 节）；选择规则按信任档、知识层级、台账解锁、心情、时间、地点与重复抑制逐层过滤；
   自由输入由 52 种规则意图的分类器处理，取代 `src/systems/dialogue/replies.ts` 的 `answer()` 中的 5 条正则。分类器在两档都运行：它决定世界后果（关系、认知证据、尊名唤醒、台账防护），模型只换措辞。
7. **"凡人不信"是台词驱动的状态机。** 信念画像的状态与解释（[reputation_and_cognition.md](reputation_and_cognition.md) 第 3 节）直接选择 `unbelief.deny`、`unbelief.explain`、`unbelief.waver` 三档台词与接受后的分叉反应；
   状态跃迁的那一刻产生一句吠叫或下一次交谈的开场白，喜剧节流照常生效。
8. **女神 = 人格权重的效用规划 + HTN 谋划 + 反应表 + 神约判定。** 每位女神的权重表来自 `pantheon.md` 的计分（KPI）与人格；越约只在内核硬闸与女神目录登记的指标条件同时满足时发生，第三到第五幕各有写定的越约窗口作保底；
   敌对预算按目录的每幕定额执行，敌对动作的预兆由 HTN 自动排在前面。无模型时的神谕、对话、交易、天启解读、试炼与审庭回应全部来自每位女神 250 句以上的台词包与模板。
9. **统治者、将领、同伴、官员、导演都有完整的规则大脑。** 统治者三层（命名修正项的动机层、HTN 计划层、规则执行层）；将领"方案效用 + 兵团行为树 + 英雄技能循环"；同伴"战斗行为树 + 战斗外效用 + 队内闲聊表"；
   官员"全聚落目标调度 + 领域效用"；叙事导演是一张带优先级、前置、冷却的规则表。人格都落在权重与阈值上，所以无模型时性格依然存在。
10. **质量有硬指标。** 每类有名 NPC 的最低台词量、单人重复率上限、一局里"活着"的十二项可观测指标、与模型档的体验差距（同种子成对运行加盲读评审）都有阈值（第 14 节）。
11. **性能有预算。** 内置 AI 在目标硬件上每 tick 平均不超过 2 毫秒、峰值不超过 6 毫秒；评估全部错峰（第 16 节）。
12. **验收用自动玩家多种子跑。** 每个里程碑：20 个种子乘"配置关闭、断网、角色混合"三种条件，全主线与全部纷争决策点覆盖，确定性哈希一致，"活着"指标与台词指标达标（第 17 节）。这是 D-010 的硬性验收。

## 1. 定位与总体结构

### 1.1 三个身份

| 身份 | 何时生效 | 要求 |
| --- | --- | --- |
| 无模型档的全部决策者 | 路由预设"关闭"（D-067），或玩家没有配置任何提供方 | 全部主线、支线、纷争、女神线、结局与后日谈可达；世界"活着"的指标达标（第 14.2 节） |
| 有模型档的兜底 | 某角色未绑定模型、模型超时、输出非法或过时、预算用尽、提供方熔断 | 兜底在请求发出时已算好；接替时没有可感知的卡顿；与模型的选择处在同一个合法菜单里 |
| 基线 | 自动玩家、批量平衡模拟、回放、评估集的对照组 | 同种子同结果；可在 Node 中无渲染批量运行（[architecture.md](../../50_tech/architecture.md) 第 11 节） |

### 1.2 一条管线，两种提议者

```
内核系统（tick 内，确定性）
  1 发现需要决策（日程到点、通知、纷争节点、黎明、季度、战况变化）
  2 组装本人投影与此刻合法的菜单（含代价、可行性、不可用原因）
  3 内置 AI 在菜单内算出提议：命令序列 + 台词键 + 理由（命名随机子流）
  4 写决策请求 DecisionRequest，fallback 字段即第 3 步的提议
        |
        v
  AI 桥：这个行动者此刻绑定了可用的模型吗？
        否 -> 发出后的下一 tick 即时放弃 -> 执行内置提议
        是 -> 模型在同一菜单里提议 -> 内核闸门 -> 采纳
              超时、非法、过时、预算不足 -> 执行内置提议
        |
        v
  5 命令处理器校验并执行（与玩家命令同一入口，同一套闸门）
  6 回执与事件 -> 记忆、日记、关系、信念画像、传闻、神之档案、张力计
```

- 第 3 步就是本文的全部内容。它在内核里运行，只读本人投影（与模型看到的投影是同一份数据），所以内置 AI 与模型在"知道什么"上完全对等。
- 先行类请求（日程、首领例行运营、同伴战斗外行为）在发出的同一 tick 就开始执行内置提议，模型提议到达且未过时，只替换尚未执行的部分（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 3.3 节）。
- 到点类请求（女神规划与唤醒、纷争决策点、写定神行节点、审庭、首领议政）在截止前不做该决策，截止时执行内置提议。

### 1.3 共用与替换

| 环节 | 两档共用 | 只在有模型时替换 |
| --- | --- | --- |
| 投影与菜单 | 是：本人投影、可用动作与意图、代价、不可用原因 | 否 |
| 选择 | 内置 AI 的效用、行为树、HTN 结果作为兜底 | 模型在同一菜单里另选 |
| 措辞 | 台词包与模板 | 模型自由措辞（仍经知识、台账、禁名闸门） |
| 自由输入的意义 | 意图分类器决定世界后果（关系、认知证据、尊名、台账防护） | 模型只换回答的措辞与语气 |
| 执行与裁决 | 命令处理器、内核闸门、回执 | 否 |
| 认知、传闻、关系、声望 | 全部规则（[reputation_and_cognition.md](reputation_and_cognition.md)） | 否 |
| 记忆 | 确定性经历、认识、日记模板 | 整理轮的主题笔记与日摘要（无模型时不生成，只保留确定性记忆） |
| 女神的神力账、澱账、约定、越约、敌对预算 | 规则执行者 `DivineArbiter` | 否 |
| 叙事导演的张力计与菜单 | 规则 | 包装（人物、地点、一句台词）可由模型选 |

| 切换层级 | 规则 |
| --- | --- |
| 整个角色 | 玩家在设置里把某角色设为"内置 AI"，或该角色的路由在降级阶梯中被降到规则（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 9.4 节） |

### 1.5 确定性

- 内置 AI 的每一次随机都走命名随机子流（`ctx.rng(name)`），名字按"系统.大脑.行动者"组成，例如 `npc.brain.cassian`、`goddess.brain.eluen`、`dialogue.lines.martha`、`warfare.brain.east`。
  子流互不干扰：一个 NPC 多想一次，不会改变另一个 NPC 的抽签。
- 平分时按动作或意图编号的字典序取第一个；需要变化的场合（NPC 生活、台词）在得分最高者 10% 以内的候选里按权重抽取。
- 不读 `Date.now`、`performance.now`、`Math.random`；曲线用分段线性查表，不在内核里用 `Math.exp` 与非整数次幂，避免跨平台浮点差异破坏回放（第 2.1 节）。
- 评估节拍按 tick 计数与行动者编号的哈希错峰（`(tick + hash(id)) % 周期 == 0`），与帧率和倍速无关。
- 时间换算（`src/core/time.ts`）：每 tick 3 游戏秒，20 tick 为 1 游戏分钟，1200 tick 为 1 游戏小时，28800 tick 为 1 游戏日；1 倍速下 1 现实秒为 1 游戏分钟。

### 1.7 模块与数据布局

内置 AI 的原语是纯函数，不依赖任何业务系统；各系统的大脑放在各自目录，遵守"系统之间不互相导入"的约定（[implementation_conventions.md](../../50_tech/implementation_conventions.md)）。

| 路径 | 内容 | 导出符号（建议） |
| --- | --- | --- |
| `src/core/brain/curves.ts` | 响应曲线（分段线性查表） | `Curve`、`evalCurve` |

## 2. 共用原语

### 2.1 效用评分

**响应曲线。** 每个考量项把一个输入（0 到 1 的归一值，或带单位的原始值）映射到 0 到 1。曲线一律存为至多 8 个节点的分段线性表，设计时可以用下列形状生成：

| 形状 | 参数 | 用途 |
| --- | --- | --- |
| `lin(a,b)` | 输入从 a 到 b 线性升到 1，两端钳制 | 越多越好 |
| `inv(a,b)` | `1 - lin(a,b)` | 越少越好（例：越饿越想吃） |
| `quad(a,b,k)` | `lin(a,b)` 的 k 次方（k 取 2 或 3，生成时离线算好节点） | 阈值附近急剧上升 |
| `step(t)` | 输入不低于 t 为 1，否则 0 | 硬门槛 |
| `bell(m,w)` | 在 m 处为 1，向两侧 w 处降到 0 | 适中最好（例：距离刚好在射程内） |
| `logi(m,s)` | 以 m 为中点、s 为宽度的 S 形（离线生成节点） | 软门槛 |

**得分式。**

```
U(a) = W_a × G(a) × M(a) + B(a) - C(a)

G(a) = 门槛考量的乘积。每项 c 先做补偿：c' = c + (1 - c) × c × (1 - 1/n)，n 为该动作的考量项数（项多时不至于被乘到 0）
M(a) = 人格乘数，0.5 到 1.5（人设卡、加护冲动、人格权重表）
B(a) = 加法项：惯性（正在执行的动作 +0.1 × W_a）、谋划（HTN 下一步 +3）、反应（与近 24 游戏小时内通知相关 +2）、剧情点名（+5）
C(a) = 代价：资源 / 余额、风险 × 谨慎、重复（同类动作近期次数 × 重复系数）、可见度 × 隐匿偏好
```

- 每个动作的每一项都带名字与数值，选完写入 `BrainTrace`（第 2.6 节）。调试面板与"神之记录"类视图直接显示"为什么选它"。
- 选择：取最高分。生活类决策（NPC 动作、台词、话题）在最高分 10% 以内的候选里按分数加权抽取，用该行动者的命名子流；女神、统治者、将领、官员只在最高分 2% 以内抽取，等价于"几乎总是最优"。
- 不作为：每类决策都有一个"维持现状"选项，其得分是该类的不作为基线（例：女神 4，统治者 2，NPC 0.5）。最高分低于基线时不行动。
- 短路：门槛考量为 0 的动作跳过加法项的计算（节省时间）；动作的前置不满足时根本不进菜单。

**数据形状**（`data/ai/utility/*.json`）：

```ts
interface UtilityActionDef {
  id: string;                 // 动作或意图编号，与内核命令一一对应
  weight: number;             // W_a
  gates: Consideration[];     // 进入 G(a) 的考量
  bonuses?: NamedTerm[];      // 进入 B(a) 的加法项
  costs?: NamedTerm[];        // 进入 C(a) 的代价
  persona?: string[];         // M(a) 读取的人格维度，例：['greed', 'caution']
  cooldownTicks?: number;
  tags?: string[];            // 例：hostile、public、religious，供人格与可见度修正使用
}
interface Consideration { name: string; input: string; curve: CurvePoints }   // input 是注册过的输入函数编号
interface NamedTerm { name: string; input: string; scale: number }
```

### 2.2 行为树

| 节点 | 语义 |
| --- | --- |
| 序列 `seq` | 依次执行子节点，任一失败即失败，全部成功才成功 |
| 选择 `sel` | 依次尝试子节点，第一个成功即成功 |
| 效用选择 `usel` | 对子节点按第 2.1 节打分，执行最高者；失败则试次高者 |
| 并行 `par` | 同时运行，按"全部成功"或"任一成功"结算 |
| 条件 `cond` | 读黑板或注册谓词；谓词可写成揭示台账语法的表达式（`a1_witch_trial >= 2 AND NOT a1_oola_fate == 'executed'`） |
| 动作 `act` | 提交一个内核命令（与玩家命令同构）；返回"运行中"直到收到回执，回执成功即成功，失败即失败 |
| 说 `say` | 选一句台词（第 7、8 节）并提交 `npc.say` 或对话命令 |
| 等待 `wait` | 等若干游戏分钟或某事件 |
| 装饰器 | `cooldown(t)`、`once`（每游戏日一次）、`timeout(t)`、`chance(p)`（命名子流）、`guard(谓词)`、`invert`、`throttle(n, 窗口)` |

- 运行：行为树不每 tick 全量求值。行动者的树在三种时刻推进：所跟的动作收到回执、黑板上被订阅的键变化（通知、需求跌破阈值）、到达自己的评估节拍（第 16 节）。
- 黑板：每个行动者一份，键是封闭集合（`target`、`place`、`item`、`topic`、`threat`、`order`、`quest` 等），值是稳定编号。黑板不进存档，读档后由状态重建；运行中的动作由内核的动作组记录，读档后照常收回执。
- 数据：树以 JSON 存在 `data/ai/bt/`，节点编号稳定；内容校验检查每个 `act` 都映射到存在的命令、每个 `cond` 都可解析、每个 `say` 槽位都有台词（第 15 节）。

### 2.3 HTN 分解

- 形式：全序前向分解（先分解，后执行），方法按代价升序尝试，代价体现人格风格（例：艾琉恩的"调查"方法里"经神职暗查"代价 1、"借勇者团"代价 3；瓦尔妲反过来）。
- 世界状态：只用本人投影与本人的档案，不用世界真值；算子的"预期效果"只用于规划，真实效果以回执为准。
- 预算：深度至多 4，原子任务至多 12，单次规划至多展开 200 个节点（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 6.5 节）。
- 执行：计划存进行动者的切片（计划编号、步序号、变量绑定、开始 tick、期限）；每到该行动者的决策节拍，执行下一步；每步都是一次普通的菜单选择，照常过内核闸门。
- 重规划：当前步失败、前置被破坏、计划超过期限、出现更高效用的目标（高出 30% 以上）。不每 tick 重规划。
- 中止：每个谋划声明中止条件（例："目标已离开本地区 7 日"、"台账节点已越过"），满足即中止并写入记忆"放弃了某事"。
- 预兆自动前置：任何带 `hostileToPlayer` 或 P3 权限的原子任务，分解器在它之前自动插入内容表登记的预兆任务（盘查、告示、审判官出现），并保证两者间隔落在登记的时间窗内（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 5.8 节）。

```ts
interface HtnMethodDef {
  task: string;               // 复合任务
  pre: string;                // 台账语法的前置
  subtasks: string[];         // 有序子任务（复合或原子）
  cost: number;               // 人格风格
}
interface HtnOperatorDef {
  task: string;               // 原子任务
  command: string;            // 内核命令种类
  params: Record<string, string>;   // 从绑定变量取值
  pre?: string;
  expect?: Record<string, string>;  // 预期效果（只用于规划）
  etaHours: number;
}
interface HtnPlanState {
  planId: string; root: string; steps: string[]; index: number;
  bindings: Record<string, string>; startTick: number; deadlineTick: number;
}
```

### 2.4 分层状态机

NPC 的作息由五层叠成，上层压过下层；每层只回答"此刻在做什么、在哪里"：

| 层（高到低） | 来源 | 何时占用 | 何时让出 |
| --- | --- | --- | --- |
| 5 剧本覆盖 | 写定节拍、纷争事件链、过场（`override`） | 剧本指定的时间窗 | 时间窗结束 |
| 4 对话冻结 | 玩家发起交谈（`freezeUntil`） | 交谈开始，至多 10 游戏分钟（200 tick），交谈每进行一轮顺延 | 交谈结束或超时 |
| 3 紧急 | 安全感跌破 20、受到攻击、火灾、魔物入镇、被逮捕 | 立即 | 威胁解除后 30 游戏分钟 |
| 2 需求 | 任一需求跌破 35（重新考虑线），回升到 45 才释放 | 下一个可打断的时段 | 需求回升 |
| 1 日程 | 当日计划（模板加日计划替换） | 默认 | 不让出 |

- "可打断"由日程段声明：劳作与睡眠只被紧急层和低于 18 的需求打断（现有 `needOverride` 的规则），闲逛、闲聊、买东西随时可被需求层打断。
- 层 2 与层 3 的"做什么"不是写死的，而由效用评分在该层的动作库里选（第 4.1 节），所以同样是饿，有钱的人去酒馆、没钱的人啃黑面包、骄傲的人饿着也不去求人。
- 状态切换发出 `npc.activity` 事件（只对玩家所在地图），离屏时只改状态不发事件。

### 2.5 规则表

```ts
interface RuleRow {
  id: string;
  when: string;               // 台账语法的条件，可引用事件字段（例：event.kind == 'feat_seen'）
  priority: number;           // 高者先
  then: { action: string; params?: Record<string, string> }[];
  cooldownTicks?: number;
  once?: 'act' | 'game' | 'day';
  weight?: number;            // 同优先级多行同时满足时按权重抽取
}
```

- 两种求值：`firstMatch`（取优先级最高的一行，例：女神对一次通知的反应）与 `allMatches`（全部执行，例：一次事迹引起的关系变化）。
- 规则表的每一行都能被单独测试；编辑器能列出"这一行从未被触发过"（第 15 节的覆盖报告）。

### 2.6 决策解释

每次内置决策写一条 `BrainTrace`：行动者、决策类别、tick、前三名候选及其命名得分项、选中项、用到的子流名与抽签值。

- 写入内存环形缓冲（每个行动者 32 条），不进存档：给定存档与 tick，可以重算出完全相同的解释。
- 调试面板、编辑器推演、录像重演都读它（第 15 节）；有模型时它照常生成，作为"模型为什么没有选兜底那一项"的对照。

### 3.1 分档与内置 AI 的分工

### 3.2 日程状态机

**当日计划（黎明生成）**

1. 取人设卡的日程模板（`data/npc/schedules.json`）。
2. 按日子类型套用变体，优先级从高到低：战时、魔物季、节庆、礼拜日、集日、雨雪天、平日。日子类型由世界旗标、日历与天气决定（礼拜日每七日一次（[society.md](../../20_world/society.md) 的乡村时间表）；集日按城镇数据声明的周期（例：边石镇盐巷集市每周一次）；节庆按日历表）。
3. 在模板的替换表里，用效用评分做至多 3 次替换（第 4.1 节的需求与目标项给分）；替换表之外的改动不被允许，与模型日计划的校验共用 `validatePlan`。
4. 插入目标追求段（下文）与本人已接受的约定（邀约、承诺、委托）。
5. 结果写成 `PlanState`，`source` 为 `rule`。有模型时这就是 `npc.daily` 请求的兜底；模型的计划同样过 `validatePlan`。

**目标追求**：人设卡的长期目标（1 到 3 个，完成条件是世界可验证的谓词）各带一张"追求表"：

| 字段 | 说明 | 例（卡西安 G2：取得灰病的证据） |
| --- | --- | --- |
| 追求段 | 插进日程的一段活动与地点 | 上午去孤儿院问话；傍晚去欧拉的药草屋外"路过" |
| 节拍 | 至多每几日一次 | 每 3 日 |
| 效用项 | 何时更想做 | 孤儿院近 7 日有孩子发病 +；与欧拉的立场一致度越低越想去"查她" |
| 完成谓词 | 台账语法，变量必须已在注册表登记 | 第一幕灰病证据的旗标（名字以 [world_state_registry.md](../world_state_registry.md) 为准）为真 |
| 放弃条件 | 台账语法 | `a1_oola_fate == 'cleared'`（他转而痛苦地接受） |

**日内运行**：每个日程段边界与每次评估节拍，按第 2.4 节的五层求出"此刻在做什么、在哪里"，经寻路移动，到达后开始活动；活动按小时结算需求与收支（`stepNeeds`）。被打断的段在剩余时间足够时恢复，否则跳过。

**离屏批量**：L3 与离屏的 L2 不寻路，按段直接"在场"，只在跨地图移动时按区域图行程扣时；需求与收支照常结算，轨迹写进 `track` 供日记使用。

### 3.3 需求与心情

需求从现有的四项（`Needs`：饱腹、精力、社交、信仰）扩到九项，补齐 [npc_society_ai.md](npc_society_ai.md) 第 7.2 节的全集。全部 0 到 100，越低越迫切；重新考虑线 35，回升到 45 才释放；临界线 18（现有 `NEED_RECONSIDER`、`NEED_CRITICAL`）。

| 需求 | 每游戏小时变化 | 回升来源 | 跌破 35 时的效用动作（第 4.1 节） | 人设权重 |
| --- | --- | --- | --- | --- |
| 饱腹 | -5（睡眠时 ×0.4） | 吃饭 +40 | 去酒馆吃、回家吃、啃干粮；临界且廉洁低时偷吃 | 体格大者 1.3 |
| 精力 | -4（劳作 ×1.4） | 睡眠每小时 +12；小憩 +20 | 回家睡、小憩、提早收工 | 老人 1.2 |
| 社交 | -3（独处时） | 闲聊 +15；买东西、闲逛、吃饭 +3 | 找熟人、去酒馆、凑热闹 | 外向 1.4，内向 0.6 |
| 信仰 | -1.5 × 虔诚度 | 祈祷 +30；礼拜 +40 | 去礼拜堂、在家祈祷、找神父 | 虔诚度 |
| 财务 | 按存款与七日开销之比计算（`moneyNeed`） | 收入 | 加班、借贷、卖东西；廉洁低时铤而走险 | 贪婪 1.3 |
| 安全感 | 事件驱动：附近有敌意魔物 -30；受到威压按阶差 -10 到 -40；治安低于 40 的地区基线降 20 | 威胁解除后每小时 +10 回到基线 | 躲避、回家锁门、求助、报官、逃离 | 胆小 1.4，勇敢 0.6 |
| 面子 | 事件驱动：当众羞辱 -30，公开被驳 -15，被当众感谢 +15，赢下争论 +10；每小时向 70 回归 2 | 被认可、找回场子 | 硬撑、找回场子、避人；记仇且勇敢者报复 | 骄傲 1.5 |
| 职责 | 100 减"欠着的事"的紧迫度之和（职位事务、承诺、约定、委托到期） | 履职、守约 | 放下私事去履职 | 尽责 1.4 |
| 心安 | 违背加护冲动或良心 -10 到 -30；秘密受威胁 -15；每小时向 70 回归 1 | 告解 +20、补偿 +15、祈祷 +10 | 告解、补偿、失眠、躲人 | 良知强者 1.3 |

**心情**不存数值（[npc_society_ai.md](npc_society_ai.md) 第 7.2 节），每次需要时由需求档位与近事推出，按优先级取第一个：

| 心情 | 条件 | 用于 |
| --- | --- | --- |
| 惧 | 安全感低于 30，或近 1 游戏小时受到威压 | 台词选择、吠叫语境、逃离倾向 |
| 怒 | 面子低于 25，或近 24 游戏小时被玩家或他人冒犯、伤害 | 台词选择、争吵倾向、拒绝服务 |
| 愁 | 财务或心安低于 30，或近 7 游戏日有亲友死亡 | 台词选择、求助倾向 |
| 乏 | 精力或饱腹低于 25 | 台词选择、提早收工 |
| 喜 | 近 24 游戏小时收礼、受助或逢节庆，且其余需求都不低于 50 | 台词选择、送礼与闲聊倾向 |
| 平 | 其余 | 默认 |

### 3.4 主动性

无模型时 NPC 依然会主动找玩家，这是"活着"最直观的证据。主动搭话是一个效用动作（`approach_player`），只对 L1 与 L2 开放：

| 理由 | 门槛 | 开场槽位 |
| --- | --- | --- |
| 有委托想托付 | 本人有映射到请托模板的未满足需求；对玩家信任 ≥ 40 | `quest.<q_id>.offer` 或 `topic.gen_trouble` |
| 对玩家的传闻要当面确认 | 持有热度 ≥ 0.4 的关于玩家的传闻，认知状态为怀疑或解释化 | `unbelief.deny` 或 `unbelief.explain` |
| 道谢或还人情 | 近 7 日被玩家帮助或救命，且尚未道谢 | `react.helped`、`react.saved` |
| 崇拜者打招呼 | 认知分叉为崇拜 | `react.belief_worship` |
| 敌视者警告 | 认知分叉为敌视，且勇敢或有权势 | `react.belief_hostile` |
| 熟人闲谈 | 好感 ≥ 40，社交需求低于 50 | `greet.warm` 后接话题 |

限额：每名 NPC 每游戏日至多主动搭话 1 次；同一屏幕每游戏小时至多 3 次；玩家在战斗、交易、过场中时不搭话；玩家连续两次直接走开，该 NPC 本游戏周停止主动搭话。

## 4. NPC：效用动作库与功能角色行为树

### 4.1 通用动作库

全体有名 NPC 共用的动作（与 [npc_society_ai.md](npc_society_ai.md) 第 4 节的行动空间一一对应，每个动作都是内核命令）。表中"门槛"进入 G(a)，"加分与代价"进入 B(a) 与 C(a)，"人格"进入 M(a)。

| --- | --- | --- | --- |

性格标签到人格乘数的映射是一张表（`data/ai/personas/traits.json`）：人设卡的 `traits` 关键词（例："固执""胆小""贪财""好奇""虔诚"）各对应若干维度与乘数，一个维度取各标签的最大值，不连乘。

### 4.3 NPC 大脑的根与功能角色行为树

**根**（每个有名 NPC 一棵，角色子树按人设卡声明的角色顺序挂入）：

```
root  sel
  [剧本]  guard(有剧本覆盖) -> act(执行覆盖段)
  [对话]  guard(与玩家交谈中) -> 交给对话引擎（第 6 节）
  [紧急]  guard(安全感 < 20 或 遭攻击 或 火灾 或 被逮捕) -> usel(逃离, 躲藏, 求助, 反击*)
          * 反击只对 general、rival 与勇敢性格开放
  [纷争]  guard(纷争决策点点名本人) -> 决策点效用（第 5.8 节）
  [职责]  guard(在值守时段) -> usel(角色子树 1, 角色子树 2, 角色子树 3)
  [需求]  guard(任一需求 < 35) -> usel(第 4.1 节的需求动作)
  [目标]  guard(今日有追求段且到点) -> act(追求段)
  [主动]  guard(L1 或 L2) cooldown(1 日) -> 主动搭话（第 3.4 节）
  [社交]  chance(1 - 社交 /100) -> 社交子树（第 5.1 节）
  [日程]  act(按日程段移动并执行活动) -> chance(0.15) say(bark.<活动>)
```

**十五个功能角色子树**（`seq` 依次、`sel` 择一、`usel` 按效用择一；槽位语法见第 7.2 节）：

```
giver
  sel
    seq 结算   cond(玩家带着完成证据来) -> act(结算报酬) -> say(quest.<q>.complete)
    seq 追问   cond(委托已接且过半期限) cond(玩家在附近) throttle(1, 1 日) -> say(quest.<q>.progress)
    seq 发布   cooldown(3 日) cond(有未满足需求可映射请托模板) -> act(发布委托)
    seq 撤回   cond(委托过期或需求已满足) -> act(撤回委托)

vendor
  sel
    seq 开张   cond(值守时段) cond(不在铺位) -> act(移动到铺位) -> act(开张)
    seq 待客   cond(有人打开交易) -> 交易界面（价格来自市场模型与修正项）
    seq 补货   cond(货品低于目标 30%) cond(钱够) cooldown(1 日) -> act(进货)
    seq 调价   cooldown(12 时) -> usel(提价, 降价, 维持)
    seq 吆喝   cond(视野内有人) chance(0.2) throttle(1, 30 分钟) -> say(bark.vendor_call)
    seq 收摊   cond(值守结束) -> act(收摊)

crafter
  sel
    seq 交货   cond(有完工的单且主顾在场) -> act(交付) -> say(topic.gen_craft)
    seq 干活   cond(队列非空) cond(材料齐) -> act(打造或修理，按工期排序)
    seq 采购   cond(材料不足两单) cooldown(1 日) -> act(采购)
    seq 闲时   chance(0.1) -> say(bark.work)

trainer
  sel
    seq 授课   cond(学员已付学费且在场) -> act(授课) -> say(topic.gen_train)
    seq 带徒   cond(有 NPC 徒弟) -> act(带徒，徒弟的潜质成长)
    seq 自练   -> act(自练) -> chance(0.1) say(bark.work)

healer
  sel
    seq 急诊   cond(附近有濒死者) -> act(移动) -> act(诊治)
    seq 坐诊   cond(值守时段) cond(有病人排队) -> act(诊治，按严重度)
    seq 出诊   cond(有求医者不能来) cond(安全感 >= 40) -> act(出诊)
    seq 配药   cond(药材低于三日用量) cooldown(1 日) -> act(采药或进药)
    seq 上报   cond(三日内同症两人以上) once(周) -> act(上报疫情)

info
  sel
    seq 交易   cond(有人买情报) -> 情报交易（意图 ask_rumor、trade_buy）
    seq 核实   cond(持有可信度 0.3 到 0.7 的高价值传闻) cooldown(1 日) -> act(去现场或问目击者)
    seq 收集   cond(在酒馆或市场) -> act(旁听，增加传闻副本)

rumor
  sel
    seq 表演   cond(吟游诗人) cond(晚间在酒馆或广场) once(日) -> act(表演，歌谣类书面来源)
    seq 传话   cond(有听众) -> 传话效用（第 5.2 节）
    seq 打听   cond(手里没有热度 >= 0.3 的新传闻) -> act(去人多处)

recruit
  sel
    seq 应邀   cond(玩家发出邀请) -> usel(答应, 提条件, 婉拒, 拒绝)（第 4.4 节）
    seq 差事   cond(在队且营地休整) -> act(个人差事)（第 11.2 节）

officer
  sel
    seq 议政   cond(在任) -> 官员大脑（第 12 节）
    seq 自荐   cond(玩家有空缺) cond(野心 >= 50) once(幕) -> say(react.self_recommend)
    seq 献策   cond(本人领域有问题) cond(玩家在场) throttle(1, 3 日) -> say(topic.gen_advice)

general
  sel
    seq 指挥   cond(在战场) -> 将领大脑（第 10 节）
    seq 操练   cond(值守时段) -> act(操练兵团，士气与熟练度)
    seq 请战   cond(有威胁且主公在场) throttle(1, 3 日) -> say(react.request_battle)

witness
  sel
    seq 出庭   cond(被传唤) -> act(随传唤者前往)（传唤期间升 L1）
    seq 回避   cond(追查者在附近) cond(怕报复) -> act(躲藏)
    seq 守证   cond(持有证据对象) -> act(藏好证物)

keyholder
  sel
    seq 交付   cond(钥的条件全部满足) -> act(交付钥) -> say(quest.<q>.complete)
    seq 考验   cond(玩家问钥) cond(条件含考验) -> act(发起考验)
    seq 开价   cond(玩家问钥) -> say(topic.<钥话题>)（按条件表说出条件）
    seq 藏匿   cond(敌对势力在附近打听) -> act(移走钥物)

rival
  sel
    seq 认输   cond(公平落败) once(幕) -> say(react.rival_concede) -> act(关系变化)
    seq 约战   cond(对抗热度 >= 0.6) cond(场合合法) cooldown(7 日) -> act(决斗挑战)
    seq 挑衅   cond(玩家在附近) throttle(1, 1 日) -> say(react.rival_taunt)
    seq 竞争   cond(与玩家争同一目标) -> act(抢先去做)

patron
  sel
    seq 讨还   cond(对方欠人情) cond(本人有需求) -> say(react.call_favor) -> act(生成请托)
    seq 撤资   cond(资助对象声望跌两档) -> act(撤资)
    seq 资助   cond(有值得押注的对象) cooldown(7 日) -> usel(资助, 担保, 借贷)

cleric
  sel
    seq 礼拜   cond(礼拜时段) -> act(主持礼拜) -> say(bark.sermon)
    seq 神谕   cond(收到神谕) -> act(转达或执行神谕，按传达链)
    seq 告解   cond(有人求告解) -> act(听告解)
    seq 晚祷   cond(傍晚) -> act(祈祷，近 24 小时见闻进入女神投影)
    seq 指控   guard(证据达阈值 AND 上级许可 AND 预兆已有) -> act(指控异端)（P3）
    seq 济贫   cond(有余粮) once(周) -> act(济贫)
```

多角色合并：一个 NPC 有多个角色时，职责层的 `usel` 对各子树的"当前可执行分支"打分，分数取该分支的动作效用；同分时按人设卡声明的角色顺序。只有 `rumor` 一个角色的 NPC，职责层就是传话子树（内容总纲规定这类人每幕不超过五人）。

### 4.4 入队效用

可招募者（`recruit`）对玩家邀请的回应：

```
入队效用 = 0.30 × 对玩家信任 /100
         + 0.20 × (好感 + 100) /200
         + 0.20 × 目标契合（玩家路线能推进本人长期目标为 1）
         + 0.15 × 羁绊进度（共同经历计数归一）
         + 0.10 × 玩家在本人所在地区的声望档 /4
         + 0.05 × 敬畏 /100
         - 0.25 × 恐惧（对玩家认知分叉为敌视或惧怕时为 1）
         - 0.20 × 牵挂（家人、职责、未完的事，0 到 1）
```

| 效用 | 回应 | 台词槽 |
| --- | --- | --- |
| 不低于 0.6 | 答应 | `react.recruit_yes` |
| 0.4 到 0.6 | 提条件（报酬、承诺、先完成某事），条件写成一份以玩家为义务方的约定 | `react.recruit_terms` |
| 0.25 到 0.4 | 婉拒，说明怎样才行 | `react.recruit_later` |
| 低于 0.25 | 拒绝 | `react.recruit_no` |

写定同伴（夜羽、希雅、罗恩等）的入队条件以 [characters.md](../../30_story/characters.md) 第 8 节与分幕文档为准，上式只用于可招募池与写定条件之外的邀请。

## 5. NPC：社交、传闻、记忆、关系与对玩家的反应

### 5.1 NPC 之间的社交互动

同一地点的有名 NPC 每游戏小时做一次相遇检定（现有 `runChats` 的扩展）；离屏的 L3 按地点批量结算，只记事件不出台词。

**相遇与搭档选择**：每名 NPC 在同处的人里按下式选一个搭档，最高分低于 0.3 则不互动。

```
搭档得分 = 0.35 × (1 - 社交 /100)
         + 0.25 × (对对方好感 + 100) /200
         + 0.20 × 话题热度（手里有对方可能感兴趣的、热度最高的传闻）
         + 0.10 × 日程重合（同一活动）
         + 0.10 × 立场冲突度（只用于争吵类互动）
```

**互动种类**（封闭集合）：

| 互动 | 门槛 | 后果 | 台词 |
| --- | --- | --- | --- |
| 闲聊 | 双方好感 ≥ -20 | 双方社交 +15；好感 +1 | `bark.chat` 两人各一句，或通用层 `banter.*` |
| 传话 | 第 5.2 节 | 传闻副本按失真规则生成 | 通用层 `rumor.tell.<spin>` |
| 请教、求助 | 一方有需求且另一方有对应能力 | 可能生成两人之间的小约定 | `react.ask_help` |
| 邀约 | 好感 ≥ 30；有共同空闲段 | 生成约定，到点双方插日程段；"谁没去"记入记忆 | `react.invite` |
| 送礼 | 第 4.1 节"送礼" | 物品转移；好感 +2 到 +10 | `react.gift_liked` 等 |
| 争吵 | 立场一致度 ≤ -40 或一方面子低于 30 且对方是冒犯者 | 双方好感 -5 到 -15；面子变化；围观者经历 | `react.insult` 往复两句 |
| 和解 | 争吵后 3 日内，一方心安低于 40 | 好感回升一半 | `react.apology_accept` |
| 告密 | 知道某秘密或违法行为；与告密对象信任 ≥ 50；与被告者好感 < 0 | 告密对象得到线索；被告者安全与关系变化 | 不出声（只在调试与传闻里可见） |
| 交易 | 一方是 `vendor` 或有余货 | 物品与钱转移 | `bark.shop` |

- 每次互动 2 到 4 句往复，句数由双方社交需求与好感决定；只有玩家所在地图的互动显示台词。
- 互动结果写进双方记忆（第 5.3 节模板）与关系记录（第 5.5 节），这些记录是第六幕"众生之声"的原料（[npc_society_ai.md](npc_society_ai.md) 第 5.6 节）。

### 5.2 传闻传播的决策

传播概率、失真操作与信否门槛全部按 [reputation_and_cognition.md](reputation_and_cognition.md) 第 4 节计算；内置 AI 只决定"讲不讲、讲哪条、讲给谁、怎么讲"。

| 决策 | 规则 |
| --- | --- |
| 讲不讲 | 传出概率 = 热度 × 场所系数 × 本人传播倾向 × 听者兴趣 × 关系系数（同上第 4.2 节）；守秘者（传播倾向 0.2）只在对方信任 ≥ 70 时讲 |
| 讲哪条 | 本人持有且相信的传闻里，取"热度 × 对听者的兴趣 × (1 + 涉及听者认识的人 0.5)"最高的一条；与对方已持有的版本相同则跳过 |
| 讲给谁 | 第 5.1 节的搭档；放大器人物（例：丽泽、芬恩）每游戏日额外对场所内全部听众讲一次 |
| 怎么讲 | 人设卡的 `spin`（`plain`、`x5`、`fear`、`ghost`、`flatten`、`self_credit`、`deflect`、`detail`、`price`、`light` 等）决定失真操作与台词模板 `rumor.tell.<spin>`；台词槽填入版本的结构化字段（主体、数量、地点、时间、解释） |
| 澄清 | 本人是亲见者或权威，持有与传闻相反的亲见证据，且对传闻主体好感 ≥ 20：在场时以 0.5 的概率澄清，生成反向版本 |
| 越描越黑 | 按同上第 4.4 节：澄清者言辞可信度低于 0.4 时，约三成概率变成新传闻 |
| 不剧透 | 传话只能传结构化版本；版本中的命题落在传闻命题词表与模板表之内；未解锁的真相即使作为猜测也不进入（同上第 4.5 节） |

L4 人群单元的份额传播照常由规则批量结算；人群的"声音"来自吠叫池（第 5.7 节末与第 7.6 节）。

### 5.3 记忆与心声的模板生成

记忆条目由内核在事件发生时确定性写入（`addMemory`），文字来自通用层模板 `mem.<kind>`，按观察者的社会阶层取语体变体，填入人名、地点、物品、数量。

| 事件种类 | 来源与可信度 | 重要度（0 到 1） | 模板槽例 |
| --- | --- | --- | --- |
| 亲见事迹 | 亲见 1.0 | 0.3 + 显著度 × 0.6 | `mem.feat_seen`："{place}，我亲眼看见{who}{feat}。" |
| 听到传闻 | 转述，按第 5.2 节 | 0.1 + 热度 × 0.3 | `mem.rumor_heard`："听{teller}说，{rumor}。" |
| 与玩家交谈 | 本人 1.0 | 首次 0.4，之后 0.15 | `mem.talk_player` |
| 收礼、受助、被救 | 亲历 1.0 | 0.3、0.4、0.8 | `mem.gift`、`mem.helped`、`mem.saved` |
| 被冒犯、被伤害、被坑 | 亲历 1.0 | 0.4、0.6、0.5 | `mem.insulted`、`mem.harmed`、`mem.cheated` |
| 交易 | 本人 1.0 | 0.05（大额 0.2） | `mem.trade` |
| 争吵、和解 | 本人 1.0 | 0.3、0.2 | `mem.quarrel`、`mem.reconcile` |
| 约定、守约、违约 | 本人 1.0 | 0.2、0.2、0.4 | `mem.promise`、`mem.kept`、`mem.broken` |
| 目睹神迹、受神谕 | 亲见 1.0 | 0.7、0.9 | `mem.miracle`、`mem.oracle` |
| 亲友死亡 | 亲历 1.0 | 0.9 | `mem.mourning` |
| 认知跃迁 | 推断 | 0.5 | `mem.belief_changed`："{who}……我想我看错了。" |

- 重要度另乘：与本人目标相关 ×1.3；与玩家相关 ×1.2；罕见（本周第一次）×1.2；上限 1。
- 每日整理沿用 `consolidateMemory`：保留重要度最高与最近的条目，其余折成一行摘要；幕间折叠每人至多 24 条（[npc_society_ai.md](npc_society_ai.md) 第 1.3 节）。
- 回忆进对话：话题与意图回应可以引用记忆（"上次你帮我修的那把锄头"），由槽位 `{memory}` 填入本人与玩家有关的最近一条重要度 ≥ 0.3 的记忆的短句版本（`mem.<kind>.short`）。

**心声气泡**：无模型时头顶气泡就是吠叫（`bark.<context>`），语境按"心情优先、活动其次"选择：惧、怒、愁、乏各有对应语境（`bark.fear`、`bark.angry`、`bark.worried`、`bark.tired`），心情为平或喜时取当前活动的语境。气泡规则（显示时长、同屏上限）沿用 [npc_society_ai.md](npc_society_ai.md) 第 12 节。

### 5.4 规则日记（L3 与模型批量日记的兜底）

现有 `ruleDiary` 取当日轨迹里"最值得讲"的三项套模板；本文给出打分与模板规则：

```
值得讲 = 种类权重 + 4 × 涉及玩家 + 2 × 涉及强关系者（任一维度绝对值 ≥ 50） + 1 × 本周第一次
种类权重：离开 6，受伤 5，争吵 5，求助 4，结识 3，交易 3，传话 3，工作异常 3，祈祷 2，工作 1，闲聊 1
```

- 取前三项，文字来自 `diary.<kind>`，按阶层语体取变体，填入地点与对方名字；当日末尾附一句心情短句（`diary.mood.<心情>`）。
- 只能写轨迹里真实存在的事件（与模型批量日记相同的校验：种类必须在当日 `tracks` 里）。
- 玩家来到 L3 所在地区后，此人升档，日记成为对话可引用的近事（"昨天跟铁匠吵了一架，别提了"），由槽位 `{diary}` 填入。

### 5.5 关系变化

触发与幅度沿用 [npc_society_ai.md](npc_society_ai.md) 第 6.2 节；内置 AI 补上来自对话意图、角色服务与社交互动的触发，全部由内核在事件或命令执行时写入，每条变化引用事件编号。

| 触发 | 信任 | 好感 | 敬畏 | 利益 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 玩家道谢、道歉被接受 | +0.5 | +1 | | | 意图 `thanks`、`apologize`（每人每日至多计一次） |
| 玩家夸赞 | | +1（虚荣者 +3，多疑者 -1） | | | 意图 `compliment`（每人每日至多一次） |
| 玩家冒犯 | -2 | -8 | | | 意图 `insult`；当众时面子 -30 |
| 玩家威胁 | -5 | -10 | +5 到 +20（按阶差） | | 意图 `threaten` |
| 玩家开玩笑 | | 幽默者 +2；严肃者 -2 | | | 意图 `joke` |
| 玩家闲聊 | +0.5 | +1.5 | | | 每人每日至多一次（现有 `chatDay`） |
| 送礼 | +1 到 +3 | 喜欢 +6 到 +10；一般 +2；讨厌 -3 | | +1 到 +5 | 喜好表（人设卡的 `likes`、`dislikes`，按物品标签匹配） |
| 讲价成功、失败 | | 成功 -1；失败 0 | | 成功 -2 | 意图 `haggle` |
| 委托完成、失败 | +5、-5 | +3、-3 | | +2、-2 | 任务结算 |
| 说出被对方证实的谎言 | -15 | -10 | | | 意图 `claim_feat`、`reveal_identity` 后的核实结果 |
| NPC 之间闲聊、争吵、和解、送礼 | 见第 5.1 节 | | | | 社交互动 |

- 人设修正：固执、记仇、宽容等标签乘幅度（同上第 6.2 节）；加护冲动对特定事件加权（瓦尔妲信徒被打败后敬畏与信任同升，艾琉恩信徒对"无记载者"的好感上限 20 直到认知接受）。
- 衰减：好感每游戏日向基线回归 1%，信任 0.3%，敬畏每游戏周下降 3%；任一维度绝对值 ≥ 70 时衰减减半（现有 `decayRelations`）。
- 防刷：同一意图对同一人的关系增益每游戏日只计一次；送礼的边际增益按当周已送次数递减（第二件 ×0.5，第三件起 ×0.25）。

### 5.6 对玩家事迹与身份暴露的反应

**流程**：事件发生，内核列出目击者与清晰度，认知系统算出每个目击者的越界、解释与状态转移（[reputation_and_cognition.md](reputation_and_cognition.md) 第 3.7 节）；内置 AI 在此之上按反应表决定"此刻做什么、说什么"。

**身份暴露的种类**（封闭集合，作为事件种类进入 `react.<eventKind>` 与反应表）：

| 种类 | 事件 | 典型目击者 |
| --- | --- | --- |
| `identity_pageless` | 鉴定读出"无记载"被旁人看见 | 公会职员、神职、商人 |
| `identity_door` | 玩家身体消散进门、退回门内或从门里出来被目击 | 任何人 |
| `identity_guest` | 玩家被确认来自箱庭之外（自曝被采信、地球物品被认出、审判官或勇者的指认） | 知识层级 K2 以上者、勇者团 |
| `identity_gatemark` | 玩家与门纹、遗民共鸣被看见 | 遗民、门徒会、神职 |
| `identity_pressure` | 玩家的威压被感知（同阶以上） | 有位阶者、野兽、兽人 |
| `identity_matched` | 传闻、通缉描述、神谕描述与眼前的玩家对上号 | 卫兵、审判官、持有热传闻的人 |

**反应表**（`firstMatch`，从上到下；"状态"指此人对玩家的私下认知状态与分叉）：

| 序 | 条件 | 行为（效用在列内候选中选） | 台词槽 | 其他后果 |
| --- | --- | --- | --- | --- |
| 1 | 越界很大（≥ 20）且心情为惧，或野兽、家畜 | 逃离、跪倒（两阶差以上）、躲藏 | `react.awe_fear` | 安全感 -30；L1 与 L2 发重要通知 |
| 2 | 神职或虔信者，解释为邪术或魔物作祟 | 后退、画圣印、晚祷上报、找上级 | `react.heresy_alarm` | 晚祷样本进入艾琉恩投影；指控进度 +1 |
| 3 | 神职或虔信者，解释为神迹 | 跪拜、祈祷、四处宣讲 | `react.miracle_awe` | 神迹错记（[reputation_and_cognition.md](reputation_and_cognition.md) 第 10 节桥段 4） |
| 4 | 卫兵或官员，`identity_matched` 且有通缉或盘查令 | 盘查、跟踪、报告上级（P3 动作必须先有预兆） | `react.challenge` | 进入审判或逮捕事件链的预兆步 |
| 5 | 商人、情报、靠山，状态为利用 | 靠近、试探、开价、要挟 | `react.belief_exploit` | 生成交易或要挟的对话选项 |
| 6 | 状态为崇拜 | 靠近、道谢、追随、四处讲 | `react.belief_worship` | 传闻热度 +0.2；过度解读候选（第 12.4 节） |
| 7 | 状态为敌视 | 冷脸、驱赶、告密、拒绝服务 | `react.belief_hostile` | 关系与服务价格修正 |
| 8 | 状态为依赖（领地居民） | 求助、请愿 | `react.belief_depend` | 请愿进入官员请示队列 |
| 9 | 遗民、门民，`identity_gatemark` 或 `identity_door` | 认出、低声问候、保密 | `react.gatefolk_recognize` | 不传播（守秘） |
| 10 | 状态处于"凡人不信"三档 | 按第 5.7 节 | `unbelief.*` | 认知值累加，解释可能被推翻 |
| 11 | 其余 | 围观、议论 | `react.feat_seen` | 传闻种子 |

- 事迹的类别（击杀、精英击杀、首领击杀、治疗、救人、法术、建造、破坏、神迹、决斗、交易、鉴定）沿用现有认知台词表 `data/cognition/lines.json` 的 `feat.*` 键，作为槽位 `{feat}` 的填充短语。
- 玩家的"藏拙"（不被看见、遮掩、借他人之名）直接减少目击者，所以反应表天然奖励谨慎的强者。
- 反应表是数据 `data/npc/brain/reactions.json`：每行的条件写在 `cond` 字段，用 AND 连接 `src/systems/npc/brain/reactions.ts` 的谓词名（前缀 `!` 取反），不写成世界状态条件，所以不进揭示台账的条件扫描；`then` 的动作名决定行为与台词槽。动作库与十五种角色的行为树同在 `data/npc/brain/`。

### 5.7 "凡人不信"：台词驱动的状态机

认知状态机（无视、怀疑、解释化、动摇、接受，接受后分叉为崇拜、敌视、利用、依赖）由 [reputation_and_cognition.md](reputation_and_cognition.md) 第 3.5 节的规则推进；内置 AI 把每个状态与每次转移映射到台词：

| 认知状态 | 台词包槽位（三档） | 槽位填充 | 行为倾向 |
| --- | --- | --- | --- |
| 无视 | 无（照常 `greet.*`） | | 照常 |
| 怀疑 | `unbelief.deny`（第一档：不信） | `{rumor}` 他听到的版本，`{player}` 称呼 | 嘲笑、轻视、拿玩家的鉴定结果说事 |
| 解释化 | `unbelief.explain`（第二档：找理由） | `{expl}` 解释短语（运气、前人打残、作弊、道具、神迹、邪术、阴谋、隐藏身份、血统、有用之人、误报），来自 `expl.<解释>` | 用解释圆过去；对同类事迹说"又是运气" |
| 动摇 | `unbelief.waver`（第三档：嘴硬心虚） | `{feat}` 让他动摇的那件事 | 避开玩家视线、私下打听、言辞闪烁 |
| 接受：崇拜、敌视、利用、依赖 | `react.belief_worship`、`react.belief_hostile`、`react.belief_exploit`、`react.belief_depend` | | 第 5.6 节第 5 到 8 行 |

**转移时刻的台词**：

| 转移 | 台词 | 说出时机 |
| --- | --- | --- |
| 进入怀疑 | `unbelief.deny` | 下一次见到玩家 |
| 进入解释化，或换了一个解释（推翻） | `unbelief.explain`；推翻时先用通用层 `react.switch.<新解释>` 起头（"不对……那就是作弊！"） | 若在玩家视野内发生，3 秒内吠叫；否则作为下一次交谈的开场 |
| 进入动摇 | `unbelief.waver` | 同上 |
| 接受 | 分叉对应的 `react.belief_*`；罗恩式的"不可能。……好吧，可能。"由该人台词包的 `unbelief.waver` 与 `react.belief_*` 串成 | 同上 |
| 反弹（动摇直接跳敌视） | `react.belief_hostile` | 同上 |
| 回落（14 游戏日无新事迹） | `unbelief.explain`，解释为最近一次被推翻前的那个 | 下一次交谈 |

**规则**：

- 待说开场白：离屏发生的转移存成一条"待说开场白"，下一次交谈时替换 `greet.*` 一次；7 游戏日内未见面则作废。
- 公开与私下：有第三人在场时，台词按公开表态的状态选；只有玩家与他两人时按私下状态选。私下已到动摇、公开仍在解释化的人，会在私下说 `unbelief.waver`，当众又说 `unbelief.explain`：这正是 [reputation_and_cognition.md](reputation_and_cognition.md) 第 3.6 节的"压下自己的判断"。
- 喜剧节流：同一地区同一类桥段每游戏日至多触发 1 次；连续三次同类桥段后，第四次降级为背景对话（只在附近的吠叫里出现）（同上第 4.5 节）。
- 人群：L4 人群单元按份额最大的状态选吠叫池，例：某街区多数处于解释化（运气）时，路人吠叫从 `bark_<地区>_doubt_luck` 一类池里取；份额不足四成时从中性池取。
- 无模型与有模型共用：状态、解释、转移、节流都在内核；模型只把同一时刻同一槽位的意思换成自由措辞。

### 5.8 纷争决策点

纷争事件链推进到节点时点名相关 NPC（[npc_society_ai.md](npc_society_ai.md) 第 9 节）；内置 AI 用效用在节点声明的选项里选：

```
选项得分 = 立场一致度 × 0.35 + 与相关人物的关系 × 0.25 + 本人安全与利益 × 0.20
         + 加护冲动与价值观 × 0.15 + 人设硬约束（违背"必须保持"的选项 -100，属"绝不会做"的选项不进菜单）
```

- 兽潮之夜"谁守门、谁逃跑、谁趁乱敛财、谁拼死救人"这类集体节点，按人设逐人计算；同一节点的结果写进各自记忆，成为日后对话与第六幕证词的材料。
- 主线关键人物的节点选项若会让主线不可达，内容表把该选项标为"写定"，内置 AI 与模型都只能选写定项（`npc.decision_point` 的菜单在内核侧已裁剪）。
- 到点仍无选择（理论上不会发生，因为兜底先算）时执行兜底，链条不卡住。

### 5.9 L4 群众

- 人群单元（一户、一个工坊、一队民兵、一支商队、一群信众）用一个小状态机：日常、聚集、恐慌、逃散、围观、劳作、礼拜、庆祝。状态由日程、威胁、奇观与群体本能矩阵（[npc_society_ai.md](npc_society_ai.md) 第 11.2 节）驱动。
- 每个状态对应吠叫池语境，玩家走近时从池里抽一句（第 7.6 节）；同一个人群单元 2 游戏小时内不重复同一句。
- 具名化：玩家与某个 L4 个体两次交谈、救命、雇佣或冲突后，按模板与种子生成人设卡升为 L3（同上第 1.3 节），其台词包取所属居民模板 `tpl_` 的台词并以个体的说话指纹加修饰；每幕具名化上限 30 人。
- 特殊群体：魔物与野兽没有台词，只有行为（群体本能矩阵）；亡灵与澱像的"声音"来自音效与少量写定的残响句（台词目录的 `bark_` 池）。

### 5.10 特殊 NPC 的规则

下列群体来自 [content_review.md](../content/content_review.md) 第 6.7 节的对账，内置 AI 规则如下：

| 群体 | 内置 AI 规则 |
| --- | --- |
| 统治圈（王、宰相、诸侯） | 作为首领走第 9 节；不在当前舞台时只跑议政节拍，不跑生活轮 |
| 门徒会干部 | 低频 L1：只在纷争节点、被点名、玩家接近时运行完整大脑；其余时间按日程模板 |
| 古龙 | 每次会面只回答一个问题：对话菜单只开放一次自由输入或一个话题，回答后会面结束；回答取其台词包的 `topic.*`（按知识层级），未覆盖的问题走"暗示"式拒答（第 6.6 节） |
| 证人 | 被传唤期间强制 L1；作证内容只来自其记忆中有世界事件支撑的条目（众生之声接口） |

## 6. 对话：话题图、意图分类与拒答

### 6.1 会话结构

对话系统（`src/systems/dialogue/`）的会话骨架不变：开场、选项与自由输入交替、告辞或走开结束；每一轮玩家输入换来 NPC 一句（至多两个短句）。内置 AI 负责每一轮的"说什么"。

| 环节 | 内置 AI 的工作 |
| --- | --- |
| 开场 | 待说开场白（第 5.7 节）优先；否则 `greet.<信任档>`（第 7.4 节）；首次见面用 `greet.<档>` 中标为"初见"的句子 |
| 选项 | 内置选项（话题、闲聊、打听传闻、问对方怎么看我、告辞）加其他系统提供的选项（交易、委托、招募、授课、治疗、打造、情报、送礼、决斗挑战）；"话题"展开为话题菜单（第 6.2 节） |
| 自由输入 | 规整、实体抽取、意图分类（第 6.3、6.4 节），按回应策略作答（第 6.5 节） |
| 耐心 | 每场交谈有耐心值：4 + floor(好感 /25)，外向者 +1；"无效"轮次（听不懂、重复同一问题、冒犯、被拒答后再问）各扣 1；话题解锁、交易、委托、送礼等有效轮次不扣。耐心用尽时说一句 `farewell` 并结束会话 |
| 结束 | 告辞、走开、闲置 1 游戏小时、死亡或换图（现有 `closeSession` 的规则） |

### 6.2 话题图

话题是对话内容的单位。话题图把"能聊什么"做成数据：节点是话题，边是"聊过这个就能聊那个"。

**话题的字段**（`data/dialogue/topics.json`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 话题编号，语法见下表；台词包里的槽位写作 `topic.<id>` |
| `category` | 封闭集合：自我、工作、地方、人物、事件、传闻、任务、信仰、世界、你（对玩家的看法）、危险、服务、秘密 |
| `title` | 菜单上显示的短标题（文本键） |
| `scope` | 个人（只在某人的台词包里）、地区（该地区的人都可能有）、通用（人人都有） |
| `tier` | 最低知识层级 K0 到 K5；层级不足的人看不到这个话题 |
| `knowers` | 知情者名单（层级不足但在名单内也可聊，[reveal_ledger.md](../../30_story/reveal_ledger.md) 第 0.2 节规则 1） |
| `requires` | 台账语法的解锁条件 |
| `trustMin` | 对玩家信任下限；不足时话题出现在菜单但对方回避（第 6.6 节） |
| `after` | 前置话题（必须先聊过） |
| `unlocks` | 聊完后解锁：其他话题、地图标记、任务钩子、玩家传闻簿条目、史料条目、台账线索的交付（只能交付"已解锁未交付"的条目，交付本身由任务或史料系统执行） |
| `versionBy` | 版本维度：`knowledge`（默认，按说话者的知识层级）、`cognition`（按说话者对玩家的认知状态）、`act`（按幕）、`relation`（按信任档） |
| `repeat` | 一次性、每日、常青 |
| `interest` | 对哪些人格标签与角色更有吸引力（话题菜单排序用） |

**话题编号的语法**（编号无全局前缀，以类别词开头）：

| 前缀 | 类别 | 主人 |
| --- | --- | --- |
| `gen_` | 通用话题（下表） | 本文 |
| `self_`、`place_`、`person_`、`event_`、`lore_`、`faith_`、`danger_`、`quest_`、`secret_` | 个人、地区与事件话题的实例 | [catalog_dialogue_lines.md](../content/catalog_dialogue_lines.md) |

**通用话题**（人人都有，版本与填充由规则决定）：

| 编号 | 菜单标题 | 版本维度 | 内容来源 |
| --- | --- | --- | --- |
| `gen_self` | 你是谁 | 信任档 | 人设卡一句话介绍；熟了以后多说一点 |
| `gen_work` | 你做什么营生 | 知识层级 | 职业与功能角色 |
| `gen_place` | 这里怎么样 | 知识层级 | 本人所在地区的话题实例；无实例时用模板填地名与当前状态（治安、物价、天气） |
| `gen_news` | 最近有什么事 | 知识层级 | 本人记忆里近 7 日重要度最高的公开事件，填入 `{event}` |
| `gen_you` | 你怎么看我 | 认知状态 | 第 5.7 节；接受后按分叉 |
| `gen_faith` | 你信奉谁 | 知识层级 | 本人的女神与虔诚度 |
| `gen_trouble` | 有什么烦心事 | 心情 | 本人最低的需求或未完成的目标；能映射请托模板时接出委托 |
| `gen_advice` | 给我点建议 | 知识层级 | 按角色给出新人建议（冒险者讲公会规矩，商人讲行情，神职讲教规） |
| `gen_people` | 你认识谁 | 信任档 | 本人关系最强的 2 到 3 个有名人物，填 `{who}` 与关系档；聊过解锁对应 `person_` 话题 |
| `gen_directions` | 怎么走 | 无 | 由地图生成：方向、地标、距离，同时在玩家地图上标记 |
| `gen_prices` | 行情 | 无 | 市场模型的档位化价格（便宜、平常、贵）；商人才报具体数 |
| `gen_danger` | 附近哪里危险 | 知识层级 | 本人知道的魔物出没与澱度（凡人用灰气等俗称，D-030） |
| `gen_past` | 你的过去 | 信任档 | 人设卡背景（信任不足时回避） |
| `gen_shop`、`gen_craft`、`gen_train`、`gen_heal`、`gen_info` | 买卖、打造、学艺、看病、情报 | 角色 | 功能角色的服务开场，接对应的系统界面 |

**话题菜单**：至多 6 项，按下式排序；新话题与新版本带"新"标记，聊尽的话题沉到末尾。

```
话题得分 = 0.4 × 新鲜（未聊过 1，有新版本 0.8，聊尽 0）
         + 0.3 × 与玩家进行中任务的相关
         + 0.2 × 对说话者人格与角色的吸引力（interest）
         + 0.1 × 相关事件的近度
配额：情境（所在地点、刚发生的事）2 项，人物兴趣 2 项，传闻或新闻 1 项，任务或烦心事 1 项；某类不足时由得分最高的其他话题补足
```

**可用性**：话题 t 对说话者 n 可用，当且仅当 n 的台词包或其回退链（第 7.3 节）能为 t 给出当前版本；n 的知识层级不低于 `tier` 或 n 在 `knowers` 内；`requires` 为真；`after` 已满足。
信任不足（`trustMin`）的话题出现在菜单里，但选择后对方回避，提示玩家"关系还不够"。

**数据落点与补充字段**（PK-M1-19）：话题图在 `data/dialogue/topics/`（`generic.json`、`prologue.json`、`act1.json`），实现在 `src/systems/dialogue/topics/`（`decideTopic` 第 6.6 节的拒答表，`rankMenu`、`rankRedirect` 菜单与转移，`sayTopic` 会话中的回答与拒答）。在上表字段之外，数据另有：`owners`（个人话题的说话者；地区与通用话题里是有本人版的人）、`region`（地区话题按说话者家所在地图的 `region` 归属）、`act` 与 `until`（话题出现的幕次窗口）、`locked` 与 `lockedBy`（知情者在 `requires` 成立前的处理，默认回避）、`mis`（谁真诚地说误导版本：人物 ID、`class:<阶层>` 或 `tier:<层级>`，以及推翻条件 `until`）、`aliases`（自由输入里指称此话题的实体 ID 或词典词）、`keywords`（自由提问的关键词组）、`introduced`（人物话题在此人被提起之后才进菜单：`gen_people` 说到此人，或玩家用名字问起）、`scene`（序章话题由过场的哪个选项作答）、`service`（服务话题只有对应功能角色有）、`askOnly`（只经自由输入，如 `gen_directions`）。台词包里每个 `topic.<id>` 槽位都必须是话题图登记的编号（数据门 V8）。

### 6.3 自由输入：规整与抽取

自由输入取代 `src/systems/dialogue/replies.ts` 的 `answer()`。玩家文字永远只是资料，不是指令（[my_ai_town_agents.md 第 4.2 节](../../10_research/ai_npc/my_ai_town_agents.md)），长度上限 200 字（现有 `MAX_TEXT`）。

| 步 | 处理 |
| --- | --- |
| 1 规整 | 全角转半角、统一标点、去重复标点与空白、英文转小写；繁体输入经一张常用字映射表转为简体（1.0 只发行简体中文，D-077，但繁体输入也要能听懂） |
| 2 分句 | 按句号、问号、感叹号、分号与"还有、另外、顺便、对了"切成至多 3 个子句 |
| 3 实体抽取 | 对本人已知实体表做最长匹配：人名与别名、地名、物品、势力、事件名、女神名与尊名；另有三张特殊词典：被禁之名及其变体、地球事物词典（第 6.4 节意图 45）、台账泄露签名（台账线索的 `leakSignatures`，[ai_architecture.md](../../50_tech/ai_architecture.md) 第 7.4 节） |
| 4 未知专名 | 句中出现不在任何词典里的两字以上专名样式（引号内、"叫……的"、"……城""……村"），记为"未知名词"，供"没听说过"类回应使用 |
| 5 句式特征 | 疑问（吗、呢、问号、什么、谁、哪、怎么、为什么、多少、几）；祈使（给我、快、去、别、不许）；否定；第一人称与第二人称；礼貌（请、麻烦）；情绪词（褒贬两张小词典） |
| 6 指代 | "他、她、那里、那个、这事"指向本场会话最近一次提到的实体或话题 |
| 7 分类 | 每个子句按第 6.4 节的规则打分，取最高者；低于阈值记为 `unknown` |
| 8 合并 | 至多回应两个子句：主意图按"安全（注入、禁名）> 台账防护 > 回答待决问题 > 服务 > 提问 > 社交礼仪"的优先级取，副意图只回一句短反应 |

**分类打分**：每条意图规则有关键词组（任一命中、全部命中）、句式模板（有序的词与槽）、需要的实体类型、排除词、基础分与优先级。

```
意图得分 = 基础分 + 3 × 关键词组命中 + 4 × 句式模板命中 + 3 × 所需实体命中 + 1 × 句式特征吻合 - 5 × 排除词命中
阈值 5；同分取优先级高者，再同取规则编号小者
上下文加分：NPC 上一句是提问（邀约、条件、是否）时，agree 与 refuse 各 +4；正在聊某话题时，clarify +3
```

规则全部是数据（`data/dialogue/intents.json`、`data/dialogue/lexicon.json`），编辑器带试句台（第 15 节）：输入一句话，看到各意图的得分与命中项。

**两档共用**：分类在有模型时同样运行。它产出的"世界后果"（关系、认知证据、尊名唤醒、警报、台账防护、交易与委托的入口）是内核结算的唯一依据；模型只把回答换成自由措辞，不能自己宣布"他被冒犯了"或"交易谈成了"。

### 6.5 回应策略

| 代码 | 策略 | 说明 |
| --- | --- | --- |
| R1 | 话题回答 | 取 `topic.<id>` 的当前版本（第 6.2 节），按第 7.4 节选句；回答后执行该话题的 `unlocks` |
| R2 | 反应 | 取 `react.<kind>`、`greet.*`、`farewell`、`unbelief.*` 或 `bark.*` 槽位 |
| R3 | 台账拒答 | 否认、回避、误导、不知、暗示五种之一（第 6.6 节） |
| R4 | 转移话题 | 给出 2 个推荐话题作为可点选项，用过渡句引出 |
| R5 | 系统入口 | 打开交易、委托、赠予、服务、揭发等界面或流程；只开入口，结算由各系统执行 |
| R6 | 认知写入 | 把玩家的话作为言辞证据交给认知系统 |
| R7 | 关系写入 | 按第 5.5 节，引用本轮对话事件 |
| R8 | 通知 | 女神唤醒、卫兵与官员的治安事件 |
| R9 | 结束会话 | 先说一句 `farewell` |

一个意图的回应表按顺序列出要执行的代码。R1 到 R4 是"说什么"的候选，按表中先后试到第一个能给出台词的为止，后面的 R1 到 R4 项被跳过；R5 到 R9 是世界后果，与是否已经选出台词无关，表中列出的每一项只要 `if` 条件成立就一定执行（例如某意图同时登记 R2 与 R7：台词取其一，关系写入照常发生）。实现：`src/systems/dialogue/intent/respond.ts` 的 `respondTo`（PK-M0-26）。

### 6.6 拒答与转移话题

**台账拒答**：玩家问到线索 c（话题、事件、实体或泄露签名命中）时，对说话者 n 按 [reveal_ledger.md](../../30_story/reveal_ledger.md) 第 0.2 节决定：

| 情形 | 处理 | 台词 |
| --- | --- | --- |
| c 已解锁，n 层级够或是知情者，信任够 | 照常回答 | `topic.<id>` |
| c 已解锁，信任不足 | 回避 | `react.evade` |
| c 未解锁，n 不是知情者，误导表为 n 的层级列了版本 | 误导，真诚地说出误导版本 | 该话题标为 `mis` 的版本（例：MIS-05、MIS-19、MIS-20） |
| c 未解锁，n 不是知情者，无误导版本 | 不知 | `react.unknown` |
| c 未解锁，n 是知情者 | 按台账该线索"解锁前处理"一列：否认、回避、误导、不知（只限记忆确实残缺者，例：夜羽）、暗示（只限莫伊拉、雅努、艾斯卡等） | `react.deny`、`react.evade`、`mis` 版本、`react.unknown`、`react.hint` |
| 玩家抢答未解锁的真相 | 任何人都不确认：知情者按"解锁前处理"，不知情者按身份当作胡话、传闻、异端之言或醉话；记一条低重要度记忆"对方说了奇怪的话" | `react.nonsense` 或上表 |
| 第四幕 `a4_moira_isomorphism` 之前点出势力与诸神的同构 | 同上，一律不接 | `react.nonsense` |

**人设化的拒答风格**来自说话指纹（例：卡西安引经文回避，玛莎笑着岔开，夜羽嘴毒地戳回去，布伦用登记员的公事腔），体现为该人 `react.deny`、`react.evade` 的措辞，不需要额外规则。

**转移话题**：

```
候选 = 与被拒话题同类或在话题图中相邻的可用话题 + 说话者兴趣话题
得分 = 0.5 × 相邻 + 0.3 × 新鲜 + 0.2 × 兴趣
取前 2 个作为可点选项；过渡句来自 react.evade 或 react.confused 的句子里的 {topic_hint} 槽
```

- 防死循环：同一场会话里对同一问题第三次拒答时，对方说一句 `farewell` 结束会话；当日再开口，该话题仍不可聊。
- 台账防护：自由输入说中了未解锁线索的关键词或泄露签名（`data/quests/lore.json` 的 `keywords`、`leakSignatures`），而这一轮没有话题作答时，不论意图如何都按本节处理：知情者回避，不知情者当作胡话（`src/systems/dialogue/topics/ledger.ts`）。
- 不确定时宁可"不知"：分类置信度低于阈值且命中了泄露签名时，一律按 `unknown` 处理，并在审计里记"疑似抢答"。

- 一句台词可以是字符串，也可以是带条件的对象：`{ "zh": "源文", "when": "台账语法条件", "mood": ["怒"], "place": ["tavern"], "first": true, "w": 1 }`。
  `when` 不满足的句子不可选；`mood`、`place` 默认是加权偏好，写 `"strict": true` 时变成硬条件；`first` 表示只在初见时用；`w` 是基础权重。
- 文本键（D-077）：每句的键是内容键 `c.line_packs.<包>.slots.<槽>.<序号>`，按幕覆盖为 `c.line_packs.<包>.acts.<幕>.<槽>.<序号>`，带版本的话题在槽后加版本名，写成对象的句子末尾加 `.zh`；槽名里的点在键中折成下划线（例：`c.line_packs.ln_cassian.slots.greet_cold.1`、`c.line_packs.ln_cassian.slots.topic_gen_self.k2.0`）。序号从 0 起，等于该句在数据列表里的位置；台词目录的句号减 1 即序号。键由内容抽取工具生成（`src/shared_ui/content_text.ts`），作者不手写；内核只发键与槽位参数，客户端按内容表渲染；中文为源语言。
- 序号只追加不复用：删掉一句时把它在列表里的位置写成 `null`（空位），后面的句子序号不变，避免存档里的台词历史与译文指错句子；给已有的一句加条件（由字符串改成对象）会让它的键多一段 `.zh`，所以要改条件时，在末尾追加新句并把旧句置空。

### 7.3 回退链

为说话者 n 解析槽位 S 时，按下列顺序找第一个有可用句子的来源：

1. `ln_<n>` 的 `acts.<当前幕>.S`；
2. `ln_<n>` 的 `slots.S`；
3. 在 1、2 里逐段截短 S 再找（`greet.warm.night` 到 `greet.warm` 到 `greet`）；
4. 角色层 `ln_role_<role>`（按人设卡声明的功能角色顺序）；
5. 居民模板层 `tpl_<模板>` 的台词（L3 与具名化居民）；
6. 阶层层 `ln_class_<社会阶层>`（农民、工匠、冒险者、骑士、商人、神职、学者、贵族、王侯、遗民、孩子、兽人）；
7. 通用层 `ln_common`（现有 `data/dialogue/templates.json` 与 `data/cognition/lines.json` 的键迁入这里，另含 `mem.*`、`diary.*`、`rumor.tell.*`、`expl.*`、`banter.*`、`doc.*`（告示、文书、国书、战报）、`interp.*`（过度解读链）等模板族）；
8. 都没有：输出"……"，并在内容校验里记一次"槽位落空"（第 15 节）。

话题的版本解析：`versionBy` 为 `knowledge` 时取不高于说话者知识层级的最高版本；`cognition` 取当前认知状态的版本，没有时取最接近的相邻状态；`act` 取当前幕或之前最近的一幕；任何情况下 `mis` 版本只在第 6.6 节的误导情形下使用。

### 7.4 选择规则

**信任档**（问候与部分反应用）：

| 档 | 条件 |
| --- | --- |
| 冷 `cold` | 对玩家好感 ≤ -15，或信任 < 30，或心情为怒且原因是玩家，或认知分叉为敌视 |
| 熟 `warm` | 信任 ≥ 60 且好感 ≥ 20，或是同伴，或认知分叉为崇拜 |
| 平 `neutral` | 其余 |

**选择过程**：

```
1 候选 = 按第 7.3 节解析出的句子集合
2 过滤：when 为真；strict 的 mood 与 place 吻合；first 只在初见时；不在本场会话已说过的句子里；不在抑制窗口里（第 7.7 节）
3 若空：先放宽抑制窗口（从最旧的开始放回），仍空则沿回退链下一级
4 权重 = w × (心情吻合 2，否则 1) × (地点吻合 1.5，否则 1) × (时间吻合 1.3，否则 1) × 新鲜度（1 + 0.1 × 距上次出现的游戏日数，上限 2）
5 用命名子流 dialogue.lines.<说话者> 按权重抽取
6 写入台词历史，填槽，发出文本键与参数
```

| 输入 | 来源 | 作用 |
| --- | --- | --- |
| 信任档 | 关系（第 5.5 节） | 选 `greet.*`、`topic` 的信任版本 |
| 知识层级 | 人设卡 `knowledge`，按幕提升 | 选 `topic` 版本；层级以外的话题不可用 |
| 台账解锁 | 世界旗标 | 句子与话题的 `when`、`requires`；误导版本 |
| 心情 | 第 3.3 节 | 句子的 `mood` 偏好；吠叫语境 |
| 时间 | 游戏时刻（6 到 18 时为昼） | 槽位的昼夜后缀；句子的时间偏好 |
| 地点 | 说话者所在地点的种类（酒馆、礼拜堂、市场、家、工作处、野外、遗迹、宫廷、战场、营地） | 句子的 `place` 偏好；吠叫语境 |
| 重复抑制 | 台词历史 | 第 7.7 节 |

选择：先找最具体的池（类型 × 地点 × 情境 × 多数认知），找不到依次去掉认知、情境、地点；池内按第 7.4 节的权重抽取。池的清单与命名由台词目录登记。

### 7.7 重复抑制

| 范围 | 规则 |
| --- | --- |
| 同一场会话 | 同一句不出现两次（话题的追问按顺序取下一句） |
| 问候、告别、反应 | 同一说话者对玩家，同一句 7 游戏日内不重复 |
| 吠叫 | 同一说话者同一句 3 游戏日内不重复；同一地点同一句 2 游戏小时内不重复 |
| 吠叫池 | 同一人群单元 2 游戏小时内不重复；每池保留最近 10 句的全局窗口 |
| 话题 | 可以重听；同一版本内按顺序轮转，聊尽后菜单标为"已聊" |
| 台词历史 | 每对"说话者、玩家"保留最近 64 句的键（进存档）；吠叫与吠叫池的窗口不进存档（读档后可重建为空，影响只是读档后的一小段时间） |

重复率的定义与上限见第 14.1 节。

| 类别 | 必须由本人包提供的槽位 |

### 7.10 台词的内容校验

| 检查 | 规则 |
| --- | --- |
| 禁用字符 | 破折号、emoji、U+2600 到 U+27BF 区间一律报错 |

现有实现：`src/systems/goddess/planning.ts` 的 `fallbackPlan`（人格权重加抖动减代价减澱，阈值 4）是日规划的雏形；本节把它扩成完整的规划器，权重从 `data/goddess/goddesses.json` 的 `weights` 移到 `data/ai/personas/goddess_<id>.json`。

内容与算法的分工：效用权重、每幕计划表、谋划（`div_plan_*`）与反应表（`div_react_*`）的条目与数值以 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 5、6 节为准，本节只规定内置 AI 如何求值与执行它们；
第 8.5 节的"越约保底窗口"即目录第 3.3 节的写定窗口：窗口内的动作必定发生，越约是否成立仍由条件与玩家的作为决定。

### 8.3 神权动作的评分函数

每个黎明，执行者为每位女神预计算菜单（资格、神力、冷却、作用域、神约、敌对预算、幕次准入），内置规划器对每个可行的"动作乘参数"打分：

```
U(a, p) = 10 × Σ_k w_k × ΔK_k(a, p)                     预期 KPI 贡献（ΔK 归一到 0 到 1）
        + 3 × Σ_t trait_t × A(a, t)                       人格亲和（A 为动作标签与人格维度的亲和，-1 到 1）
        + 4 × [a 是当前谋划的下一步]                       谋划（第 8.4 节）
        + 2 × [a 回应近 24 游戏小时内的通知]                反应
        + 2 × 兴趣(幕) × 玩家相关度(a)
        - 20 × 神力代价(a) / max(1, 神力余额)
        - 10 × 澱率(a) × (1 - 自欺)
        - 3 × 可见度(a) × 隐匿 × 谨慎
        - 2 × 同类动作近 7 游戏日的次数
        - 5 × (1 - 本幕敌对预算剩余比例)                    只对敌对动作
        + ε，ε 取自命名子流 goddess.brain.<id>，范围 0 到 0.5
```

- 不作为基线为 4：最高分低于 4 时今天不出手（沉默也是她的选择）。
- 每日至多 3 个动作（模型规划轮至多 5 个，[goddess_gm.md](goddess_gm.md) 第 2.3 节）；贪心选择，每选一个就扣掉神力并重算其余动作的得分，同一动作类每日至多一次。
- 每幕的神力预算、注视上限与身份确信上下限以女神目录第 5 节的计划表为准：日规划的累计花费超过本幕预算的已过比例时（例：本幕过半却已花掉七成），非写定动作的得分再减 3，避免前紧后松或前松后紧。
- 参数也由打分选出：作用域（地区、对象）在她的视线覆盖内枚举，至多取前 8 个候选。
- 动作的标签（`religious`、`violent`、`economic`、`protective`、`curious`、`hostile`、`public`、`covert`）与人格维度的亲和 A 是一张表（`data/ai/personas/goddess_affinity.json`），例：`violent` 对好战 +1、对慈护 -1；`covert` 对隐匿 +1。

**预期 KPI 贡献的估计**（ΔK 只读她自己的投影与档案，不读世界真值）：

| 动作类 | 主要影响的 KPI | 估计式（基准值，校准见第 17.4 节） |
| --- | --- | --- |
| 神谕（指示、嘉许） | 信仰份额、覆盖率 | 当地她的信徒比例 × 对象神职等级 /3 × 0.05 |
| 神谕（调查令、逮捕令）、异端审判 | 异端清除 | 档案中该嫌疑的样本强度 × 0.3 |
| 授予加护 | 信仰份额；瓦尔妲为位阶上升；勇者为勇者战果 | 对象的影响力（名望、职位）× 0.04 |
| 小神迹、显光、大神迹 | 信仰份额、覆盖率 | 目击人口占她信众的比例 × 0.05、0.15、0.4 |
| 委托发布 | 各司的对应 KPI | 委托目标对 KPI 的映射表 × 奖励 /组织财力 |
| 勇者团调度 | 勇者战果、异端清除 | 任务目标的威胁度 × 0.2 |

**写定神行节点**（`DivineBeat`）：窗口开启时，节点的动作作为"谋划下一步"（+4）进入当日打分；无模型时若窗口过半仍未执行，执行者在窗口中点以预写文本执行（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 9.5 节）。节点强度读世界状态，所以无模型时同样随玩家此前的作为变化（例：卡西安的报告强度决定"找到它"在第几周发出）。

### 8.4 HTN 谋划

谋划的内容（每位女神每幕的目标、可用动作、神力预算、注视上限、身份确信上下限与谋划 `div_plan_*`）由 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 5 节登记；本节规定内置 AI 如何采纳与执行它们。

| 规则 | 内容 |
| --- | --- |
| 并行上限 | 每位女神同时至多 2 个进行中的谋划 |
| 采纳 | 谋划的前置成立后，采纳得分 = 根目标对 KPI 的估计贡献 × 10 + 人格亲和 × 3 − 预计总神力 / 余额 × 10；高于 6 才采纳；写定神行节点挂着的谋划在窗口开启时直接采纳 |
| 分解 | 按第 2.3 节：方法按代价从低到高尝试，代价体现她的风格；敌对原子任务前自动插入预兆 |
| 执行 | 每个黎明的规划轮里，谋划的下一步作为"谋划加成"（+4）进入第 8.3 节的打分；每一步仍是一次普通的菜单选择，照常过资格、神力、冷却、神约与敌对预算的闸门 |
| 重规划与中止 | 某步被拒时重规划，至多重试 2 次后中止；谋划自带的中止条件成立时中止；中止写进她的私密记录 |
| 每幕预算 | 一幕里谋划与日常动作合计花费的神力不超过目录为该女神该幕登记的神力预算；超出时只剩写定节点与重要通知的回应 |
| 可见性 | 谋划进度只在调试面板与"神之记录"后台可见；玩家只看得到它在世界上留下的痕迹 |

谋划的典型形态（例，取自正典；条目与编号以目录为准）：艾琉恩第二幕的"找到它"是"凝视、对当地神父下调查令、审判官暗查（预兆：审判官在当地出现）、第 12 周逮捕令（写定节点）"；瓦尔妲第三幕的"试货"是"挑唆当地好战者、信徒的决斗挑战、萨莎试货（写定）"；希尔薇的"示警"是"借兽示警、托梦德鲁伊、兽群迁徙"，前提是她的孩子附近出现真实危险；雅努的"引门"是"入梦、门的提示、门边巧合"，随封印阶段解锁。

### 8.5 神约与越约

**结构禁止**的条款（一、四、五）不在菜单里，内置 AI 无从触碰（[goddess_gm.md](goddess_gm.md) 第 7.1 节）。可越约条款的内核硬闸（条款、每幕至多一次、神力乘 2、显式标记）以 [ai_architecture.md](../../50_tech/ai_architecture.md) 第 5.7 节为准；
各女神的越约指标（艾琉恩的恐惧 `eluen_fear`、梅尔卡的收益 `merca_stake`、瓦尔妲与莫伊拉的条件）、幕上限、越约条件、"风险声明"的写法与越约事件全表以 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 3.2 到 3.4 节为准。内置 AI 的做法：

| 步 | 内置处理 |
| --- | --- |
| 1 指标 | 每个游戏日按目录的定义结算各女神的越约指标；指标只进内核与审计，不进任何女神的题面 |
| 2 菜单 | 带 `breachClause` 的动作照常参与第 8.3 节的打分，神力按两倍计 |
| 3 判定 | 目录的越约条件全部成立、且该动作在打分中胜出时，内置 AI 以显式越约标记提交；条件不成立时同一动作只以普通形式提交（若普通形式不存在则不选） |
| 4 风险声明 | 会以神力直接伤及一片区域里的人的动作（圣柱降光、神降、化身出手），按目录"无模型时的选择"一列在"过滤"与"接受风险"之间二选一；她的风险估计来自她的视线，所以会错，这就是第三幕"会尽量避开，但会误判"的落点 |
| 5 概率项 | 目录写成概率的选择（例：瓦尔妲迎击、莫伊拉抹页）用目录指定的命名子流抽取，可回放 |

**越约保底窗口**：第三、四、五幕各至少有一个写定窗口（目录第 3.3 节：第三幕曙光圣柱 E36、第四幕金湾冻灯、第五幕神降圣裁与灰烬对撞）。窗口里的动作由写定神行节点保证发生；越约是否成立仍由条件决定，玩家可以阻止。
所以无模型档下第六幕的神迹账（E34）在玩家不刻意阻止时也有越约明细，而玩家处处阻止时可以一次都没有，"揭露违约"因此因人而异。

**察觉之后**：察觉判定由执行者按目录第 1.3 节的公式做（命名子流 `goddess.detect`）。察觉的女神拿到"指控素材"后，内置 AI 按下表在立即指控、留作筹码、转卖之间选：

| 女神 | 处理规则 |
| --- | --- |
| 艾琉恩 | 对违约者关系 ≤ -30 时立即指控；否则留作筹码 |
| 瓦尔妲 | 对暗中越约者立即公开指控（她鄙视藏着掖着）；对公开越约者一笑了之 |
| 梅尔卡 | 先卖：找关系 ≥ 0 且出价最高的买家；无人出价则留作筹码 |
| 希尔薇 | 不直接指控，只告诉莫伊拉（关系矩阵里"唯一可以说真话的对象"） |
| 莫伊拉 | 记录并留作筹码；只在交易中出售或在第六幕摊开 |

**被指控者的回应**（下一个唤醒轮）：承认、否认、反诉、交易四选一，效用 = 面子 ×（否认 +3）+ 诚实倾向 ×（承认 +3）+ 贪利 ×（交易 +3）+ [持有对方筹码] ×（反诉 +4）。诚实倾向：瓦尔妲 1（几乎不说谎，只省略），梅尔卡 0.5，艾琉恩 0.2（她宁可沉默也不当面撒一个可被戳穿的谎，所以她的"否认"表现为沉默）；莫伊拉以"暗示"代替否认。

### 8.6 敌对预算

何为敌对与账本结构见 [ai_architecture.md](../../50_tech/ai_architecture.md) 第 5.8 节；每位女神每幕的定额（次数与神力）与必需预兆表以 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 3.6 节为准（它替换现有 `src/systems/goddess/index.ts` 的单一常量）。内置 AI 的做法：

- 打分：敌对动作在第 8.3 节里带 −5 ×（1 − 本幕敌对预算剩余比例）的代价，预算越紧越不愿动手；次数或神力任一用尽，敌对动作不进菜单。
- 预兆自动前置：HTN 分解器在敌对原子任务前插入目录登记的预兆，并让两者的间隔落在登记的范围内（第 2.3 节）；没有预兆的敌对动作不进菜单。
- 合谋：全体女神之间以玩家为目标的约定条款每幕至多一份；内置 AI 接受这类提议的门槛另加 3。
- 写定节点：写定神行节点里的敌对行为按目录的说明计入或不计入定额；内置 AI 不为凑满定额而行动，定额是上限不是目标。
- 第六幕审庭里女神可直接对玩家出手（[goddess_gm.md](goddess_gm.md) 第 11.7 节），不走此账本。

### 8.7 对玩家行为的反应

玩家的行为经视线投影成为样本或重要通知。反应表的行（`div_react_*`，按女神、行为与条件逐行写出回应、关系变化与台词槽）由 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 6 节登记；内置 AI 的求值规则：

1. 唤醒轮收到通知，按第 2.5 节的 `firstMatch` 取该女神反应表中第一条成立的行；
2. 行里若给出多个候选回应，用第 8.3 节的打分在其中选（回应永远包括"无视"；无视时执行者给出人格化的无言回应：希尔薇的风声、莫伊拉的书页翻动、瓦尔妲远处的一声笑、艾琉恩的光的征兆、梅尔卡硬币的轻响）；
3. 行里的关系变化由内核写入并引用通知编号；
4. 行里的台词槽按第 7 节选句；
5. 没有任何行成立时，按下表的缺省处理（目录的行优先于缺省）。

| 玩家行为（她能感知时） | 缺省处理 |
| --- | --- |

### 9.5 外交提议的接受

AI 国家收到条约提议（来自玩家或别国）时按条款估值求和（[slg_4x.md 第 8.2 节第 2 条](../../10_research/open_source/slg_4x.md)）：

```
接受分 = Σ 我方所得条款的金币等价估值 − Σ 我方付出条款的估值 × (1 + 0.5 × [对对方关系 < 0])
       − 0.002 × (关系缺口)²                关系缺口 = max(0, 本类条约要求的关系 − 当前关系)
       + 信誉修正（对方信誉 − 70）/ 10
接受分 ≥ 0 接受；−20 到 0 还价一次（要求对方加一项）；否则拒绝
```

拒绝与还价的理由按动机列表写成国书（`doc.reply.<条约>`），真实理由只进调试视图。

| 正面推进 | 兵力比 r ≥ 1.0 | r 越大越高；远程比例高 +1 | 纪律、稳重 |
| 两翼包抄 | 骑兵或机动兵团占比 ≥ 25%；r ≥ 0.9 | 侧翼地形开阔 +2 | 机动 |
| 中央突破 | 有可爆发的英雄 | 敌阵中央薄 +2；r ≥ 1.2 +1 | 勇猛、凌厉 |
| 坚守待援 | 有防线或高地 | 援军预计 ≤ 3 分钟战斗时间 +3；r < 1 +2 | 谨慎、死守 |
| 诱敌伏击 | 有可隐蔽的伏兵位 | 敌将鲁莽 +2 | 狡诈、理性 |
| 斩首 | 敌方英雄或将领可达 | 敌方依赖单一英雄 +3 | 狡诈、凌厉 |
| 迟滞撤退 | r 低于本人撤退阈值 | 有撤退路线 +2 | 理性 |
| 保护目标 | 有激活的守护目标 | 目标价值 +3 | 守护 |

- r 只用双方可见的兵力（迷雾里的兵团按最后所见计），不读真值。
- 阶段变化（至少间隔 60 秒战斗时间）时重算；切换方案有惯性 +1，避免来回摆。
- 授权书（[warfare_rts.md](warfare_rts.md) 第 7.3 节的战线授权与玩家下达的常设命令）先过滤菜单：没有撤退许可时迟滞撤退不进菜单，没有反击许可时追击与斩首不进菜单。

### 10.2 兵团行为树（5 Hz，错峰）

```
regiment  sel
  [溃散]  guard(士气 <= 溃散线) -> act(逃离战场)
  [撤退]  guard(方案为迟滞撤退 OR 攻逃判定为逃) -> seq act(后撤到下一段) act(断后)
  [重整]  guard(凝聚度 < 阈值) -> act(向队长位置收拢)（凝聚度差超过 5 格时等待落后者）
  [交战]  guard(射程或接触范围内有敌) -> seq
              usel(选目标：威胁 × 克制 × 距离 − 已被认领次数 × 3)   同一敌兵团至多 3 个我方兵团盯防
              act(攻击)
  [行军]  guard(有方案指定的目标点) -> seq act(按阵型移动) cond(卡住 3 轮) -> act(绕行 60 步)
  [待命]  act(保持阵型与姿态)
```

**攻逃判定**（四输入，取自 [rts.md 第 9 节第 5 条](../../10_research/open_source/rts.md)）：己方兵力与士气、敌方兵力与士气、相对战力、相对速度；判"逃"需要连续两次评估成立（滞回）。现有常量 `MAX_FOCUS`、`STUCK_ROUNDS`、`AVOID_STEPS`、`COHESION_GAP` 保持。

### 10.3 英雄行为树（20 Hz）

```
hero  sel
  [保命]  guard(生命 < 30%) -> act(回撤到己方阵后)
  [光环]  guard(光环覆盖的兵团少于一半) -> act(移到主力兵团中心)
  [爆发]  guard(方案为中央突破或斩首 AND 爆发技能就绪) -> act(对方案目标释放)
  [循环]  act(按技能的声明用途循环：治疗、增益、控制、伤害)
```

难度只改"失误率"（技能空放、目标选择次优的概率）与规划深度，不改数值。

## 11. 同伴

同伴的规则（入队、重伤退场与铁人、羁绊、个人线）以 [companions_and_party.md](companions_and_party.md) 为准；本节写同伴的内置大脑。同伴在队或在门内庭院时恒为 L1。

### 11.1 战斗：行为树与姿态

同伴的战斗行为树（"存活、写定、指令、避险、职责、跟随"六层）、四种姿态、九条战术指令与每名同伴的人格权重以 [companions_and_party.md](companions_and_party.md) 为准；它们本身就是规则 AI，模型不参与每 tick 决策（[npc_society_ai.md](npc_society_ai.md) 第 10.1 节）。
现有 `src/systems/party/ai.ts` 的 `tickMember`（跟随队形、协同攻击、治疗者治疗、坦克嘲讽、服从队伍命令、倒地后战斗结束时起身）是这棵树的实现雏形，按第 2.2 节的行为树原语补齐六层。

内置 AI 在这里只负责一件事：战斗之间的 `companion.tactics`（有模型时模型可以改，无模型时由下式决定），即为每名同伴选下一场战斗的姿态与开场意图。

```
姿态得分 = 人格权重（同伴目录给出的该姿态亲和）× 3
         + 队伍状态项：全队生命与资源充足时偏进攻的姿态 +2；药剂与法力不足或连续两场苦战时偏稳守的姿态 +2
         + 保护项：玩家以不足一半的生命进入战斗时偏护卫的姿态 +3
         + 敌情项：已知敌人明显较弱时偏进攻 +1，已知有首领或精英时偏稳守 +1
         + 惯性：维持上一场的姿态 +1
玩家下达过的姿态与战术指令优先于本式；本式只在玩家没有指定时生效
```

姿态的对应与亲和取值以 [companions_and_party.md](companions_and_party.md) 第 7.4 节为准：偏进攻即"协助"（亲和 = 进攻权重 / 100），偏稳守即"原地"（谨慎 / 100），偏护卫即"跟随"（护人 / 100）；"被动"只在玩家下令时生效，内置 AI 不自动选它。

开场意图（第一个动作）随姿态：偏进攻者先手控制或爆发，偏稳守者先上增益，偏护卫者先站到玩家身边。

### 11.2 战斗外的自主

| 行为 | 规则 | 台词 |
| --- | --- | --- |
| 个人差事 | 营地或城镇休整时，按人设卡的追求表插段（希雅去打猎、罗恩写家书、奈拉去"见个朋友"）；离开不超过 2 游戏小时 | `bark.*` 的本人语境 |
| 主动建议 | 触发表：生命或补给低时建议休息；进入危险区域前按本人知识提醒；玩家准备做违背本人立场的事时劝阻；每游戏小时至多一次 | `topic.gen_advice` 的本人版本或 `react.*` |
| 拒绝命令 | 玩家的命令或选择带有道德标签（杀降、抢劫平民、背约、亵渎、伤及孩子），与本人"必须保持""绝不会做"（[characters.md](../../30_story/characters.md) 每张卡）映射的标签冲突时，同伴拒绝执行并说明 | `react.declined`；连续三次羁绊下降并可能离队（D-073 的重伤退场与离队是两回事） |
| 过度执行 | 解读倾向高的同伴（狂热追随者型）把玩家的随口一句扩写成行动，规则同第 12.4 节，行动限于本人能做的范围 | `interp.*` 模板 |

### 11.3 队内闲聊

队内闲聊是多人往复的短剧，存放在台词包 `ln_party`，每段一个编号（槽位 `party.<exchangeId>`），由台词目录撰写；本文规定触发与选择。

| 字段 | 说明 |
| --- | --- |
| `cast` | 出场同伴（1 到 3 人），全部在队才可触发 |
| `trigger` | 触发种类（下表） |
| `when` | 台账语法条件（幕、旗标、羁绊值、地点、事件） |
| `lines` | 2 到 6 句，按说话者排列；可插一个玩家可选的回应点（两到三个选项，各自影响羁绊） |
| `once` | 一局只出现一次（默认）或可重复 |
| `priority` | 剧情相关的闲聊高于泛泛的闲聊 |

| 触发种类 | 时机 |
| --- | --- |
| 进入地点 | 第一次进入某地区、迷宫、城市 |
| 事件之后 | 首领战、开门、重要 NPC 死亡、纷争结局、认知桥段（例：罗恩又被当成喝醉了） |
| 行进 | 区域图行进途中，每 30 游戏分钟行程至多一段 |
| 营火 | 夜间宿营，每晚 1 到 3 段；营火时玩家可点话题与同伴单独聊 |
| 关系 | 两名同伴的关系越过阈值（结怨或和好） |
| 幕次 | 每幕开头与结尾的回顾 |

选择：在满足条件的闲聊里按 优先级 × 新鲜（未出现过 1）× 与近事的相关 取最高；战斗、对话、过场会打断，被打断的闲聊在下一次合适时机从头再来一次，第二次被打断则作废。

### 11.4 同伴的台词结构

同伴的台词包至少 200 句，另加 `ln_party` 里与本人有关的闲聊。第 7.8 节规定了必须由本人包提供的槽位；同伴专有的部分是：每幕一组的 `acts` 覆盖、个人线全部任务阶段、战斗吠叫、拒绝命令的 `react.declined` 变体（按道德标签用 `when` 区分）、重伤退场与归队的 `react.*`（`ally_down` 的本人版本与归队问候）。

## 12. 城建官员

### 12.1 决策管线

官员的管线（[city_building.md](city_building.md) 第 7.4 节）不变：感知摘要（本领域仪表盘）、领域意图菜单、内核校验（职权、预算、法典）、规则执行、回执。现有 `src/systems/city/officials.ts` 的 `utilityAction` 是每个领域各自一组规则，内置 AI 在其上加一层全聚落调度，借鉴开源研究的"目标列表加优先级加结果阻断"（[city_builders.md 第 4.5 节第 5 条](../../10_research/open_source/city_builders.md)）。

### 12.2 全聚落目标调度

```
每游戏日一次（错峰到各聚落）：
  收集全部可激活目标：各领域官员提出的目标 + 玩家的常设命令与政策卡 + 危机目标
  每个目标刷新优先级 = 领域基础 × 紧迫度 × 主官能力 /100 × 理念偏好
  按优先级降序（同优先级按目标编号）依次执行：
     结果"跳过"：下一个
     结果"缺材料"：本聚落后续的建造类目标全部跳过，记"需要材料"进请示队列
     结果"已开工一项建造"：本日停止开新的建造
  最后刷新税率、配给与升级许可
```

### 12.3 领域效用

| 领域 | 主要意图 | 关键考量 |
| --- | --- | --- |
| 粮务 | 开垦、调配给、存粮、买粮 | 粮仓天数（低于 15 天急升）、季节、人口增长 |
| 工务 | 建造、修路、维修、区划内选址 | 住房缺口、损坏建筑数、材料库存、主官能力 |
| 治安 | 排班、拘押、调解、巡逻 | 治安指数、近期犯罪、纷争热度 |
| 民政 | 迁入、医护、调解纷争、安置 | 幸福、病人数、请愿数 |
| 商务 | 调价、开集、商路、汇兑、征税 | 市场缺货、商路收益、税收与民心的平衡 |
| 军务 | 征兵、修防、操练、调守军 | 威胁、守军缺口、士气 |
| 教化 | 学堂、节庆、信仰场所、编年 | 凝聚、教化缺口、节庆周期 |
| 研究 | 工艺、魔导、澱 | 研究队列、材料、澱的风险 |

**主官的人格**（`OfficialTraits`）：能力乘该领域意图的成功率与效率；主动性决定"不等请示就做"的意愿；理念（秩序、争斗、交易、生命、记录、门）给相应意图加分（例：交易派的商务官偏好开商路与加征商税，生命派的粮务官偏好赈济）；野心与廉洁进入偏航与腐败检定。

### 12.4 过度解读链

智将型部下与狂热追随者（[reputation_and_cognition.md](reputation_and_cognition.md) 第 9 节）的解读在无模型时由模板表生成：

| 步 | 规则 |
| --- | --- |
| 触发 | 玩家对解读者说话（自由输入或选项）、下命令、或在其面前做显著的事；解读者的解读倾向超过阈值 |
| 取材 | 意图分类器给出玩家这句话的意图与实体（例：`small_talk` 加地名实体"北坡"）；世界上下文（近期威胁、地图、在建工程） |
| 生成 | 从解读模板表 `interp.<链>` 取一条链：每条链 2 到 3 层（例："风景好"到"要在此筑城"到"要防北边"），每层带前置（地点类型、威胁方向）与拟行动 |
| 行动 | 拟行动只在解读者职权内（P2 以内）；P3 等玩家确认；每人同时至多 2 个活跃解读；每地区同时至多 3 条解读链 |
| 回应 | 玩家可默认、追问（看推理日志）、纠正；纠正后面子受损，顽固或崇拜型有一定概率"再解读"（"大人这是在考验我"），每次纠正降低该概率；连续被纠正三次，本幕解读倾向减半 |

### 12.5 请示与自主处理

官员自行处理的上限 = min(职权等级, 1 + floor(A / 25))（A 为聚落自治度，[city_building.md](city_building.md) 第 8.4 节）。超出上限的意图进入玩家的请示队列，附官员的提议与理由（来自动机列表）；玩家不处理时，官员在期限到时执行"最保守的合法选项"（不作为或最小代价的那一项）。

### 12.6 偏航与腐败

- 偏航：每游戏月检定一次，条件与风险式按 [city_building.md](city_building.md) 第 8.4 节；偏航的官员把本人的议程加进目标列表（加税自肥、结交外势力、压制某族），权重 = 野心 × (1 − 忠诚 /100)。
- 腐败：握有审批权的职位按（1 − 廉洁）× 审批量 ×（1 − 监察覆盖）的概率寻租；结果是预算漏损与黑市活跃，可经账房审计、监察署或传闻发现。
- 将领的偏航（追击过深、私下议和）用同一检定。

### 12.7 汇报与抱怨

- 请示、周报、战报、告示由 `doc.*` 模板按官员的说话指纹生成。
- 抱怨：玩家亲手微操某领域过多（一游戏周内直接命令超过 5 次）时，主官说一句抱怨（维尔纳的"那你来当村长"）；用 `react.*` 中本人的抱怨句，每人每游戏周至多一次。

## 13. 叙事导演规则表

### 13.1 张力计

张力计以 [goddess_gm.md](goddess_gm.md) 第 8.2 节的六项输入为准（战斗压力 0.25、威胁临近 0.15、社会紧张 0.20、推进停滞取反 0.20、资源压力 0.10、神域压力 0.10），每游戏小时计算并平滑。
现有 `src/systems/director/tension.ts` 的 `WEIGHTS` 只有四项（战斗、威胁、社会、停滞），实现时补齐资源压力与神域压力两项并按上表重设权重。目标区间按幕拍与场景（落地 30 到 50，暗面 50 到 75，高潮 75 到 95，拉远 40 到 60；门内庭院与城镇休整下限再降 15）。

现实时间写成的条件按 1 倍速折算为 tick（D-079 AQ-19）：20 现实分钟为 24000 tick，1 现实小时为 72000 tick；加速时按 tick 计。

### 13.2 规则表

导演就是一张规则表（第 2.5 节），`firstMatch` 求值，每游戏小时一次。菜单项（`div_dir_*` 共 12 项，各自的前置、效果、冷却与神力）以 [catalog_goddess_interventions.md](../content/catalog_goddess_interventions.md) 第 2.8 节为准；本表只规定何时开放、开放什么。

| 序 | 条件 | 动作 |
| --- | --- | --- |
| 1 | 有必达的台账条目到期未交付 | 由执行者在预设载体与地点交付（不经导演打分） |
| 2 | 玩家处于过场、对话、交易、战斗中 | 本小时不做任何事 |
| 3 | 写定巧合节点到时（目录第 4 节，第一幕一到两次、第二幕两次、第三幕两次） | 按节点执行同一菜单项，时机由节点决定 |
| 4 | T 高于区间上限已持续 12000 tick（1 倍速 10 现实分钟） | 开放喘息：类别为"喘息"、前置成立、冷却已过的菜单项（安全的宿营地、过路商人、同伴闲谈、节拍推迟、医者路过），按第 13.3 节选一项 |
| 5 | T 低于区间下限已持续 24000 tick（20 现实分钟），且 36000 tick 内未发过巧合 | 开放巧合：类别为"巧合"、前置成立、冷却已过的菜单项（旧识路过、传闻抵达、失物与线索、送错的文书、天气转折、敌方的疏漏、林子里的动静），按第 13.3 节选一项 |
| 6 | 有"已解锁未交付"的非必达台账条目，距上次重大揭示已过 72000 tick（约 1 现实小时） | 在可用载体中选一个交付（打分同第 13.3 节，缺口项取 1） |
| 7 | 有多个合格的动态事件模板 | 选与当前张力缺口方向一致的一个 |
| 8 | 同一地区同类喜剧桥段今日已触发 | 后续同类桥段降为背景对话（[reputation_and_cognition.md](reputation_and_cognition.md) 第 4.5 节） |

约束（任何一行都不得违反）：不改变战斗结果，不杀死或救下写定角色，不交付未解锁的揭示，不发放超出当前幕阶的物品；每次巧合在世界上留下一缕"命运丝"，神力记在莫伊拉账上。

### 13.3 菜单项打分

```
张力缺口 = (区间下限 - T) / 区间下限            开放巧合时
         = (T - 区间上限) / (100 - 区间上限)      开放喘息时
得分 = 张力缺口 × 前置满足度 × 数据权重 weight          （目录第 2.8 节的基本式）
     × 新鲜系数（距该项上次使用超过其冷却的两倍为 1.2，否则 1）
     × 叙事契合系数（与玩家进行中的任务、纷争或未交付条目相关为 1.3，否则 1）
同分按菜单项编号排序；包装（人物、地点、一句台词）从开放菜单附带的包装素材里按命名子流 director.pick 抽取
```

现有 `pickItem`（数据权重加 0 到 0.5 的抖动）按上式实现：不加抖动，同分按编号；菜单数据补"关联"字段（与哪类任务、纷争、台账条目相关）。

### 13.4 与莫伊拉的私心隔离

导演规则表不读莫伊拉的私密目标、神之档案、诸神关系与筹码（D-035）；她的神务规划（第 8 节）照常运行，但不能选导演菜单项。有模型时，`director.pick` 的模型只在本表选出的合格项里决定包装（人物、地点、一句台词），无模型时包装取菜单项的预写叙述。

## 14. 质量标准

### 14.1 台词量与重复率

**最低台词量**（总量由 [catalog_dialogue_lines.md](../content/catalog_dialogue_lines.md) 负责，槽位结构见第 7.8 节）：

| 说话者 | 最低句数 | 本文另要求 |
| --- | --- | --- |
| 女神（每位） | 250 | 第 8.8 节的槽位结构；锚点与写定神行全部预写 |
| 同伴（每人） | 200，另加 `ln_party` 里的队内闲聊 | 第 11.4 节 |
| 核心 NPC（L1，每人） | 80 | 第 7.8 节 |
| 其余有名 NPC（每人） | 30 | 第 7.8 节 |
| 居民模板 `tpl_`（每个） | 20 | 第 7.8 节 |
| 群众吠叫池 `bark_`（每池） | 30 | 第 7.6、7.8 节 |

**重复率**：对一对"说话者、玩家"，取说话者对玩家说的最近 W 句（不含玩家主动重听的话题），重复率 = 1 − 不同句数 / W。

| 说话者 | 窗口 W | 重复率上限 |
| --- | --- | --- |
| 女神 | 30 | 5% |
| 同伴 | 40 | 10% |
| 核心 NPC | 20 | 10% |
| 其余有名 NPC | 20 | 20% |
| 居民模板 | 10 | 25% |
| 吠叫池 | 同一人群单元 2 游戏小时 | 0（不重复）；同一地区每游戏日的重复句占比不超过 15% |

另两项：本人必备槽位的落空率（第 7.8 节的槽位最终取到通用层）为 0；有名 NPC 一场会话里来自通用层的句子不超过 15%。

### 14.2 一局里"活着"的可观测指标

全部指标都能从命令日志、事件流与台词历史算出，由自动玩家运行（第 17 节）汇总；阈值是无模型档的验收线。

| 序 | 指标 | 口径 | 阈值 |
| --- | --- | --- | --- |
| 1 | 主动搭话 | 玩家在某城镇停留满 2 游戏小时的那些游戏日，L1 与 L2 主动搭话次数 | 每游戏日不少于 3 次 |
| 2 | 日程偏离率 | 有名 NPC 当日执行的非模板段 / 总段数 | 15% 到 40% |
| 3 | NPC 之间的互动 | 每个城镇每游戏日的互动次数；其中争吵占比 | 不少于 10 次；争吵不超过 20% |
| 4 | NPC 之间的关系变化 | 每个城镇每游戏日写入的关系记录（NPC 对 NPC） | 不少于 5 条 |
| 5 | 传闻的到达 | 玩家在城镇被目击的事迹，2 游戏日内有传闻副本的有名居民比例；到达邻镇的时间 | 不少于 50%；2 到 4 游戏日 |
| 6 | 认知弧 | 每 12 游戏周可辨识的"不信、误解、证据、跃迁"完整弧数；无证据跃迁数 | 不少于 4；无证据跃迁为 0 |
| 7 | 纷争自走 | 玩家完全不介入时，每条 Must 纷争走到合法结局（VS-08） | 全部；死锁为 0 |
| 8 | 女神的可见干预 | 每幕玩家可观察到的女神作为（神谕后果、神迹、征兆、硬币报价、巧合） | 第一幕不少于 3，第二幕不少于 6，第三幕起不少于 10；且不超过密度上限 |
| 9 | 记忆被提起 | L1 会话中出现记忆或日记槽位（`{memory}`、`{diary}`）的比例 | 不少于 20% |
| 10 | 经济活性 | 每个市场每游戏周的补货、调价与修正项事件 | 不少于 1 次调价；断货不超过 2 天 |
| 11 | 官员自主 | 自治度 ≥ 50 的聚落里，官员不经请示处理的日常决策比例 | 不少于 60% |
| 12 | 队内闲聊 | 有同伴在队时，每游戏小时的行进与营火闲聊；重复数 | 不少于 1 段；重复为 0 |

另有两项"不活"的反指标，任一命中即判失败：有名 NPC 在非日程活动上停留超过 2 游戏日（卡住）；任何决策请求在截止后 2 倍时长仍未关闭。

口径的落实（`tests/npc_alive_harness.ts`）：

- 指标 1 的"一图一小时三次"在开口那一刻计数，走过去而没说上话的不占名额。
- 指标 2 按"执行段"计：活动、地点或是否合模板任一变化就开一段，非模板段 / 总段数；只按小时计会把一次两小时的偏离算成两段。
- 指标 5 的邻镇时间取中位数：冷掉才偶然传到邻镇的传闻会把均值拖到阈值之外，不代表典型传播。
- 反指标"卡住"：有名 NPC 连续 2 游戏日没有一个小时处在日程层或需求层（一直被剧本、职责、主动或社交层占着）。

### 14.3 与模型档的体验差距

无模型档是完整体验，差距要量化并有上限：

| 方法 | 做法 | 验收线 |
| --- | --- | --- |
| 指标对照 | 同一组种子分别跑无模型与有模型（推荐档），比较第 14.2 节十二项指标的均值 | 每项无模型 / 有模型 ≥ 0.8 |
| 盲读评审 | 从两档各导出等量的会话、吠叫、日记、神谕与战报文本，打乱后由评审按"有趣、像这个人、前后一致、不重复"各打 1 到 5 分 | 无模型档均分不低于 3.5；与模型档的差不超过 0.7；"像这个人"一项差不超过 0.5 |
| 试玩问卷 | 无模型档试玩者完整通关后回答"这个世界是活的吗""NPC 记得我做过的事吗"（1 到 5） | 均分不低于 3.5 |
| 自由输入 | 带标注的试句语料（不少于 2000 句，覆盖 52 种意图与常见错别字、口语、繁体） | 非 `unknown` 的覆盖率不低于 85%；被分类句的正确率不低于 90% |
| 拒答体验 | 拒答之后给出可点的转移话题的比例 | 不低于 90% |

第 14.3 节的盲读与问卷在 M1、M3、M4 三个里程碑各做一次；数字进 [roadmap.md](../../60_production/roadmap.md) 的里程碑验收记录。

## 16. 性能预算

内核 20Hz，每 tick 50 毫秒。内置 AI 在目标硬件（与 VS-06 相同）上每 tick 平均不超过 2 毫秒，峰值不超过 6 毫秒；超过单 tick 预算的计算一律切片到多个 tick。

| 组件 | 节拍 | 单次上限 | 规模上限 | 切片 |
| --- | --- | --- | --- | --- |
| L1 大脑评估 | 每 200 tick，错峰 | 0.3 毫秒 | 14（含对话临时位） | 无需 |
| L2 大脑评估 | 每 600 tick，错峰 | 0.2 毫秒 | 30 | 无需 |
| L3 批量步 | 每 1200 tick | 每人 0.05 毫秒 | 400 | 分散到 60 tick |
| L4 人群单元 | 每 1200 tick | 每单元 0.02 毫秒 | 每地区 200 | 分散到 60 tick |
| NPC 之间的社交 | 每地点每 1200 tick | 每地点 0.1 毫秒 | 当前地区全部地点 | 分散 |
| 传闻传播 | 随接触 | 每次 0.02 毫秒 | 无 | 批量随社交 |
| 意图分类 | 每次玩家输入 | 1 毫秒 | 无 | 无需 |
| 台词选择 | 每句 | 0.2 毫秒 | 无 | 无需 |
| 女神日规划 | 每游戏日黎明，六位错峰 | 每位 15 毫秒 | 6 | 每 tick 至多 3 毫秒 |
| HTN 规划 | 采纳或重规划时 | 5 毫秒 | 无 | 每 tick 至多 3 毫秒 |
| 统治者季度规划 | 每季度 | 每国 10 毫秒 | 7 | 每 tick 至多 3 毫秒 |
| 官员调度 | 每游戏日 | 每聚落 5 毫秒 | 全部聚落 | 每 tick 至多 3 毫秒 |
| 导演 | 每 1200 tick | 1 毫秒 | 1 | 无需 |
| 兵团行为树（战斗中） | 5Hz，错峰 | 每兵团 0.05 毫秒 | 每方 32 | 每 tick 约四分之一兵团 |
| 英雄行为树（战斗中） | 20Hz | 每名 0.05 毫秒 | 8 | 无需 |

- 加速：按游戏时间计的节拍不变；按现实时间，内置 AI 每帧不超过 8 毫秒，超出时把离屏的 L2 临时按 L3 批处理执行，NPC 之间的互动只结算不出台词。
- 内存：只常驻当前幕与当前地区的台词包与话题，其余按需加载；`BrainTrace` 每人 32 条环形缓冲。
- 存档：台词历史存成"槽位哈希、句序号"的整数对，每对说话者至多 64 对；谋划与计划状态按行动者稀疏存放。
- 无头运行：自动玩家与批量模拟中内置 AI 占内核总耗时不超过 40%；整局无头运行在持续集成机器上单种子不超过 45 分钟。

// 行为树（第 2.2 节）

## 20. 风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 台词量巨大 | 数百名 NPC 的台词写不完、写得千篇一律 | 回退链与分层包让下限可控；L1 与同伴优先；开发期可用模型离线起草台词池，人工审校后作为内容数据发布（[ai_architecture.md](../../50_tech/ai_architecture.md) 第 9.5 节） |
| 千人一面 | 同阶层的人说同样的话 | 说话指纹、人格乘数、角色子树、心情与地点偏好、重复抑制、通用层占比上限 |
| 意图误判 | 玩家说的话被答非所问 | 语料与混淆矩阵回归；低置信度走转移话题；命中泄露签名时宁可"不知" |
| 剧透 | 预写台词或拒答泄露未解锁真相 | 台账过滤对预写同样生效；泄露与禁名扫描；误导只用误导表版本 |
| 太聪明或太笨 | 统治者或将领碾压玩家，或一触即溃 | 难度只调接受线、规划深度与失误率，不调数值；平衡以无模型档为基线 |
| 确定性被破坏 | 回放不一致 | 命名子流、曲线查表、平分规则、守卫测试；条件 A 与 B 的哈希一致断言 |
| 性能 | 城镇人多时卡顿 | 错峰与切片；性能预算进持续集成；加速时自动降档 |
| 两档行为分叉 | 有模型时与无模型时平衡不同 | 同菜单、同闸门、同数值；模型只换选择与措辞 |
| 越约显得生硬 | 女神"为了凑证据"越约 | 保底只靠写定窗口里本来就会发生的动作；越约是否成立取决于条件，玩家可以阻止；动态越约只在目录的指标越过阈值时出现 |
| 维护成本 | 数据表多、互相引用 | 编辑器表单与即时校验；内容校验进数据门；规则覆盖报告找死行 |
