## 0. 一页结论

1. **名单**：主要同伴 13 人（夜羽、希雅、罗恩、奈拉、欧拉、卡西安、玛莎、赛琳、陆辰、白石结衣、艾登、马库斯、萨莎），随行同伴 10 人（人物目录的人才与诸国可招募者），
   从者（夜羽与经契约之门缔结的从兽、人形从者），兽伴（半契）。只当将领或官员的盟友另列，不进个人队伍。九职能都有可随队的人，各职能在哪几幕出现见 2.6。
2. **队伍**：随队位第一幕 3、第二幕起 4（玩家加四人，夜羽随队时占一位）；兽伴一只另计；大迷宫与写定团战可编"团"（玩家加至多 9 人）；
   任职（官员）、统兵（将领）、休养与随队互斥。
3. **等级**：同伴的等级就是铭录等级。随队时任务与探索经验与玩家同额、击杀经验按经典组队分配（玩家所得不减），落后 3 级以上加倍、8 级以上三倍；
   不过关就卡在关前一级（五道关），过关靠各人的个人线与事迹；离队时得一半经验，并在每幕开始时至少升到角色设定集写的该幕锚点。
4. **羁绊与信任是两个量**：羁绊值是同伴入队后和玩家一起经历出来的量（0 到 100，记在 party 切片），分六级；日常来源只能推到下一道"羁绊关"（60、80、90）之前，过关靠个人线；
   十六扇羁绊之门、九条羁绊事迹、羁绊合技都挂在羁绊上。人物对玩家的信任 `trust.<id>` 是关系系统对每个人物都有的态度，管招募、对话与台账。
5. **战斗**：行为树按"存活、写定、指令、避险、职责、跟随"六层；四种姿态加九条战术指令；每名同伴有一组人格权重进树，无模型时性格照样看得见。
6. **重伤退场（默认）**：倒地不是死；队伍溃败、致命一击或战场阵亡时重伤退场，到门内庭院休养 1 到 4 个游戏日（基准 2 日）后归队。
   **铁人（开局可选，开局后只能关不能开）**：上述情形都算死亡，进泉畔期；合法复活每人一生一次；"护命期"内的写定角色仍按重伤退场处理。
   **剧情之死**两档都有，只有渡魂之门能拉回。
7. **将领**：千军之门后同伴可转将领，档案字段（统帅、战术、勇武、鼓舞、主动、忠诚、特质）由等级、潜质、人格与羁绊推出；启才之门把潜质写实。
8. **个人线**：每名主要同伴四段加终段，钩子 `PL-<id>-<段>`；任务目录给每段登记 `q_` 编号并在条目里写 `hook`，本文只引用钩子。
9. **台词需求量**：约 3,440 句加 200 条吠叫（第 10 节），全部交[台词目录][dlg]。
10. **两种驱动**：模型只提议台词与反应类别；信任变化、战斗、招募、离队全部由内核按表结算；无模型时用话题图与台词包。

### 2.5 招募的方式

| 方式 | 适用 | 规则 |
| --- | --- | --- |
| 剧情 | 夜羽、罗恩，以及分幕写定加入的人 | 场景结算时写 `companion.<id>.recruited` |
| 邀请 | 主要同伴与多数随行同伴 | 条件满足后，对话里出现"跟我走"；对方的回答由内核按条件与羁绊裁决（模型只写措辞） |

### 3.3 编成规则

- **职责建议**：守一、医一、两名输出或一名输出一名辅助（[迷宫 1.4][dgn]）；界面给出"队伍缺什么"的提示，不强制。
- **不同队**：以下组合在某些时段拒绝同队（对话说明理由，不是系统报错）：
  - 卡西安在信仰危机结算前与夜羽（他视她为异端）；
  - 赛琳归附前与欧拉（她会依规程拘捕）；
  - 第四幕奈拉身份暴露后、抉择结算前，奈拉与希雅（希雅不肯）。
- **张力**：其余关系不好的组合照样能同队，只是会触发拌嘴（第 10 节）与少量羁绊变化（第 8.4 节）。
- **阵型**：同伴自动按职责排位（守在前、远程与治疗在后）；玩家可在战斗外选三种站位预设：楔、环、散。
- **过门**：行路之门初阶只能带一名随行，进阶带整支小队加一匹坐骑（[千门 15.4][tdr]）；回门符带 20 码内的随队同伴（[千门 16][tdr]）。
- **庭院访客**：随队与候命的同伴都在庭院受邀者名单内；有页者进出庭院，页显示"所在不明"（[城建 2.5][cb]）。

## 4. 等级与成长

### 4.1 基本规则

- 同伴的等级就是铭录等级（D-069），与玩家的历练等级用同一条标尺；鉴定读得到（夜羽例外：残页，显示"？"，D-052）。
- 同伴的战斗数值按其等级与职能计算，命中惩罚、威压等规则与 NPC 相同。

### 4.2 经验

| 规则 | 内容 |
| --- | --- |

| 击杀 | 每名随队同伴按魔物对其自身等级的经典单人值，乘经典人数加成（`groupXpBonus`：1、1、1.166、1.3、1.43）再除以随队同伴数（[成长 3.3][prg]）；玩家的击杀经验照单人值，不受影响 |

### 5.1 槽位与熟练

| 槽 | 数 | 说明 |

### 5.3 换装

- 同伴的装备从玩家的背包与庭院仓库里换；同伴自己不买东西。
- "交给他们自己挑"开关：开启时，同伴每次回到庭院或旅店，从仓库里按自己职能的属性权重换上最好的一件（确定性：同分取物品 ID 字典序），
  玩家锁定过的槽不动。无模型时同样可用。
- 送礼与装备是两回事：送出的礼物进同伴的私人物品，不进槽位（礼物规则见 8.4）。
- 同伴是有页者，可以接受女神的加护与附物加护；附物加护物品对同伴照常生效。

## 7. 战斗行为树与指令

### 7.1 行为树

同伴的大脑是一棵行为树（D-068），复用现行 `src/systems/party/ai.ts` 的 `tickMember` 骨架，按下列优先级自上而下：

| 层 | 节点 | 内容 |
| --- | --- | --- |
| 1 存活 | 保命 | 生命低于"后撤线"（人格的谨慎决定：25% 到 40%）且不是守：后撤到治疗者身边，用保命技能 |
| 2 写定 | 场景动作 | 分幕写定的站位、台词、动作覆盖一切（例：第五幕夜羽恢复巨鸦原形接住坠落的人） |
| 3 指令 | 玩家指令 | 当前生效的战术指令（7.3） |
| 4 避险 | 机制回避 | 地面危险区与首领的大技能预兆：离开范围；反应延迟按难度（7.5） |
| 5 职责 | 守 | 嘲讽正在攻击队友的敌人，面朝外，站在队伍前方 |
| 5 职责 | 医 | 治疗生命比例最低且低于阈值的友方；驱散；战斗复活（有技能时，冷却长） |
| 5 职责 | 输出 | 目标选择：玩家的目标、攻击治疗者的敌人、最近的敌人；保留打断技能给施法者 |
| 5 职责 | 控 | 打断读条；控制落单的小怪 |
| 5 职责 | 侦 | 夜羽：战斗外在"跟随"姿态下先行侦察，发现伏兵时报警 |
| 6 跟随 | 队形 | 按阵型预设回到自己的位置 |

### 7.4 人格权重

人格权重写在同伴数据里（`ai` 字段），是行为树各节点的参数，无模型时性格也看得见。权重不抽随机：同一局面同一反应。

| 同伴 | 进攻 | 谨慎 | 护人 | 服从 | 个人规则 |
| --- | --- | --- | --- | --- | --- |
| 夜羽 | 50 | 40 | 90（护短） | 70 | 玩家生命低于三成时，无视姿态对攻击玩家的敌人放鸦群；不进她害怕的地方（`avoid` 含 `fear`） |
| 希雅 | 70 | 30 | 70 | 80 | 孩子与遗民被攻击时，被动姿态也会出手；不射向逃跑的野兽 |
| 罗恩 | 30 | 70 | 80 | 100 | 后撤线 35%；嘴上说"不可能"，指令照做 |
| 奈拉 | 50 | 60 | 30 | 70 | 不站正面；优先打断与绕后 |
| 欧拉 | 10 | 60 | 90 | 80 | 先治孩子与平民 |
| 卡西安 | 20 | 50 | 70 | 90 | 不对放下兵器的人出手 |
| 玛莎 | 80 | 20 | 60 | 60 | 一场至多出一刀；出刀之后回到守势 |
| 赛琳 | 60 | 40 | 60 | 80 | 先审后刑：不攻击已力竭认输的人形敌人 |

"服从"决定个人规则能否压过玩家指令：服从 100 时个人规则只在没有指令时生效；服从低于 70 时，个人规则在指令之上（例：萨莎）。

**姿态亲和（供内置 AI 选姿态，[内置 AI 11.1][bai]）。** 玩家没有指定姿态时，战斗之间由内置 AI 为每名同伴选下一场的姿态；姿态亲和直接取上表的权重除以 100：

| 姿态 | 内置 AI 的读法 | 亲和 |
| --- | --- | --- |
| 协助 | 偏进攻 | 进攻 / 100 |
| 原地 | 偏稳守 | 谨慎 / 100 |
| 跟随 | 偏护卫（贴近玩家） | 护人 / 100 |
| 被动 | 不自动选择，只在玩家下令时生效 | 0 |

例：马库斯的跟随亲和 1.0、协助 0.4、原地 0.3，所以没有指令时他总是贴着玩家；萨莎的协助亲和 0.95，几乎总是冲在前面。

### 7.5 避险与难度

| 难度 | 同伴对危险区的反应延迟 | 同伴对首领大技能的规避 |
| --- | --- | --- |
| 简单 | 0.3 秒 | 总是规避 |
| 普通 | 0.6 秒 | 总是规避 |

大迷宫里标为"需要下令"的机制（[迷宫 1.4][dgn]），主队同伴只在玩家下令时执行；副队由战术 60 以上的将领带领时自动执行。

### 7.6 倒地与救起

- 倒地的同伴在战斗中可被战斗复活技能救起；战斗结束、全队 15 秒无人处于战斗时自动起身，带"倒地虚弱"`aur_st_downed_weak`
  与一处轻伤（倒地不是死，不经泉畔）。
- 倒地升级为重伤退场的条件见第 11 节。

### 7.7 战场层

同伴在战场上作为完整实体（A 层，[战争 2.1][rts]）出现时用同一棵树，职责层加入战场效用（光环覆盖、士气、破阵）；
指挥模式下玩家对英雄的命令就是第 7.3 节的指令加战场专用的"冲锋""守点"。

## 8. 羁绊

### 8.1 羁绊与信任

- 同伴的羁绊值（`bond`，0 到 100）记在 party 切片的同伴条目上，入队时从 0 起算；跨过 20、40、60、80、100 时另记一笔，之后羁绊回落，跨过的门槛仍算数
  （`src/systems/party/bond.ts` 的 `bondReached`）。羁绊不是世界状态变量，不镜像为旗标（[注册表 1.2][wsr]）。
- 人物对玩家的信任 `trust.<id>`（0 到 100）是 NPC 关系的信任维度（`src/systems/npc/relations.ts`，揭示台账 0.4），对每个人物都有，入队前后都在：
  招募条件、对话、台账线索与非同伴人物的缘钥读它。
- 两个量分开，是因为入队前的交情不等于一起出生入死：读信任的同伴门会在开局就开（例：希雅的人设起始信任），同伴的门要等真正同行之后才开。
- 门钥：同伴的缘钥用门钥类型 `bond`（`{ type: bond, companion, min }`，[千门 5.4][tdr]）；门目录与本文写在同伴身上的 `trust.<同伴 ID> >= N` 缘钥按羁绊导入；
  落在非同伴人物身上的缘钥读信任。旗标写法 `bond.<id>`、`bond.<id>.<N>` 是注册表里读信任的别名，新内容不写。
- 同伴系统的羁绊来源（同场击杀、礼物、营地谈话、剧情旗标 `bondFlags`）写羁绊值并发 `party.bond` 事件，带原因记录。
- 夜羽在 `data/npc/personas.json` 里补一张人格卡，信任键 `trust.yeyu`。

| 4 | 托付 | 80 到 89 | 个人线第 4 段；多数羁绊之门的门槛 |

### 8.3 羁绊关

日常来源（8.4 表里标"日常"的）只能把羁绊值推到下一道关之前：个人线第 2 段完成之前至多 59，第 3 段之前至多 79，第 4 段之前至多 89。
剧情与个人线事件不受此限。这样羁绊的深处一定来自一起经历过的事，而不是礼物（[事迹目录 2.10][dt]"传闻不能刷"的同一精神）。
羁绊值入队时从 0 起算，所以每名同伴面对的关都一样；入队前的交情留在信任里。

## 10. 队内闲聊与评论：台词需求量

### 10.1 台词的种类与触发

| 类 | 触发 | 节流 |
| --- | --- | --- |
| 区域与地标 | 进入地区、看见地标 | 每名同伴每地区一次 |
| 事件评论 | 任务节点、玩家的抉择、世界事件 | 只有在场或事后得知的同伴说 |
| 战斗情境 | 开战、击杀首领、倒地、被救起、低血、玩家开了大招 | 每名同伴 8 秒一次 |
| 营地谈话 | 入睡前选一名同伴说话 | 每晚一次；话题来自话题图（15 节） |
| 门的评论 | 玩家开门、闭门、开禁门、门失灵 | 每扇门至多一名同伴评论 |
| 礼物反应 | 送礼 | 喜、可、拒三档 |
| 名册事件 | 招募、离队、重伤、归队、复活、渡回、冷离、和解 | 每次 |
| 红线对峙 | 8.5 | 每次 |
| 对话对与多人闲聊 | 两到三名同伴同时随队；进入地点、事件之后、区域图行进、营火、同伴关系越过阈值、幕的开头与结尾 | 探索中每 10 现实分钟至多一段；行进途中每 30 游戏分钟行程至多一段；营火每晚 1 到 3 段 |
| 任职与统兵报告 | 官员与将领的事务报告 | 按事件 |

**全局节流**：探索中每名同伴每 3 现实分钟至多主动说一句；过场与对话中不插话；同一时刻至多一名同伴说话。
**优先级**：剧情写定、红线、个人线、事件评论、门的评论、区域、闲话。
**揭示**：任何台词都过揭示台账与禁名过滤；台账未解锁的内容不进入台词池。
**回应**：一部分闲聊带玩家回应（两到三个方向），回应写信任 +1 或 -1（8.4）。
**多人闲聊的结构**：以[内置 AI 11.3][bai]为准。每段存于台词包 `ln_party`，一个编号（槽位 `party.<exchangeId>`），字段 `cast`（出场同伴 1 到 3 人，全部在队才触发）、`trigger`（上表的触发种类）、
`when`（台账语法条件）、`lines`（2 到 6 句，按说话者排列，可插一个玩家回应点）、`once`、`priority`；选择按优先级乘新鲜度乘与近事的相关取最高，被打断的闲聊下一次合适时机从头再来一次，第二次被打断则作废。

## 11. 重伤退场、死亡与铁人（D-073）

### 11.1 四种结果

### 11.2 重伤退场的条件

| 条件 | 说明 |

| 战斗以失败结束时仍倒地 | 玩家退回门内，或用回门符撤走而同伴倒在原地 |

## 12. 将领转化

### 12.1 何时

- 第二幕同行之门之后，同伴可以带一支小队（[D-045][dlog] 的小队级），这时仍可随队。
- 第三幕千军之门之后，同伴可任将领，统兵期间不随队（3.2）；第五幕战线按授权书分配将领（[战争 7.3][rts]）。
- 同伴的将领档案（[战争 4.4][rts] 的 `General`）在任命时生成，之后随等级、潜质、立名与羁绊更新。

### 12.2 档案字段的来源

| 字段 | 公式 |
| --- | --- |
| 统帅 `command` | 潜质档基（S 70、A 55、B 40、C 25、无 15）+ floor(等级 / 4)；启才之门写实统帅潜质后 +20；上限 100 |
| 战术 `tactics` | 人格的战术基 + 谋士潜质（S 25、A 15、B 8）+ floor(等级 / 6) |
| 勇武 `valor` | min(100, floor(等级 × 1.5) + 职能修正：战士与圣骑士 +10，猎人与盗贼 +5，其余 0) |
| 鼓舞 `rally` | 人格的鼓舞基 + 立名之后 +10 + 每个传颂级称号 +5 |
| 主动 `initiative` | 人格的主动基 + 羁绊级 × 5 |
| 忠诚 `loyalty` | = `trust.<id>` |
| 特质 `traits` | 人格卡派生（下表） |
| 潜质 `potential` | 识才之门可见；启才之门写实 |

## 14. 后日谈命运表接口

后日谈的"同伴"一层（[六幕 12.1][a6] 第 7 层）为每位存活或有结局的主要同伴写一条。本系统向后日谈生成器提供输入记录，默认走向取自
[六幕 11.1.5 与 11.5b][a6]，模板编号归[过场与结局目录][cut]。

```
CompanionFate {
  id
  status: 'alive' | 'dead' | 'left' | 'hostile' | 'missing'
  statusAct                         // 状态在哪一幕定下
  cause?: 'story' | 'ironman' | 'consumed'      // 死因：剧情之死、铁人战殁、灵魂被耗尽
  ferried: boolean                  // 被渡回过（逆泉）
  bondLevel: 0..5                   // 羁绊级
  plStage: 0..5                     // 个人线进度
  roles: { office?, general? }      // 最后的官职与统兵
  generalRecord: { battles, heldUnaided }
  keyChoices: string[]              // 与此人相关的已写入标记，例：beast_king、selene_stance_4、cassian.path、nera.choice
  titles: string[]                  // 传颂级称号
  handover: string[]                // 离手时交给此人的门（千门 20.2）
  lastPlace
  memoryRef                         // NPC 记忆摘要的引用（AI 运行时）
}
```

| 规则 | 内容 |
| --- | --- |
| 覆盖 | 每名主要同伴在每种结局（离手的温柔与艰难、离手·未竟、新神、五种某神之治、门之复辟）各有至少一条模板；回收结局一律"不明" |
| 选择 | 结局类型 × 同伴 × 条件（`keyChoices`、`status`、`ferried`）选模板；同一同伴多条命中时取条件最具体的一条 |
| 插槽 | 地名、官职、数字、称号、交给他的门；插槽内容只取输入记录里的事实 |
| 显著度 | 主要同伴全部入选；随行同伴按显著度（状态变化幅度加羁绊级）取前三 |
| 约束 | 已死者不写死后的事；被渡回者带"逆泉"的写法；离队者写他离开之后的那一方；不替玩家决定情感归属与去留（[角色 2][chr]） |
| 无模型 | 规则按条件选模板、填插槽（D-010）；有模型时模型只在模板含义之内润色，不改插槽里的事实，生成后由内核逐条比对（[六幕 12.4][a6] 第 8、9 条） |

## 15. 两种驱动下的人格表现

| 战斗 | 不参与：战斗只由行为树驱动 | 行为树（第 7 节） | 人格权重进树；同一局面同一反应 |
| 闲聊与评论 | 模型按人格卡、台账切片、近期记忆即兴；台词首句可流式显示 | 话题图选话题，台词包按条件选句，模板插槽填名字与地点 | 节流与优先级（10.1）；揭示与禁名过滤 |
| 营地谈话 | 模型对话，玩家可自由输入 | 话题图：每名同伴每幕 4 个话题节点，每个节点 2 到 3 个回应方向 | 回应只产生"反应类别"（相合、相冲、红线、中性），信任变化由内核按 8.4 表结算 |
| 礼物反应 | 模型说一句 | 喜、可、拒三档台词 | 信任按 8.4 结算 |
| 个人线 | 模型在任务台词的锚点含义内即兴 | 任务目录的预写台词 | 段的完成条件由内核判定 |
| 招募与离队 | 模型写措辞 | 预写措辞 | 是否加入、是否离队由内核按条件裁决，模型不能改变结果 |
| 记忆 | AI 运行时的长期记忆；内核存有界日记（D-079 的 AQ-07） | 只用内核的有界日记与标记 | 记忆不得引入台账未解锁的真相 |
| 红线 | 模型写对峙的措辞 | 预写对峙场景 | 触发与后果由内核结算 |
| 降级 | 模型连续失败时逐级回到规则（D-036） | 不适用 | 无模型档是完整体验，每个里程碑硬性验收（D-010） |

**人格在无模型时如何看得见**（每名主要同伴都要满足）：

1. 行为树里的个人规则（7.4）至少一条在第一次随队的那场战斗里就会出现。
2. 口头禅按人格卡的频率出现在台词包里（夜羽的"门把手"、罗恩的"不可能"、玛莎的"喝你的酒"一类）。
3. 话题图的话题与人格卡的目标、恐惧对应；秘密只在台账解锁后才进入话题图。
4. 称呼演变按人格卡（例：夜羽第一、二幕叫"门把手"，第三幕起叫"开门的"，第六幕送出第七封信时第一次叫玩家的名字），由标记驱动，两种驱动一致。

## 17. 数据结构与验收

### 17.1 内容：`CompanionDef`（`data/party/companions.json`）

```
CompanionDef {
  id, name, title, personaId          // 人格卡 ID（data/npc/personas.json）
  tier: 'main' | 'escort'
  classId, role, school               // 铭录职能、战斗定位、定流后的流派
  appearance
  recruit: { act, cond, mode: 'story' | 'invite' | 'hire', wage? }
  window: { from, to? }               // 可随队的幕
  anchors: Record<act, level>         // 4.3
  gates: { gate: 'settle' | 'temper' | 'name' | 'resolve' | 'beyond', cond }[]   // 4.4，cond 为台账表达式
  potentials: Record<code, grade>
  ai: { aggression, caution, protect, obedience, rules: string[] }               // 7.4
  avoid?: string[]
  likes?: { kinds?, items? }
  trustFlags?: { flag, equals?, amount }[]     // 现行 bondFlags
  values: { likes: string[], dislikes: string[], redLines: { cond, delta, hook }[] }
  personalLine: { hook, act, cond, deadline? }[]
  armor?: string                      // 护命期截止的标记（11.4）
  loss: { kind: 'leave' | 'betray' | 'death', cond }[]
  general?: { commandGrade, counselGrade, tacticsBase, rallyBase, initiativeBase, traits, variance }
  office?: Record<'food'|'works'|'civil'|'security'|'military'|'commerce'|'research'|'culture', number>
  signature?: string                  // 标志技能（技能目录 ID）
  talentLean: string[]                // 各道铭纹的人格偏好项（技能目录 ID，战斗系统 6.4）
  lines: { pack: string, barks: string }  // 台词包与吠叫池（台词目录 ID）
}
```

现行字段的去向：`level` 由 `anchors` 的第一项取代；`levelOffset` 删除（成长按第 4 节）；`bondFlags` 改称 `trustFlags`；`personality` 并入人格卡。

### 17.2 状态：`PartySlice`

```
PartySlice {

  raid?: string[]                     // 团的副队
}
Member {

  state: 'party' | 'standby' | 'office' | 'command' | 'resting' | 'away' | 'left' | 'spring' | 'dead' | 'hostile'
  order, tactic?                      // 姿态与当前战术指令
  xp, gates: string[]                 // 已过的关
```

### 17.4 内容校验

1. 每名同伴的 `personaId` 存在；`classId` 是九职能之一；`school` 属于该职能的三派之一。
2. 每个 `cond`、`gates.cond`、`loss.cond`、`armor` 引用的键已登记在 `data/registry/vars.json`（D-076）。
3. 每名主要同伴有五段 `personalLine`，钩子格式为 `PL-<id>-<段>`；任务目录里每个钩子恰有一个"段结"任务（跨目录校验）。
4. 锚点单调不降；锚点不越过该幕之前没有写定过关事件的关（例：罗恩的立名关事件在第五幕，第四幕锚点因此不超过 34）。
5. 护命期标记存在且在该同伴可能战殁之前可写入。
6. 每名主要同伴在 14 节的每种结局都有模板（跨目录校验，过场目录）。
7. 台词包覆盖 10.2 表的每一类（跨目录校验，台词目录）。
