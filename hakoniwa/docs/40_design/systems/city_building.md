## 0. 定位与硬约束

### 0.1 一句话

经营层让玩家从"门后的一间小屋"一路长成"一个国家的主人"，并在这条路上亲身体会诸神的难题：
**亲手管，还是放手让它自己长。**

### 0.2 服务的支柱

| 支柱                   | 本系统如何服务                                               |
| ---------------------- | ------------------------------------------------------------ |
| 从一人到一国（支柱 6） | 规模阶梯从门内庭院到首都，每一级都换一套操作颗粒度           |
| 活着的众生（支柱 4）   | 居民与官员是 AI，纷争由 AI 社会自然产生，结果以内核结算为准  |
| 诸神的棋局（支柱 5）   | 女神的灾害、价格、神谕以注册修正项进入领地；神殿是女神的眼睛 |
| 谨慎的强者（支柱 3）   | 门内庭院在神之视线之外，是秘密积累的私域；领地张扬会招来注视 |
| 离手（主题）           | 自治度贯穿全层，决定效率、抗风险与真结局                     |

### 0.3 硬约束（来自决策日志与总框架）

1. **同一张地图、同一个时钟。** 领地就画在 RPG 层的世界地图上，玩家可以走着进出自己的村子；
   领主视图只是同一时钟的加速与俯视（[`game_framework.md`](../game_framework.md) 第 6 节）。画面是 HD-2D 像素微缩场景（D-003）。
2. **居民分级推理（D-009）。** 官员与具名居民是 AI（L1 到 L3），普通居民是规则批量模拟的人口池（L4），不逐个调用大模型。
   依据：[`comparison_and_plan.md`](../../10_research/ai_npc/comparison_and_plan.md) 第 6.2 节；
   [`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.4 节的"群体层、个体层、表达层"三层结构。
3. **模型提议，内核裁决（D-007）。** AI 官员只能从枚举菜单里提意图；产出、消耗、伤亡全部由确定性内核结算。
4. **注册修正项（D-013）。** 女神的灾害、价格、天气、加护进入领地时，只能以"注册过的修正项"作用于有限的通道，
   显性或半显性、可追溯（修正项合同见 [`economy_and_trade.md`](economy_and_trade.md) 第 7 节）。
5. **防滚雪球。** 每类优势都有上限、递减或反制（第 13 节逐项审计）。
6. **每升一层都有委托。** 新规模解锁的同时解锁新的委托工具，避免经营压过主线与决策疲劳（第 9 节）。
   依据：[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.6 节与借鉴清单第 30 条。

### 0.4 不做什么

- 不做独立的城市模拟器：经营是主线的支持层，不是第二款游戏。
- 不让玩家给几千个居民逐个派活：L4 人口池只接受配额与政策。
- 不做"刷满所有建筑"的数值终点：建筑有维护、容量与互斥，扩张的边际收益递减。
- 不让大模型决定产出、伤亡或灾害强度。

### 1.3 规模上限与"换赛道"

- 每个阶段都有容量上限（地段数、行政容量、维护开销），超过上限的扩张效率递减（第 13 节）。
- 每进入更大的舞台，玩家原有的规模就相对变小：第三幕一个领地的年收入，只是第四幕一个国家的零头。
  这是资料里"换赛道的相对贬值"，也是本作"逐层拉远"在经营层的投影
  （[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 4.7 节）。

## 2. 门内庭院

### 2.1 正典定位

门内庭院是千门的第三项特性：门后的私人空间，起初是一间小屋和一小片园子，逐步扩展为仓库、修炼场、复活点、研究所，
后期是隐秘的城。【真相】它是雅努领域的残片（[`world_bible.md`](../../20_world/world_bible.md) 第 11 节）。
玩家死亡时"退回门内"，在庭院复苏（同上第 5 节第 9 条）。第一幕末的梦后，回廊里出现"门内庭院"这扇门（`story_outline.md` 第一幕拉远）。

力量体系的细则（[`power_system.md`](../../20_world/power_system.md) 第 9.6 到 9.8 节）本文照单全收：

- 庭院严格说是庭间之隙的一角，**在箱庭之外**；任何女神都看不进来。
- 只能经玩家的门、且须玩家允许才能进入；从者与伙伴可以被允许长期出入。
- 庭院里的灵素清澈无澱（澱度为清域），适合修炼、休养与研究；长期休养能缓慢消除玩家门中的淤塞。
- 时间与箱庭同步。
- 庭院经"庭院扩建之门"成长：小屋与园子、仓廪、演武场、研究所，后期是隐秘的城。【真相】每一次扩张也是雅努领域的一点复原；
  第四幕前后庭院边缘会出现玩家从未开过的回廊。
- 复苏的代价：时间、门疲、遗落、目击、在深澱以上死去时的澱回流（`power_system.md` 第 9.8 节）。

### 2.3 空间与扩展

- **庭格**（Courtyard Cell）：庭院的抽象容量单位，一个庭格约等于领地的一个地段。建筑占用庭格，借鉴洞府的
  `size_units` 抽象容量（[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.3 节）。
- **门息**（Door Breath）：庭院的供能。它来自门本身（雅努领域的残余），只供庭院内建筑使用，不能带出。
- 扩展靠"庭院扩建之门"（物钥与历钥的组合，`power_system.md` 第 9.9 节通例），其次才是材料；钱几乎买不到庭格。

| 扩展             | 钥（示例，具体见 `thousand_doors.md`）    | 庭格上限 | 门息 | 新增                                       |
| ---------------- | ----------------------------------------- | -------- | ---- | ------------------------------------------ |
| 初开：小屋与园子 | 第一幕末梦境（门内庭院）                  | 3×3      | 10   | 小屋、园子、小仓库                         |
| 扩建 I：仓廪     | 首次在庭院里救治同伴 + 木材 200           | 5×5      | 20   | 仓廪、晾架、第二间屋                       |
| 扩建 II：演武场  | 商契之门已开 + 一次险胜                   | 6×6      | 35   | 训练桩、冥想位、门扉（连商会仓库）         |
| 扩建 III：研究所 | 第三幕：与守门人阿什的一次长谈 + 一本古籍 | 8×8      | 60   | 书斋、秘仓、工坊位、门扉（连领地）         |
| 扩建 IV：隐城    | 第四幕：立国之门已开 + 遗民长老的信任     | 10×10    | 100  | 隐城街区、无名祠                           |
| 扩建 V（提案）   | 第五幕：众门环核心节点锁定                | 12×12    | 160  | 门路调度室（众门环的庭院一侧，第 12.3 节） |

- **代价**：每一次扩展都是开门，雅努的封印随之松动（[`world_bible.md`](../../20_world/world_bible.md) 第 11 节【真相】）。
  第三幕以后玩家知道这一点，"扩不扩庭院"因此也是后半程的抉择之一。

### 2.4 与领地的关系

| 关系                    | 规则                                                                                                                                                                                                                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 物资往来                | 经门扉进出，每扇门扉每天有吞吐上限（初值 50 单位/日，随庭院扩展到 300），超出部分必须走陆路。这条上限同时是套利审计的一项（[`economy_and_trade.md`](economy_and_trade.md) 第 5.5 节）                                                                                                                          |
| 人员进出                | 只有玩家、从者与"受邀者"能进；受邀者名单有上限（仓廪阶段 5 人，隐城阶段 200 人）                                                                                                                                                                                                                               |
| 产出归属                | 庭院产出归玩家个人账，入领地仓库视为"玩家直接投放"，计入依赖（第 8.2 节）                                                                                                                                                                                                                                      |
| 隐城居民                | 第四幕起可在庭院常住；他们不纳税、不出兵、不进市场，只在庭院内生产与研究                                                                                                                                                                                                                                       |
| 复活与指挥              | 玩家在庭院复苏后，可经门扉回到任意有门扉的聚落（受行路之门冷却约束）                                                                                                                                                                                                                                           |
| 灰烬流亡（`ash_exile`） | 第三幕灰烬防线失守时，领地焚毁大半，玩家与居民退入荒原深处与门内庭院，立国之门在荒原中开启（act3 第 7.4 节、act4 第 4.1 节）。此时庭院进入"庇护模式"：受邀者上限临时放开到全部流亡居民，代价是门息透支（庭院内生产几乎停摆）、每日泄密权重上升、雅努的封印额外松动；立国后庇护模式结束，居民迁回地上或留在隐城 |

### 2.5 神之视线之外

正典：女神只能经由信徒见闻、神殿、铭录、神谕对象感知箱庭；玩家无页，女神看不见玩家，只能靠目击
（[`world_bible.md`](../../20_world/world_bible.md) 第 5 节第 6 条、第 11 节）。庭院是雅努领域的残片，因此规定：

1. 庭院内发生的事不进入任何女神的观察投影；庭院内不能建神殿或神龛（无名祠除外）。
2. 信徒在庭院内祈祷，祷告不会抵达女神。
3. **页的异常**：有页者进入庭院时，其页显示"所在不明"（`power_system.md` 第 9.6 节）。莫伊拉读得到这个异常；
   同一个人反复"所在不明"，会在她的档案里累积成一条线索（经她的情报交易可能流向别的女神，[`goddess_gm.md`](goddess_gm.md) 第 7.6 节）。
4. **泄密**：受邀者离开庭院后，他们记得自己看到的东西。虔诚的信徒日后在神殿祈祷时，这段见闻可能按虔诚度加权进入女神视线。
   这是确定性规则：受邀者的虔诚度、在庭院停留的天数、看见的秘密等级决定"泄密权重"，祈祷时结算一次。
5. 推论：庭院适合藏遗民、做禁忌研究（澱、门、天穹），不适合把大量居民搬进去（每多一个人，就多一个可能开口、可能"所在不明"的人）。

### 2.6 防滚雪球

| 风险                             | 限制                                                                       |
| -------------------------------- | -------------------------------------------------------------------------- |
| 庭院变成无限仓库与无限产出       | 庭格与门息上限；庭院产出不受天灾但量小（每庭格日产约为同类领地地段的 30%） |
| 用门扉绕开物流                   | 每日吞吐上限；吞吐消耗门息                                                 |
| 把全部人口藏进庭院躲避神之视线   | 受邀者上限；泄密规则；庭院居民不产税、不出兵                               |
| 庭院物资随叫随到，让领地永远不缺 | 庭院投放计入依赖，压低自治度                                               |

## 3. 地图与布局

### 3.1 同一张世界地图

- 世界地图在数据上是一张俯视格网，RPG 层、经营层、战场层共用。分块沿用 [`geography.md`](../../20_world/geography.md) 第 7.1 节：
  区域（一组地块加一张节点式的区域图）、地块（一张连续可走的地图，96×96 到 192×192 格）、场景（室内、迷宫、战斗地图）。
  聚落是画在一个或多个地块上、被"宣称"的一片范围（聚落图），玩家可以从野外走进村口，也可以在领主视图里俯瞰它。
- 镇内按 1 格约 1 米画（同上第 7.2 节），建筑与人物比例可信；野外地块做视觉压缩。
- 领主视图与行走视图只是镜头与时钟速度不同，地段、建筑、居民是同一份数据。
- 美术侧：HD-2D 斜俯视镜头（默认俯角 36 度，方位可转）；建筑是带像素贴图的立体墙与屋顶，门洞、开窗、夜窗自发光；
  玩家所在或选中的建筑屋顶按有序抖动溶解掀开，外墙降为半高剖面露出室内
  （[`art_pipeline.md`](../../50_tech/art_pipeline.md) 第 2.6、5.6 节；
  [`my_ai_town_visual_and_client.md`](../../10_research/art_style/my_ai_town_visual_and_client.md) 第 2.7、4.9 节）。

### 3.2 地图数据三层

沿用 my_ai_town 的"一张地图喂三个读者"（同上第 4.1、4.10 节）。三层与 [`art_pipeline.md`](../../50_tech/art_pipeline.md) 第 5.1 节的
逻辑层、外观层、空间层一一对应；风格包与建筑外观在布局层（外观层），只有渲染器读，改外观不改玩法：

| 层     | 内容                                                                                                                                           | 读者                       |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 拓扑层 | 处所（驻留型：建筑与广场；穿过型：路段，带分钟数）、通道（连通与能力：步行、车、军队、视、听）、落脚点（到达点、操作位，操作位带活动与姿势族） | 内核、AI 题面、L4 批量模拟 |
| 布局层 | 格、地段、建筑外观与变体、道路折线、装饰                                                                                                       | 渲染器                     |
| 空间层 | 可走格、占地、操作锚点、路线                                                                                                                   | 寻路、摆放校验             |

好处：L4 人口池按拓扑图上的分钟数估算通勤与搬运，不跑逐格寻路；具名居民的题面只看到地点名与"含路程预计 X 分钟"
（[`my_ai_town_agents.md`](../../10_research/ai_npc/my_ai_town_agents.md) 第 6.4 节的可行性预计算）。

### 3.3 地段

- **格**：渲染与可走性的最小单位（1 格 = 1 米 = 16 像素，[`art_pipeline.md`](../../50_tech/art_pipeline.md) 第 1.3 节；`geography.md` 第 7.1 节）。
- **地段**（Plot）：建造的最小规划单位，暂定 4×4 格。聚落图由地段组成。术语注意：`geography.md` 的"地块"指一整张连续地图，
  本文的"地段"是地块里的建造格子，两者不要混用。
- 每个地段带标签：

| 标签   | 取值                                                                           | 影响                         |
| ------ | ------------------------------------------------------------------------------ | ---------------------------- |
| 地形   | 平地、林地、岩地、水边、湿地、坡地、荒原                                       | 可建建筑、建造成本、产出     |
| 肥力   | 0 到 3                                                                         | 农田产量                     |
| 资源点 | 无、木、石、矿脉、草药、灵脉、澱晶脉、灰石（荒原拾遗）                         | 采集建筑的前置               |
| 澱值   | 与 [`goddess_gm.md`](goddess_gm.md) 第 4.5 节同一标尺（0 到 800 以上，分六级） | 魔物、澱病、作物（第 12 节） |
| 归属   | 公有、私有（某户）、教会、商会、军用                                           | 谁能在上面建造               |
| 区划   | 未划、居住、生产、商业、宗教文化、军事、行政                                   | 城镇起生效（第 3.6 节）      |

### 3.4 摆放规则与可走性校验

所有布局来源（玩家亲手摆、AI 工务官规划、剧情预置、程序生成）都过**同一个确定性校验器**，失败时返回"机器码 + 人话原因"，
并在画面上给出证据（压暗不可用区、亮出可用格、描红挡路物、画出走线）。这是 my_ai_town 运行期摆道具检查的放大版
（[`my_ai_town_visual_and_client.md`](../../10_research/art_style/my_ai_town_visual_and_client.md) 第 4.5、4.8 节）。

| 代码         | 检查                                                                         | 玩家看到的话（示例）     |
| ------------ | ---------------------------------------------------------------------------- | ------------------------ |
| `bounds`     | 占地全部在聚落宣称范围内、在区划允许内                                       | 这里不在村子的地界里     |
| `terrain`    | 地形标签允许该建筑（矿井要矿脉、渔屋要水边）                                 | 这里没有矿脉             |
| `overlap`    | 占地加外扩不与既有建筑、道路、树石重叠                                       | 这里已经有木屋           |
| `road`       | 不压主路；压支路时要求同时改线                                               | 大路上不能盖房           |
| `entrance`   | 入口到达点落在可走格上，且离别的建筑入口 ≥ 2 格                              | 门口会被堵住             |
| `slot`       | 每个操作位锚点在建筑外、在可走格上                                           | 干活的人站不到跟前       |
| `reach`      | 入口经道路或可走格连通聚落中心（Dijkstra 可达）                              | 从村里走不到这里         |
| `keep_reach` | 放下之后，所有既有建筑仍然可达，任何通道宽度不小于 2 格                      | 这样会把粮仓围死         |
| `defense`    | 不在城墙线上（城墙另有规则）；不堵城门内外各 3 格                            | 城门口不能盖房           |
| `taboo`      | 浓澱及以上（澱值 ≥ 100）的地段只能建防御、采集与众门环建筑；神殿不能建在庭院 | 这块地的澱太重，住不了人 |

- my_ai_town 的摆放检查已有"操作锚点必须落在可走格里"一项（同上第 4.8 节代码 `w`）；其内核 `navigation` 模块的注释还记录过
  锚点落在可走格外、居民之后每个动作都被拒而困死的事故（源码注释，调研归档未收录）。本作在此基础上把"放完后全局可达"
  （`keep_reach`）也列为硬约束。
- AI 工务官规划的布局与玩家摆放走同一个校验器；AI 不能"发明"例外。

### 3.6 区划、覆盖与邻接

- **区划**（城镇起）：玩家用笔刷涂区划，工务官在区划内按规则自动选址建造。这是城镇级最重要的委托工具。
  玩家仍可亲手摆"地标"（神殿、城主府、纪念碑），但亲手摆普通建筑计入依赖。
- **服务覆盖**：医馆、卫兵所、神龛、市集、学堂等有覆盖半径（按拓扑分钟数计，不是直线），覆盖内的居民才享受效果
  （补充资料：《凯撒 III》《模拟城市》式覆盖半径，见 [`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.3 节）。
- **邻接**：少量建筑有邻接加成或惩罚（熔炉旁不宜住人，磨坊挨农田省搬运，神殿旁地价上升）。邻接规则保持在每栋建筑 ≤ 2 条，避免变成拼图。

## 4. 建筑

### 4.1 通用字段

建筑拆成"功能、外观、占地与通行"三份数据各自演化（同上第 4.10 节）：

```
BuildingDef {
  id, category, tier
  footprint: { w, h }               // 地段数
  stations: { arrivals[], slots[{ activityId, poseFamily }] }
  terrainTags[], prereqs[]          // 前置建筑、科技、门、幕次
  build: { materials{}, labor, days }
  upkeep: { coinPerMonth, materials{} }   // 维护
  staff: { jobs[{ jobId, count, minSkill }] }
  recipes[]                          // 允许的配方集合（只是允许集，开工时再校验）
  capacity: { housing?, storage?, power? }
  coverage?: { radiusMinutes, effect }
  modifierChannels[]                 // 本建筑接受哪些修正项通道
  visibility: { goddessSight?: radius }  // 神殿类：扩大女神视线
}
BuildingInstance { defId, plotIds[], condition 0..100, upkeepState, queue[], staffAssigned[] }
```

- **生产队列**：完成时间写世界时钟绝对时刻，读档或切图不重复结算；开工时同时校验配方、建筑等级、供能、耐久、维护状态、
  材料与队列容量（[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.1 节，修仙 GDD 43 的设施队列规格）。
- **维护欠缴**按三段处理，不产生隐藏负债：宽限 7 天（无影响）、降效 14 天（产出与效果 ×0.5）、停机（停止产出，耐久每日 -2）
  （同上借鉴清单第 4 条）。
- **耐久**：使用、灾害、袭击会降低耐久；耐久 < 50 降效，< 20 停机，0 为废墟。修理消耗原材料的 30%。

### 4.3 主工程映射说明

- 主工程的采集点（矿、木、草约各 11 个）与工站（熔炉、厨房、药剂间、制革间、织机、工具间）天然对应城建的资源地段与生产建筑；
  制作环十种专业对应 P9 到 P16 与 R4、X1 的配方集合（[`combat_and_content_inventory.md`](../../10_research/woc_reuse/combat_and_content_inventory.md) 第 7.7、8.2 节）。
- 改造方向是把"个人背包经济"扩展为"领地库存经济"：同一份配方数据，个人制作时从背包扣料，领地生产时从仓库扣料并由工人执行。
  配方的杰作（masterwork）机制保留，成为名匠的成长出口（第 7.3 节）。
- 采集专业等级（上限 100 到 200）映射为工人的"职业熟练度"，玩家本人的专业等级只影响玩家亲手制作。

HappinessLedger { poolId, factors: [{ source, value, expiresDay? }] , total }
示例：旧哨村·人族·农夫池
  +6 需求：粮食充足（公灶）
  +3 需求：有木屋
  -4 事件：门徒会夜袭（剩 9 天）
  -2 政策：延长工时（法令）
  +2 修正项：希尔薇·丰年（神意，半显性，剩 21 天）
  = +5
```

- 幸福 < -10 时劳动效率下降并开始外逃；< -25 时出现骚乱事件。
- **治安**（0 到 100）：卫兵覆盖、犯罪率（贫富差、失业、黑市活动）、外部渗透。治安 < 40 时盗窃、黑市、渗透事件概率上升。
- 具名居民的心情可以由模型在台词里表达，但数值只来自账本（my_ai_town"不从模型写的文字里猜情绪"，
  [`my_ai_town_agents.md`](../../10_research/ai_npc/my_ai_town_agents.md) 第 3.4 节）。
- 集体指标（幸福均值、治安、存粮天数、不满）写进每位具名居民的观察栏，供模型理解处境（同上第 10 节第 21 条）。

### 5.6 迁入与迁出

```
吸引力(聚落) = 需求满足度 × 0.35 + 治安 × 0.15 + 就业 × 0.15 + 风评 × 0.15
             + 种族包容 × 0.10 + (1 - 战争风险) × 0.05 + (1 - 澱害) × 0.05 - 税负感 × k
澱害：清域、薄澱为 0，积澱 0.3，浓澱 0.7，深澱及以上 1（第 12.1 节）
```

- 每游戏日按吸引力差在相邻聚落（世界地图上的通行天数 ≤ 5）之间结算迁移流，流量有上限（每日不超过人口的 1%）。
- 风评来自社会层的传闻画像（`reputation_and_cognition.md`）："那个 F 级的村子收留烙印者"会让一部分人族不来，让遗民来。
- 特殊流入（难民潮、立国后的投奔潮）由剧情事件注入，不走吸引力公式。

### 5.7 人口的四种用途

人口同时是劳动力、兵源、税基、信仰来源，四者互相争抢（[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.2 节分析）：

- 征兵从劳动人口里抽人，产出立刻下降；
- 加税提高国库，降低幸福与迁入；
- 建神殿提高信仰与幸福，同时扩大女神视线；
- 让人进学堂提高未来的人才，短期少一份劳力。

### 6.3 劳力分配

- 每栋生产建筑有岗位；人口池按"岗位吸引力"（工资、距离、种族加成、危险）自动填岗，工头或部门官可以设优先级。
- 玩家可以亲手指定某个具名居民去某个岗位（计入依赖），也可以只设"优先级与配额"（不计入依赖）。
- 具名居民的职业选择由其 AI 在菜单内提议（"我想去锻造坊当学徒"），内核按岗位空缺与资格裁决。

## 7. 人才

### 7.1 人才金字塔

正典的位阶金字塔（[`world_bible.md`](../../20_world/world_bible.md) 第 10.1 节）就是领地的人口结构骨架。人族地区的密度低于大陆平均，
以 [`society.md`](../../20_world/society.md) 第 2.1、2.2 节为准：

| 位阶                  | 人族地区成年人占比                  | 在领地里的角色                 |
| --------------------- | ----------------------------------- | ------------------------------ |
| 凡阶·初（Lv1 到 9）   | 约 86.5%                            | 劳动力、税基、民兵             |
| 凡阶·熟（Lv10 到 19） | 约 13%                              | 工头、熟练工匠、老兵、小吏     |
| 精英阶（Lv20 到 34）  | 约 0.45%（村庄更低，城市略高）      | 官员、名匠、将领、宫廷法师候选 |
| 英雄阶（Lv35 到 49）  | 约 0.004%（两万五千个成年人里一个） | 国之柱石；一国几十人           |
| 传说阶以上            | 一国零到两人                        | 只以盟友、剧情人物的身份出现   |

- 推论（`society.md` 第 2.2 节的估算表）：一个约 200 人的村子精英阶 0 到 1 人（约四个村有一个，多半隐藏）；约 800 人的小镇 3 到 4 人；
  约 4 万人的城市约 125 人。所以旧哨村在第二幕几乎不可能从本地找到精英阶官员，第一批官员多是凡阶·熟的老兵与工头；
  精灵（精英阶约 4%）与魔族（约 2.5%）的移民会明显抬高人才密度。人才稀缺是天然的上限，也是招募与培养的意义。

### 7.2 识才之门

- 每个居民（含人口池里被具名化的）都有隐藏的**潜质**：标签（统帅、匠心、商才、治理、学识、信仰、武勇、灵感）与等级（C、B、A、S），
  以及可达位阶上限的估计。
- 正典：潜质写在门侧的"底页"里，所有鉴定都只走录侧，读不到；唯一的例外是识才之门（[`power_system.md`](../../20_world/power_system.md) 第 2.2、2.5 节）。
  没有识才之门时，潜质只能靠"表现"慢慢露出：在对应岗位累积熟练度越过阈值，内核按种子揭示一项（慢、有误差）。
- 识才之门开启后（第一幕后段），玩家注视一个居民即可看到潜质；随门的进阶，能看到更多标签与更准的上限
  （[`world_bible.md`](../../20_world/world_bible.md) 第 11 节：识才之门"看见 NPC 的隐藏潜质，招募与培养的核心"）。
- 剧情锚点：罗恩的"统帅"、希雅的"猎王"（`story_outline.md` 第一幕）。罗恩的统帅潜质成长与"玩家插手越少，罗恩成长越多"挂钩
  （`act2_wallenburg.md` 支线 A2-S17），这是自治度主题在人才层的第一次教学。

### 7.3 职业成长

| 成长                   | 来源                   | 规则                                                                                                                                                                                          |
| ---------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 职业熟练度（0 到 100） | 在岗劳动、学堂、导师   | 决定产出效率与杰作概率；人口池按平均熟练度计                                                                                                                                                  |
| 铭录等级               | 劳动、训练、战斗、事件 | 凡人升级很慢；位阶跨越（凡阶到精英）需要"潜质达标 + 机遇"（导师、战役、事件）                                                                                                                 |
| 导师                   | 精英阶居民或同伴带徒   | 每位导师同时带 2 名，徒弟熟练度增长 ×2                                                                                                                                                        |
| 庭院修炼               | 训练桩、冥想位         | 同伴与将领在庭院训练潜质；占用庭格与门息                                                                                                                                                      |
| 门的加成               | 识才之门进阶；启才之门 | 被玩家"点名培养"的人潜质成长 +，但计入依赖（玩家亲手培养 vs 学堂体系）。启才之门可把底页的潜质直接写进其录侧（例：罗恩的统帅），会触发莫伊拉的异动提醒（`power_system.md` 第 9.9 节第 19 项） |
| 授权                   | 官员独立处理事件       | 授权越多，潜质成长越快（act3 第 7.2 节）                                                                                                                                                      |

### 7.4 官员体系

**政务领域**：八个，随规模解锁。

| 领域 | 职责                         | 解锁 |
| ---- | ---------------------------- | ---- |
| 粮务 | 农牧渔、粮仓、配给           | 据点 |
| 工务 | 建造、道路、维修、区划内选址 | 据点 |
| 治安 | 卫兵、司法、拘押             | 村落 |
| 民政 | 住房、迁入、医护、纷争调解   | 村落 |
| 商务 | 市集、税收、商路、汇兑       | 城镇 |
| 军务 | 民兵、守军、防御、征兵       | 城镇 |
| 教化 | 学堂、信仰场所、节庆、编年   | 城市 |
| 研究 | 工艺、魔导、澱               | 城市 |

**职位与属性**：

```
Office { domain, rank: 主官 | 副手, holderId?, authority: 1..4, budgetCapPerMonth, standingOrders[] }
OfficialTraits {
  competence[domain]: 0..100   // 能力
  loyalty: 0..100              // 对玩家的忠诚
  ambition: 0..100             // 野心
  integrity: 0..100            // 廉洁
  initiative: 0..100           // 主动性
  creed: 秩序 | 争斗 | 交易 | 生命 | 记录 | 门   // 理念倾向（加护冲动）
}
```

- **职权等级**（authority）：1 日常（排班、补货）、2 重要（建造、调价、小额支出）、3 重大（征发、法令执行、动用守军）、
  4 危机（全城动员、对外求援、开仓赈济）。玩家授予每个职位的最高等级。
- **理念倾向**：信仰某位女神的官员会被她的价值观轻微牵引（"加护冲动"，
  [`synthesis.md`](../../10_research/anime/synthesis.md) 第 2.11 节；[`comparison_and_plan.md`](../../10_research/ai_npc/comparison_and_plan.md) 第 6.3 节）。
  这让同构嵌套落到经营层：玩家的内阁会自然分出"秩序派、交易派、生命派"（[`narrative_design.md`](../../30_story/narrative_design.md) 第 3 节）。
- **决策管线**：主官是 L1 或 L2 的 AI，按"感知摘要（本领域仪表盘）-> 从领域意图菜单选择（含理由）-> 内核校验（职权、预算、法典）
  -> 规则执行 -> 回执写回"运行；每游戏周一次规划轮，事件触发即时轮；模型不可用时由 Utility 打分直接选意图兜底
  （[`comparison_and_plan.md`](../../10_research/ai_npc/comparison_and_plan.md) 第 6.5 节；完整管线见
  [`grand_strategy_slg.md`](grand_strategy_slg.md) 第 3.2 节）。
- **观察栏预计算**：官员题面只列此刻合法的命令、代价、预计耗时，来不及的写明"不要开始"
  （[`my_ai_town_agents.md`](../../10_research/ai_npc/my_ai_town_agents.md) 第 10 节第 7 条）。
- **公开与内心分离**：官员的公告与请示进入世界；其真实理由只进调试视图与（后期解锁的）玩家"内阁记录"（同上第 9 条）。
- **腐败与寻租**：握有审批权的职位有寻租风险，概率随（1 - 廉洁）× 审批量 ×（1 - 监察覆盖）上升；结果是预算漏损、
  民心下降、黑市活跃，可经账房审计、监察署或传闻发现
  （[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 5.3 节"寻租"）。
- **放手的代价**：官员会做出玩家不会做的选择（例：克拉拉为筹军费把拾遗营挖出的澱晶卖给黑市；乌尔萨克把玩家留作牧场的地分给族人），
  战报只陈述，不评判（act3 第 7.2 节）。
- **任命来源**：

## 8. 自治度

### 8.1 定义与同构

自治度（Autonomy）衡量"这个聚落或国家在玩家不直接操控时，能否自己运转、自己扛住危机"。
它是"离手"主题在玩家层的同构（[`narrative_design.md`](../../30_story/narrative_design.md) 第 6 节）：

| 诸神层                             | 玩家层                               |
| ---------------------------------- | ------------------------------------ |
| 女神降神迹，立刻见效，留下澱       | 玩家亲手微操，立刻见效，留下依赖     |
| 众生依赖神迹，信仰被收割           | 居民依赖领主，自己不长本事           |
| 审定：箱庭能否在无人照看下自行繁茂 | 决战：国家能否在玩家不在场时守住战线 |

关键设计：**依赖之于玩家，正如澱之于女神。** 玩家越爽快地亲手解决问题，就越像他将来要质问的那些神。

### 8.2 计算

分幕文档已给出自治度的变量与关键节点：第二幕 `village_autonomy`；第三幕 `territory_autonomy`（0 到 100，起点 = 10 + 第二幕
`village_autonomy` × 0.4，市民议会结局再加 10，act3 第 7.2 节）；第四幕 `autonomy`（act4 第 4.7 节，带入第五幕）。
本节给出这些变量在幕内如何逐日演化的系统规则：幕开头按分幕文档的起点初始化，之后按下式结算。

每个聚落一份自治账本，每游戏日结算一次：

```
A_raw = 100 × ( 0.25·I + 0.20·T + 0.20·D + 0.15·S + 0.20·C ) - P_dep
A(今日) = A(昨日) 向 A_raw 靠拢，每日变化不超过 ±1        // 惯性，防止临时刷分
```

| 分项  | 名称     | 取值       | 计算（初值，待调）                                                                             |
| ----- | -------- | ---------- | ---------------------------------------------------------------------------------------------- |
| I     | 制度覆盖 | 0 到 1     | 已解锁领域中，"有主官 × 有常设命令或法典条目 × 主官能力系数"的平均值                           |
| T     | 人才厚度 | 0 到 1     | 已解锁领域中，"至少有一名合格继任者（副手或学堂毕业者）"的领域占比                             |
| D     | 授权比   | 0 到 1     | 近 30 天内，1 -（玩家直接决定的事务权重 / 全部事务权重）；权重：日常 1、重要 3、重大 5、危机 8 |
| S     | 自持记录 | 0 到 1     | 考验记录：(Σ成功权重 + 1) / (Σ成功权重 + Σ失败权重 + 3)；超过 180 天的记录权重减半             |
| C     | 凝聚     | 0 到 1     | 幸福、治安、种族和睦、官员忠诚均值的加权                                                       |
| P_dep | 依赖     | 0 到 40 分 | 玩家直接干预的累积，每日衰减 2%（半衰期约 34 天）                                              |

**依赖增量表**（初值，待调）：

| 玩家行为                                             | 依赖 +                                         |
| ---------------------------------------------------- | ---------------------------------------------- |
| 越过工务官亲手建造或拆除一栋普通建筑                 | 0.3                                            |
| 亲手给具名居民派岗、亲手改生产队列                   | 0.2                                            |
| 越级处理请愿或纷争                                   | 0.5                                            |
| 推翻官员已作出的决定                                 | 1.5                                            |
| 以个人武力或门的能力解决守军与居民本可处理的危机     | 3.0                                            |
| 从门内庭院向聚落直接投放物资；用庭院产出填补国库缺口 | 每 100 单位 1.0                                |
| 某领域主官空缺超过 30 天                             | 每天 0.1                                       |
| 国主敕令（王政国体专属的单次高效指令）               | 2.0                                            |
| 玩家离开期间出事，由玩家紧急返回处理                 | 2.0                                            |
| 第五幕决战中的"急令"                                 | `autonomy` 永久 -3（act5 第 7.3 节，不经衰减） |

反向（降低依赖、抬高 I 或 S）的行为与 act4 第 4.7 节一致：建立制度、把纷争交给法庭与议会、官员独立处理事件成功、
议事日采纳国民提案、玩家离开国土期间国家无事。

**政策与指令**：第三幕起每周可下"政策"（持续生效）或"指令"（一次性）。指令见效快、短期结果好，但每条按上表计入依赖；
政策计入制度覆盖 I（act3 第 7.2 节）。本文的"直接命令"即分幕文档的"指令"。

**考验**：严重度"中"以上的事件，在玩家不在该聚落、或玩家选择"旁观"时发生，即为一次考验。结局按事件定义的目标判定成功或失败。
玩家亲自出手的事件不算考验（但会加依赖）。

**示例**（第二幕第 12 周的旧哨村）：已解锁粮务、工务、治安、民政四域；维尔纳任民政、罗恩任治安、一名工头任工务，粮务空缺。

| 分项  | 值    | 说明                                                                                  |
| ----- | ----- | ------------------------------------------------------------------------------------- |
| I     | 0.60  | (0.9 + 0.7 + 0.8 + 0) / 4                                                             |
| T     | 0.25  | 只有治安有继任者                                                                      |
| D     | 0.60  | 玩家亲手决定了约四成的加权事务                                                        |
| S     | 0.40  | 门徒会夜袭时玩家在瓦伦堡，民兵守住了：(1 + 1) / (1 + 0 + 3) = 0.5，再按其他小事件修正 |
| C     | 0.65  |                                                                                       |
| P_dep | 8     | 第 3 周粮价战时从庭院放粮                                                             |
| A_raw | 约 42 | 100 × (0.15 + 0.05 + 0.12 + 0.06 + 0.13) - 8                                          |

### 8.3 微操与授权的取舍

| 方式                                 | 好处                                     | 代价                                               |
| ------------------------------------ | ---------------------------------------- | -------------------------------------------------- |
| 亲手微操（直接命令）                 | 立即执行；效率 ×1.15；精确；危机里能救火 | 依赖上升；官员不成长；规模一大，玩家的时间根本不够 |
| 授权（常设命令、政策卡、预算、区划） | 不耗玩家注意力；自治度上升；人才成长     | 短期慢；结果受官员能力与理念影响；有偏航与腐败风险 |
| 制度（法典条目、监察、学堂）         | 长期稳定；降低偏航；继任者源源不断       | 前期投入大，见效以月计                             |

- 直接命令只能下给"玩家所在的聚落"或"有门扉相连的聚落"；其他聚落经信使传令，有延迟（驿站缩短）。
  这让"空间稀缺"自然约束微操：玩家在 A 城救火，B 城就只能靠自己。
- 授权并不等于万事大吉：高自治度的聚落里，忠诚低、野心高的官员更容易"自主偏航"（第 8.4 节）。

### 8.4 对效率与抗风险的影响

所有影响都走**可解释的通道**，不是隐藏乘数；每一项都能在"自治报告"里看到原因。

| 通道               | 公式（初值，待调）                                                                    | 说明                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 自主运营效率       | E = 0.70 + 0.004 × A                                                                  | 不经玩家直接命令的生产、维护、建造效率。A=0 时 0.70，A=50 时 0.90，A=100 时 1.10                                                |
| 官员自行处理的上限 | min(职权等级, 1 + floor(A / 25))                                                      | A 低时，官员连自己有权的事也"不敢做主"，堆进玩家的请示队列                                                                      |
| 危机响应时间       | 基准 × (1.6 - 0.6 × A / 100)                                                          | 玩家不在场时，民兵集结、灭火、开仓、疏散的启动时间                                                                              |
| 应对完成度上限     | 0.5 + 0.5 × A / 100                                                                   | 玩家不在场时，事件"应对措施"最多能完成到的比例                                                                                  |
| 预案覆盖           | 有对应常设命令或法典条目时，响应时间再 ×0.7                                           | 制度是最便宜的抗风险手段                                                                                                        |
| 守土士气           | 守军士气基线 + 0.2 × A                                                                | 居民为自己的家而战（接入 [`warfare_rts.md`](warfare_rts.md) 第 3.4 节）                                                         |
| 第五幕战线         | 自治系数 = 0.5 + autonomy / 100；autonomy < 40 时有"待令"概率                         | 战线方程与待令规则以 act5 第 7.3 节为准；上面几条通道在战线层被汇总成这一个系数（[`warfare_rts.md`](warfare_rts.md) 第 7.3 节） |
| 自主偏航风险       | 每月检定：忠诚 < 40 且野心 > 60 且 A ≥ 50，风险 ∝ A × (1 - 忠诚/100) × (1 - 监察覆盖) | 偏航不是叛乱：官员开始按自己的议程办事（加税自肥、结交外势力、压制某族）。监察署、法典、赛琳式法官可抑制                        |
| 民意抵制           | A ≥ 80 时，违背法典的直接命令会引发请愿                                               | 不阻止执行，但扣凝聚。这是"他们终于会说不了"的正面信号                                                                          |

### 8.5 国家自治度

立国后另算国家层：

```
A_nation = 0.6 × (按人口加权的各聚落自治度) + 0.4 × A_core
```

A_core 用同一公式计算国家层的领域，领域即 act4 第 4.5 节的官职（军务、财务、民生与医、门务与交通、人簿与登记、外务、
礼与教化、学术与星象、治安、北境防务）。A_nation 就是分幕变量 `autonomy`。

- **国体**：立国时的国体决定自治度的成长速度（act4 第 4.4 节：王政最慢且第五幕易"待令"；门庭议会快；界石联邦地方极快、
  中央慢；行会共和中；学士宪政中后期最稳；隐藏的无主之制最快但开局最脆弱）。系统实现为对 I、D 两项增长速度的乘数，
  以及第五幕待令概率的修正；"改制"时一年内成长减半。
- **制度**：act4 第 4.6 节的首批制度（人簿、界石誓、门券、凡约、无神之礼、澱哨、议事日）是国家层"制度覆盖 I"的条目，
  每建立一项，相关事务就不再需要玩家亲手处理。
- 国家自治度在战略层的作用（AI 国家同样有自治度、"神依赖度"）见 [`grand_strategy_slg.md`](grand_strategy_slg.md) 第 2.6 节。

### 8.6 与结局的关系

正典要求真结局"离手"中玩家的国家与同盟在无神干预下挺过第九代魔王危机（[`world_bible.md`](../../20_world/world_bible.md) 第 14 节）；
总框架第 11 节与 D-011 把它落为"国家自治度达到阈值，并且决战中不在场战线守住"；D-043 把阈值定为显式条件（初值 60，待调）。
可结算的触发条件以 act6 第 11.1.1 节为准，其中与本系统相关的是：

| 条件（act6）                               | 变量                                                                                                              | 本系统如何影响它                                                                                               |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 无神干预挺过危机                           | 无战线为溃败，且 `held_unaided` ≥ 3（整场未收到急令、最终守住或僵持的非核心战线数，最多 5），且 `janu_act` = 接人 | `autonomy` 经自治系数与待令进入每条战线的回合结算（act5 第 7.3 节）；急令让该线不再计入                        |
| 众生的办法                                 | `purge_route` = 众生 且 `gate_ring` ≥ 5                                                                           | 众门环节点的建设与守备（第 12.3 节）                                                                           |

- 第五幕开战前，罗恩会在军议上问"要是您不在，我们能撑几天？"作为提示（act4 第 4.7 节）。

- **教学链**：第二幕罗恩带队（插手越少成长越多）、城下潮"第一次把一条战线交给别人"；第三幕骨原夜袭可以"让罗恩全权指挥"、

- **反向路线**：长期低自治、开过许多危险之门的玩家会走向"新神"结局的倾向（`characters.md` 第 4.8 节无貌者条目的对照）。
- **后日谈**：每个聚落的后日谈按其自治度、凝聚、人才厚度分档生成（莫伊拉的"最后的记录"）。

### 8.7 可读性与反刷

- **自治报告**：第二、三幕作为正式指标可见（act3 第 1.1 节"自治度（正式指标）"）：每个聚落一页，列出五个分项、
  依赖的来源明细（哪一次亲手操作加了多少）、近 30 天趋势。第四幕起国家层的界面只显示"国家运转"的状态
  （"议会正在讨论""法庭已裁决"）与趋势，不显示数值，也不预告它与第五幕后果的挂钩（act4 第 4.7 节）；
  依赖的来源仍以叙事条目的形式可查（"那次您亲自裁决了配给所的斗殴"）。
- **叙事提示**：官员会抱怨（维尔纳："那你来当村长"）；守门人阿什、莫伊拉、雅努在关键节点各有一句点题的话。
- **反刷**：每日 ±1 的惯性、考验只在玩家不在场时计入、继任者需要时间培养，因此"决战前临时撒手"刷不起来。

- 危机必须保留关键物资的合法来源，并进入软锁审计（[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.5 节）：

## 11. 防御与 RTS 的衔接

- **防御评分只是摘要**：围墙、哨塔、守军汇总成一个"防御评分"给 AI 与界面看，真正的袭击由战斗规则结算
  （修仙 GDD 43 的 `defense_rating` 原则，[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 2.5 节）。
- **袭击来临时**：玩家在场或选择亲自指挥，进入 RTS 守城战；否则由同一确定性内核无渲染结算（D-012；[`warfare_rts.md`](warfare_rts.md) 第 2.4 节）。
- **城建实体进入战场**：

| 城建对象       | 战场表示                                                   |
| -------------- | ---------------------------------------------------------- |
| 围墙段、城门楼 | 有耐久与护甲类型（建筑）的阻挡实体；被摧毁处变为可通行缺口 |
| 箭塔           | 静态远程兵团，驻守人数决定输出                             |
| 营房中的常备兵 | 兵团                                                       |
| 民兵           | 从劳动人口池临时转换的兵团；动员期间产出下降               |
| 平民           | 不参战；未疏散的平民伤亡计入战后结算并压低幸福             |
| 军械库、粮仓   | 补给点；被攻破则守军补给中断                               |

- **围困**（不进攻城门的长期包围）在战略层按存粮天数结算（[`grand_strategy_slg.md`](grand_strategy_slg.md) 第 5.4 节）。
- **守城战里的个人**：玩家与将领是完整实体，可以亲自守城门；但城墙缺口有多个，玩家一次只能守一处（英雄是乘数，见 [`warfare_rts.md`](warfare_rts.md) 第 4 节）。

## 12. 澱与净化

### 12.1 领地的澱

正典：澱是被神力强行扭结、再也松不开的灵素；每次神力干预都会在当地留下澱，越逆势越多；澱不流动，会沉积、汇聚、凝形，
滋生魔物、使野兽异变、结晶为迷宫；灰烬荒原积存着大断绝留下的巨量古澱（[`world_bible.md`](../../20_world/world_bible.md) 第 5 节第 3 条；
[`power_system.md`](../../20_world/power_system.md) 第 7.1 节）。玩家的领地就在荒原边上，因此澱是领地的"环境压力"。

每个地段有澱值，与 [`goddess_gm.md`](goddess_gm.md) 第 4.5 节的地区澱值同一标尺（地区值是其下地段的汇总），
浓度分级用 `power_system.md` 第 7.2 节的六级加临界（D-039）：

| 级   | 名称 | 澱值（goddess_gm 初值）                                                | 对领地的效果（初值，待调）                                                                 |
| ---- | ---- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 0    | 清域 | 0 到 4                                                                 | 无                                                                                         |
| 1    | 薄澱 | 5 到 29                                                                | 偶有异兽；无其他影响                                                                       |
| 2    | 积澱 | 30 到 99                                                               | 植物发育异常（作物 -10%）；澱巢；久居者有澱斑风险，幸福 -1；未处理的尸骸开始有起身的可能   |
| 3    | 浓澱 | 100 到 299                                                             | 不宜住人（数月即可染上澱病）；迷宫开始形成；精英魔物；只能建防御、采集与众门环建筑         |
| 4    | 深澱 | 300 到 799                                                             | 数周即病；大迷宫；只有据点式的前哨能维持                                                   |
| 5    | 渊澱 | 800 以上                                                               | 寸草不生、亡灵游荡、神之视线失效；魔王可在此诞生（受台账锁定，只在灰烬荒原、只在天启之后） |
| 临界 | 澱满 | 由天启「荒原之澱满」锁定（[`goddess_gm.md`](goddess_gm.md) 第 9.2 节） | 只出现在灰烬荒原中心；有灵智的容器出现时魔王诞生；领地不可能处于此档                       |

- 浓澱以上的区域，神殿覆盖与信徒的见闻都会变得模糊，成为神的盲区（`power_system.md` 第 7.2、8.6 节）。
  对位于荒原边缘的庭外之国，这是天然的掩护，也是天然的危险。

**来源与流动**：

| 来源     | 规则                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 古澱     | 荒原的蓄积；随时间极缓慢地沉降、扩散                                                                                                                                                 |
| 神力干预 | 任一女神在当地生效的动作，按"神力 × 澱率系数"留下澱（顺势 0.01、转势 0.1、逆势 0.3，[`goddess_gm.md`](goddess_gm.md) 第 4.4 节）。封印常耗也在封门遗迹周边持续留下澱                 |
| 圣教净化 | 不消除澱，只把它从城市推开，顺河流与地脉沉向下游荒野（`power_system.md` 第 7.2 节【真相】）。领地若在教会城市下游，会被动接收                                                        |
| 余澱     | 魔晶燃尽或澱晶散逸时，一部分澱慢慢散回周围；大量使用魔道具的聚落，地下会积起薄澱，最终在下水道里长出迷宫（同上第 7.7 节）                                                            |
| 讨伐魔物 | 魔物被杀，大部分澱凝成澱晶留下，少部分散回环境；不收澱晶、任其腐烂，澱就回到原地（同上第 7.3 节）。因此"讨伐 + 收晶 + 入窖"能真正把澱从当地搬走；只讨伐不净化，澱只是被压住（D-039） |

- 设计意图：凡人的生产不"制造"澱，只"搬运"澱（澱晶是凝固的澱）。收晶能让本地变清；未净炼的澱晶（俗称灰晶）不得合法流通，
  须经持证工坊（教会、学院、公会）净炼为魔晶，净炼会减少余澱，出售魔晶等于把剩下的澱送到使用地（D-040）；
  燃烧魔晶能换来魔道具的便利，也把余澱放回了自家地下。这让"澱晶经济"成为带道德重量的取舍
  （第一幕代官莫斯沿灰路走私澱晶的回响，[`geography.md`](../../20_world/geography.md) 第 6.1 节）。

### 12.2 迷宫的处置与凡人的净化手段

迷宫是浓澱长期淤积后的结晶（`power_system.md` 第 7.5 节）。领地里的迷宫有三种处置，正典本身就把它定为经营层的抉择：

| 选择 | 结果                                                                               | 系统表现                                                                         |
| ---- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 养   | 定期清理、收澱晶，迷宫被"圈养"成矿场；城市获利，澱被集中在一处（小型的排澱）       | 冒险者公会分部（A4）管理入口；稳定的澱晶与魔物素材产出；迷宫有"活性期"与溢出风险 |
| 毁   | 打碎迷宫核，迷宫在数日内塌缩；核里的澱散回周边，整片地区浓度上升一级，持续一段时间 | 一次性王晶；周边地段临时降级为不宜居                                             |
| 净   | 用澄流之门、灵泉之水或森之祭司的仪式把澱解开；慢、贵、需要合作，但不留后患         | 见下表                                                                           |

凡人与玩家能用的净化手段（澱"可以解开"，但慢，远远赶不上诸神制造它的速度，`power_system.md` 第 7.1 节）：

| 手段                       | 谁                                   | 规模                                   | 代价           |
| -------------------------- | ------------------------------------ | -------------------------------------- | -------------- |
| 封澱窖（Z2）               | 领地                                 | 只阻止散逸，不减少                     | 维护费         |
| 森之祭司与萨满的仪式、草药 | 德鲁伊、萨满（欧拉一系）             | 小，一处澱巢                           | 时间与人手     |
| 灵泉之水                   | 希尔瓦                               | 小，按水量                             | 外交与贸易     |
| 澄流之门                   | 玩家（第三到第四幕，与渊契之门互斥） | 小范围把澱解回灵素，也清除玩家自身淤塞 | 开门即松动封印 |
| 术士的解澱                 | 契约者                               | 少量                                   | 澱染累积       |

- 推论：在众门环出现之前，领地层的净化只能"压住"局部，不能处理荒原的古澱。这正是第五幕必须"众生一起来"的原因。

### 12.3 众门环：第五幕"众生的办法"的物质基础

正典与分幕：第五幕"众生的办法"是重建一张小型门网"众门环"，七个节点经门路相连；决战中主门坑的古澱经众门环分流到各节点，
由当地众生用各自的办法一点点消化掉。门本身不产生澱，门只是把澱"分开"，让它小到凡人消化得了
（`../../30_story/arcs/act5_war_of_races.md` 第 6.2 节；对应 `power_system.md` 第 9.9 节第 30 项"千径之门"）。

节点、承建种族与消化法以 act5 第 6.2 节为准：主门坑（核心，遗民执钥人与玩家）、世界树根下（精灵，根滤）、炉心（赤砧山矮人，炉炼）、
祖灵石（风牙兽人，祖舞）、月井（夜境魔族夜后派，饮月）、旧水道（瓦伦堡人族，盐封）、眠鳞碑下（龙族，龙息）；
半身人的"百足商队"在节点间运送澱晶，冒险者公会护送。

本系统负责把它落成可建设、可守备、可结算的工程：

| 要素     | 分幕给定                                                                                                                                 | 本系统的实现                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 门路     | 每个节点需要玩家亲自到场以行路之门开出门路，并以一枚门钥或一队执钥人锁定；封印松动度足够高时玩家的门可代替锁，但每次锁定都让封印继续松动 | 节点建筑 Z4 的"门路锁定台"；锁定是一次建造事务，失败可回滚                                                                   |
| 执钥人   | 每个节点一队；遗民人数决定可组建的队数（初值：20 人对应三队、40 对应五队、60 对应七队）                                                  | 遗民人口池与梅芙、塔维等具名者的信任；执钥人驻所占用人口，不能同时做别的工作                                                 |
| 承建同意 | 各族各有条件（`refuge_state`、凡约、`beast_king`、`night_pact`、瓦伦堡掌权者、`eska_consent`）                                           | 由战略层的外交与第四幕纷争结局决定（[`grand_strategy_slg.md`](grand_strategy_slg.md) 第 8.2 节）                             |
| 时间     | 1000 年春约八周的 SLG 时间，节点并行建设，每处需要守备                                                                                   | 节点工期与守备兵团；建设期间节点是敌方的战略目标                                                                             |
| 结算     | `gate_ring` = 决战开始时建成并守住的节点数（含核心）；≥ 5 为众生的办法成立，4 为半成，≤ 3 不成立                                         | 决战中每失守一个节点，首领战澱灌加一脉、节点所在地区爆发局部魔物潮（门环线战线，[`warfare_rts.md`](warfare_rts.md) 第 8 节） |
| 代价     | 兵力被分去守节点；各族承担消化代价；教国派"拆门队"、瓦尔妲在节点附近催动魔物潮                                                           | 维护费、驻守兵团、消化代价写入各节点所在聚落的事件与幸福账本                                                                 |

- **提前教学（提案）**：第三到第四幕，玩家可在领地里以澄流之门处理一处澱巢、或在旧水道迷宫以"养"的方式圈住澱，
  让玩家在第五幕前理解"分开、消化、守住"的逻辑；不另设一个会与 act5 节点编号冲突的"试验节点"。
- 这条工程把城建（节点建筑与遗民）、外交（承建同意）、战争（守护节点）、千门（门路与封印）四层系统拧在同一个目标上，
  是"从一人到一国"的终局形态。也正因为门网重建了，雅努会想要它：众门环的每一个节点都是第六幕"门之复辟"的诱惑来源（act5 第 6.2 节）。

## 13. 防滚雪球审计

| 空间     | 地段越多越好           | 聚落宣称范围；行政容量              | 离行政中心越远的地段，效率越低                                           | 澱值高的地段不可住人                     |
| 时间     | 加速度过经营期         | 加速时 AI 决策降频（总框架第 6 节） | 无                                                                       | 危机自动暂停                             |
| 心理     | "我已经很强了"         | 无                                  | 无                                                                       | 每幕换赛道：新舞台的基准整体上移         |
| 社交     | 名声越大，移民越多     | 每日迁入上限 1%                     | 风评有衰减                                                               | 名声越大，神之视线越近；教会、金冠的打压 |
| 门内庭院 | 私域无限积累           | 庭格与门息                          | 庭院产出只有地段的 30%                                                   | 投放计入依赖；泄密                       |

- 特别检查"庭院 + 门扉 + 地球知识商品"三者叠加的套利循环，归入经济系统的套利审计（[`economy_and_trade.md`](economy_and_trade.md) 第 5.5 节）。

  topology: { locales[], passages[], stations[] }
  buildings: BuildingInstance[]
  cohorts: CohortPool[]
  namedResidents: residentId[]
  offices: Office[]
  policies: PolicyCard[]            // 法令、政策卡（不可撤销的标注 irrevocable）
  standingOrders: StandingOrder[]   // { domain, condition, action, priority }
  stockpile: { [resourceId]: qty }
  budget: { monthly: { [domain]: coin } }
  autonomy: AutonomyLedger
  defense: { summaryRating, wallSegments[], garrison[] }
  dianByPlot: { plotId: number }    // 与 goddess_gm.md 第 4.5 节同一标尺
  modifiers: modifierId[]           // 注册修正项实例的引用
  eventLog: EventRecord[]           // 只增不改，供回放与传闻
}
CohortPool { race, stratum, job, count, skillAvg, happinessLedger, needsTier, faith{goddess: share} }
AutonomyLedger { I, T, D, S, C, P_dep, raw, value, history[], dependencyEntries[{ day, action, delta }], trials[] }
PolicyCard { id, domain, effects: modifierTemplate[], irrevocable, cost, enactedDay }
```

- 所有资源变动都带 reason 枚举与变动后余额（资源事件模型），便于经济模拟与回放
  （[`game_dev_methodology.md`](../../10_research/open_share/game_dev_methodology.md) 第 5.3 节分析）。
- AI 官员与具名居民的输出作为"外部输入"写进事件流，回放读取记录而不重新调用模型，保持内核确定性
  （[`city_rts_slg.md`](../../10_research/open_share/city_rts_slg.md) 第 6.4 节）。
