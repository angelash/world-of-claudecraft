- 2D 小团队首版宜控制链条长度：先保证"原料、加工品、成品"三级以内能闭合，每级都过一遍供给链审计，再加深。

### 2.2 人口与需求

**资料要点**

- 人口在资料中被归为"容量资源"，设计重点是"扩容是否改变策略"（`10_md/game-dev-knowledge/03-core-gameplay-design/resource-system.md`）。
- 取舍设计要求选项"依赖局势"，不能永远固定答案（`10_md/game-dev-knowledge/03-core-gameplay-design/trade-off-design.md`）。
- 资料库没有讨论人口增长、需求层级、幸福度的专文。

**补充（非资料库来源）**

| 作品                      | 人口与需求机制                                             | 可借鉴点                                   |
| ------------------------- | ---------------------------------------------------------- | ------------------------------------------ |
| 《纪元 1800》             | 居民分阶层，满足需求才能升级住宅、解锁下一阶层             | 需求阶梯驱动生产链和城市形态               |
| 《冰汽时代》（Frostpunk） | "希望"与"不满"两条社会指标，法典（Book of Laws）政策取舍   | 政策是可读的显性选择，代价写在条文里       |
| 《环世界》（RimWorld）    | 殖民者心情由大量带时效的正负因子叠加，越过阈值触发精神崩溃 | 可解释的情绪账本，玩家能看到"为什么不开心" |
| 《海岛大亨》（Tropico）   | 居民分属不同政治派系，对政策有不同反应                     | 人口不是同质的，政策会分化民意             |

**分析：对《箱庭纪》的含义**

- 正典的"位阶与人才金字塔"（凡阶约 99%，精英阶约 1%，英雄阶万分之一量级，见 `hakoniwa/docs/20_world/world_bible.md` 第 10.1 节）天然适合作为人口结构的骨架：大部分居民是劳动力与税基，少数精英是官员、将领、匠师的候选。
- 人口可同时承担"劳动力、兵源、税基、信仰来源"四种用途（信仰来自正典第 5 节"神力与信仰"），四者互相争抢，正好构成 `trade-off-design.md` 所说的"真正互斥的取舍"。
- 需求层级建议用显性账本表达（类似 RimWorld 心情因子），这与 `information-design.md` 的"反馈是否能归因"一致，也方便 AI 居民用自然语言解释自身状态。

**补充（非资料库来源）**

- 《模拟人生》的"智能物件"思路：物件广播自己能满足哪些需求，居民按需求缺口给物件打分，属于 Utility AI 的经典形态，计算成本低，适合大量居民。
- 《矮人要塞》《环世界》证明纯规则驱动的性格、心情、关系也能产出大量可复述的涌现故事。
- 斯坦福 Generative Agents（Park 等，2023）用"记忆流、反思、计划"让 25 个大模型居民在小镇中自主生活，展示了大模型居民的上限，也暴露了调用成本与一致性问题（细节待核实）。

**分析：对《箱庭纪》的含义**

- 一座城可能有成百上千居民，不可能每人都调用大模型。资料指向的可行结构是三层：

**补充（非资料库来源）**

- 《环世界》的"AI 叙事者"（Cassandra、Phoebe、Randy 三种风格）按殖民地财富与距上次事件的间隔投放事件，袭击强度随财富上升。这是"GM 型 AI 调度灾害"的成熟样本，与本作"女神担任 GM"高度相关。
- 《冰汽时代》的暴风雪是预告过的终局压力，玩家有时间准备；预告让灾害从"惩罚"变成"挑战"。

**分析：对《箱庭纪》的含义**

- 正典已规定"任何干预都要消耗神力，干预越大消耗越大"（`hakoniwa/docs/20_world/world_bible.md` 第 5 节），这天然就是女神灾害的预算与冷却，可与 RimWorld 叙事者的"财富与间隔"调度结合。
- 女神降灾属于 `rubber-banding.md` 所说的干预，宜显性或半显性：给出神谕预兆、事后可追溯原因（谁干的、为什么），避免玩家觉得"系统在暗中针对我"。
- 灾害必须保留关键物资的合法来源，防止软锁（修仙 GDD 14 的危机规则）。

### 2.6 成长阶段

**资料要点**

| 要点           | 内容                                                                                                                       | 来源                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 三层循环链     | 核心循环"生产-销售-收益"，中层循环"升级-解锁-扩展"，外层循环"目标-成就-荣誉"，驱动关系为收益到升级到目标                   | `10_md/uwa-day/2022/uwaday-2022-魂世界游戏设计方法论.md`                          |

**分析：对《箱庭纪》的含义**

| 阶段（对应正典幕次）               | 玩家主要操作颗粒度         | 应自动化或委托的部分               |
| ---------------------------------- | -------------------------- | ---------------------------------- |
| 据点（第一、二幕：门内庭院、商会） | 亲手摆放、亲手生产         | 无，或只有搬运                     |
| 城（第二、三幕：城建入门）         | 规划区块、定政策、处理请愿 | 单个建筑的生产排程交给工头/AI 居民 |
| 领地（第三幕：领地经营、RTS）      | 指派代理人、定预算、打战役 | 城市内部运营交给城主类 NPC         |
| 国（第四幕起：立国、SLG）          | 外交、战略、法令           | 领地运营交给官员，战场可自动结算   |

- 修仙项目的选型提醒了混合品类的最大风险：经营或战略层一旦压过 RPG 主线，"主角中心"就会被稀释。本作支柱 6 已要求"个人强大永远是战略层的王牌"，每升一层时，下层微操必须有可信的委托机制，否则玩家会陷入决策疲劳。
- 同一战斗是否同时存在"手动 RTS"与"自动结算"两种模式，属于修仙项目明确规避的双规则风险；本作若采用，应让两种模式共享同一套确定性结算内核（见第 3.3 节）。

## 3. RTS

### 3.1 单位与兵种

**资料要点**

| 要点         | 内容                                                                             | 来源                                                                        |
| ------------ | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 战斗定位     | 坦克、输出、爆发、刺客、控制、辅助、治疗、召唤、破坏者、炮台；定位决定互补关系   | `10_md/game-dev-knowledge/09-combat-design/combat-role.md`                  |
| 非对称平衡   | 每个阵营给一个明确优势和一个可利用弱点；"反制不能只有另一名特定角色"；有强弱窗口 | `10_md/game-dev-knowledge/10-multiplayer-game-theory/asymmetric-balance.md` |
| 优势策略来源 | 数值过高、成本过低、反制不足、叠加失控                                           | `10_md/game-dev-knowledge/05-numerical-design/dominant-strategy.md`         |
| 兵种成长样本 | Wesnoth：兵种克制配合地形加成，老兵升级换职业                                    | `00_raw/_external/2026/external-2026-开源游戏源码大全-原始材料.md`          |

**补充（非资料库来源）**

- 经典克制三角（枪克骑、骑克弓、弓克枪）可读性强，但若是唯一的克制维度，容易变成纯石头剪刀布。《全面战争》在其上叠加士气、侧翼与背击、疲劳，使同样的兵种在不同站位下价值不同。

**分析：对《箱庭纪》的含义**

- 正典的九个职能（`hakoniwa/docs/20_world/world_bible.md` 第 10.2 节）可作为兵种的来源维度：兵种 = 职能（定位）× 位阶（品质）× 装备/种族（变体）。这样 RPG 层的职业认知能直接迁移到 RTS 层。

**资料要点**

**补充（非资料库来源）**

- 阵型通常实现为"编队锚点加槽位偏移"：整支小队寻一条路，个体只追随自己的槽位并做局部避让，既省寻路开销又保持队形。
- 《全面战争》的士气与溃逃机制让战斗不必打到最后一兵一卒，阵型被击穿的后果通过士气连锁表现出来。

**分析**

- 2D 俯视或斜视角下，阵型的可读性比 3D 更好，可以把"前排、侧翼、后排"作为显式槽位，玩家给小队下达阵型指令，内核按槽位结算接敌与仇恨。

**分析：对《箱庭纪》的含义**

- 本作支柱 6"个人强大永远是战略层的王牌，但一个人赢不了整场战争"（`hakoniwa/docs/00_vision/vision.md`）与上表的共同结论一致。资料与补充案例归纳出的杠杆：

| 杠杆         | 作用                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 空间稀缺     | 英雄一次只能在一个战场、一段战线；在 A 战场就意味着 B 战场空虚             |
| 乘数而非加数 | 英雄的价值体现为光环、士气、指挥半径、破阵，而不是一个人打掉整支军队的血量 |
| 爆发窗口     | 英雄的毁灭性能力有冷却和灵素消耗，形成"王牌时刻"而非常态                   |
| 对等威胁     | 敌方也有英雄、他神勇者、隐藏强者（正典第 12 节），能牵制主角               |
| 信息与时间   | 主角强但不知道敌人底牌（支柱 3），侦察与情报决定王牌何时出手               |
- 若主角能单人清场，RTS 层会退化为"跑去开大"的单一解，落入 `dominant-strategy.md` 描述的风险。

**分析**

- 正典的"神之视线"（女神只能通过信徒见闻、神殿、铭录、神谕对象感知世界，见 `hakoniwa/docs/20_world/world_bible.md` 第 5 节第 6 条）与"世界真值、知识层分离"的数据结构完全吻合：每个 AI 国家、每位女神、玩家都有自己的知识层，谍报就是在知识层之间移动、伪造、延迟信息。
- 这要求 AI 统治者的大模型输入只能是其知识层的摘要，不能是世界真值，否则既违反公平原则，也破坏"女神会误判"的剧情引擎。

### 4.5 科技或文化树

**资料要点**

- 资料库没有科技树专文。相关只有：点数天赋常见于养成、SLG、模拟经营，核心是路线取舍（`10_md/game-dev-knowledge/04-system-design/talent-system.md`）；数值膨胀与优势策略的风险（`power-creep.md`、`dominant-strategy.md`）。
- 一个值得注意的类比："掌天瓶"的本质不是直接给钱，而是压缩生产周期、提高资本周转速度，是生产率技术（`10_md/_external/2026/凡人修仙传-人界地理与现实映射/04-资源物品技术与市场.md`）。这提示科技的价值可以设计成"改变周期与效率"，而不只是"加攻击力"。
- 开源样本：FreeOrion（舰船设计、外交与科技树）、Freeciv-web（城市、政府、军队）（`10_md/_external/2026/external-2026-开源游戏源码大全-玩法与引擎索引.md`）。

**补充（非资料库来源）**

- 《文明 6》分科技树与市政树两条线，并用"尤里卡"（完成特定行为加速研究）把研究和玩法行为挂钩。
- 《群星》用"从若干候选中抽选研究项目"的方式降低固定最优路线。

**分析**

- 正典已有"千门回廊"作为个人成长树（`hakoniwa/docs/20_world/world_bible.md` 第 11 节）。国家层是否另起一棵科技/文化树，还是让"立国之门"等门延伸到国家层，属于设计决定，本文只指出：资料支持"用行为解锁"（尤里卡、钥匙）而非"纯资源堆研究点"，与"钥是经历、物品、人物羁绊、抉择、地点"的正典设定一致。

### 5.5 防止通胀

| 手段           | 内容                                               | 来源                                                                      |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| 四张表         | 每种资源都要有产出、消耗、库存、价格四张表         | `10_md/game-dev-knowledge/11-economy-monetization/inflation.md`           |

### 6.3 "大模型出意图，内核出动作"的管线（分析）

在游戏内，`human-in-the-loop.md` 中"人"的角色由"规则校验器加设计师预设的上限"替代。结合上表，一条可行管线如下：

| 步骤         | 内容                                                                                            | 依据                                                             |
| ------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 1 感知摘要   | 从该 AI 的知识层（不是世界真值）生成结构化摘要：国力、威胁、关系、近期事件、可选行动菜单        | 修仙 GDD 13 的真值/知识分离；`behavior-ai.md` 信息边界           |
| 2 大模型提议 | 从枚举菜单中选择意图并填参数，附理由；不能发明菜单外的动作                                      | `llm-agent.md` 的 allowed_tools 与 output_contract               |
| 3 内核校验   | 合法性（资源、权限、条约、正典约束）、预算（神力、国库、频率）、风险等级                        | `agent-safety.md` P0 到 P4；`ai-npc.md` 禁止内容                 |
| 4 规划分解   | HTN 或 GOAP 把意图分解为可执行计划                                                              | `goap.md`                                                        |
| 5 执行       | 行为树、状态机、Utility、寻路在确定性 tick 中执行                                               | `behavior-tree.md`、`deterministic-simulation.md`                |
| 6 回写与记忆 | 结果作为事件写入时态快照与 AI 记忆，供下次感知                                                  | 修仙 GDD 13 的事件与快照；`procedural-narrative.md` 世界状态字段 |
| 7 日志与表达 | 记录 plan、tool_call、observation、decision、output、rollback；大模型把结果写成国书、宣言、传闻 | `llm-agent.md` 执行日志                                          |
| 兜底         | 模型不可用、超时、输出非法时，由 Utility 打分直接选意图                                         | `ai-npc.md` 回退；`goap.md` 兜底                                 |

**风险分级示例（分析，借用 agent-safety 的分级思路）**

| 动作                                   | 建议等级                         | 理由                                                                     |
| -------------------------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| 生成外交文本、传闻、请愿书             | 低风险，模型直接输出             | 只影响表达，不改状态                                                     |
| 调整本国预算比例、建造队列             | 受控写入，内核校验上下限         | 影响经济，但可逆、有上限                                                 |
| 宣战、缔约、毁约、处决有名 NPC         | 高风险，需满足规则前置条件与冷却 | 不可逆，影响剧情与玩家利益                                               |
| 修改他国状态、改写正典、直接改战斗结算 | 禁止                             | 违反"模型提议，内核裁决"（`hakoniwa/docs/00_vision/vision.md` 不做什么） |

### 6.4 确定性、回放与批量模拟

- 资料要求模拟与线上逻辑同源，种子与配置可追溯（`10_md/game-dev-knowledge/18-ai-pcg/simulation.md`、`deterministic-simulation.md`）。
- 分析：大模型输出天然不确定，若把它当作"外部输入"（与玩家命令同等）记录进事件流，回放时读取记录而不重新调用模型，就能保持内核确定性。
- 分析：平衡验证需要批量跑局，而大模型调用成本高。规则档（Utility 加 HTN）应能独立驱动全部 AI 国家，作为批量模拟的基线；这也正是愿景中"降级档可完整通关"的要求（`hakoniwa/docs/00_vision/vision.md` 产品形态）。

### 6.5 调用频率与成本预算（分析）

| AI 主体              | 建议调用时机                                             | 是否必须有规则兜底 |
| -------------------- | -------------------------------------------------------- | ------------------ |
| 女神（GM）           | 事件驱动（祈祷、神迹、重大战报）与固定周期（如每游戏月） | 必须               |
| 国家统治者           | 季度或重大事件（宣战、联姻、灾害）                       | 必须               |
| 城主、将领、商会首脑 | 月度，或玩家对话触发                                     | 必须               |
| 有名有姓的 NPC       | 对话触发，加日程节点                                     | 必须               |
| 普通居民、普通士兵   | 不调用大模型，纯规则                                     | 不适用             |

依据：`goap.md`"每帧重规划性能不可控"；`llm-agent.md`"限额与停止条件"；DOTS 仿真的"按状态分类批处理"。
