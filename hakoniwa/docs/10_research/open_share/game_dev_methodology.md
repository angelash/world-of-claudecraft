### 2.2 核心体验：MDA、DPE 与复杂度治理

**MDA 八类体验与本作取舍**（来源：`10_md/game-dev-knowledge/01-game-design-theory/mda-mechanics-dynamics-aesthetics.md`）

| 体验            | 含义               | 本作取舍（分析）                         |
| --------------- | ------------------ | ---------------------------------------- |
| Fantasy 幻想    | 扮演身份           | 全程主轴：穿越者、龙傲天、立国者         |
| Discovery 发现  | 探索未知、理解世界 | 全程主轴：千门回廊、层层揭秘             |
| Narrative 叙事  | 故事推进           | 全程主轴                                 |
| Challenge 挑战  | 克服困难           | 战斗与 RTS/SLG 阶段加重                  |
| Expression 表达 | 风格与创造         | 城建、立国、技能搭配阶段加重             |
| Fellowship 社交 | 与人连接           | 单机下替换为与 AI 同伴、居民、女神的关系 |
| Sensation 感官  | 视听刺激           | 战斗打击感与 2D 演出，服务而非主轴       |
| Submission 消遣 | 放松打发时间       | 只在城建的"恢复段"少量出现               |

MDA 使用流程：先写 1 到 3 个具体的 A，再写支撑它的 D，再写诱发 D 的 M；原型后反向验证，删掉解释不了 A 的 M。
风险信号："只说爽、好玩"；为了"丰富"而加机制；改完只看胜率、不看行为路径。

**DPE 五层并行**（来源：`10_md/game-dev-knowledge/01-game-design-theory/dpe-design-play-experience.md`）

| 层         | 关注               | 本作风险（分析）                                 |
| ---------- | ------------------ | ------------------------------------------------ |
| Learning   | 是否理解、能否应用 | 揭秘必须来自调查与行动，而不是女神旁白           |
| Story      | 意义与记忆点       | 每层拉远是否真的改写了认知                       |
| Gameplay   | 玩法本身           | 三套玩法叠加后的主要动作是否清楚                 |
| UX         | 清楚、低摩擦       | 多层 HUD 叠加                                    |
| Technology | 稳定、不打断体验   | LLM 延迟与一致性直接决定叙事能否成立，要单独评审 |

**深度与复杂度**（来源：`10_md/game-dev-knowledge/01-game-design-theory/depth-vs-complexity.md`）

- 四象限处理：低复杂高深度重点保护；高复杂高深度分层教学、隐藏高级信息、提供工具；高复杂低深度优先裁剪或重构。
- 复杂度六个来源：规则、信息、操作、计算、记忆、维护。增加深度六种方法：互动、取舍、反制、信息差、时机窗口、组合空间。
- 关键检查：能否用已有规则表达新效果，而不是新增例外。
- 分析：技能、城建、RTS、SLG 叠加极易落入"高复杂低深度"。建议全作共用一套规则语义（同一套标签、属性、效果枚举同时作用于技能、建筑、兵种），并让旧阶段的事务逐步自动化。

**设计分层（GDC 2025，Harvey Smith 讲 Prey）**（来源：`10_md/gdc/2025/gdc-2025-游戏设计规则2025.md`）

- 用"决策丰富的空间"实现深度：不是无限自由，而是"策划空间内的玩家自由"。
- 六层叠加：非线性可探索空间、有限资源、响应式物理、基于感官的 AI、战术优势空间、环境推理与叙事。
- 一致性规则：物品用途永远一致，"永远不是假装的"。
- 同一篇里的简化算法（Noah Falstein）：找到乐趣 -> 加特性 -> 简化直到坏掉 -> 退回一步 -> 重复。
  "如果不影响玩家情感状态，可能是在浪费时间。"

### 2.3 核心循环：分钟级、小时级、周目级

**资料框架**

| 来源                                                          | 层级划分                                                                                                             |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `10_md/game-dev-knowledge/01-game-design-theory/core-loop.md` | 微循环（秒到几十秒）、核心循环（几十秒到几分钟）、单局循环（几分钟到一局）、局外循环（天到周）、运营循环（周到赛季） |
| `10_md/game-dev-knowledge/09-combat-design/combat-loop.md`    | 微循环 0.2 到 3 秒、技能循环 3 到 30 秒、遭遇循环 30 秒到数分钟、对局循环、局外复盘                                  |
| `10_md/uwa-day/2022/uwaday-2022-魂世界游戏设计方法论.md`      | 循环链：核心循环（生产、销售、收益）、中层循环（升级、解锁、扩展）、外层循环（目标、成就、荣誉），循环间相互驱动     |
| `10_md/game-dev-knowledge/04-system-design/session-design.md` | 会话七段：入口、开局、中段、高潮、收束、结算、再入口；每 30 到 60 秒一次可感知进展；每局至少一个转折                 |

奖励要改变下一轮选择而不只是加数值；能承载新内容。常见误区："战斗 -> 成长 -> 更强战斗"写得太粗；
把奖励循环当核心循环；运营循环压过核心循环。

**分析：本作多尺度循环映射**（与 `hakoniwa/docs/40_design/game_framework.md` 第 3 节对齐）

| 尺度   | 资料层级           | 前期（个人、队伍层）                                       | 中期（经营、战场层）              | 后期（战略、神域层）         | 主动机       |
| ------ | ------------------ | ---------------------------------------------------------- | --------------------------------- | ---------------------------- | ------------ |
| 秒级   | 微循环             | 选目标、技能、走位、冷却                                   | 下令、框选、技能释放              | 地图指令                     | 能力感、感官 |
| 分钟级 | 核心循环           | 探索 -> 遭遇 -> 获得情报或钥 -> 开门                       | 规划 -> 建造/调兵 -> 结算 -> 调整 | 外交提案 -> 回应 -> 局势变化 | 发现、能力感 |
| 小时级 | 单局/会话          | 卷入一条纷争 -> 与 AI 众生周旋 -> 本层高潮 -> 结果写回世界 | 一次远征、一个内政周期、一场战役  | 一轮诸国博弈                 | 叙事、自主   |
| 幕级   | 局外循环           | 落地 -> 暗面 -> 拉远                                       | 同左，规模放大                    | 同左                         | 发现、叙事   |
| 周目级 | 运营循环（单机化） | 审定 -> 结局 -> 下一期                                     |                                   |                              | 表达、可重玩 |

阶段转换的硬要求（分析，依据 core-loop、skill-floor-ceiling、sunk-cost）：
主要动作换了，就要配一次"二次 Onboarding"；动机要连续（国家力量是勇者力量的放大），否则玩家会感觉换了一款游戏；
前期学会的东西要折算进后期，不能作废。

### 2.4 玩家动机模型

**SDT 与动机质量光谱**（来源：`10_md/game-dev-knowledge/02-player-psychology/self-determination-theory.md`）

- 自主（"这是我选的"）、能力（"我变强了、我懂了"）、关系（"我和人、角色、社群有连接"）。
- 光谱从低到高：无动机 -> 外在调节（为奖励或避免惩罚）-> 内摄调节（压力、攀比）-> 认同调节 -> 整合调节（与自我身份一致）-> 内在动机。
- 风险信号：奖励一停核心玩法就没人碰；玩家上线像上班。
- 分析：龙傲天幻想的终点应是整合调节（"我是这个国家的缔造者"），用身份认同而不是日常任务维持中后期。

**十个动机维度与选择方法**（来源：`10_md/game-dev-knowledge/01-game-design-theory/player-motivation.md`）

- 维度：能力感、自主感、关系感、成就、社交、沉浸、探索、表达、竞争、放松，每个都有对应风险（例如自主感的风险是"选项过多成负担"）。
- 理论来源：SDT、Yee 在线游戏动机、Quantic Foundry、Bartle。
- 方法：只选 2 到 3 个主动机，映射到核心循环，分阶段配置（新手靠能力感，熟练靠策略深度，长期靠目标、社交、表达），
  分别检查 1 分钟、1 局、1 周各满足了什么。

**Bartle 的两条轴**（来源：`10_md/game-dev-knowledge/02-player-psychology/bartle-player-types.md`）

- 关注对象（World 或 Players）乘以行为方式（Acting 或 Interacting），二维结构比四个标签更重要。
- 分析：单机下把 Players 轴替换为 AI NPC：成就（等级、领土）、探索（真相、隐藏能力）、社交（NPC 羁绊）、支配（征服、权谋）。

**关系感的六种连接**（来源：`10_md/game-dev-knowledge/02-player-psychology/relatedness.md`）
玩家与玩家、角色、阵营、社群、系统（系统记住并回应玩家）、创作者。
分析：本作把"玩家与创作者"的关系具象为女神与造主，可作为元叙事层；"玩家与系统"由 NPC 记忆实现。

**分析：分阶段主动机配置**

| 阶段         | 主动机         | 次动机     | 需要警惕的风险                       |
| ------------ | -------------- | ---------- | ------------------------------------ |
| 序章到第一幕 | 发现、能力感   | 沉浸       | 开场看太久剧情，首个有效行动太晚     |
| 第二到三幕   | 自主、关系     | 成就、表达 | 系统叠加导致认知负荷与决策疲劳       |
| 第四到六幕   | 表达、整合身份 | 挑战、发现 | 只剩管理杂务；正反馈失控导致没有悬念 |

### 3.2 能力发掘感

| 方法                 | 要点                                                                                                                                 | 来源                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 变强也变懂           | 能力感六个来源：清晰目标、即时反馈、可学习的失败、难度递进、技能表达、成长可见；风险信号是"玩家只看到战力变高，说不出自己学会了什么" | `10_md/game-dev-knowledge/02-player-psychology/competence.md`                                                                     |
| 渐进揭示与代价换信息 | 七种信息（公开、私有、隐藏、概率、模糊、历史、元信息）；可见性结构含"渐进揭示"与"代价换信息"；隐藏信息要留推理线索                   | `10_md/game-dev-knowledge/03-core-gameplay-design/information-design.md`                                                          |
| 先看见后获得         | 视觉、机制、威胁、奖励、叙事、系统六类预示；不可达目标要告诉原因或暗示未来能力                                                       | `10_md/game-dev-knowledge/06-level-design/foreshadowing.md`                                                                       |
| 进度赠予             | 初始赠予、历史折算、回流赠予、阶段解锁、预填进度条；赠予要有可信理由                                                                 | `10_md/game-dev-knowledge/02-player-psychology/endowed-progress.md`                                                               |
| 目标梯度             | 越接近目标投入越多；长目标拆成阶段奖励                                                                                               | `10_md/game-dev-knowledge/02-player-psychology/goal-gradient.md`                                                                  |
| 随机奖励与保底       | 好的随机让玩家"应对变化"；关键内容要有保底和历史记录                                                                                 | `10_md/game-dev-knowledge/02-player-psychology/variable-reward.md`、`10_md/game-dev-knowledge/05-numerical-design/pity-system.md` |
| 构筑与信息风险       | 六种风险收益结构，其中"构筑风险"与"信息风险"适合试用未知能力                                                                         | `10_md/game-dev-knowledge/01-game-design-theory/risk-reward.md`                                                                   |
| 线性与自主并存       | 给有限但真实的选择；过度自动化替玩家做关键判断是误区                                                                                 | `10_md/game-dev-knowledge/02-player-psychology/autonomy.md`                                                                       |
| 动词随阶段扩张       | 五层动词：基础、系统、策略、社交、叙事（选择、背叛、结盟、保护）；核心动词能用 3 到 5 个词说清                                       | `10_md/game-dev-knowledge/03-core-gameplay-design/verb-design.md`                                                                 |

由此可得的本作原则（分析）：

1. 每扇门揭示一条可理解的新规则（原理、限制、组合），并配一个专门考它的遭遇，让"变强"同时是"变懂"。
2. "解锁顺序线性，使用方式自主"：主线保证的门是线性的，门后能力的用法、组合、路线由玩家决定；天赋可用"主线必得加二到三选一倾向"。
3. "女神恩赐"或"灰色的技能栏"是叙事上可信的进度赠予，也是最直接的系统预示。
4. 关键觉醒走兑换保底或软保底，不让龙傲天幻想被运气否定。
5. "能做什么"跟着"知道什么"一起解锁：动词表按幕扩张（前期移动、攻击、释放、观察；中期建造、任命、交易；后期结盟、宣战、册封）。

**补充（非资料库来源）：三轴信息差。** 《月光下的异世界之旅》式的喜剧与揭示，来自主角实力远超常人却长期不自知，
周围人又反过来误判他。可以把"能力发掘"拆成三条独立推进的信息轴：

| 轴       | 谁掌握           | 玩法载体（分析）                    | 揭示方式           |
| -------- | ---------------- | ----------------------------------- | ------------------ |
| 实际强度 | 内核（真实数值） | 隐藏属性、门后能力                  | 只通过结果被观察到 |
| 自我认知 | 玩家             | 鉴定上限、能力描述的"已知/未知"字段 | 开门、试用、事故   |
| 世界认知 | AI 众生与女神    | 传闻、信任、"凡人不信"              | 目击、传播、失真   |

三条轴错位产生喜剧（自我低估）与悬念（世界高估或低估）。这与 `vision.md` 的"谨慎的强者"支柱和
`game_framework.md` 第 9 节"认知与凡人不信"一致，资料库中 information-design 的"私有信息、模糊信息、元信息"可作为字段依据。

### 3.3 心流与"龙傲天"的结构性矛盾

**心流四格**（来源：`10_md/game-dev-knowledge/01-game-design-theory/flow.md`）

| 状态               | 处理                       |
| ------------------ | -------------------------- |
| 低能力高挑战：焦虑 | 降低惩罚、拆小目标、给示范 |
| 高能力低挑战：无聊 | 加变化、约束、更高阶目标   |
| 低能力低挑战：冷淡 | 给清晰奖励和学习路径       |
| 高能力高挑战：心流 | 保持反馈清晰，逐步加深     |

检查项：目标 3 秒内能理解；先给一次能成功的挑战，再逐个加变量；进阶靠技能空间，不靠数值门槛；
动态难度如果偷偷调，会破坏公平感和控制感。

**矛盾与解法。** 龙傲天设定天然容易落入"高能力低挑战"的无聊区。资料给出的解法组合：

| 解法                   | 要点                                                                                     | 来源                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 阶梯式成长并重置参照系 | 增长曲线选阶梯式，与揭秘层级同步；每升一层重置参照系（小镇无敌，到国家层又成为挑战者）   | `10_md/game-dev-knowledge/03-core-gameplay-design/snowball.md`          |
| 难度转向非数值来源     | 七种难度来源：数值、规则、时间、信息、空间、资源、对手；不要只加血加攻；高压后安排恢复段 | `10_md/game-dev-knowledge/05-numerical-design/difficulty-curve.md`      |
| 用约束而不是削弱       | 七种约束（资源、时间、空间、信息、规则、操作、社交）；信息和规则约束优于直接削数值       | `10_md/game-dev-knowledge/03-core-gameplay-design/constraint-design.md` |
| 分层 TTK               | 普通单位、精英、Boss 分别设目标区间；"秒杀杂兵"是爽点可保留，精英与 Boss 必须留反制窗口  | `10_md/game-dev-knowledge/05-numerical-design/ttk-time-to-kill.md`      |
| 避免多指数叠加         | 列出所有战力来源并估算贡献占比；不要把多个指数增长系统叠在一起                           | `10_md/game-dev-knowledge/05-numerical-design/power-curve.md`           |
| 压抑后释放             | 战斗紧张六段：进入、试探、升温、高潮、收束、复盘                                         | `10_md/game-dev-knowledge/09-combat-design/tension-curve.md`            |
| 力量要可归因           | 爽感可以强，但要有成本、条件、冷却或反制；新手早期给小力量幻想，后期给策略力量幻想       | `10_md/game-dev-knowledge/07-narrative-design/power-fantasy.md`         |
| 技能表达转移           | 角色层面差异被压缩时，技能表达转到战术组合与战略规划；RPG 到 RTS/SLG 是典型曲线断层点    | `10_md/game-dev-knowledge/01-game-design-theory/skill-floor-ceiling.md` |

### 3.4 长期目标与节奏曲线

| 方法         | 要点                                                                                     | 来源                                                                |
| ------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 分层目标     | 目标按 5 分钟、1 天、7 天、30 天、1 赛季分层（本作可换成会话、幕、周目）                 | `10_md/game-dev-knowledge/04-system-design/progression.md`          |
| 未完成效应   | 未完成目标要可管理；完成时要有释放感；风险是"心理债务"（完成一个立刻又塞三个）           | `10_md/game-dev-knowledge/02-player-psychology/zeigarnik-effect.md` |
| 峰终定律     | 峰值来自玩家行动而不是开奖动画；结尾讲清发生了什么、获得了什么、下一步做什么             | `10_md/game-dev-knowledge/02-player-psychology/peak-end-rule.md`    |
| 尊重沉没成本 | 用纪念、称号、记录承认玩家的老投入；改版要尊重已有投入                                   | `10_md/game-dev-knowledge/02-player-psychology/sunk-cost.md`        |
| 好重复       | 每次有新局势、新判断；内容生产速度要赶得上消耗速度；完成型叙事游戏不要强行加刷取         | `10_md/game-dev-knowledge/01-game-design-theory/replayability.md`   |
| 节奏六段     | 进入、教学、紧张、高潮、恢复、期待；画节奏曲线，标出压力峰值和恢复点；学完立刻高压是风险 | `10_md/game-dev-knowledge/06-level-design/pacing.md`                |
| 决策疲劳     | 低价值操作自动化；默认方案附推荐理由并能一键恢复；高价值选择提供预览和撤销               | `10_md/game-dev-knowledge/02-player-psychology/decision-fatigue.md` |

分析：

- 每一层（小镇、城市、王国、诸国、诸族、诸神）都设计一个"揭秘峰值"（必须由玩家行动触发）和一个"阶段结尾"，结尾自然引出下一层的悬念。
- 层层揭秘是未完成效应的正向用法：每层解开一个旧悬念、埋下一个更高层的悬念，但每层都要有明确的"真相结算"，NPC 产生的支线要限量并标优先级。
- 立国阶段内政用"AI 大臣给带理由的默认方案、玩家保留否决权"缓解决策疲劳；这也是本作"离手"主题（`game_framework.md` 第 11 节）的玩法化落点。

**4.3.2 补充（非资料库来源）：影视与文学中的成熟技巧**

资料库没有"拉远镜头""天上序幕"等叙事结构专卡。以下为行业与叙事学常识，`hakoniwa/docs/30_story/narrative_design.md`

| 技巧                                                     | 操作要点                                                               | 对本作的提示                                                 |
| -------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ |
| 拉远镜头（Zoom-out，如短片《十的次方》式的连续尺度跳跃） | 每次后撤都保留上一帧的主体在画面里，让旧画面获得新意义                 | 每层拉远必须"回扣"上一层的具体人物或事件，而不是换一个新舞台 |

| 契诃夫之枪                                               | 出现在第一幕的枪，后面必须开火                                         | 序章的每个专有名词都要在台账里有回收位置                     |

### 4.5 不可靠叙述者

资料库没有"不可靠叙述者"专卡，可用的相邻材料：

| 材料                   | 要点                                                                                                | 来源                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 模糊信息与隐藏信息     | NPC 的态度属于模糊信息，真实目的属于隐藏信息，都要配推理线索                                        | `10_md/game-dev-knowledge/03-core-gameplay-design/information-design.md` |
| 信息边界表             | AI 可用：按规则可感知的单位与位置、公开数值、根据已发生行为的推测；禁止读取隐藏随机结果、未揭示奖励 | `10_md/game-dev-knowledge/18-ai-pcg/behavior-ai.md`                      |
| 角色发言与规则解释分离 | 误区："把角色自然聊天和官方规则解释混在一起，玩家分不清承诺来源"                                    | `10_md/game-dev-knowledge/18-ai-pcg/ai-npc.md`                           |
| 规则文案一致           | UI 文案与实际配置不一致会严重破坏信任                                                               | `10_md/game-dev-knowledge/03-core-gameplay-design/rule-system.md`        |

**补充（非资料库来源）：不可靠叙述的类型与公平规则。**

| 类型           | 说明                       | 本作对应（分析）         |
| -------------- | -------------------------- | ------------------------ |
| 有立场的说谎者 | 知道真相但出于利益只说一半 | 各位女神                 |
| 无知者         | 真心相信错误信息           | 凡人居民、传闻           |
| 偏见者         | 事实正确但解释带偏         | 教会、各国史官           |
| 自欺者         | 对自己也不诚实             | 可用于个别女神或上代勇者 |

公平规则（分析）：

1. **系统层永远可靠，角色层可以不可靠。** 内核结算、鉴定结果（在上限内）、任务条件、奖励承诺必须真实；只有"角色说的话"可以失真。UI 要区分两者。
2. **谎言可验证。** 每条重要谎言在台账中登记真相与可验证途径，玩家事后能找到"她当时为什么那样说"的证据。
3. **偏差是人格的一部分。** 每位女神写一份"偏差档案"（她会夸大什么、隐瞒什么、在什么条件下说真话），作为提示词的固定输入，而不是每次即兴。

| 五个互动层次     | 即时（Fable 式反应、解说、对话树）、任务级（Fallout 3）、多路径（Fallout 4，成本高）、角色级（State of Decay、Watch Dogs Legion）、完全模拟（Dwarf Fortress）                                  | 同上                                                                  |
| Barks 最重要     | 过场可能只看一次，闲聊台词一直陪伴玩家，"如果糟糕会成为主要印象"；可做到形势判断（"我们处于劣势"）                                                                                             | 同上                                                                  |
| 循环回收结构     | 选项 A、B、C 汇合到同一点再继续，"感觉有选择、不会无限分叉"                                                                                                                                    | 同上                                                                  |
| 第一次扮演自己   | The Suffering 的观察：几乎所有人第一次都选善良；"第一次玩扮演自己，第二次扮演对立面"；演讲者偏好不明确标记善恶的灰色道德                                                                       | 同上                                                                  |

分析：本作适合的互动层次组合是"即时反应（LLM Barks 与认知系统）+ 任务级（纷争结果写回世界）+ 角色级（同伴与 AI 众生）"，
多路径只在幕级做少量高影响分支并在下一幕开头汇合。序章就要用一次"被记住的选择"建立"世界会回应你"的规则，避免"开头有选择，之后没有"的问题模式。
NPC 记忆是"承认反馈"最自然的实现，主线收束时也要提及玩家走过的不同路径。

### 4.7 叙事测试

- 资料：叙事难测，因为完整叙事要整体才能评估；方法是垂直切片测试、纸面测试（有人向测试者口述叙事并观察反应）、完整后的最终调整
  （`10_md/gdc/2025/gdc-2025-游戏故事的互动性设计.md`）。
- 资料：试玩询问玩家记住了谁、发生了什么、为什么行动；验证玩家能否记住角色与阵营，而不只看剧情文本
  （`10_md/game-dev-knowledge/07-narrative-design/storytelling.md`、`narrative-design.md`）。
- 分析：每幕的验收问题至少包含"序章哪句话换了意思""你觉得哪位女神在说谎""你为什么帮了这一方"。

### 5.2 数值框架

| 方法           | 要点                                                                                                                                            | 来源                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 三张图对齐     | 时间轴、经济曲线、强度曲线必须对齐；先画曲线再填表                                                                                              | `10_md/game-dev-knowledge/05-numerical-design/scaling.md`           |
| 缩放公式       | 线性 `base + level*k`；指数 `base*r^level`；多项式 `base + aL + bL^2`；乘法 `A*B*C`；递减 `x/(x+k)`；分段、阶梯、软上限；同类加成优先加法或递减 | 同上                                                                |
| 伤害公式       | 先定目标 TTK 再反推攻防血与倍率；基础、增伤、暴击、减免、护盾、最终修正分开算；明确同类增益是加法还是乘法；高风险属性设上限；日志记录各项       | `10_md/game-dev-knowledge/05-numerical-design/damage-formula.md`    |
| 战力来源       | 列出所有来源并估算贡献占比；关键节点做倍率表；看斜率不看单点                                                                                    | `10_md/game-dev-knowledge/05-numerical-design/power-curve.md`       |
| 爆发与续航分维 | 有效 DPS、窗口 DPS、1 到 3 秒峰值、覆盖率、续航净值；爆发要有冷却、预警或成本                                                                   | `10_md/game-dev-knowledge/05-numerical-design/dps-burst-sustain.md` |
| 期望值与长尾   | `EV = Σ(结果价值 × 结果概率)`；EV 之外看方差、P50、P90、P99                                                                                     | `10_md/game-dev-knowledge/05-numerical-design/expected-value.md`    |
| 性价比         | `有效性价比 = 期望收益 × 适配系数 × 成功概率 / (资源 + 时间 + 机会 + 风险成本)`；不同收益不要硬合成一个战力分                                   | `10_md/game-dev-knowledge/05-numerical-design/cost-efficiency.md`   |
| 优势策略       | 七种来源；识别为高使用、高胜率、难反制；优先调成本、条件、成型速度和反制，而不是削到没人玩                                                      | `10_md/game-dev-knowledge/05-numerical-design/dominant-strategy.md` |
| 平衡流程       | 先写设计目标再看数据；每次调整记录原因、预期、指标、回滚条件；先用模拟器跑极端组合，再找真人验证                                                | `10_md/game-dev-knowledge/05-numerical-design/balance.md`           |

分析：

- 龙傲天题材最大的数值风险是"主角乘装备乘同伴乘女神加护乘国力"的连乘。建议先定乘区结构（同类加法、异类少量乘区），
  主角用阶梯或 S 曲线，国力另起一套坐标，两者用带上限的转换器连接。
- 本作在三张图之外再加一张"幕间衔接图"，因为中期断档、中期卡点都集中出现在阶段边界。
- SLG 部队战斗复用个人战斗的公式骨架与事件链，只是尺度不同。

### 5.3 经济平衡

| 方法       | 要点                                                                                                                                             | 来源                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 经济七要素 | Source 来源、Sink 消耗、Faucet 水龙头、Drain 排水口、Converter 转换器、Store 储存、Market 市场；产销闭合；不能有套利；区分"体验奖励"和"经济投放" | `10_md/game-dev-knowledge/03-core-gameplay-design/economy-design.md`     |
| 资源分类   | 货币、行动、时间、容量、风险、信息、组合；每种资源至少对应一个高频决策；转化链过长会黑箱；排查资源死路和无限循环                                 | `10_md/game-dev-knowledge/03-core-gameplay-design/resource-system.md`    |
| 经济曲线   | 早期缺口、中期卡点、后期通胀、消耗不足、消耗过重、套利循环；画 1、7、30 日库存曲线并看分布                                                       | `10_md/game-dev-knowledge/05-numerical-design/economy-curve.md`          |
| 回收       | 回收要和目标绑定、口径可算、有替代路径；每种资源写主要产出、主要消耗、目标库存区间                                                               | `10_md/game-dev-knowledge/11-economy-monetization/economy-sink.md`       |
| 通胀       | 七种来源；不要靠持续涨价解决通胀；针对头部库存设专门回收口                                                                                       | `10_md/game-dev-knowledge/11-economy-monetization/inflation.md`          |
| 软硬通货   | 硬通货稀缺高价值，软通货大量产出；各货币用途不要重叠                                                                                             | `10_md/game-dev-knowledge/11-economy-monetization/hard-soft-currency.md` |
| 反馈循环   | 正反馈放大差距，负反馈抑制差距；按目标选结构；风险信号：优势过早锁定、多个循环叠加后失控                                                         | `10_md/game-dev-knowledge/01-game-design-theory/feedback-loop.md`        |
| 翻盘       | 好翻盘可解释、需代价、领先方能防守；翻盘点集中在关键阶段形成情绪峰值                                                                             | `10_md/game-dev-knowledge/03-core-gameplay-design/comeback.md`           |
| 经济模拟   | 产消表含基础、活动、长期消耗与异常项；误区：玩家模型过于理性、只模拟产出不模拟消耗上限                                                           | `10_md/game-dev-knowledge/18-ai-pcg/procedural-economy-simulation.md`    |

分析：

- 从 RPG 到立国，相当于从"个人经济"迁移到"长线养成加市场"。旧资源要通过转换器接入新经济，不能直接作废；
  国家产能起来后冒险金币会贬值，冒险奖励要转向国家生产不了的东西（人才、神器、情报）。
- 硬通货（神恩、信仰、神器碎片）只来自关键事件与女神，城建刷不出来，这同时是女神 GM 介入经济的唯一受控入口。
- SLG 的"领土、资源、军力、领土"是强正反馈，用维护成本、边际递减、AI 势力联合制衡抑制，联合反扑必须可预警。
- 资源 ID 与 source/sink 的 reason 枚举在概要设计期就定稿（`10_md/game-dev-knowledge/13-data-analysis/event-schema.md` 要求资源事件带 reason 与 balance_after）。

## 6. AI 与 PCG

资料库总原则：AI 产物默认是草案或候选，只有通过业务验收、规则校验和责任确认后才能进入正式流程；
任何生成或 Agent 流程都必须有输入版本、输出契约、校验规则、人工 owner 和回滚路径（`10_md/game-dev-knowledge/18-ai-pcg/README.md`）。
运行时的大模型在本作应定位为"表达层加提议层"，不做裁决，与 `game_framework.md` 第 13 节"模型提议，内核裁决"一致。

分析：每位女神和每个有名 NPC 的知识，就是"按 applies_to（该角色或阵营）与 permission（当前揭秘阶段）过滤后的检索视图"。

资料未涉及：NPC 之间的流言传播模型、NPC 说谎或误信的建模、长期记忆的摘要压缩、多个 LLM 角色互相对话时的信息隔离。

### 6.4 与确定性内核的隔离

**资料中的明确说法**

| 说法                                                                                                                                                                            | 来源                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 确定性条件：固定 tick、稳定输入顺序、统一 RNG、配置版本一致、稳定排序、"状态隔离：表现、动画、物理、网络延迟不直接改规则"、checksum；误区"机器人使用真实时间或异步结果影响决策" | `10_md/game-dev-knowledge/15-tech-architecture/deterministic-simulation.md`               |

**资料未涉及，分析补齐**：LLM 输出如何在固定 tick 内注入、如何进回放。推论做法：

1. LLM 在内核外异步运行，订阅领域事件作为感知；输出解析为带 actor 标记（女神、NPC）和目标 tick 的结构化命令，进入权威命令队列，由内核校验后执行。
2. 回放记录 LLM 的结构化输出（以及 prompt_version、model_version、知识库版本），回放时重放记录，不重新调用模型。
3. 绝不把 LLM 输出当脚本解释执行；LLM 的"随机性"按随机源管理：种子、输出夹取、日志
   （来源：`10_md/game-dev-knowledge/03-core-gameplay-design/randomness-design.md` 的七种随机控制工具）。
4. LLM 供应商按插件模块抽象，测试时换成固定回放替身（`10_md/game-dev-knowledge/15-tech-architecture/plugin-module-architecture.md`）。

| ---------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 原型八类               | 玩法、手感、技术、UI、数值、美术、运营、数据，各自允许粗糙的部分不同                                | `10_md/game-dev-knowledge/14-production-management/prototype.md`       |
| 原型流程               | 写假设、定范围、定成功标准、快速实现、测试反馈、记录结论、丢弃或重构（原型代码默认不进生产）        | 同上                                                                   |
| 原型验收六问           | 假设回答了没有、拿到反馈没有、能否决策、继续是否值得、还剩哪些风险、哪些能复用                      | 同上                                                                   |

| 纸面原型适用度         | 很适合卡牌与经济；适合 RPG 成长与 UI 流程；部分适合实时战斗（验证规则，不验证节奏）；不适合动作手感 | `10_md/game-dev-knowledge/14-production-management/paper-prototype.md` |

分析：本作原型池建议分开：技能战斗手感、千门发掘感、AI 居民社会与传闻、女神 GM 事件调度、城建经济、RTS 指挥、SLG 外交、2D 美术管线。
立国政策、外交、技能树、产业链可先做桌面推演；让 LLM 扮演女神参与跑团时，提示词版本就是"规则版本"，要固定下来。
AI 出原型很快，所以更要守住"原型代码默认丢弃"。

### 7.3 垂直切片

- 八个维度：玩法（一段完整核心循环）、系统（关键战斗、经济、成长、结算链路）、UI/UX、美术（接近最终质量）、音频、技术（构建、配置、资源加载、性能预算）、数据（关键事件、日志、看板）、QA（冒烟用例、验收标准、已知问题）。
- 选取原则：选最能代表最终风险的部分，而不是最简单的部分；范围小但链路完整；临时方案要标记；完成后复盘量产成本。
- 常见误区：做成宣传 Demo；用一次性手工方案堆出来；太大变成半个游戏；太薄只验证一个功能。
- 来源：`10_md/game-dev-knowledge/14-production-management/vertical-slice.md`。

分析：`game_framework.md` 第 15 节建议以"序章 加 第一幕"为切片，与资料的"选最能代表最终风险的部分"一致。
按资料补两点：切片必须产出"每单位内容（地图、角色、门、NPC 人设）的 AI 辅助量产工时与 token 成本"；
"无模型降级档能否完整通关"应列为切片的硬验收项。经营层、战场层的跨玩法衔接风险需要单独的第二切片或原型来回答。

### 7.4 MVP、里程碑与范围控制

| 方法       | 要点                                                                                                                                                         | 来源                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| MVP        | 先写 1 到 3 个核心假设；试玩前定义成功、失败、继续观察三档标准；结束后必须决策（继续、转向、砍掉、重做）                                                     | `10_md/game-dev-knowledge/14-production-management/mvp.md`            |
| 里程碑     | 管理门槛，不是日历节点；"通过不等于没有问题，而是遗留问题被接受并记录"；未完成项明确延期、砍掉、降级还是转入下一阶段                                         | `10_md/game-dev-knowledge/14-production-management/milestone.md`      |
| 范围分类   | Must、Should、Could、Won't、Cut Candidate、Stretch Goal；每个版本都有不做清单；点名误区"首版想同时验证玩法、社交、商业化、剧情和大量内容"                    | `10_md/game-dev-knowledge/14-production-management/scope-control.md`  |
| 裁剪线六层 | 保底线、体验线、品质线、扩展线、展示线、风险线（高成本高不确定，优先评估砍或降级）；裁剪方式含后置、降级、缩量、替代、合并、关闭、灰度；降级后也要有验收标准 | `10_md/game-dev-knowledge/14-production-management/cut-line.md`       |
| 变更请求   | 审批按阶段收紧：预研鼓励探索但要记录；Alpha 后新增要配砍项；Beta 后原则上只修 Bug                                                                            | `10_md/game-dev-knowledge/14-production-management/change-request.md` |
| Pre-mortem | "Here lies our brilliant idea, killed by ___"；把限制转化为设计考量；陷阱是"太多想法存活太久"                                                                | `10_md/gdc/2025/gdc-2025-游戏设计规则2025.md`                         |
| 一次性内容 | "玩家会记住游戏给他们的感受，而不是代码有多整洁"；抵制过早锁定内容模式，模式在游戏形成身份后自然结晶                                                         | 同上                                                                  |

分析：资料点名的"首版同时验证玩法、社交、商业化、剧情和大量内容"几乎就是本作的风险画像。
LLM 自由对话天然落在"风险线"上，要预设"关闭"或"替代"方案（模板台词、选项式对话、离线预生成）；
城建与 SLG 宜"缩量"（先只做一种城镇形态、一个对手势力）而不是整块删除。

### 7.6 完成标准与验收标准

- DoD 分任务级、功能级、版本级、资产级、数据级；功能 DoD 项为需求、实现、UI、配置、数据、测试、性能、文档、验收；DoD 随阶段收紧
  （`10_md/game-dev-knowledge/14-production-management/definition-of-done.md`）。
- 验收标准常用写法：Given/When/Then、条件列表、状态表、数据要求、性能要求、异常要求；AC 不要写成实现方案；资料没有给 AC 字段模板
  （`10_md/game-dev-knowledge/14-production-management/acceptance-criteria.md`）。
- 分析：增设"AI 生成物 DoD"（代码有测试；资产过规格与风格审查；文本过设定与安全审查）与"LLM 功能 DoD"（有降级路径、有成本埋点、提示词版本化）。
  LLM NPC 的 AC 要写成可检验的约束（"不泄露未解锁剧情""不越出人设""超时回退到模板台词"），而不是"对话自然"。

### 7.9 上线质量评估的迁移

`10_md/game-dev-knowledge/上线质量评估.md` 的场景是竞技小游戏，但其方法论可迁移：

| 原文方法                                                                                               | 迁移到本作（分析）                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "上线质量不能只看功能是否完成，还要看生态是否可控"                                                     | 本作的"生态"是世界经济、AI 社会、女神干预三套生态，验收要问"它们会不会把世界打穿"                                                                                                        |
| 积分模型要给结论（长期通胀、能力收敛、前期通胀高段收敛），并给 50%、55%、60% 胜率下的每 100 局期望变化 | 资源经济、国力、女神好感要给出同样格式的结论：在轻度、普通、重度画像下每 10 小时的期望变化                                                                                               |
| 机器人对局可刷分是上线前风险项                                                                         | AI 居民与 AI 势力的固定行为漏洞可被玩家套利（例如固定交易差价、固定外交反应），需要专项"打穿测试"                                                                                        |
| 新手前 30 分钟评估："新手期不是只要让玩家赢，而是要让玩家觉得我学会了"                                 | 首小时验收：穿越开场、第一次战斗、第一次开门、第一次 NPC 对话、第一次女神介入、第一次失败、第一个据点                                                                                    |
| 战斗可读性："你刚刚这局输在哪里？"                                                                     | 每次试玩问"你为什么赢、为什么输、哪位女神做了什么"                                                                                                                                       |
| 内测分五轮，每轮有明确任务（"今天专门测机器人能不能被固定套路刷"）                                     | 内测每轮只测一个问题：功能跑通、新手理解、经济是否可控、AI 是否可套利、降级档是否可玩                                                                                                    |
| 机器人强度、积分收益、奖励最好都能配置化，配置开关与回滚                                               | LLM 模型、token 预算、女神干预强度、降级开关全部配置化并有审计（与 `10_md/game-dev-knowledge/12-liveops-versioning/feature-flag.md`、`remote-config.md` 一致；远程改提示词要防绕过测试） |
| 先补"最容易被忽略的五项"：排行榜可信度、新手前 30 分钟、战斗可读性、埋点与监控、配置开关与回滚         | 对应本作：世界状态可信度、首小时、战斗与 RTS 可读性、LLM 与经济埋点、降级与回滚                                                                                                          |

### 7.10 项目视角范式

`10_md/game-dev-knowledge/90-project-lenses/auto-battler-minigame.md` 的六块结构可直接复用为《箱庭纪》的项目视角：
项目约束（约束到设计含义）、首版重点（模块、关键问题、对应领域）、MVP 边界（必须有、暂缓）、首局验收（按"第一次"节点逐个写问题）、

"LLM 可用不等于体验好""降级档不能等 LLM 版完成后再补"。
