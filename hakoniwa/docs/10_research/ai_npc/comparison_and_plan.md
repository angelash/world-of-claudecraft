# AI 思考决策：my_ai_town 与 world-of-claudecraft 对比，及《箱庭纪》方案

> 依据：[my_ai_town_agents.md](my_ai_town_agents.md)（源码级调研）、[woc_ai_npc.md](woc_ai_npc.md)（源码级调研）、
> [../open_share/city_rts_slg.md](../open_share/city_rts_slg.md)（策略 AI 与权限分级）、
> [../anime/](../anime/)（女神与 NPC 设定参照）。
> 本文给出结论与方案方向；落地的架构设计见 `../../50_tech/ai_architecture.md`，玩法设计见
> `../../40_design/systems/npc_society_ai.md` 与 `../../40_design/systems/goddess_gm.md`。

## 1. 一页结论

**用户的直觉是对的，而且差距是结构性的，不是提示词写法的问题。**

- my_ai_town 的居民是"活着的人"：每人一个跨天持续的会话，看见自己上一步行动的真实结果再决定下一步；
  行动会真的改变世界；记忆带来源与可信度；只有需要时才问模型；模型出的每一步都要过多道内核闸门。
- world-of-claudecraft 现有的 AI 是"围着玩家转的表演层"：玩家靠近或轮询到期时触发一次性作业，
  输出以台词编号和表现层动作为主，几乎不改变世界；人设只有一句话，记忆以会话 id 为键、只存标签，
  传闻只回声给同一个玩家，没有玩家在线时 NPC 不存在。
- 但 world-of-claudecraft 有 my_ai_town 没有的长处：版本化的决策契约、意图白名单与目标校验、
  正典主体分级、口吻控制、本地兜底、全链路审计与后台、成体系的 AI 测试。这些是"外壳"，值得带走。
- 两者都没有、《箱庭纪》必须自己设计的：由大模型驱动的 GM 循环（女神）、多位 GM 之间的协商与冲突、
  叙事张力调度、几百个 NPC 规模下的分级推理（LOD）、世界级的传闻网络、势力首领的决策管线。

**一句话方案：用 my_ai_town 的"居民内核"做心脏，用 world-of-claudecraft 的"契约与审计"做外壳，
再补上"分级推理、女神 GM、势力议政、认知传闻"四个新器官。**

## 2. 逐项对比

| 维度 | my_ai_town | world-of-claudecraft 现状 | 谁更好 | 《箱庭纪》取向 |
|---|---|---|---|---|
| 存在性 | 居民一直在生活，世界有自己的时钟 | 只在在线玩家 28 码内、触发或轮询时出现 | my_ai_town | 全部 NPC 常驻，按分级用不同精度模拟 |
| 决策单元 | 跨天持续会话（目标、承诺、待完成工具、事件游标、累积摘要） | 一次性作业，有效期最长 60 秒 | my_ai_town | 重要 NPC 用持续会话 |
| 闭环 | 模型提议，内核执行，回执（成功、失败原因、被打断）写回会话再唤醒 | 意图多数只变成徽标或台词 | my_ai_town | 必须闭环，回执是事实来源 |
| 行动空间 | 走路、劳动、使用道具、交谈、交易、玩法动作，会改变世界 | NPC 侧步、回家；怪物开怪逃跑呼救（规则选定） | my_ai_town | 生活、经济、社交、政治、军事动作 |
| 调用时机 | 懒唤醒：空闲、轮到发言、收到邀请、重要通知 | 玩家触发与周期轮询；人越多轮询越少 | my_ai_town | 懒唤醒 + 分级节拍 |
| 世界与模型的时间一致性 | 世界不等模型，用动作版本号判过时，过时整条作废重想 | 无此机制 | my_ai_town | 照搬 |
| 校验 | 八道闸门，拒绝原因可读并回给模型自我修正 | 意图白名单三重交集 + 目标可见性校验 | 各有所长 | 两者合并：白名单分角色，拒绝原因回会话 |
| 人设 | 人设卡含长相、背景、私密人设、处境 | 一句英文 persona + 标签，无目标、立场、秘密 | my_ai_town | 人设卡 + 立场 + 秘密 + 知识层级 + 加护冲动 |
| 目标 | 目标必须有世界证据才算完成，放弃需写原因 | 无 | my_ai_town | 照搬 |
| 记忆 | 不可改写的世界事件；确定性生成的经历与认识（亲见、转述、推断，带可信度）；整理轮次写主题笔记，须引用事件编号 | 7 套各自 TTL 的存储，只存 lineId 与标签，以会话 id 为键 | my_ai_town | 照搬分层与来源，记忆以稳定居民 id 与世界历法为键 |
| 认知纪律 | 转述不是事实，"支持中"的认识需两次独立经历，引文要逐字并由后端核对 | 无 | my_ai_town | 这就是"凡人不信"的引擎，照搬并扩展 |
| 关系 | 只存在于各人的笔记里，无数据结构 | 单调递增的 affinity | 都不够 | 新设计：多维关系（信任、敬畏、利益、立场），可增可减 |
| NPC 间社交 | 真实交谈、结伴、邀约，影响各自记忆 | 演给单个玩家看的 2 到 3 句 | my_ai_town | 照搬并加入传闻传播 |
| 信息传播 | 通过交谈自然传递，转述可信度 0.5 | 只回声给同一玩家，90 秒过期 | my_ai_town | 新设计：世界级传闻网络，传播、失真、核实 |
| 日程与需求 | 有日程与生理、情绪需求影响决策 | 即时 routine 标签 | my_ai_town | 照搬，并让规则层能在离屏时跑日程 |
| 上下文压缩 | 稳定前缀命中缓存、慢变字段只发变化、事件只列最近 24 条、可回查原文、旧轮次确定性折叠、"题面只写给模型看的东西" | 按触发类型裁剪上下文的策略表 | my_ai_town 更深，WoC 的分类策略可借 | 两者合并 |
| 口吻控制 | 心声与台词分开，心声有写法规则 | 说话指纹、反助手腔规则、后处理润色 | world-of-claudecraft | 带走 |
| 正典守卫 | 靠世界真相只在内核，模型只能看见本人投影 | 子串黑名单 + 正典主体分级（黑名单会误杀） | 各有所长 | 结构化正典事实库 + 知识层级可见性 + 主体分级；不用子串黑名单 |
| 主持者 | 法官是确定性状态机；"智子"是普通 LLM 居民 + 秘密任务 + 舞台时刻 | 无 | my_ai_town 思路 | 女神 = 规则执行者（确定性）+ 人格（LLM） |
| 成本控制 | 每日与总额度先预留后结算，按真实 usage 校准；但成本随人数线性增长 | 部分预算与人口分档，无金额与全局上限，token 按字符数除以 4 估算 | my_ai_town 更扎实，但都不够几百人 | 分级推理（LOD）+ 批处理 + 模型分档 + 金额预算 |
| 稳定性 | 有界退避重试；连续失败、额度不足、回复连续过时时全镇停表并给出原因 | 本地兜底优先，模型挂掉世界照常 | 各有所长 | 规则兜底为主，必要时停表 |
| 审计与可观测性 | 状态广播、轨迹日志、录像重演、台词与心声字幕 | 全链路审计记录（含 prompt 与原始输出）与后台页面 | 各有所长 | 两者合并：轨迹 + 审计 + 录像 + 后台 |
| 测试 | 关键行为回归，协议样本测试 | 40 多个 AI 测试文件 | world-of-claudecraft 覆盖更广 | 保持测试密度 |
| 模型接入 | 单一网络出口；支持本地 Qwen（JSON Schema 约束输出）与微调的内置小模型 | 默认每次调用起一个 Codex CLI 子进程，单厂商 | my_ai_town | 直连 API + 本地小模型 + 单一出口 |
| 与宿主耦合 | 内核、Agent、host 三层分离 | AI 处理器与计时器挂在 `GameServer` 上 | my_ai_town | AI 运行时独立，经稳定接口读写世界 |

## 3. my_ai_town 为什么做得好（根因）

1. **会话连续性**：模型不是每次"从零看一眼世界再说一句话"，而是在一个持续的会话里，带着目标与承诺，
   看着自己上一步的结果行动。这让行为有因果、有坚持、有纠错。
2. **行动有后果**：模型的输出是改变世界的动作，内核执行后的回执才是事实。NPC 因此"活在世界里"，而不是"站在玩家面前表演"。
3. **认知有纪律**：记忆区分亲见、转述、推断，可信度不同；认识要有证据才能升级。这同时解决了幻觉与"凡人不信"两个问题。
4. **只在需要时思考**：懒唤醒让成本与人数、事件密度挂钩，而不是与时间挂钩。
5. **校验能自我修正**：每道闸门的拒绝原因都写成人话回给模型，模型下一步就能改对。
6. **题面干净**：只给模型它需要的、人能读的信息，并有回归测试守护。
7. **可观测**：每一次思考都可回看、可重演、可定位问题，所以能持续迭代。

## 4. world-of-claudecraft 现有实现值得带走的外壳

| 带走 | 来源（主工程） | 在《箱庭纪》的用途 |
|---|---|---|
| 版本化决策契约 | `server/ai/ai_types.ts` 的 `AiJobContextV1`、`AiDecisionV1` | 女神、首领、NPC 共用的决策 IO 外壳，按角色扩展 |
| 意图白名单与目标校验 | `server/ai/intent_validator.ts` 的 `validateAiDecision` | 每类角色一套意图集合，与情境、正典主体取交集 |
| 正典主体分级 | `server/ai/canon_guard.ts` | 主线关键人物、剧情物件、女神神谕收窄行为空间 |
| 本地兜底 | `npcLocalFallbackEvent` 等 | 无模型降级档的基础 |
| 口吻控制 | `SPEECH_FINGERPRINTS`、`polishDynamicSpeech` | 女神与 NPC 的说话指纹 |
| 审计与后台 | `server/ai_audit.ts`、`ai_audit_records`、后台 AI 页面 | 每个 AI 决策可回放，供"造主"（开发者）复核 |
| 记忆预算策略 | `AiMemoryBudgetPolicy` | 几百个 NPC 的记忆容量治理 |
| 种子哈希个体性 | `individualProfileFor` | 让少数个体更聪明，把推理集中在少数人身上 |
| 群体本能矩阵 | `FAMILY_SEMANTICS` | 魔物与无名群众的廉价群体人格（LOD 最低档） |
| 世界导演提案的字段形状 | `AiWorldDirectorProposal` | 女神 GM 提案的雏形（但要补上审批与执行生命周期） |

不带走：会话 id 为键的记忆、按玩家隔离的回声、只围着玩家的调度、子串黑名单、CLI 子进程式 provider、
单调好感、AI 与渲染两套天气模型、挂在协调器上的 AI 运行时（理由见 [woc_ai_npc.md](woc_ai_npc.md) 第 8.2 节）。

## 5. 两者都没有、必须新设计的部分

| 缺口 | 为什么需要 | 方向 |
|---|---|---|
| 分级推理（LOD） | 全作 300 到 400 个有名 NPC，my_ai_town 的"一人一长会话"成本线性增长，默认额度只按 4 人 10 天设计 | 五档分级，按距离、剧情相关度、事件动态升降档（第 6.2 节） |
| 女神 GM 循环 | my_ai_town 的主持者不是模型；我们的女神要真的"观察全局、决定干预" | 规则执行者 + 人格会话 + 神权菜单 + 神力预算 + 神之视线投影（第 6.4 节） |
| 多 GM 协商与冲突 | 六位女神有神约、交易、违约与指控 | 女神之间的"约定"对象：提醒、履约记录、违约证据 |
| 叙事张力调度 | 法官只按时间表推进，不会调节节奏 | 莫伊拉的导演职能：确定性张力计 + 从菜单选择"巧合"或"喘息" |
| 世界级传闻网络 | 凡人不信、误会链、声望都依赖信息如何传播与失真 | 传闻作为一等数据对象：来源、可信度、失真度、传播路径 |
| 势力首领与统治者决策 | 公会长、领主、国王、教皇要做政策、外交、战争决策 | 感知摘要 + 枚举意图菜单 + 内核校验 + HTN/Utility 分解执行（来自开源资料的管线） |
| 规则数据化 | my_ai_town 每个玩法手写上千行状态机 | 神权、事件链、纷争推进用数据描述：阶段、资格、期限、兜底 |

## 6. 《箱庭纪》AI 方案（方向）

### 6.1 总原则

1. **模型提议，内核裁决**：任何 AI 都只能产出结构化意图；内核校验后执行，回执是唯一事实。
2. **正典约束，台账开放**：AI 只能看到其知识层级与揭示台账允许的知识（`../../30_story/reveal_ledger.md`）。
3. **规则兜底，模型增色**：所有角色都有规则层行为；模型不可用时世界照常运转（降级档）。
4. **只在需要时思考**：懒唤醒、事件驱动、分级节拍。
5. **每个决策可回放**：轨迹、审计、录像三件套。

### 6.2 五档分级推理（LOD）

| 档 | 谁 | 决策方式 | 节拍 | 记忆 |
|---|---|---|---|---|
| L0 神 | 六位女神 | 持续人格会话 + 规则执行者 | 游戏内每天一次规划轮；被点名（例如有人念诵尊名、重大神迹被目击）时即时唤醒 | 完整，私密目标只进本人上下文 |
| L1 核心 | 同伴、从者、当幕主要角色、在场的势力首领 | my_ai_town 式持续会话，多轮工具循环 | 懒唤醒（空闲、轮到发言、邀请、重要通知） | 完整分层记忆 + 整理轮次 |
| L2 在场居民 | 玩家所在地区的有名居民 | 持续会话但低频：每天一次"日计划"轮 + 事件触发轮；日常行动由规则执行日程 | 日计划 + 事件 | 分层记忆，整理轮次降频 |
| L3 离场居民 | 其他地区的有名居民 | 规则驱动日程（Utility）；每个地区每天一次"批量日记"调用：一次请求推演多名居民的一天，输出结构化事件，内核校验 | 每地区每天一次 | 经历与认识由确定性代码生成，不跑整理轮次 |
| L4 群众 | 无名居民、士兵、魔物 | 纯规则：状态机与群体本能矩阵，批量模拟 | 每 tick 或按需 | 无个人记忆，只有群体统计 |

升降档规则：玩家进入地区、事件点名、成为任务对象时升档（加载记忆进会话）；离开、事件结束、长时间无关联时降档
（会话折叠成确定性摘要后存档）。升档总数受预算上限约束，超出时按剧情相关度排序。

### 6.3 NPC 居民（L1 到 L3）

- **人设卡**：沿用 my_ai_town 的人设卡字段，加上：所属势力、立场、秘密、知识层级、位阶、常识上限、
  加护与"加护冲动"（信仰某位女神的人会被她的价值观轻微牵引，这是女神利益在凡人层的投影）。
- **认知纪律**：照搬亲见 1.0、转述 0.5、推断的来源分级与"两次独立经历才能支持"的门槛，
  并新增"常识上限"：越出 NPC 常识的事迹，即便亲见也优先被解释为运气、作弊、魔法道具或阴谋，
  直到证据强度越过该 NPC 的"信念跃迁阈值"。这是"凡人不信"的系统来源。
- **关系**：多维（信任、敬畏、好感、利益、立场一致度），可增可减，有衰减，NPC 之间也有。
- **传闻**：交谈中可以传递"关于某人某事的说法"，带来源、可信度与失真度；传闻在社交网络中扩散，
  失真规则由社会学设定决定（`../../20_world/society.md`）。
- **行动空间**：生活（移动、劳动、饮食、休息、祈祷）、经济（买卖、雇佣、借贷）、社交（交谈、邀约、结伴、
  传话、告密）、政治（请愿、站队、投票）、冲突（争吵、斗殴、报官）。每个动作有内核定义的前置与后果。

### 6.4 女神 GM（L0）

照 my_ai_town 的"法官 + 智子"思路拆成两半：

| 半边 | 实现 | 负责 |
|---|---|---|
| 规则执行者 | 确定性代码（数据驱动的规则描述） | 神力预算与结算、冷却、神约检查、作用域、期限与兜底、澱的产生、天启的执行 |
| 人格会话 | 大模型持续会话 | 观察（只经由她的神之视线投影）、解读、规划、对玩家与信徒说话、与其他女神谈判 |

- **观察投影**：她只能看到信徒所见（按虔诚度加权）、神殿覆盖区、向莫伊拉"借阅"的铭录片段；
  玩家无页，因此她对玩家的认识只来自目击与传闻。这使女神天然会误判。
- **神权菜单**：神谕、加护授予与剥夺、神迹、灾害、任务发布、价格修正、托梦、勇者调度、召唤等，
  每项是带参数的动作，有资格、代价、冷却、作用域与可读的拒绝原因；价格与灾害等效果作为"注册过的修正项"
  进入内核，而不是直接改数值（来自开源资料的经济与橡皮筋建议）。
- **唤醒**：每游戏日一次规划轮；"尊名机制"：凡人念诵女神全名、在神殿重大祈愿、目击大型神迹时，
  向她发送重要通知并即时唤醒（降低成本，也是世界观里的仪式与风险）。
- **女神之间**：约定、交易、情报买卖、指控，都是一等对象，有提醒与履约记录。
- **造主天启**：开发者在后台以造主身份发布天启（规则变更 + 一句古庭语），规则执行者先落地规则，
  再把天启作为重要通知唤醒全部女神解读。

### 6.5 势力首领与统治者（L1 的一个分支）

采用开源资料中的统治者管线：

```
国家/组织知识层 -> 感知摘要 -> [大模型] 从枚举意图菜单中选择（含理由） -> 内核校验（权限分级 P0 到 P4）
   -> HTN/GOAP 分解为计划 -> 行为树/Utility 执行 -> 回执写回首领会话
   模型不可用时：Utility 打分直接选意图（兜底）
```

权限分级沿用开源资料的 P0 到 P4：说话与文书直接输出；调整预算受控；宣战、缔约有前置条件；
改他国状态、改战斗结算一律禁止。

### 6.6 成本控制

- 模型分档：女神与关键剧情用大模型；L1 用中模型；L2、L3 批量日记用小模型或本地模型
  （参照 my_ai_town 的本地 Qwen 与微调内置小模型）。
- 稳定前缀缓存、慢变字段只发变化、事件窗口有界、旧轮次确定性折叠、题面清洗（照搬 my_ai_town）。
- 真实 usage 计费与金额预算，每日额度先预留后结算；超预算时按档自动降级，而不是停摆。
- 估算口径（仅作量级参考，以实测为准）：第一幕边石镇约 40 名有名 NPC，L1 约 5 到 8 人、L2 约 15 人、
  L3 按地区批量，加上六位女神，每游戏日（约 24 分钟现实时间）约 100 到 150 次模型请求。

### 6.7 可观测性

- 轨迹日志：每次请求、回复、工具、回执、预算、折叠、过时。
- 审计后台：女神、首领的每个决策可回放，带理由（理由只给开发者与"神之记录"界面，不进凡人世界）。
- 录像重演：不调模型重演一局，导出台词与心声字幕，用于调试与宣传素材。
- 游戏内呈现：心声气泡、动态列表、女神的"神之记录"（后期解锁，给玩家看诸神的公开动向）。

## 7. 对 world-of-claudecraft 现有 AI 的改进路线（附带结论）

本文主要服务《箱庭纪》，但调研同时发现了当前游戏可以改进的地方，按收益排序：

1. **先修已发现的漂移缺陷**（见 [woc_ai_npc.md](woc_ai_npc.md) 结论 17）：环境机器人仍发旧的认证消息，
   已被 `server/ws_auth.ts` 拒绝；托管游玩只在 `send()` 捕获事件，大概率收不到走 `sendRaw` 的私聊和组队邀请；
   主动触发没有过滤机器人会话。
2. **记忆改为以角色 id 与世界时间为键，存内容而不只是标签**，解决换会话失忆。
3. **让决策产生世界后果**：把 `AiLifeLayer` 的意图接到真正的动作桥上，而不只是徽标。
4. **引入持续会话与回执闭环**：先从少数关键 NPC（如主城的几位 NPC）开始试点 my_ai_town 式会话。
5. **传闻改为世界共享**，去掉按玩家隔离与 90 秒过期。
6. **正典守卫从子串黑名单改为结构化事实库与知识可见性。**
7. **AI 运行时从 `GameServer` 中拆出**，经稳定接口读写世界。

这些改动是主工程的独立工作，不属于《箱庭纪》概要设计的范围。
