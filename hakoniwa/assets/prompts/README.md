# 提示词库使用说明：用小九 AI 生成《箱庭纪》的美术素材

> 归属：`assets/prompts/`（提示词库）。作用：告诉生成者（用户）怎样把这里的提示词交给小九 AI、按什么顺序生成、怎样验收、产物放到哪里、怎样登记与回收不合格品；
> 同时给条目作者与维护者写清模板、风格包与条目的格式。
> 上游：`../../docs/00_vision/decision_log.md` 的 D-018（美术与音频全部 AI 生成）与 D-078（头像、半身立绘、4 向）；美术方案 `../../docs/50_tech/art_pipeline.md`（规格、数量、一致性、导入、审核）；
> 素材目录约定 [../README.md](../README.md)；音频的生成与验收见 `../../docs/40_design/audio_direction.md`（音频模板 `templates_audio.json` 与本说明共用同一套流程）。
> 约束：提示词与条目里不出现其他作品、作者、画师、工作室与商标的名字，也不写"HD-2D"；素材里不能有文字。

## 0. 一页结论

1. **先锚后量：** 每个风格包先出"风格板"，每个人物、服装、物种先出三视图，主审通过后再批量出动作条、头像、图标。参照不过，后面全白做。
2. **先展开再取用：** 仓库里提交的是源：`templates.json`、`templates_audio.json` 与 `specs/*.json`。展开后的 `out/`（约 100 MB）只在本机生成、不提交（`hakoniwa/.gitignore`）：开始生成前先在 `hakoniwa/` 运行 `npm run prompts`，`npm run prompts:check` 确认 `out/` 与条目一致。
3. **一条一图：** `out/<名>.md` 里每个条目是一段可复制的提示词，对应一张图、一个编号、一个文件名。复制，附参照图，生成 4 张候选，挑一张。
4. **按名落盘：** 选中的图下载为 PNG，文件名就是条目编号，放进条目写的目录，例如 `assets/art/monsters/art_mon_dian_rat_d.png`。
5. **登记再审：** 运行 `npm run assets:register` 登记（或照 [../README.md](../README.md) 第 3.1 节手工登记），`npm run assets:import` 导入，在编辑器素材浏览器里审核；不合格的标原因、移走、重生成。
6. **按里程碑分批：** 全库 10,342 条：美术 9,128 条（M0 51 条全链路样板、M1 序章与第一幕 2,229、M2 3,110、M3 3,447、M4 6），音频 1,214 条（M1 726、M2 308、M3 180）。数字以提示词库统计为准（`node tools/prompts/build.ts --validate` 的统计表），条目增删后以它的输出为准；每批不超过 50 条，同模板同风格包一起做。

## 1. 文件是什么

| 文件                       | 谁维护                 | 内容                                                                                                              |
| -------------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `templates.json`           | 美术方案的维护者       | 全局反向提示词；16 个风格包（中英文风格锚与 8 到 16 色锚色）；82 个美术模板（画布、入游戏尺寸、帧格、背景、目录、中英文模板句） |
| `templates_audio.json`     | 音频方案的维护者       | 音频模板（时长、循环、格式与中英文模板句）                                                                        |
| `specs/<名>.json`          | 条目作者（主会话与写作代理） | 按类别的条目：编号、模板、风格包、中英文主体描述、补充说明、对应的内容 ID、参照依赖、里程碑、给生成者的提醒       |
| `out/<名>.md`              | `npm run prompts` 在本机生成，不提交 | 每个条目一节：编号、文件路径、画布与帧格、参照依赖、中文提示词、英文提示词、反向提示词、提示词哈希；按里程碑与依赖顺序排列 |
| `out/<名>.csv`             | 同上                   | 同一批条目的表格版，便于在表格软件里筛选里程碑、勾选进度                                                          |
| `out/manifest.json`        | 同上                   | 预期素材清单：全部编号与预期文件路径；登记与覆盖测试拿它对账                                                      |

`out/` 下的文件不要手改，也不提交（`hakoniwa/.gitignore` 已列出）：改模板或条目、或拉取别人改过的条目后，重跑 `npm run prompts`（第 9 节）；`npm run prompts:check` 确认 `out/` 与条目一致。

### 1.1 一条提示词是怎么拼出来的

```text
最终提示词 = 模板的 zh（或 en）句子，其中
  {subject} 换成条目的 subject.zh（或 subject.en）
  {style}   换成条目所选风格包的风格锚 zh（或 en），再加"主色："与锚色列表；条目不写风格包时为空
  {extra}   换成条目的 extra.zh（或 extra.en）；没写时为空
反向提示词 = 模板的 negative 为 true 时，附上 templates.json 的全局反向提示词
```

占位为空时，紧随其后的句号一并去掉。

## 2. 工作流总览

```text
风格板（每个风格包一张） ─┐
固定人台三视图（三种体型）├─ 主审通过，成为参照
人物、服装、物种三视图 ───┘
        │
        v
批量条目：动作条、头像、半身立绘、魔物各朝向、地面、墙面、道具、图标、特效……（每条附上它依赖的参照图）
        │
        v
下载 PNG -> 按编号命名 -> 放进目录 -> 登记 -> 导入 -> 自动校验 -> 主审 -> 通过 / 返工 / 淘汰重生成
```

## 3. 每生成一张图的步骤

| 步  | 做什么                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 打开 `out/<名>.md`，找到要做的条目；先确认它的"参照依赖"都已经通过（没通过就先做依赖）                                                                                   |
| 2   | 在小九 AI 里新建一次生成：比例或尺寸按条目写的"生成画布"设置（工具不支持该尺寸时选最接近的比例，见第 4 节）                                                             |
| 3   | 复制中文提示词（工具对中文理解差时改用英文提示词，并在登记时写 `promptLang: en`）                                                                                        |
| 4   | 工具有"反向提示词"栏时，把反向提示词粘进去；没有时，把它接在提示词末尾，前面加"不要："                                                                                    |
| 5   | 工具支持参考图时，附上条目列出的参照图（原文件，在 `assets/art/.../ref/` 或风格板的条目里）；参照强度从中等起试，要求"保持外形与配色，允许姿势变化"                          |
| 6   | 一次生成 4 张候选；挑格子最整齐、外形最贴近参照、没有文字的一张；都不行就换种子再来一轮，两轮都不行就在条目的提醒里记下问题，交给条目作者改描述                              |
| 7   | 下载为 PNG（不要 JPG：有损压缩会弄脏像素），文件名改成条目编号，放进条目写的目录                                                                                        |
| 8   | 登记（第 7 节）；工具界面显示种子与模型版本时记下来                                                                                                                     |

## 4. 小九 AI 的设置建议

| 设置                         | 建议                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 尺寸与比例                   | 尽量按条目的生成画布设置；不支持时选最接近的比例（例如 8:3 的 1536×576 用 16:9 代替），格子仍按条目的行列等分，导入工具按格检测 |
| 张数                         | 每次 4 张候选                                                                                                              |
| 风格预设                     | 选"无"或最中性的一项；不要用以其他作品、画师命名的预设                                                                      |
| 高清修复、超分、细节增强     | 关闭（像素画会被糊掉）；需要大图时用条目的画布尺寸直接生成                                                                  |
| 水印                         | 必须关闭可见水印；关不掉的工具不能用于入库素材                                                                              |
| 格式                         | PNG；能输出透明背景时可以输出透明 PNG（等同洋红背景）                                                                       |
| 种子                         | 同一主体的第一张通过的图记下种子，后续条目从同一种子起步                                                                    |
| 模型版本                     | 一个里程碑内不换模型版本；必须换时先重出风格板与三个代表条目，主审确认风格一致再继续                                        |

## 6. 条目作者须知（写 `specs/*.json` 的人）

### 6.1 条目格式

```json
{
  "category": "monsters",
  "title": "魔物立牌",
  "sources": ["docs/40_design/content/catalog_bestiary.md"],
  "items": [
    {
      "id": "art_mon_dian_rat_d",
      "template": "mon_small",
      "style": "ash_waste",
      "subject": { "zh": "主体描述", "en": "subject description" },
      "extra": { "zh": "整张图的所有帧都面向镜头（朝下）。", "en": "Every frame in this sheet faces the viewer (down)." },
      "ref": "dian_rat",
      "deps": ["art_mon_dian_rat_ref"],
      "milestone": "M1",
      "notes": "给生成者的提醒"
    }
  ]
}
```

- **一条一图：** 一个条目只对应一张图。魔物、首领、兽伴坐骑、兵团的动作表每个朝向一个条目（编号以 `_d`、`_r`、`_u` 结尾），三条共用同一段 `subject`，`extra` 写朝向。
- **编号：** `art_<类>_<主体>[_<部分>][_<朝向或序号>]`，全库唯一；类别前缀与模板家族一致（`chr_*` 模板用于主要角色时编号前缀是 `art_chr_`，用于纸娃娃服装时是 `art_doll_`）。编号里不写剧透。
- **主体描述：** 中英文都要写，具体到外形、配色（可以写十六进制）、材质、姿态与辨识特征；同一主体在所有条目里用完全相同的一段描述（固定描述块）；不写凡人看不见的真相。
- **参照依赖：** 动作条、头像、立绘依赖本人的三视图；魔物各朝向依赖本物种三视图；世界类素材依赖本风格包的风格板条目；依赖的里程碑不晚于自身。
- **风格包：** 世界类素材必须写风格包；人物、魔物按其主要出没地写风格包（只影响风格锚的气质，颜色由生灵色板统一）；图标、界面主题件、地图插画可以不写。
- **里程碑：** M0 到 M6，按 `../../docs/50_tech/art_pipeline.md` 第 9 节的分配。

### 6.2 标准补充句（`extra`）

| 用途                     | 中文                                                                                                                                                         | 英文                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 朝向：下                 | 整张图的所有帧都面向镜头（朝下）。                                                                                                                           | Every frame in this sheet faces the viewer (down).                                                                                                                       |
| 朝向：右                 | 整张图的所有帧都朝画面右方（侧面）。                                                                                                                         | Every frame in this sheet faces screen right (side view).                                                                                                                |
| 朝向：上                 | 整张图的所有帧都背向镜头（朝上），看到的是背面。                                                                                                             | Every frame in this sheet faces away from the viewer (up), showing the back.                                                                                             |
| 纸娃娃人台的动作条       | 主体是纸娃娃固定人台：中性灰色光头人台，没有头发、衣服细节与性别特征，双手半握。                                                                             | The subject is the fixed paper-doll mannequin: a neutral gray bald mannequin with no hair, clothing detail or gender features, hands half closed.                         |
| 纸娃娃服装的动作条       | 穿在固定的灰色光头人台上，姿势与人台的同名动作条逐格一致；保留人台的灰色光头，不画头发与头饰；服装用键色：主色纯红系、副色纯蓝系、皮革棕系、金属灰系、点缀绿系；双手空握，不拿武器。 | Worn by the fixed gray bald mannequin, matching the mannequin's strip of the same action frame by frame; keep the mannequin's gray bald head, no hair or headwear; outfit in key colors: primary pure red tones, secondary pure blue tones, leather brown, metal gray, accents green; hands empty in a grip, no weapon. |
| 风格板                   | 这是本风格包的风格板，画面要最能代表风格锚描述的气质。                                                                                                       | This is the style board for the pack and should embody the style anchor most faithfully.                                                                                 |

- **只放选中的那一张：** 没选中的候选留在本机，不放进仓库。
- **登记：** 在 `hakoniwa/` 目录运行 `npm run assets:register`，按提示选工具（`tools.json` 里的编号）并确认日期；它会写入 `assets/manifest.json`，状态为 `review`。

## 8. 审核与回收不合格品

- **在哪里看：** 编辑器的素材浏览器（原图与处理结果并排，1 倍与 3 倍）与 HD-2D 预览（放进目标风格包的场景，看白天、金色时刻与夜）。
- **怎么定：**

| 结论   | 什么时候                                         | 怎么做                                                                                                                         |
| ------ | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 通过   | 符合清单                                         | 状态设为 `approved`，填审核人与日期                                                                                            |
| 返工   | 导入参数或局部修图能解决（例：基线差 1 像素）     | 状态设为 `rework`，写原因码；修好后回到 `review`                                                                               |
| 淘汰   | 必须重画（例：朝向混了、出现文字、外形不像）     | 状态设为 `rejected`，写原因码；把原文件移到 `assets/_rejected/<类>/`；在条目的 `notes` 里写清问题，必要时请条目作者改 `subject`；重跑 `npm run prompts` 后用同一编号重新生成并登记 |

- **原因码：** `identity`（不像本人）、`frames`（帧数或帧序错）、`direction`（朝向错）、`silhouette`（剪影不对或撞了别的物种）、`scale`（比例不对）、`light`（光向错或自带投影）、
  `text`（出现文字）、`seam`（有接缝）、`palette`（颜色失真）、`readability`（小尺寸认不出）、`originality`（和知名作品过近）、`spoiler`（泄露剧情）、`quality`（畸形、糊、杂点）。
- **自动校验先过一遍：** `npm run assets:check` 不合格的会直接标成 `rework` 并写原因，主审只需看通过了自动校验的图。

## 9. 重跑 `npm run prompts`

- **什么时候重跑：** 改了 `templates.json`、`templates_audio.json` 或任何 `specs/*.json` 之后；拉取了别人改过的条目之后；准备开始一个新批次之前。
- **怎么跑：** 在 `hakoniwa/` 目录运行 `npm run prompts`。脚本 `tools/prompts/build.ts` 读取全部模板与条目，先校验（编号唯一、模板与风格包存在、依赖存在），再在本机输出（`out/` 不提交）：
  - `out/<名>.md`：每个条目一节，可直接复制；
  - `out/<名>.csv`：同样内容的表格版；
  - `out/manifest.json`：预期素材清单（编号、预期路径、模板、里程碑、提示词哈希）。
- **提示词变了怎么办：** 已通过的素材不会自动作废；登记里的 `promptHash` 与新提示词不一致时，自动校验把它列入"提示词已变更"清单，由主审决定保留还是重生成。
- **核对：** `npm run prompts:check` 不写文件，只确认本机的 `out/` 与当前的模板和条目一致；不一致时重跑 `npm run prompts`。
- **只看统计：** `node tools/prompts/build.ts --validate` 只校验并打印按类别与里程碑的条目统计表（各文档里的数量以它为准）。
- **校验失败：** 脚本会指出哪个文件的哪个条目有问题（例如引用了不存在的模板）；改好再跑。

## 11. 常见问题

| 现象                                   | 处理                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 图上出现了字或像字的花纹               | 淘汰（`text`）；在条目提醒里加"招牌、书页、碑面不写字"，换种子重来                                                                   |
| 格子数不对、帧排乱了                   | 先确认画布比例与条目一致；仍不行就把提示词换成英文再试；两轮都不行交给条目作者，把这一条拆成两张图                                   |
| 一张图里混了好几个朝向                 | 魔物类条目确认 `extra` 写了朝向标准句；人物动作条确认三行顺序（面向镜头、朝右、背向镜头）                                            |
| 角色每张都长得不一样                   | 一定要附三视图作参照；确认 `subject` 和三视图条目一字不差；记下第一张通过图的种子，从同一种子起步                                    |
| 背景不是纯洋红，有渐变或杂物           | 导入能抠掉轻微偏色；杂物多的淘汰；工具能输出透明 PNG 时直接用透明                                                                    |
| 地面或墙面有明显接缝                   | 淘汰（`seam`）；在提示词末尾加"四边颜色与纹理完全连续"再生成                                                                         |
| 32 像素下图标认不出                    | 淘汰（`readability`）；请条目作者把主体描述简化成一个物件、一个轮廓                                                                 |
| 画风偏写实或偏三维渲染                 | 确认反向提示词已附上；把风格预设关掉；仍偏的话在补充里加"平涂色块、硬边像素"                                                         |
| 工具只能下载 JPG 或 WebP               | 先找工具的 PNG 选项；没有的话另存为 PNG，登记时写 `converted: true` 并照抄原文件的隐式标识                                           |
