# tools/：开发服务与工具

| 文件 | 内容 |
|---|---|
| `dev_api.ts` | Vite 开发服务插件：`/api/llm`（模型代理，收中立调用规格 `LlmCallSpec`）、`/api/llm/status`、`/api/llm/test`、`/api/llm/models`、`/api/data`（编辑器读写 `data/`，合入批次时删除 `data/_staging/` 的暂存文件）、`/api/audit`（审计日志） |
| `llm_proxy.ts` | 用官方 Claude SDK 调用模型（只在服务端，密钥不进浏览器）；兼容与本机服务走 `src/ai/providers/` 的共用适配器；游戏与编辑器都经 `DevProxyTransport` 调它 |
| `release_bundle.ts` | 发布包扫描：发布构建（`npm run build:release`，Vite 的 `desktop` 目标）只含游戏入口，产物里不得出现编辑器页面、开发服务的路由与 `@anthropic-ai/sdk`；构建插件、`desktop/pack.ts` 与 `tests/release_bundle.test.ts` 共用 |
| `data_paths.ts` | `data/` 路径解析与防路径穿越、JSON 写盘格式 |
| `refs/fetch_refs.ts`、`refs/manifest.json` | 开源参考源码镜像：清单记录每个仓库的固定提交、许可与稀疏目录；工具把只读镜像拉到仓库外（`npm run refs -- --dir D:/hakoniwa_refs`），说明见 `docs/10_research/open_source/README.md` 第 5 节 |
| `prompts/build.ts` | AI 素材提示词库：校验 `assets/prompts/` 的模板（`templates.json`、`templates_audio.json`）与条目（`specs/*.json`），展开为逐条可复制的提示词、表格与预期素材清单 `assets/prompts/out/`（`npm run prompts`；`npm run prompts:check` 只校验并确认 `out/` 是最新的），说明见 `assets/prompts/README.md` |
| `replay/run.ts`、`replay/main.ts` | 回放工具（发行工程第 13.6 节）：`node tools/replay/run.ts replay --dir <存档目录> --slot <槽位>` 从槽位头的锚点加之后的命令分段无模型回放到槽位的 tick，比对世界哈希与完整状态哈希（`worldHash`、`stateHash`；`--all` 每个锚点到终点，`--hops` 逐段，`--shard i/n` 分进程，`--days` 输出逐游戏日哈希）；`record` 用自动玩家跑一条路线并定期存档到目录（可另存快照夹具）。`run.ts` 由 Node 直接运行，再经 Vite 的模块运行器加载 `main.ts`（内容装配用 `import.meta.glob`） |
| `registry/build.ts`、`registry/parse.ts`、`registry/options.ts` | 世界状态变量注册表：读 `docs/40_design/world_state_registry.md` 第 2.8、2.9、6.2、7、8 节的表格，生成 `data/registry/vars.json`（`npm run registry`，重跑结果不变）；`npm run registry:check` 核对文件是最新的，再跑 `tests/registry.test.ts`（第 9.3 节校验与数据、代码零别名）；`--report` 列出解析时跳过的行；文档没定下的两处（第 7.6 节无法对位的值别名、第 6.2 节留给任务目录的编号）在 `options.ts` |
| `content/validate.ts`、`content/validators/` | 内容校验层 V1 到 V10（发行工程第 7.4 节）：`node tools/content/validate.ts` 校验 `data/`（`--milestone M0` 到 `M6` 切换里程碑门槛，`--batch <批次名>` 按暂存批次合入后的样子校验，`--only V1,V5`，`--warnings` 另列警告，`--json <文件>`）；全绿退出码 0。校验器是纯函数，与 `tests/content_validation.test.ts`、导入工具和编辑器的批次视图共用；复用 `validateContent` 与各 pack 校验（含 `atlasProblems`）、外观的 `appearanceProblems`、注册表的 `registryProblems`、揭示台账的 `findLeaks`、编辑器的任务与剧情图分析、素材管线的 `uncoveredContent`；引用字段表在 `src/content/references.ts`，实体种类表在 `src/content/entity_kinds.ts`（与内容 ID 守卫共用）；专有名词清单在 `content/names/`，已审例外在 `validators/*_reviewed.json`、`namespace_legacy.json`（到期即阻断，失效条目报错） |
| `content/import_catalog.ts`、`content/catalog/`、`content/mappings/` | 内容导入批次（发行工程第 7.1、7.3 节）：`node tools/content/import_catalog.ts mappings`、`extract --mapping <映射> --batch content_<幕>_<类别>_<两位序号> [--ids a,b]`（立包与抽取，暂存到 `data/_staging/<批次>.json`，列出未映射的列与待补字段）、`fill`（补全）、`validate`（V1 到 V10）、`promote`（合入 `data/`，批次记录存 `data/_batches/<批次>.json`，删除暂存文件）、`verify --note`（验证）、`report`（批次报告）、`status`；映射按目录表格声明式编写（`mappings/<目录>.ts`），解析引擎通用（`catalog/markdown.ts`、`parsers.ts`、`mapping.ts`），批次的差异、叠加与合入在 `catalog/batch.ts`；`data/_staging/index.json` 列出全部批次供编辑器批次视图读取 |
| `assets/` | AI 生成素材的导入管线（美术方案第 13 节、音频方向第 8、9 节）：`register`、`import`、`atlas`、`check` 四个入口（`npm run assets:register` 等，用仓库根的 tsx 运行），纯逻辑核心在 `assets/core/`（自写 PNG 编解码、抠色、切格、像素网格、色板量化、描边、锚点、帧、检查、图集、联系表）与 `assets/core/audio/`（拼接与切分、循环接缝、BS.1770 响度与真峰值、限幅、Ogg 编码）；同一原图同一工具版本得到同一结果，`check` 给出原因码，`--mark` 才改状态 |
| `gate.ts`、`gate/` | 本地全量门：禁用字符扫描、改动文件的 Biome 检查、类型检查、测试、提示词库核对、构建，`--full` 另跑无模型通关；每步失败不中断，最后汇总各步退出码与耗时（`npm run gate`）；提交流水线 `.github/workflows/hakoniwa-ci.yml` 在 `hakoniwa/` 改动时运行它 |
